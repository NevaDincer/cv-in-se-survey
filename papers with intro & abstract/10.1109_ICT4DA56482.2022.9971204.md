# Automatic Code Generation From Low Fidelity Graphical User Interface Sketches Using Deep Learning

- **Year:** 2022
- **Venue/Source:** 2022 International Conference on Information and Communication Technology for Development for Africa (ICT4DA)
- **DOI:** 10.1109/ICT4DA56482.2022.9971204

## Metadata

- **se_area:** Development (UI implementation from design artifacts)
- **se_task:** Sketch-to-code generation, converting hand-drawn, low-fidelity UI wireframe sketches into client-side Bootstrap-based skeleton code
- **cv_technique:** object detection for UI component recognition, comparing three CNN-based detectors, Faster R-CNN with Inception V2 backbone, SSD MobileNet v2, and Faster R-CNN with Inception ResNet v2; semi-automatic image annotation via Canny edge detection, morphological rectangle operations, and contour extraction
- **platform:** Web (general website UI wireframes, rendered as Bootstrap HTML)
- **rationale:** ease of use (automates a manual, effort-intensive step in translating sketches to code); robustness (comparing multiple detector backbones to select the most accurate one, Inception ResNet v2); context-driven (a custom 14-class taxonomy derived from surveying real website UIs, rather than a generic fixed set)
- **artifact_type:** full-interface (whole sketched wireframe images are processed end to end, with detected components reassembled into a complete generated UI)
- **eval_method:** component recognition evaluated with PASCAL VOC metrics (precision, recall, mAP at 0.5 IoU) on a held-out test set of 112 images and 1,900 annotated components across the three detector backbones; code generation evaluated via a user study with 24 IT-background participants rating visual similarity between 10 generated UIs and their source sketches
- **challenges:** only 562 sketch images and 11,152 annotated components were collected in total, a relatively small custom dataset; hand-drawn sketches vary significantly in style and legibility; overlapping bounding boxes had to be resolved via a custom grid-based layout algorithm; final code-generation quality is bounded by upstream component-recognition accuracy

Notes explicit overlap with prior sketch-to-code work cited in its own related work, and its dataset is hosted on Kaggle. Worth checking against the other sketch-to-code papers already in this corpus for close duplication.

## Summary

Presents a two-stage system that converts hand-drawn, low-fidelity UI wireframe sketches into working Bootstrap-based client-side code. The first stage, component recognition, treats the problem as object detection over a custom taxonomy of 14 UI component classes (button, label, textbox, paragraph, textarea, checkbox, radio button, dropdown, image, link, table, carousel, pagination, heading), built from a dataset of 562 sketch images and 11,152 annotated components. Comparing three pretrained detectors, Faster R-CNN with Inception ResNet v2 achieves the best mAP (95.5%) after 50,000 training steps, against 91.2% and 87.5% for the alternatives. The second stage takes the detector's output and maps detected component bounding boxes onto an 80x80-grid, 12-column Bootstrap grid, then assembles a final HTML page from per-class code templates. A 24-participant visual-similarity user study across 10 test sketches shows generated UIs mostly match their source sketches correctly or partially, with only a small share of clear mismatches.
