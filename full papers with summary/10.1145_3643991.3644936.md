# GuiEvo: Automated Evolution of Mobile Application GUIs

- **Year:** 2024
- **Venue/Source:** MSR 2024 (21st International Conference on Mining Software Repositories)
- **DOI:** 10.1145/3643991.3644936

## Metadata

- **se_area:** Maintenance (GUI evolution / mobile app maintenance), with elements of development (code generation)
- **se_task:** Detecting and classifying GUI changes between an existing app release and a proposed mock-up for the next release, then automatically reconstructing updated GUI metadata (dynamic UI hierarchy) and implementing the identified changes in the app's source code.
- **cv_technique:** Multi-scale template matching; Structural Similarity Index (SSIM); Canny edge detection; image contouring; Euclidean-distance-based color difference measurement; Google Cloud Vision API (OCR-based text detection); a pre-trained CNN-based GUI component classifier reused from ReDraw for classifying newly added components.
- **platform:** Mobile (Android)
- **rationale:** 
- **artifact_type:** Full-interface (whole-screen screenshots and their entire UI hierarchies are analyzed and reconstructed, though the underlying change detection also produces localized, per-component analysis and cropped component images).
- **eval_method:** Empirical evaluation on 22 real GUI-change screen pairs manually curated (via two-author cross-validation, third-author tie-break) from 119 open-source Android apps (drawn from an F-Droid list of 987 apps, filtered by ≥1000 Google Play downloads) mined via GitHub and explored with the CrashScope automated input-generation tool, yielding 49,466 raw screen/metadata pairs before filtering. Metrics: accuracy, precision, recall, F1-score for GUI change-type identification (RQ1); tree edit distance (TED) for dynamic UI hierarchy reconstruction (RQ2); SSIM, MSE, and MAE for pixel-level comparison of recompiled apps' screenshots against mock-ups, benchmarked against the REMAUI baseline (RQ3); and TED comparison of recompiled UI hierarchies against REMAUI and ReDraw baselines (RQ4), evaluated for both manually-injected and GPT-4-injected code changes. Reported results: 87% app-wise accuracy/precision, 91% recall, 88% F1 for change detection; average TED of 5.9 for hierarchy reconstruction; average TED of 11.8 (manual) / 24.4 (GPT-4) versus 44.5 (REMAUI) and 55.2 (ReDraw); average SSIM of 0.99 versus REMAUI's 0.77.
- **challenges:** The authors explicitly report that GuiEvo's added-component classification (reused from ReDraw's CNN classifier) sometimes mispredicts the component's class/type even when correctly detecting that a component was added (e.g., a "TextView" misclassified as "ImageView" in the Hangar app case study). They also note that only 5 of the 22 evaluated apps could be successfully recompiled after code changes were applied, limiting the scope of the code-implementation (RQ3/RQ4) evaluation, and that similarity/matching thresholds (e.g., 0.7–0.95 depending on screen type) were empirically tuned on a small development dataset and must be manually selected by the developer per screen type, which could limit generalizability. ## Summary

GuiEvo is a fully automated tool for supporting the evolutionary maintenance of Android app GUIs by detecting and implementing changes between an app's current release and a mock-up of its next design. Given a screenshot, its uiautomator XML metadata, and a mock-up image, GuiEvo applies a pipeline of classical computer vision techniques (multi-scale template matching, SSIM-based similarity on Canny-edge images, image contouring, and Euclidean color-distance measurement) to identify which GUI components persist, are removed, or are newly added between the two screens, and classifies each detected change into text, layout, or resource categories using OCR (Google Cloud Vision) and a reused ReDraw component classifier. It then automatically reconstructs an updated dynamic UI hierarchy (XML) reflecting the mock-up and either hands this off to GPT-4 or a developer to implement the changes in source code. The main contribution is bridging a gap in prior GUI-evolution and mock-up-to-code tools: GuiEvo is the first to reconcile an existing implementation with a mock-up that has no associated metadata, purely from pixel data, and to update existing GUI code rather than regenerate it from scratch. A distinctive detail is its evaluation pipeline recompiling actual Android apps after code changes and comparing rendered screenshots (SSIM/MSE/MAE) and hierarchies (tree edit distance) against REMAUI and ReDraw baselines, showing substantially closer structural and visual fidelity to the target mock-ups (average TED 5.9–24.4 vs. 44.5–55.2 for baselines).
