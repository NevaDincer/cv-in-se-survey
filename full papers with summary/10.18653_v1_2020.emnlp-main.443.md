# Widget Captioning: Generating Natural Language Description for Mobile User Interface Elements

- **Year:** 2020
- **Venue/Source:** Proceedings of the 2020 Conference on Empirical Methods in Natural Language Processing (EMNLP 2020), pp. 5495-5510
- **DOI:** 10.18653/v1/2020.emnlp-main.443

## Metadata

- **se_area:** Development / Maintenance (accessibility annotation and repair tooling); see scope flag above. Not a conventional SE lifecycle paper
- **se_task:** Automatic generation of natural-language captions (alt-text-like descriptions) for mobile UI widgets that are missing accessibility labels, to support screen readers and language-based UI interaction
- **cv_technique:** CNN (7-layer ResNet-style image encoder) over a cropped, grayscale 64×64 pixel image of the target widget, combined with a Transformer encoder (over structural view-hierarchy features: text, type, clickability, bounding-box position, DOM tree position) and a Transformer decoder for caption generation
- **platform:** Mobile (Android; built on the RICO UI corpus, expanded with an additional 12K crawled screens)
- **rationale:** Context-driven (the paper's central empirical finding is that screen/view-hierarchy context is necessary to disambiguate captions, e.g., two visually identical magnifier icons need "search contact" vs. "search music" depending on screen context); Ease of use (automates a captioning task that otherwise requires manual developer effort, addressing a documented widespread accessibility gap)
- **artifact_type:** Localized (per-element cropped image) enriched with screen-level structural context, not full-interface, not temporal, not natural (touch/gesture) input
- **eval_method:** Automatic captioning metrics (BLEU-1, BLEU-2, ROUGE-L, CIDEr, METEOR, SPICE) against a multi-reference human-authored test set (61,285 widgets / 162,859 captions, app-wise train/val/test split); human evaluation via crowd-worker endorsement rating (1+/2+/3+ raters agreeing); ablation study removing individual structural features
- **challenges:** Authors' own error analysis identifies three recurring failure modes: confusion by nearby elements on the same screen, confusion by visually similar-looking elements, and overly generic captions; long-tail/data-sparsity issues (a classification-over-fixed-vocabulary baseline performs worse than sequence decoding precisely because predicate+object combinations form long-tail phrases); missing or inaccurate view hierarchies had to be filtered out via manual crowd verification before use; captions are inherently vision-impaired-user-facing, so unlike many CV-in-SE tasks the "user" of the CV output is an end user, not a developer/tester.

## Scope note

This article's fit with the CV-in-SE survey is arguable. It is an HCI, accessibility, and multimodal-NLP paper (EMNLP, not an SE venue), and its central contribution is a captioning dataset and model, not a software engineering process, tool, or lifecycle activity in the usual sense. The CV component, a ResNet image encoder over cropped widget screenshots, is real but is only one of two input modalities, and the paper leans more heavily on structural and view-hierarchy encoding (Transformer) than on vision. Relevance to SE comes through accessibility repair and annotation tooling, a maintenance and development task, though that framing is looser than papers whose primary focus is explicitly software engineering.

## Summary

The paper introduces widget captioning: given a UI element's cropped screenshot and its structural view-hierarchy properties (text, type, clickability, bounding box, tree position), generate a short natural-language caption describing its function, for use by accessibility services like TalkBack. The authors first build a large corpus from RICO plus newly crawled screens, then have crowd workers caption widgets whose accessibility fields (contentDescription/text) are missing, finding that missing captions affect the majority of image-based widgets (95% of floating action buttons, 83% of image views) and even more than half of switches, checkboxes, and toggle buttons. They collect 162,859 captions for 61,285 widgets across 21,750 screens from 6,470 apps. Their best model ("Pixel+Local+Context") encodes each element's cropped image with a ResNet CNN and its structural properties with a Transformer encoder that attends across all elements on the same screen, providing the disambiguating context each caption needs, then decodes captions with a Transformer decoder, training all screen-cohabiting missing-caption elements in parallel. This configuration outperforms image-only and element-only-structure baselines across all six standard captioning metrics, and especially on a Predicate+Object phrase subset where screen context is most needed (e.g., disambiguating "search location" vs. "search music" for visually identical magnifier icons). Human raters endorsed 78.6% of the full model's captions as correct versus 62.4% for an image-only baseline. The paper is a dataset+model contribution for accessibility/HCI rather than a software-engineering-process paper per se, hence the scope flag above.
