# Transforming Ideas into Code: Visual Sketching for ML Development

- **Year:** 2023
- **Venue/Source:** Companion Proceedings of the 2023 ACM SIGPLAN International Conference on Systems, Programming, Languages, and Applications: Software for Humanity (SPLASH Companion '23)
- **DOI:** 10.1145/3618305.3623588

## Metadata

- **se_area:** development (code generation/authoring support); positioned as a new "Sketch Programming" paradigm for early planning and later documentation
- **se_task:** generating executable code (Jupyter notebooks) for ML/data-science workflows from hand-drawn sketches; sketch-to-code traceability/linking
- **cv_technique:** image segmentation and classification models (planned/prototype-level) to identify sketch symbols (e.g., plots, neural network diagrams), arrows, and text regions in hand-drawn images; not a single named algorithm, described generically as leveraging computer vision segmentation/classification advances
- **platform:** general / desktop (Jupyter notebook environment); domain-specific to ML and data-science application development rather than mobile/web/game UI
- **rationale:** ease of use (lowers the barrier for novice ML developers/students to go from mental model to code); context-driven (captures spatial/diagrammatic information, e.g., system architecture, data pipelines, that text-only code generation tools cannot express); the paper also motivates via reducing time-to-code and improving code understanding/traceability
- **artifact_type:** natural input (hand-drawn sketches as the primary artifact) that is converted into full-interface-adjacent code artifacts (Jupyter notebook cells); not a screenshot- or GUI-based artifact
- **eval_method:** planned mixed-methods evaluation (not yet executed at time of writing): interviews and surveys with ML developers/data scientists about sketching practices; iterative prototype releases with user feedback; planned quantitative comparison of synthetic vs. real hand-drawn sketch datasets for training CV models; planned productivity study (task completion time, code understanding via bug-injection tests) and code-quality study
- **challenges:** CV must robustly interpret ambiguous, informal hand-drawn notations and reconstruct clean diagrams; scarcity of large, diverse annotated hand-drawn sketch datasets, motivating a synthetic-data-generation approach whose fidelity to real sketches is itself an untested hypothesis; designing a Domain-Specific Language (DSL) that balances simplicity and expressiveness while bridging visual and code semantics; needs real-time conversion and robust handling of complex/multi-element diagrams; overall the work is at an early, low-fidelity prototype stage with no reported accuracy numbers.

## Scope note

## Summary

This SPLASH Companion doctoral-symposium paper presents an early-stage research proposal (not a completed, evaluated system) for a "Sketch Programming" code assistant aimed at ML and data-science developers. The core idea is to let developers hand-draw diagrams, for example sketches representing a neural network architecture or a data pipeline, and have a tool convert these into functional Jupyter notebook code, using computer vision to segment the sketch into symbols, arrows, and text, and an LLM to generate code from the extracted description of each symbol. The author frames this as bridging two previously separate research threads: HCI work on how developers use sketches as externalized mental models (during planning and later as documentation), and "Img2Code" research that converts images into structured formats like LaTeX or HTML. The proposed contribution is threefold: an improved tool, new empirical knowledge about how ML developers sketch and express intent, and a new programming-assistant paradigm distinct from natural-language-to-code approaches. The paper's evaluation methodology is prospective: it plans productivity studies (time-to-code, later code comprehension via injected bugs), a code-quality study, and validation of a synthetic-sketch-generation approach meant to overcome the scarcity of annotated real-world hand-drawn training data, comparing model metrics on synthetic vs. real test sets. Because the current prototype has only "limited accuracy" and no quantitative results are reported, this paper is best read as a research vision/roadmap rather than a validated CV-in-SE technique, which is why it has been flagged above for a scope check.
