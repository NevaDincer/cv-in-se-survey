# Feature Matching-based Approaches to Improve the Robustness of Android Visual GUI Testing

- **Year:** 2021 (published November 2021; article number 21)
- **Venue/Source:** ACM Transactions on Software Engineering and Methodology (TOSEM), Vol. 31, No. 2, Article 21
- **DOI:** 10.1145/3477427

## Metadata

- **se_area:** Testing
- **se_task:** Visual GUI Testing (VGT) for Android apps, specifically robust widget/locator identification and matching across heterogeneous devices (device/hardware fragmentation), to make record-and-replay visual test scripts portable and to serve as visual oracles for GUI interaction execution
- **cv_technique:** Local feature-matching algorithms: SIFT, SURF, and AKAZE keypoint detectors/descriptors, combined with brute-force keypoint matching, RANSAC-based outlier removal (Graph-Cut RANSAC variant) for geometrically consistent matches, and MeanShift clustering to localize the final interaction coordinates; compared against classical template (pixel-to-pixel) matching used by baseline tools Sikuli and EyeAutomate
- **platform:** Mobile (Android; emulated Android Virtual Devices of varying screen sizes/pixel densities, screenshots captured via ADB rather than host-desktop renderings)
- **rationale:** Robustness (the primary motivation is improving portability of visual locators/oracles across device fragmentation, i.e., different screen sizes, resolutions, pixel densities); context-driven (Fullscreen variant exploits whole-screen visual context and RANSAC's spatially-consistent homography to disambiguate repeated/similar widgets, which cropped-widget-only approaches cannot do)
- **artifact_type:** Full-interface (Fullscreen algorithm operates on entire screen screenshots plus a bounding box) and localized (Cropped algorithm operates on a cropped widget image only, matching the input format used by prior tools like Sikuli/EyeAutomate); both are static single-screenshot comparisons, not temporal/video data
- **eval_method:** Two-part empirical evaluation with PERM-ANOVA statistical testing and Bonferroni-corrected post-hoc pairwise permutation tests plus Cliff's delta effect sizes. (1) RQ1: large-scale, automated precision/recall/execution-time evaluation of matching-algorithm × descriptor combinations across ~95 real Android apps (Writing/Notes category, mined from UpToDown) rendered on 3 source × 13 target devices (39 pairs), using ground truth derived from uiautomator screen-hierarchy dumps (widget IDs/text/content-desc), contributing the new DatAndroid dataset (~100 apps × 14 devices, ~1,400 combinations). (2) RQ2: application-level evaluation on two real open-source apps (PassAndroid, AntennaPod) with hand-built Appium test suites (190/306 interactions), executing test suites across 14 emulated devices and measuring % correctly executed interactions, % correctly found locators, % passing tests, and execution time per interaction, compared against state-of-the-art VGT tools Sikuli and (a from-scratch OpenCV reimplementation matching) EyeAutomate.
- **challenges:** Authors report: higher computational cost of the Fullscreen algorithm vs. Cropped and vs. template-matching baselines (Sikuli/EyeAutomate are much faster per interaction, e.g., ~370–550ms vs. 1.2–2.7s); false positives/negatives from widgets containing long text strings, which generate many keypoints and can be matched to the wrong word/location, degrading RANSAC's outlier-filtering effectiveness; the Cropped algorithm can fail outright when repeated/similar widgets exist on the target screen since it lacks whole-screen spatial context; inherent limits from Android's own layout adaptation (widgets resized, regrouped, or hidden behind scrolling on smaller screens), meaning a non-trivial percentage of source widgets simply have no counterpart on some target devices regardless of matching-algorithm quality (up to ~10%+ for very disparate device pairs like Nexus S vs. Pixel 3 XL); generalization limited to a single app category and to 14 default Android-Studio emulated devices (not real hardware or heavily customized OS/GUI skins); need for future integration of semantic (text/content) interpretation alongside purely visual features to address remaining edge cases.

## Summary

This paper targets the well-documented "graphical fragility" and hardware-fragmentation problems that plague Visual GUI Testing (VGT) tools for Android, where widgets captured as visual locators on one device often fail to be recognized on a differently-sized/resolution target device, breaking record-and-replay test portability. The authors design and compare two feature-matching-based locator-matching algorithms: Fullscreen (matches keypoints across entire source and target screenshots, then uses a source widget's bounding box plus RANSAC-filtered, spatially-consistent matches and MeanShift clustering to localize it) and Cropped (matches only a pre-cropped widget image against the target screen, mirroring how existing tools like Sikuli work), each evaluated with three classical local feature descriptors (SIFT, SURF, AKAZE). Through a large, automated, ground-truth-driven study across ~95 apps and 14 emulated devices (contributing the new public DatAndroid benchmark), they find the Fullscreen algorithm is substantially more robust than Cropped because RANSAC's homography estimation implicitly favors spatially coherent matches, letting it correctly disambiguate repeated or near-identical widgets (e.g., calendar day numbers) that trip up Cropped-style matching; SIFT and SURF clearly outperform AKAZE and template matching. On two real apps with hand-authored Appium test suites, the best feature-matching configurations (e.g., SIFT/SURF-Fullscreen) raise the percentage of fully passing, portable test cases to ~75–77%, versus only ~11–17% for the state-of-the-art commercial/open-source VGT tools Sikuli and EyeAutomate, a gain of more than 30 percentage points, though at the cost of noticeably higher per-interaction execution time. A particularly notable methodological contribution is bypassing the host-desktop AVD rendering layer entirely by capturing screenshots directly via ADB, removing an additional source of visual distortion that affects prior tools.
