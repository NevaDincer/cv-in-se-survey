# Widget Detection-based Testing for Industrial Mobile Games

- **Year:** 2023
- **Venue/Source:** 2023 IEEE/ACM 45th International Conference on Software Engineering: Software Engineering in Practice (ICSE-SEIP)
- **DOI:** 10.1109/ICSE-SEIP58684.2023.00021

## Metadata

- **se_area:** testing
- **se_task:** Automated GUI testing of industrial mobile games via widget detection: (1) benchmarking object-detection techniques for GUI widget recognition on a new large-scale mobile-game GUI dataset, and (2) building and deploying a widget-detection-based automated exploratory test framework (WDTest) that uses only screenshots as input to drive click-based random exploration and measure UI coverage, industrially deployed at NetEase Games.
- **cv_technique:** Faster R-CNN (two-stage anchor-based CNN object detector); YOLOv3; YOLOv5 (one-stage anchor-based detectors); CenterNet (one-stage anchor-free keypoint-based detector); CenterNet2 (two-stage anchor-free detector); Xianyu (traditional CV pipeline: image binarization, edge detection, contour extraction, flood-fill merging); UIED (hybrid detector combining OCR-based text-element detection with a deep-learning-based non-text GUI element detector); perceptual hashing (used downstream to detect "unique" UI screens during testing, not for widget detection itself); traditional image-matching/template-matching based GUI testing (evaluated early on and found inadequate, e.g. edge-detection-based matching).
- **platform:** mobile (Android mobile games; generalization also evaluated on general-purpose mobile apps)
- **rationale:** Primarily robustness/compatibility and non-intrusiveness: the industrial requirement was a testing technique that works across many device resolutions/platforms without instrumenting the game's source code (unlike engine-specific hooks such as POCO), motivating a purely screenshot-based, vision-driven approach. Context-driven necessity also plays a role: mobile games render GUIs via game engines rather than native OS widgets, so accessibility-tree/DOM-based testing (used for ordinary apps) is unavailable, forcing reliance on CV-based widget detection directly on screenshots. Ease of use / deployability is also cited (developers rated compatibility and ease-of-use highly), while functional/semantic testing was reported as a weak point.
- **artifact_type:** localized (bounding-box detection of individual GUI widgets/buttons within full screenshots, used to drive click actions); the framework operates on full-interface screenshots as input but the CV output is per-widget localization (12 widget categories, e.g., Button, Checkmark, Dropdown, ScrollView, Slider, Toggle Button, Background Return, InputField, LiveStream, Locked Button, Scrollbar, Horizontal ScrollView).
- **eval_method:** Two evaluation stages. (1) Widget-detection benchmark: a newly constructed dataset of 14,442 GUI screenshots / 227,221 annotated widgets across 33 mobile games (12 publishers, 11 game genres), manually annotated/cross-checked by 8 recruited developers plus the first four authors; split 8:1:1 train/val/test (no game split across sets); 7 detection techniques (Faster R-CNN, YOLOv3, YOLOv5, CenterNet, CenterNet2, Xianyu, UIED) trained for 45,000 iterations and evaluated with Precision/Recall/F1 at IoU thresholds 0.5/0.75/0.95; generalization also tested on 2 general (non-game) mobile apps (NetEase Cloud Music, Weipinhui, 100 labeled screenshots) comparing F1 and average inference time. (2) End-to-end testing evaluation: WDTest instantiated with each detection backbone (C-Test, C2-Test, F-Test, Y3-Test, Y5-Test, U-Test, X-Test) compared against Monkey (baseline random tool, 200ms throttle) and a human tester (H-Test) on 3 unseen mobile games (Apex Legends Mobile, GI4, D10) on a real Samsung S20 FE (Android 12) device via Airtest/ADB; metric = average number of unique UIs (via perceptual hashing, hash distance <0.5) covered per hour and execution rounds, each run repeated 3 times. (3) Practitioner survey: 42 NetEase Games testers (21 script-based, 21 manual, testing experience 1.5-10 years, median 3.4) answered an 8-question questionnaire (time saved, problems encountered, advantages/disadvantages, general-app vs. game differences, ideal tool features). (4) Industrial deployment record: WDTest integrated into NetEase's "Quick and Intelligent Compatibility Testing" pipeline, used on 18+ games pre-release, found 19 crashes (16 confirmed/fixed).
- **challenges:** Explicitly reported by the authors: (1) Faster R-CNN/CenterNet2 and other deep detectors miss widgets that are closely packed together (e.g., card decks, in-game stores), producing false negatives that degrade the whole pipeline. (2) Traditional/old-fashioned CV techniques (Xianyu, image-matching approaches) perform poorly on industrial game UIs because of high visual/image complexity (quantified via higher spatial-information/SImean than the RICO dataset) and fancy visual effects; an early attempt at template/image-matching-based testing achieved only 3.2% accuracy. (3) Dynamic/nondeterministic resource loading screens (10+ seconds) invalidate actions during loading, hurting coverage. (4) The randomized click-based action-planning strategy lacks semantic understanding of widgets/scenarios, so WDTest can get stuck in a scenario requiring a specific sequence of actions, and 57% of testers were dissatisfied with it for functional testing (it cannot target a designated button to test a specific game outcome). (5) UIED's OCR component produces many false positives in games because in-game text is often non-clickable background/lore text, unlike in general apps. (6) Threats to validity acknowledged by the authors: potential selection bias in the 33 chosen games and 7 chosen detection models; subjectivity/noise in manual widget labeling (mitigated by triple cross-checking with 8 developers); randomness in the testing process (mitigated by 3 repeated runs).

## Summary

This paper reports an industrial experience study on applying computer-vision-based widget detection to automated GUI testing of mobile games at NetEase Games. The authors first construct by far the largest GUI dataset for mobile games (14,442 screenshots, 227,221 widgets across 33 games spanning 11 genres), addressing the small scale and limited diversity of prior game-GUI datasets. They benchmark seven representative widget/object-detection techniques (Faster R-CNN, YOLOv3, YOLOv5, CenterNet, CenterNet2, Xianyu, UIED) at multiple IoU thresholds and show models trained on the new dataset transfer reasonably well to general (non-game) mobile apps without fine-tuning. Using the best-performing detector (Faster R-CNN) as backbone, they build WDTest, a screenshot-only, non-intrusive automated testing framework that randomly selects and clicks detected widgets (via the Airtest automation library) and measures coverage as unique UIs seen per hour (via perceptual hashing); WDTest achieves roughly 3x the unique-UI coverage of the Monkey baseline on three unseen commercial games, though it still falls well short of a human tester. A 42-participant practitioner survey at NetEase further finds testers value WDTest's device/resolution compatibility and ease of use, but are largely dissatisfied with its purely randomized clicking for functional testing due to lack of semantic action selection. A notable detail: WDTest has been deployed in NetEase's production compatibility-testing pipeline across 18+ games and found 19 real crashes (16 confirmed/fixed), and the paper documents an earlier failed attempt at traditional image-matching-based testing (3.2% accuracy) that motivated the shift to deep-learning-based detection.
