# An Approach to GUI Test Scenario Generation Using Machine Learning

- **Year:** 2022
- **Venue/Source:** 2022 IEEE International Conference On Artificial Intelligence Testing (AITest)
- **DOI:** 10.1109/AITest55621.2022.00020

## Metadata

- **se_area:** Testing (with an element of design/requirements, since input is a mockup diagram rather than a live app)
- **se_task:** GUI test scenario generation for (AI-powered) mobile applications; GUI element detection and screen/relationship (node and link) classification from mockup diagrams
- **cv_technique:** YOLOv5 (object detection); Detectron2 (Base-RCNN-FPN, i.e., Faster R-CNN with Feature Pyramid Network); EfficientDet-D0
- **platform:** Mobile (Android/iOS intelligent mobile apps; case studies include a math-solving app and the Hound voice-assistant app)
- **rationale:** Ease of use / automation (reduces manual effort in designing test scenarios); context-driven (classifies elements/screens as AI vs. non-AI to reflect app-specific functional semantics); robustness (comparison of multiple detection architectures)
- **artifact_type:** Localized (bounding-box detection and classification of individual GUI elements/buttons) combined with full-interface/temporal (whole mockup screens represented as graph nodes, with DFS-traversed paths representing temporal test scenarios)
- **eval_method:** Precision/Recall via confusion matrix; training/validation loss curves (box loss, objectness loss, classification loss) tracked with TensorBoard across 100-150 epochs; accuracy comparison table (72% YOLOv5 GUI-detection precision; 79% YOLOv5 relationship-classification accuracy; ~67-75% overall element detection/classification after fine-tuning with added training data); qualitative demonstration of graph-based scenario generation (NetworkX + DFS) with a web-based scenario selector.
- **challenges:** Relatively modest detection accuracy (67-75%) even after fine-tuning; small custom-labeled dataset (1.1k training images, 123 validation/test each, 128 labeled elements, later extended by 249 images); dependence on manually created/annotated mockup diagrams to build the relationship database rather than fully automatic app crawling; generalizability of AI/non-AI node and button classification across diverse app domains.

## Summary

This paper proposes a four-stage pipeline that uses deep-learning object detection to automatically generate GUI test scenarios for AI-powered mobile applications, starting from mockup diagrams rather than a running app. The first stage, GUI element detection, trains and compares YOLOv5, Detectron2, and EfficientDet-D0 to locate and label UI elements, buttons, input and output fields, camera and AI controls, on individual screenshots. The second stage reuses the same three detectors to classify whole screens as AI or non-AI nodes, and their buttons as AI-function or non-AI-function elements. The third stage builds a relationship database from source and target screen pairs plus transition logic to determine edge types between screens. The fourth stage assembles the classified nodes, elements, and links into a directed graph visualized with NetworkX and Plotly, over which a depth-first search enumerates possible navigation paths as candidate test scenarios, exposed through a web interface where testers can search paths and inspect each node's GUI elements. The models reach modest but improving accuracy: element detection precision climbs from 60% to 75% after adding training data, and relationship classification lands around 79% for YOLOv5. What sets this paper apart from prior GUI-detection or prototyping work is combining element and relationship detection with automatic, graph-based test scenario enumeration, rather than stopping at UI element recognition or code generation.
