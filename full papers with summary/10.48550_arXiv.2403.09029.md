# Unlocking the conversion of Web Screenshots into HTML Code with the WebSight Dataset

- **Year:** 2024
- **Venue/Source:** arXiv technical report (Hugging Face), arXiv:2403.09029 [cs.HC]
- **DOI:** 10.48550/arXiv.2403.09029

## Metadata

- **se_area:** Development (front-end/UI implementation: screenshot-to-code)
- **se_task:** Automatic generation of functional HTML + Tailwind CSS code from a screenshot (or hand-drawn sketch) of a web page
- **cv_technique:** End-to-end vision-language model (Mistral-7B language backbone + SigLIP-SO400M vision encoder, Patch n' Pack strategy for variable-resolution/aspect-ratio image input, OCR capability inherited from pretraining); fine-tuned via parameter-efficient DoRA (rank 64); no separate/explicit CV algorithm (e.g., no standalone object detector or segmentation model) is used or described
- **platform:** Web
- **rationale:** Ease of use (unblocks no-code tooling for UI/web developers, e.g., Figma plugins); robustness (Patch n' Pack preserves arbitrary image resolutions/aspect ratios up to 980px per side; model shown to generalize to out-of-distribution inputs such as a handwritten sketch)
- **artifact_type:** Full-interface (whole webpage screenshot to a complete, self-contained HTML page); one qualitative example also demonstrates natural input (a handwritten paper sketch converted to a styled webpage)
- **eval_method:** Purely qualitative: visual side-by-side comparison of original screenshots vs. rendered generated code (Figures 1, 3, 4); explicit note that validation loss was found to be a poor proxy for real-world generation quality, so checkpoint selection was done by manual inspection; no quantitative accuracy, precision/recall, or benchmark scores are reported in this report itself (authors cite that a related benchmark, Design2Code, was built by other researchers using the dataset's earlier version)
- **challenges:** No quantitative evaluation metric for the fine-tuned model is presented in this paper; model fails on complex layouts, pages with excessive text, or designs highly divergent from the synthetic training distribution; generated elements (images, text, buttons) sometimes fail to render due to syntax errors or same-colour text/background bugs, indicating incomplete mastery of Tailwind CSS syntax (attributed to Tailwind's underrepresentation in the base LLM's pretraining data relative to traditional CSS); dataset itself relies on synthetic LLM-generated HTML rather than real-world webpages, which may limit ecological validity

## Scope note

This paper's core contribution is a synthetic dataset of 2 million HTML and screenshot pairs and the fine-tuning of a general-purpose vision-language model, not a discrete or analyzed computer vision technique. The CV component is essentially the vision encoder (SigLIP) embedded inside a multimodal LLM used end to end for image-to-code generation; the paper does not isolate, evaluate, or discuss CV methodology, no object detection, no segmentation, no explicit visual-feature analysis, the way most CV-in-SE papers do. It is also not peer reviewed, being an arXiv technical report rather than a published paper.

## Summary

WebSight is a synthetic dataset of 2 million paired HTML/Tailwind-CSS code snippets and their rendered screenshots, created to address the shortage of clean, self-contained screenshot-HTML pairs for training vision-language models on the screenshot-to-code task. Rather than scraping noisy real-world HTML (which is often long, dependency-laden, and hard for models to learn from), the authors generate website concepts with Mistral-7B-Instruct and then synthesize corresponding HTML+Tailwind CSS code with DeepSeek-Coder-33B-instruct, inserting contextually relevant stock images via Unsplash's keyword-based image API and rendering screenshots with Playwright. They fine-tune a forthcoming foundation VLM (Mistral-7B + SigLIP-SO400M vision encoder, variable-resolution "Patch n' Pack" input) using parameter-efficient DoRA fine-tuning to produce a specialized model called Sightseer. Sightseer can convert simple website screenshots into visually similar, functional HTML, accurately preserving short text and page structure, and shows some generalization to out-of-distribution inputs, including converting a handwritten webpage sketch into a working styled page. However, evaluation is entirely qualitative in this report, and the authors document clear failure modes: complex layouts, dense text, and non-standard designs degrade output quality, and generated code sometimes contains rendering bugs (invisible text/buttons, malformed Tailwind syntax) attributed to Tailwind CSS's relative scarcity in the base LLM's pretraining corpus compared to traditional CSS. The dataset and (an earlier v0.1 version of) the model have already been used by other researchers to build the Design2Code benchmark.
