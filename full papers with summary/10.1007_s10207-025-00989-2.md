# Software vulnerability detection under poisoning attacks using CNN-based image processing

- **Year:** 2025
- **Venue/Source:** International Journal of Information Security, 24:75
- **DOI:** 10.1007/s10207-025-00989-2

## Metadata

- **se_area:** development and testing (source code vulnerability detection, applied as a static analysis step over existing code)
- **se_task:** binary classification of source code samples as vulnerable or non-vulnerable across nine CWE types, with a second focus on evaluating how robust that classifier is to data-poisoning (backdoor) attacks during training
- **cv_technique:** a custom CNN with three convolutional layers (32, 32, 64 filters) each followed by ReLU and 2x2 max pooling, dropout after the last convolutional layer, a 128-neuron fully connected layer with ReLU, and a final 2-neuron softmax output layer; trained with the Adam optimizer (learning rate 0.001, dropout 0.4, 15 epochs). This is standard image classification, not object detection or segmentation; the novelty is entirely in how the input images are constructed, not in the CV architecture.
- **platform:** general (source code, not a GUI or device platform; languages tested are C# and PHP, with C/C++ tried and rejected)
- **rationale:** context-driven (code samples are converted into images specifically so a general-purpose CNN image classifier can be applied without engineering per-language code features); ease of use (the authors state explicitly that this approach removes the need for feature extraction, dependency-graph construction, or tokenization that other vulnerability detectors require, reducing time and effort in code processing)
- **artifact_type:** synthetic/derived image, not a captured visual artifact. Each code sample is converted to a UTF-8 byte array, reshaped into a square matrix (truncating leftover bytes), rendered as a grayscale image, and resized to 224x224. RGB encoding was tried and discarded for giving worse results.
- **eval_method:** SARD (Software Assurance Reference Dataset) code samples across nine CWE types in C# (about 32,000 samples) and PHP (about 290,000 samples), split 60/40 train/test with balanced vulnerable/non-vulnerable classes, each configuration run 5 times over 3 random splits (15 runs averaged) for baseline and for poisoned conditions. Metrics: accuracy, TPR/TNR, FPR/FNR, and the difference in these metrics before versus after poisoning. Baseline accuracy ranges from 82% to 99% across CWEs and languages. Three backdoor poisoning attacks were tested (function renaming, deadcode insertion, space insertion) at 10/25/40% poisoning rates, and two existing poison-detection methods (spectral signatures, activation clustering) were applied to check whether the poisoned samples could be caught; neither reliably detected them, so the attacks are described as stealthy. PHP was found to be generally more resilient to the attacks than C#. The approach's baseline accuracy is compared narratively against other vulnerability detectors in the literature (Table 9) rather than run head to head on the same data.
- **challenges:** the authors report that the method does not generalize to C/C++: baseline accuracy stayed under 70% for nearly every CWE tested on the DiverseVul and CVEfixes datasets (one exception at 72%), and they trace this to C/C++ code having substantially higher cyclomatic complexity and lines of code than the C# and PHP samples the method works on (R^2 = 0.82 between these code metrics and accuracy). Other stated limitations: the byte-to-square-image conversion discards trailing bytes (average loss of 2.4% to 4.9% of a sample's bytes); the image construction method itself is simple and other encodings could be explored; CNN was chosen because it is the standard technique for image classification, but the authors note large language models could be tried, at higher computational cost; the system only performs static analysis and has no dynamic component; and the two poisoning-detection algorithms tested (spectral signatures, activation clustering) failed to reliably flag the poisoned training samples, meaning defenders currently have no strong method for catching these attacks before training.

## Scope note

This is a code-as-image application rather than a GUI or screenshot-based one. The visual artifact being classified is a synthetic grayscale image generated from raw source-code bytes, not a rendered interface, diagram, or captured user-facing screen. The CNN classification technique itself is genuinely central to the paper's contribution (it is the entire detection mechanism, not an auxiliary step), so it is included on that basis, but it sits at the edge of a corpus otherwise focused on visual software artifacts that a human would actually look at.

## Summary

This paper proposes IVul, a vulnerability detector that converts source code samples directly into grayscale images and classifies them with a CNN, then studies how that detector holds up against data-poisoning attacks. Each code sample is turned into a UTF-8 byte array, reshaped into a square matrix (with truncation of any excess bytes), rendered as a grayscale image, and resized to 224x224 before being passed through a CNN with three convolutional layers, max pooling, dropout, and a softmax output over two classes. The main argument for this design is that it avoids the feature engineering, tokenization, or dependency-graph construction that other ML-based vulnerability detectors typically require. IVul is evaluated on SARD code samples across nine CWE categories in C# and PHP, reaching baseline accuracy between 82% and 99%, described as comparable to or better than prior state-of-the-art detectors. The paper's core contribution is testing IVul against three backdoor poisoning attacks (function renaming, deadcode insertion, space insertion) at several poisoning rates, measuring the resulting drop in accuracy and change in false positive and false negative rates under two threat models. Results show PHP is generally more resilient than C# to these attacks, and that two existing poison-detection techniques, spectral signatures and activation clustering, fail to reliably identify the poisoned samples, meaning the attacks go largely unnoticed. A separate analysis finds the image-based approach does not transfer to C/C++ code, which the authors attribute to higher code complexity and length in that language compared to C# and PHP.
