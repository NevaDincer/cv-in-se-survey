# Seenomaly: Vision-Based Linting of GUI Animation Effects Against Design-Don't Guidelines

- **Year:** 2020
- **Venue/Source:** 42nd International Conference on Software Engineering (ICSE '20), Seoul, Republic of Korea
- **DOI:** 10.1145/3377811.3380411

## Metadata

- **se_area:** Testing / Maintenance (GUI linting, a static/dynamic quality-assurance step analogous to lint tools, applied to GUI design compliance rather than source code)
- **se_task:** GUI animation linting: automatically detecting violations of GUI animation design-don't guidelines (e.g., Android Material Design) in mobile apps, framed as a multi-class GUI-animation classification / few-shot anomaly-retrieval problem
- **cv_technique:** Unsupervised adversarial autoencoder combining: 3D Convolutional Neural Networks (3D-CNN) for spatio-temporal feature extraction; a Variational Autoencoder (VAE) for dimensionality reduction/reconstruction; a Generative Adversarial Network (GAN, DCGAN-style discriminator) for adversarial training to sharpen reconstructions; an additional feature encoder network for more abstract latent features; k-Nearest Neighbor (KNN) search over the learned latent feature space for classification/linting
- **platform:** Mobile (Android applications; GUI animations captured as screencasts/GIF sequences of screenshots)
- **rationale:** Robustness (handles large visual/content diversity across apps without needing large labeled datasets, via few-shot learning through unsupervised representation learning); ease of use / practicality (avoids manual rule engineering for animation guidelines that are hard to express as static code-analysis rules)
- **artifact_type:** Temporal (GUI animation screencasts, sequences of 8 screenshots/frames captured at 5 fps per user action, treated as spatio-temporal video-like data, not single static screenshots)
- **eval_method:** Quantitative classification metrics (Accuracy, Precision, Recall, F1-score) via KNN search against: (1) a semi-automatically constructed synthetic dataset of 9,000 labeled GUI animations (1,000 per guideline across 9 design-don't guidelines) for large-scale KNN-parameter (T,K) sensitivity analysis and ablation of model components (VAE-only vs. VAE+GAN vs. VAE+FE vs. full model); (2) a manually curated real-world dataset of 225 labeled GUI animations (25 per guideline across 9 guidelines) for practical validation (RQ3); (3) cross-dataset (synthetic↔real) generalization experiments (RQ4) to test latent feature-space transferability; unsupervised training performed on 91,370 unlabeled real-application GUI animation screencasts derived from the Rico dataset.
- **challenges:** Authors report: limitations on simultaneous multiple-component animations (e.g., stacking multiple snackbars/banners) and instantaneous component animations (e.g., dialog popups with abrupt, minimal screen change), both of which are the hardest cases to classify (F1 as low as 0.31–0.32 for two guidelines); the current model encodes foreground animation and background screenshot jointly rather than separately, causing confusion when snackbars/app-bars have similar visual features to background UI; the fixed animation-capturing method (max 5s duration, 1s static-frame stop threshold) can drop important frames for long multi-step animations; synthetic and real-world GUI animations occupy substantially different latent feature spaces, so cross-dataset (synthetic→real or real→synthetic) linting performs poorly, meaning synthetic data cannot substitute for real training/evaluation data; scalability of manually collecting labeled real-world examples remains a bottleneck despite the few-shot design.

## Summary

Seenomaly tackles a gap in existing lint/testing/GUI-comparison tools: none of them can "see" GUI animations (component motion, appearing/disappearing, elevation/shadow changes) well enough to check them against platform design-don't guidelines (e.g., Android Material Design rules about scrims, shadows, and stacked snackbars). The authors reformulate this as a multi-class few-shot classification problem, since only a handful of illustrative "don't" examples exist per guideline and large-scale labeled data is infeasible to collect. Their solution is an unsupervised adversarial autoencoder, a 3D-CNN-based VAE enhanced by GAN adversarial training and an auxiliary feature encoder, trained on 91,370 unlabeled real-app GUI animation screencasts mined via automatic GUI exploration of the Rico dataset, learning to compress animations into an abstract spatio-temporal latent vector. At inference time, both the "linted" animation and a small set of labeled do/don't exemplars for each guideline are embedded into this space, and a KNN majority vote determines which guideline (if any) is violated. Across nine carefully chosen, deliberately confusable design-don't guidelines (covering elevation, shadow, content display, and component motion/interaction), the tool implemented for nine Android Material guidelines achieves up to ~0.90 accuracy/~0.83 F1 on synthetic data and up to ~0.87 accuracy on real-world data, outperforming ablated variants (VAE-only, VAE+GAN, VAE+FE). A striking finding is the cross-dataset experiment: a feature extractor trained on synthetic GUI animations transfers very poorly to real-world linting (and vice versa), showing that seemingly realistic synthetic augmentation (compositing cropped real animations onto Rico screenshots) still leaves detectable, non-human-visible "unrealistic" artifacts that an unsupervised model treats as anomalies. This is a cautionary result for any CV-in-SE work relying on synthetic GUI data.
