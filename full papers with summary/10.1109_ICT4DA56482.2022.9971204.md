# Automatic Code Generation From Low Fidelity Graphical User Interface Sketches Using Deep Learning

- **Year:** 2022
- **Venue/Source:** 2022 International Conference on Information and Communication Technology for Development for Africa (ICT4DA)
- **DOI:** 10.1109/ICT4DA56482.2022.9971204

## Metadata

- **se_area:** Development (UI implementation from design artifacts)
- **se_task:** Sketch-to-code generation, converting hand-drawn, low-fidelity UI wireframe sketches into client-side (Bootstrap-based) skeleton code
- **cv_technique:** Object detection for UI component recognition, comparing three CNN-based detectors, Faster R-CNN with Inception V2 backbone, SSD MobileNet v2, and Faster R-CNN with Inception ResNet v2; semi-automatic image annotation via Canny edge detection + morphological rectangle operations + contour extraction (used to generate PASCAL VOC-format bounding-box labels)
- **platform:** Web (general website UI wireframes, rendered as Bootstrap HTML)
- **rationale:** Ease of use (automates a manual, effort-intensive step in translating paper-prototyped sketches to code); robustness (comparing multiple detector backbones to select the most accurate, i.e., Inception ResNet v2, for reliable component classification); context-driven (custom 14-class taxonomy, e.g., carousel, pagination, dropdown/select, derived from surveying real website UIs rather than a generic fixed set)
- **artifact_type:** Full-interface (whole sketched wireframe images are processed end-to-end, with detected components subsequently reassembled into a complete generated UI via a layout algorithm)
- **eval_method:** Component recognition evaluated with PASCAL VOC metrics (precision, recall, mAP@0.5 IoU) on a held-out test set (112 images, 1900 annotated components) across the three detector backbones; code generation evaluated via a user study with 24 IT-background participants rating visual similarity ("matches correctly" / "partially" / "does not match") between 10 generated UIs and their source sketches
- **challenges:** Only 562 sketch images / 11,152 annotated components were collected in total (a relatively small custom dataset, split 80/20), which the authors note constrains generality; hand-drawn sketches vary significantly in style/legibility, motivating deliberate lighting/style variation during data collection; overlapping bounding boxes/components had to be explicitly resolved via a custom grid-based layout algorithm; final code-generation quality is bounded by upstream component-recognition accuracy ("the generality of the framework depends on the performance of the component recognition layer")

## Summary

This paper presents a two-stage system that automatically converts hand-drawn, low-fidelity UI wireframe sketches into working Bootstrap-based client-side code, aiming to remove the manual, delay-prone step where developers translate paper-prototyped mockups into HTML by hand. The first stage, component recognition, is framed as an object-detection problem over a custom taxonomy of 14 UI component classes (button, label, textbox, paragraph, textarea, checkbox, radio button, dropdown/select, image, link, table, carousel, pagination, heading), derived from surveying common website UI elements. The authors built a dataset of 562 sketch images (11,152 annotated components, varied lighting/style) and compared three pretrained deep object detectors, Faster R-CNN with Inception V2, SSD MobileNet v2, and Faster R-CNN with Inception ResNet v2, finding the last achieves the best mAP (95.5%) after 50,000 training steps, versus 91.2% and 87.5% for the alternatives, with per-class AP tables reported across all 14 classes. The second stage, code generation, takes the detector's JSON output and applies a custom layout-structuring algorithm that maps detected component bounding boxes onto an 80×80-grid, 12-column Bootstrap grid system (resolving row/column alignment and overlap via intersection thresholds), then assembles a final HTML page from per-class code templates via a template engine. The approach is positioned against prior sketch/screenshot-to-code work (REMAUI, REDRAW, pix2code, sketch2code, and a RetinaNet-based hand-drawn approach), which the authors argue either lack component-type classification, are tied to specific screen sizes, or were not rigorously evaluated. A 24-participant visual-similarity user study across 10 test sketches shows generated UIs mostly "match correctly" or "partially" their source sketches, with only a small proportion of clear mismatches.
