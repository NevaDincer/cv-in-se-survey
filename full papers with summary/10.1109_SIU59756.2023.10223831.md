# Test Automation for Symbol Recognition on the Map (Harita Üzerinde Sembol Tanıma İçin Test Otomasyonu)

- **Year:** 2023
- **Venue/Source:** 2023 31st Signal Processing and Communications Applications Conference (SIU)
- **DOI:** 10.1109/SIU59756.2023.10223831

## Metadata

- **se_area:** Testing
- **se_task:** Automated visual test-oracle / verification of symbol placement and recognition on map-displaying software, replacing manual visual inspection in (military) system testing
- **cv_technique:** Template Matching (normalized cross-correlation, TM_CCOEFF_NORMED, with sliding window and Non-Maximum Suppression); HOG feature extraction + Linear SVM classifier; Faster R-CNN (ResNet-50 backbone, COCO-pretrained); YOLOv5
- **platform:** Desktop (map-based software used in military systems; methodology is domain-general for any color-map GUI)
- **rationale:** Ease of use (automates a previously fully manual, error-prone, repetitive visual verification task); robustness (explicitly tested against color diversity, near-duplicate/similar symbols, multi-scale symbols, transparent symbols, and overlapping/occluded symbols)
- **artifact_type:** Localized (bounding-box detection/classification of individual symbols overlaid on map imagery)
- **eval_method:** mean Average Precision (mAP) computed via Precision-Recall curve area, compared across the four methods on a custom dataset of 144 map images (16 designed military-style symbol classes, ~50 examples per class, 60/20/20 train/validation/test split for the trainable methods); additionally a qualitative behavior table summarizing each method's success/failure against five identified real-world difficulty categories.
- **challenges:** High color diversity in elevation-type maps versus satellite maps lowers recognition performance across all methods; visually similar (especially black, round) symbols are frequently confused, particularly by HOG+SVM and to a lesser extent Faster R-CNN/YOLOv5; large scale variation of symbols across images degrades template matching and fixed-window HOG+SVM; transparent symbols (background showing through) are difficult for template matching and HOG+SVM; overlapping symbols cause the occluded (bottom) symbol to go undetected by all compared methods.

## Summary

This Turkish-language paper addresses the problem of automating the currently manual visual verification of military symbols overlaid on color maps in map-based software testing, where testers must otherwise check each symbol by eye against a large and easily confused symbol vocabulary. The authors constructed a custom dataset of 144 realistic, complex color map images (elevation and satellite imagery) with 16 purpose-designed military-style symbols placed randomly, at varying scales, with some overlapping and some rendered transparent to stress-test detection difficulty. Four representative image-analysis/ML approaches are implemented and compared: classical template matching (with NMS), a HOG feature + Linear SVM sliding-window classifier, Faster R-CNN with a COCO-pretrained ResNet-50 backbone, and YOLOv5. Performance is measured via mAP, with Faster R-CNN achieving the best result (0.915), closely followed by YOLOv5 (0.865), while template matching (0.445) and HOG+SVM (0.439) perform substantially worse. Beyond the aggregate mAP comparison, the paper's distinguishing contribution is a systematic qualitative "behavior table" that maps each of five concretely identified map-symbol-recognition difficulties (color diversity, visually similar symbols, scale variation, transparency, and symbol overlap/occlusion) to how each of the four methods handles it, providing practical guidance for choosing a recognition method based on the specific visual challenges expected in a given map-testing scenario. The authors conclude that neural-network-based detectors (Faster R-CNN, YOLOv5) are clearly preferable to classical image-processing/ML baselines for this test-automation use case, and propose extending the approach to also cover text detection on maps in future work.
