# GUIDER: GUI Structure and Vision Co-guided Test Script Repair for Android Apps

- **Year:** 2021
- **Venue/Source:** ISSTA '21 (30th ACM SIGSOFT International Symposium on Software Testing and Analysis)
- **DOI:** 10.1145/3460319.3464830

## Metadata

- **se_area:** maintenance
- **se_task:** GUI test script repair (regression testing maintenance)
- **cv_technique:** SIFT (Scale-Invariant Feature Transform) for extracting feature descriptors from cropped widget images and computing visual similarity between candidate widget matches; OpenCV (v3.1) contour detection and Tencent OCR API used as a fallback pure computer-vision-based widget/screen matcher (reusing the prior METER approach) when structural information from UI Automator is unavailable or unreliable
- **platform:** mobile (Android)
- **rationale:** robustness (visual information disambiguates widgets when structural identity properties collide or degrade after major GUI changes); context-driven (visual similarity is used to rank/sort close and remote widget matches rather than to make binary decisions); ease of use / practicality (no application model required, unlike model-based repair approaches)
- **artifact_type:** localized (SIFT applied to individually cropped widget-level screenshots, using the widget's bounding box to isolate the region of interest, rather than reasoning over the full screen image)
- **eval_method:** Industrial case study on WeChat (1.2B+ MAU): 277 developer-maintained GUI test scripts across 5 base-to-updated version pairs, 171 scripts / 3322 test actions affected. Comparison against two baselines relying solely on visual (METER) or structural (WATEROID) information, plus an ablation variant (GUIDER-) without visual information. Correctness determined by manual review from 5 professional test engineers requiring full consensus. A prior 32-app exploratory study (Section 2) and a parameter sensitivity study for thresholds θ1 (screen-matching similarity) and θ2 (number of candidate matches examined) were also conducted.
- **challenges:** Five test actions were incorrectly repaired because GUIDER selects list items based on visual appearance, which fails when the correct choice depends on environment-specific index/content (e.g., message lists) rather than appearance; intention-based correctness oracle is described by the authors as 'weak' and can fail to catch such errors. 70 of 3322 test actions could not be repaired at all: 35 due to inability to locate the correct widget (either because changes to widget properties/appearance were too large, or because of the same list-selection issue), and 35 more where the right widget was found but drastic GUI changes meant no constructed repair satisfied the intention-preservation oracle. The approach also depends on UI Automator structural data being reliable, falling back to slower vision-only matching when it is not (e.g., security-restricted or backgrounded activities).

None. This paper is a strong fit for the CV x SE survey scope. It is fundamentally about using computer vision (SIFT-based visual similarity) in combination with structural GUI information to solve a software engineering maintenance task (test script repair), with visual information playing a load-bearing, non-trivial role (not superficial).

## Summary

GUIDER addresses the problem of automatically repairing obsolete GUI test scripts for Android apps after an app's UI evolves between versions. The paper's core contribution is combining structural information (widget properties such as resource-id, content-desc, and text, extracted via Android's UI Automator framework) with visual information (SIFT-based feature descriptor similarity between cropped widget screenshots) to determine which widgets in an updated app version correspond to widgets referenced in obsolete test scripts. The approach first classifies widgets into three confidence tiers: α-typed (unique "sure" match), β-typed (multiple "close" matches sharing at least one identity property), and γ-typed (only "remote" matches sharing no identity properties), using structural comparison, then uses visual similarity (SIFT) to rank and disambiguate among candidate matches within the β/γ tiers. Repairs are validated using an "intention-preserving" oracle: a screen-transition-based definition of correctness derived from how the original test action behaved on the base app version. The tool falls back to pure computer-vision matching (as used in the authors' prior tool METER) when structural information from UI Automator is unavailable or inconsistent with the visible screen, e.g., due to Android security restrictions on certain activities. Evaluated on WeChat's internal, developer-maintained test suite, GUIDER outperformed both a purely visual (METER) and a purely structural (WATEROID) baseline, and an ablated version without visual information, demonstrating that structural and visual signals are complementary rather than redundant for this task.
