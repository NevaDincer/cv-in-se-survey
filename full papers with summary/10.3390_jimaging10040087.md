# Measuring Effectiveness of Metamorphic Relations for Image Processing Using Mutation Testing

> **SCOPE WARNING**: Likely out of scope, and notably the *inverse* relationship to what this survey targets. This paper does not apply computer vision as a technique to accomplish a software engineering task; instead, it applies software testing methodology (metamorphic testing + mutation testing) *to test image-processing programs themselves* (Sobel edge detection, morphological dilation, morphological erosion). The image-processing algorithms here are the system under test (SUT), not a technique used to solve an SE problem. This is "SE-for-CV testing" rather than "CV-for-SE," which is the reverse of Bajammal et al.'s framing. Recommend excluding unless the survey explicitly wants a section on testing methodologies for CV/image-processing software as a related but distinct thread.

- **Year:** 2024
- **Venue/Source:** Journal of Imaging (MDPI), vol. 10, issue 4, article 87
- **DOI:** 10.3390/jimaging10040087

## Metadata

- **se_area:** Testing (specifically, test-oracle-problem mitigation via metamorphic testing, and test-suite/relation-quality evaluation via mutation testing), applied to image-processing application (IPA) software.
- **se_task:** Evaluating the fault-detection effectiveness of metamorphic relations (MRs) for image-processing programs, Sobel edge detection, morphological dilation, and morphological erosion, using mutation testing as the evaluation vehicle; proposing new MRs to complement existing ones and assessing which mutation operators are most effective for this domain.
- **cv_technique:** Not applicable in the "CV solving an SE task" sense. The image-processing operations under test, Sobel edge detection, morphological dilation, and morphological erosion, are classical, well-known digital image processing algorithms that serve as the systems under test (SUTs), not techniques the authors employ to accomplish testing. The authors' own methodology (metamorphic relations, mutation operators, coverage criteria) is standard software-testing methodology, independent of any CV/ML technique.
- **platform:** General (desktop Python programs implementing image-processing operations; applied to MRI brain-scan images as the test-input domain, relevant to medical-imaging/radiology software quality assurance)
- **rationale:** Not applicable in CV-adoption terms. If reframed as motivation: image-processing software is safety/mission-critical (medical radiology, biometric and surveillance systems), and lacks a reliable test oracle (there is no ground-truth "correct" edge-detected or dilated/eroded image to directly compare against), which motivates metamorphic testing as an oracle-problem workaround, a testing-methodology rationale and not a CV-usage rationale.
- **artifact_type:** Not applicable. No widget, screen, or GUI artifact is produced or consumed; the "artifacts" are whole MRI images processed by edge-detection/dilation/erosion operators and the relations (MRs) between their inputs and outputs (e.g., rotation-invariance, transposition-invariance, duality, translation-invariance).
- **eval_method:** Mutation testing using 9 applicable mutation operators for edge detection (AOD, AOR, LOR, ROR, OIL, RIL, SIR, SDL, ZIL) and 8 for dilation/erosion (same set minus LOR), generating 162 mutants for edge detection and 130 for dilation/erosion, substantially more than prior work (Sim et al.: 31 mutants via 2 operators; Jameel et al.: 33 mutants via 1 operator). Source test cases (95, reused from the authors' prior paper) generated via black-box equivalence-class testing (grouped by horizontal/vertical dimension, resolution, bit depth, image type) plus white-box coverage criteria (100% statement and branch coverage confirmed on all three SUTs), applied to a dataset of 3,000 MRI brain images (1,500 tumor / 1,500 non-tumor) from Kaggle, of which 95 were selected as source test cases. Effectiveness measured via fault detection rate (FDR) = killed mutants / total non-equivalent mutants, computed both per mutation operator and per MR, and statistically compared against the existing MRs/results of Sim et al. and Jameel et al.
- **challenges:** Authors explicitly state study limitations: (1) only one dataset (MRI brain images) was used, limiting generalizability, "we can use more datasets for convincing testing"; (2) only one edge-detection algorithm (Sobel) was evaluated, when multiple alternative edge-detection algorithms exist and could yield different results; (3) only one programming language (Python) was used, limiting the applicable mutation-operator set; using additional languages (Java, C++) could enable more operators. They also report methodological gaps found in prior literature that motivated this work: prior MR-evaluation studies used too few mutation operators (max 33 mutants generated) and relied on non-diverse, randomly-selected images from published libraries with narrow property ranges (fixed bit depth, resolution, dimensions), likely under-representing the true input space and inflating or deflating reported fault-detection rates.

## Summary

This Journal of Imaging paper addresses a testing-methodology problem within image-processing applications (IPAs) rather than applying CV to a software-engineering task. The core issue is the classic "test oracle problem": for operations like edge detection, dilation, and erosion, there is no readily available "correct" reference output to compare against, since the expected result is not obvious a priori. Metamorphic testing (MT) sidesteps this by defining metamorphic relations (MRs), properties that should hold between the outputs of an original ("source") test case and a systematically transformed ("follow-up") test case, e.g., that dilating a 90°-rotated image should equal 90°-rotating a dilated image. The authors first adopt four existing MRs for Sobel edge detection (from Sim et al.) and eight existing MRs for dilation/erosion (from Jameel et al.), then propose six new MRs of their own for dilation and erosion: four general MRs (rotation invariance, transposition invariance, applied separately to dilation and erosion) that prior work had only partially evaluated, one dilation-specific "enhanced associative property" MR, and one erosion-specific translation-invariance MR. To assess how strong (i.e., fault-detecting) each MR is, they use mutation testing: seeding synthetic faults into the Python source code of each SUT via nine (edge detection) or eight (dilation/erosion) mutation operators, substantially more than the one or two operators used in prior comparable studies, and computing each MR's fault detection rate (FDR) as the proportion of generated mutants it can "kill" (detect a violation for). Source test cases were generated using a combination of equivalence-class testing (across image dimension, resolution, bit depth, and type) and code-coverage criteria, applied to a curated set of 95 MRI brain-scan images achieving 100% statement/branch coverage on all three SUTs. Results showed that for edge detection, the arithmetic-operator-replacement (AOR) mutation operator was most effective, and all four MRs showed improved FDR versus the prior Sim et al. study (up to 32 percentage points higher for MR1). For dilation/erosion, four of the eight existing MRs showed improved FDR versus Jameel et al. (up to 39 percentage points higher), and the six newly proposed MRs achieved moderate, non-trivial FDRs (43–52%) that specifically detected faults the existing MRs missed, demonstrating complementary rather than redundant fault-detection coverage. While methodologically rigorous, the paper's subject matter, testing image-processing algorithms as the software under test, sits outside the scope of a survey on CV techniques applied to accomplish SE tasks, since here the roles are reversed: SE testing techniques are being applied to CV/image-processing code.
