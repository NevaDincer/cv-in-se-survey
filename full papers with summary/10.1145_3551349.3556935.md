# The Metamorphosis: Automatic Detection of Scaling Issues for Mobile Apps

- **Year:** 2022
- **Venue/Source:** ASE '22, 37th IEEE/ACM International Conference on Automated Software Engineering
- **DOI:** 10.1145/3551349.3556935

## Metadata

- **se_area:** Testing (GUI/accessibility testing, cross-configuration UI consistency testing)
- **se_task:** Automated detection of "scaling issues", text truncation, component overflow, component/content overlap, component/content cropping, and missing components, that occur when Android apps are rendered at a larger font or display scale, relevant to accessibility QA
- **cv_technique:** Template matching / normalized cross-correlation (TM_CCOEFF_NORMED) for view-visibility detection; alpha-channel-based image analysis and bit-wise AND operations to construct and compare per-view "visible matrices" for overlap/crop detection; connected-component detection/labeling for extracting semantic text/foreground regions and computing text scaling ratios; Structure Similarity Index Measure (SSIM) for comparing non-text view appearance across the two scales
- **platform:** Mobile (Android)
- **rationale:** Context-driven (comparing the identical UI rendered under two different runtime display-scale contexts, motivated by accessibility needs of elderly/low-vision users, 33% of users increase font size); robustness (fine-grained pixel/alpha-channel-level comparison rather than coarse bounding-box overlap, to avoid noise from non-rectangular real content); ease of use (avoids expensive manual side-by-side exploration of an app across every scale combination)
- **artifact_type:** Localized (per-view bounding-box-level scaling-issue detection) built on top of full-interface page-level screenshot/view-tree comparison
- **eval_method:** Empirical evaluation on 60 real-world F-Droid apps (96 buggy UI pages / 147 buggy views) reporting precision/recall/F1 for page-level detection (RQ1) and view-level localization (RQ2), compared against OwlEyes and DiffDroid baselines; a separate real-world usefulness study (RQ3) applying the tool to 80 additional sampled apps and submitting GitHub issue reports (21 issues found, 20 confirmed/fixed by developers)
- **challenges:** Accurately pairing the same logical view across two different display scales is difficult because resource-id/XPath alone are unreliable, especially inside scrollable layouts (addressed via injected mapping IDs in decompiled layout XML); interaction effects between sibling and parent-child views complicate isolated per-view analysis; different content types (text vs. image) scale differently and require separate detection strategies; failure cases include false positives on scrollable views that are not truly "cropped" and false negatives when ellipsized text masks genuine content loss.

## Summary

This paper presents dVermin, a computer-vision-driven approach for automatically detecting "scaling issues", UI inconsistencies such as text truncation, component overflow, overlap, cropping, or missing elements, that appear when Android apps are viewed at larger font or display-scale settings, a problem with direct accessibility implications for elderly and vision-impaired users. The authors first conduct a motivational study on 200 F-Droid apps, finding that 20.1% of scaled screenshots exhibit issues, and derive a five-category taxonomy (component/content overlapping, component/content cropping, and component missing). dVermin operates in three phases: (1) view pairing, which injects unique mapping IDs into decompiled app layout XML files (rather than relying on the unreliable resource-id/XPath matching used by prior cross-platform work) to precisely match views across the default and larger-scale UI renderings; (2) inter-view inconsistency detection, which uses alpha-channel-derived "visible matrices," bit-wise AND operations, and Intersection-over-Union computations to detect changes in sibling overlap and parent-child cropping status between the two scales; and (3) intra-view inconsistency detection, which separately handles text views (via connected-component analysis on binarized foreground images and a computed area-scaling ratio γ²) and non-text views (via connected-component counts plus SSIM structural similarity). Evaluated on 60 real apps, dVermin achieves 97%/97% precision/recall for page-level detection and 84%/91% for view-level localization, substantially outperforming the OwlEyes and DiffDroid baselines, which were not designed for this cross-scale comparison scenario. A real-world usefulness study across 80 sampled apps yielded 21 detected scaling issues, 20 of which developers confirmed or fixed, with several explicitly noting the tool surfaced an accessibility problem they had not previously tested.
