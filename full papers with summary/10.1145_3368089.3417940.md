# UIED: A Hybrid Tool for GUI Element Detection

- **Year:** 2020
- **Venue/Source:** ESEC/FSE 2020 (28th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering), pp. 1655-1659 (tool demo paper)
- **DOI:** 10.1145/3368089.3417940

## Metadata

- **se_area:** Development / Maintenance (supports GUI reverse engineering / UI2Code and automated GUI testing as downstream tasks)
- **se_task:** GUI element detection (localizing and classifying widgets, images, and text in a GUI screenshot or design drawing) as the foundational step for UI-to-code generation and GUI test automation
- **cv_technique:** Hybrid pipeline combining "old-fashioned" (non-learned) CV methods and deep learning: flood-fill algorithm + Sklansky's convex-hull/boundary algorithm for layout-block detection; gradient-based image binarization; connected-component labelling for non-text element extraction; ResNet50 classifier (trained on 90,000 GUI element instances, 15 categories) for non-text element classification; EAST deep scene-text detector for text element detection; also implements/benchmarks 2 prior non-learned baselines (Xianyu, REMAUI, both using Canny edge detection + Tesseract OCR) and 3 deep object detectors (Faster-RCNN, YOLOv3, CenterNet) retrained on the Rico dataset for comparison
- **platform:** Mobile (Android; models retrained on the Rico mobile-app screenshot dataset), with authors noting applicability to design drawings/web GUIs as well
- **rationale:** Ease of use (delivers an interactive, off-the-shelf web tool requiring no scripting/back-end access, unlike instrumentation-based methods); robustness (proposes a top-down coarse-to-fine detection strategy specifically to handle GUI-specific challenges (large in-class variance, high cross-class similarity, tightly packed/close-by heterogeneous elements) that make generic bottom-up CV/object-detection methods perform poorly); context-driven (separates text vs. non-text detection to reduce mutual interference, tailored to GUI image structure rather than natural-scene images)
- **artifact_type:** Full-interface (detects and classifies all GUI elements across an entire input screenshot/design image, exportable as a complete UI kit/JSON)
- **eval_method:** Quantitative object-detection evaluation on 5k Android GUIs from Rico using F1-score at IoU > 0.9, plus average per-image runtime, comparing UIED's hybrid approach against 5 baseline detectors (Table 1); qualitative usability evaluation via a survey of 10 professional developers/researchers (including UI2Code and robotic GUI-testing practitioners) on tool usefulness and future potential
- **challenges:** Authors note the underlying Rico ground-truth dataset itself is "not perfectly precise," which caps achievable F1 scores; existing old-fashioned CV methods (REMAUI, Xianyu) perform poorly on GUI images (F1 = 0.106-0.183) because their bottom-up edge/contour aggregation over-segments elements in complex/packed GUI layouts; generic deep detectors alone (Faster-RCNN, YOLOv3, CenterNet) also underperform (F1 = 0.249-0.282) despite retraining on GUI-specific data; even UIED's best hybrid result (F1 = 0.524) remains far from perfect, requiring the tool's manual drag-and-drop correction dashboard as a practical mitigation; runtime cost is non-trivial (4.8s average per image, slower than pure deep-learning baselines though faster than REMAUI)

## Summary

UIED is an interactive, web-based GUI element detection toolkit that treats GUI element detection as a variant of natural-scene object detection but tailored to the distinct visual characteristics of interfaces (dense packing, high cross-class similarity, heterogeneous widget/image/text mixtures). The authors first implement and benchmark two "old-fashioned" (non-learned) CV pipelines (Xianyu, REMAUI) and three retrained deep object detectors (Faster-RCNN, YOLOv3, CenterNet) as baselines, retraining the deep models on the large-scale Rico mobile-app screenshot dataset. Finding all five baselines inadequate, they propose a novel hybrid, GUI-specific detection method that splits the problem into non-text and text detection. Non-text elements are located via a top-down coarse-to-fine pipeline (flood-fill + Sklansky's algorithm for layout blocks, gradient-based binarization, connected-component labelling for element boundaries) and then classified by a ResNet50 classifier trained on 90,000 labelled GUI element instances across 15 categories; text elements are detected separately using the deep scene-text model EAST, avoiding interference between text and non-text detection. The resulting UIED web application lets users upload a GUI image, view/edit detected elements on an interactive dashboard (drag-and-drop repositioning, attribute editing, deletion), accumulate reusable "UI kits," and export a JSON description of all detected elements (position, size, class) for downstream use in UI2Code or GUI-testing pipelines. On 5k Rico Android GUIs (F1 @ IoU>0.9), UIED's hybrid method scores 0.524, clearly outperforming the two non-learned baselines (0.106-0.183) and the three retrained deep detectors (0.249-0.282), though the authors attribute part of the residual gap to imperfect ground-truth labels in Rico itself. A survey of 10 professional developers/researchers, including GUI-reverse-engineering (UI2Code) and robotic GUI-testing practitioners, confirmed that accurate off-the-shelf GUI element detection was a significant unmet need and that an easy-to-use tool like UIED would be "more than helpful," with strong interest in a future integrated code-generation extension.
