# Appaction: Automatic GUI Interaction for Mobile Apps via Holistic Widget Perception

- **Year:** 2023
- **Venue/Source:** ESEC/FSE '23, 31st ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering
- **DOI:** 10.1145/3611643.3613885

## Metadata

- **se_area:** Testing: automated mobile GUI/functional testing, specifically automating the manually-intensive "form page" interaction step of industrial mobile app testing.
- **se_task:** Automatic GUI interaction with form pages: recognizing GUI "widgets" (semantically coherent groups of UI elements, e.g., a labeled text-input box plus its icon) from a screenshot and UI hierarchy, then generating and injecting proper, valid text inputs so that order-placement/registration-style form pages can be automatically and correctly exercised for functional testing, replacing hard-coded, XPath-based test scripts that break on frequent UI updates.
- **cv_technique:** Multi-modal transformer-based encoder: BERT for embedding user-visible widget/element text; Vision Transformer (ViT) for embedding cropped screenshot regions of each UI element (visual appearance/clickability cues such as button lightness/darkness); a fully-connected layer encoding element attributes (boolean properties like "Clickable" + 4-value bounding-box position); the three embeddings are concatenated and passed through a self-attention encoder to fuse holistic, cross-element context. A two-stage classification head then performs (1) multi-label element classification (2-layer FC network) and (2) pairwise binary "same-widget" grouping (2-layer FC network) to assemble elements into widgets. Compared in ablation against YOLOv7 (image-only object detector baseline) and six single-/dual-modality variants of Appaction itself.
- **platform:** Mobile (Android). Primary target is Meituan's commercial e-commerce app (600M+ users); generalizability additionally tested on five other popular Chinese commercial apps (Dianping, Feizhu, Gaode, Kwai, Taobao).
- **rationale:** Context-driven: explicitly designed to mimic how humans holistically perceive a GUI widget (combining text, image, and interaction attributes together) rather than analyzing each UI element in isolation, motivated by an empirical study on Meituan's app showing that same-function widgets have average pixel/grayscale-histogram similarity below 40% and textual cosine similarity of only 0.45–0.69, making rule-based widget identification infeasible. Also robustness-driven: aims to reduce brittleness of hard-coded test scripts (bound to XPath/IDs) against frequent UI hierarchy changes from app updates.
- **artifact_type:** Localized: the CV/ML pipeline operates on cropped, element-level and widget-level regions within a full GUI screenshot (grouped clusters of UI elements), not on the whole interface as a single unit, a temporal sequence, or natural-scene input.
- **eval_method:** Manually collected and labeled dataset of 158 order-placement form pages from Meituan (123 train / 35 test), spanning hotels, tickets, catering, entertainment, labeled into 7 widget categories (User Info, Product Info, Coupon, Submit, Info. Input, Quantity, Price) chosen jointly with Meituan engineers. Three research questions: **RQ1** (widget recognition accuracy): ablation study measuring element-classification F1 vs. YOLOv7 and six single-/partial-modality variants (Appaction: mean F1 0.861 vs. YOLOv7's 0.551; best variant using only two modalities still below 0.84), plus widget-grouping performance via the Rand index (avg. F1 0.773, though "Price" category recall/F1 only 0.296/0.441). **RQ2** (interaction performance): real-world deployment on 519 order-placement pages across 5 Meituan business lines: 96% page-level success rate, 98% widget recall, 4.1 s/page average recognition time, plus failure-cause analysis (mostly server-side purchase-limit restrictions, not misrecognition) and efficiency analysis. **RQ3** (generalizability): Appaction trained only on Meituan data, zero-shot evaluated on order-placement pages of 5 other commercial apps (100 pages total): 89% page-level success, 148/160 target widgets correctly identified. Additional qualitative case studies: (1) tarpit avoidance: bypassing 590/619 (95%) form pages that block the Monkey random-testing tool; (2) labor-cost case study: engineer-estimated ~37.5% average reduction (up to 50% for the travel business line) in script writing/maintenance time. Threats-to-validity addressed via independent double-labeling with a third-author tiebreaker.
- **challenges:** Certain widget categories are intrinsically hard to recognize: "Price" widgets are numeric, contain few elements, and change frequently, yielding the lowest recall/F1 of all categories; most real-world interaction failures were not attributable to the widget-recognition model at all but to server-side business logic (e.g., one-item-per-user purchase limits causing repeated submissions to fail); valid text-input generation depends on a manually curated `<input_type, value_list>` dictionary partly hand-collected from requirement documents and test scripts (not a fully generative/semantic approach like the LLM-based QTypist/Form-BERT baselines discussed in related work), trading generative flexibility for lower computational/data requirements and more controllable output quality; the widget-recognition dataset itself is small (123 training pages) due to the cost of manual multi-modal annotation.

## Summary

Appaction is an industrial, learning-based tool developed at Meituan to automate one of the most labor-intensive parts of mobile GUI testing: correctly filling out and submitting "form pages" (e.g., order-placement flows) that require semantically valid inputs rather than the random gestures/text used by conventional automated GUI exercisers (Monkey, Sapienz, etc.). The paper first presents an empirical study showing that GUI widgets serving the same function (e.g., name-input boxes) vary enormously in appearance and text across Meituan's app, ruling out rule-based or purely visual recognition. Appaction's core contribution is a two-stage, multi-modal deep learning pipeline that mirrors human "holistic widget perception": BERT encodes visible text, a Vision Transformer encodes each UI element's cropped screenshot region, and element attributes (clickability, position) are separately embedded; all three streams are fused via a self-attention encoder before a multi-label classifier assigns semantic categories to elements and a binary classifier groups co-referring elements into widgets. Once widgets are identified, Appaction matches widget text against a curated dictionary of valid input values (built from requirement docs and test scripts) via cosine similarity, then injects the resulting UI events top-down through Appium. Evaluated on Meituan's real production apps, Appaction substantially outperforms YOLOv7 and ablated variants in widget recognition, achieves 96% page-level interaction success across five business lines in production, generalizes zero-shot to five unrelated commercial apps with minimal training data, and is reported by Meituan engineers to cut script writing/maintenance labor by roughly a third, offering a concrete industrial case study of multi-modal CV+NLP fusion applied directly to automated software testing.
