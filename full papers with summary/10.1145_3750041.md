# Detecting Outdated Screenshot from GUI Document

- **Year:** 2026 (published online April 2026)
- **Venue/Source:** ACM Transactions on Software Engineering and Methodology (TOSEM), Vol. 35, No. 5, Article 133
- **DOI:** 10.1145/3750041

## Metadata

- **se_area:** maintenance (specifically documentation maintenance / software artifact obsolescence detection)
- **se_task:** detecting outdated GUI screenshots embedded in software documentation (app-store websites and IDE/tool documentation), so that stale visuals that no longer match the current UI can be flagged and fixed
- **cv_technique:** pixel-level image classification via a Random Forest (ensemble of Decision Trees, Gini-index splitting) trained directly on flattened RGB pixel vectors of resized screenshots; image resizing/resampling via Lanczos-kernel interpolation (compared against Nearest, Box, Bilinear, Hamming, Bicubic filters); screenshot cropping to remove noisy status/navigation bar regions
- **platform:** mobile (Android) and desktop (VS Code IDE)
- **rationale:** robustness (the classifier is explicitly trained to ignore pixel regions affected by dynamic/irrelevant content and focus on the subtle, meaningful pixel differences that indicate obsolescence, rather than relying on a naive similarity threshold, which the paper shows fails); ease of use / automation (removes tedious, error-prone manual screenshot-vs-app comparison from documentation maintenance)
- **artifact_type:** full-interface (whole cropped screenshots are classified, not individual localized widgets)
- **eval_method:** mixed: (1) an in-the-wild deployment on 50 real Android app websites (Google Play) plus the full VS Code documentation (~1,500 screenshots), with manually verified true positives and real bug reports filed against VS Code (17/17 confirmed and fixed by VS Code developers); (2) a controlled benchmark of 9 Android apps + VS Code with per-app Random-Forest classifiers evaluated via 10-fold cross-validation (accuracy/precision/recall/F1, F1 ranging 0.87–1.00); (3) ablation studies comparing the RF classifier against 1/3/5-NN, Logistic Regression, SVC, Decision Tree, and MLP classifiers (RF/DT best, statistically significant only vs. SVC), comparing 6 resampling filters, and comparing several target image resolutions; preceded by an empirical preliminary study (RQ1–RQ2) mining 210 real VS Code "outdated screenshot" bug reports to characterize who reports/fixes them and showing that a simple last-modified-time threshold is not viable (70.3% false-alarm-prone).
- **challenges:** authors' own stated limitations: a separate classifier must be trained per application and retrained on each new release (no cross-project generalization, consistent with prior findings that cross-project learning underperforms in-project learning); effectiveness drops on visually complex/dynamic-animation apps (games like 2048 and Cube Solver, F1 down to 0.87–0.89) since screenshots there are far more variable; rare/insufficiently-sampled screenshots can be missed if the underlying GUI-testing/capture tool (Fastbot, or OBS for VS Code) fails to exercise those states; no feedback could be obtained from Android app developers to independently confirm the 20 in-the-wild Android findings (only the VS Code findings, 17/17, were externally confirmed); the approach requires re-implementing a document/screenshot extractor for each new document format (web pages vs. PDFs, etc.).

## Summary

This paper introduces DOSUD, the first approach to automatically detect outdated screenshots embedded in software documentation (app-store pages, IDE tutorials), motivated by an empirical study of 210 real "outdated screenshot" bug reports mined from VS Code's issue tracker showing the problem affects both novice and experienced developers and that a naive heuristic, flagging screenshots that haven't been updated in longer than the median fix interval (297 days), produces an unacceptable 70%+ false-positive rate. DOSUD instead trains a per-application Random Forest classifier directly on raw pixel data: it uses GUI testing (video capture via OBS for apps with existing test scripts like VS Code, or Fastbot's UCB-guided reinforcement-learning crawler for Android apps without scripts) to automatically harvest and self-label screenshots from the current and prior app versions (screenshots unique to the current version are "not outdated," others are "outdated"), resizes/crops each screenshot (removing noisy status/navigation bars, Lanczos-filtered to an empirically tuned resolution such as 36×64), flattens it to an RGB pixel vector, and trains an RF whose ensemble of decision-tree if-statements learns which pixel regions actually distinguish outdated from current UI, implicitly learning to ignore areas affected by dynamically-changing but functionally-irrelevant content. On a 10-app benchmark the approach reaches F1 scores of 0.87–1.00 via 10-fold cross-validation (dropping only for visually complex animated games), and RF/Decision-Tree classifiers statistically outperform SVC while a 1-NN direct-comparison baseline is shown to fail on a real motivating example. The most striking result is the in-the-wild deployment: applied unmodified to 50 live Android app websites and the full current VS Code documentation, DOSUD surfaced 20 previously-unknown outdated Android screenshots and 17 previously-unreported VS Code documentation bugs, all 17 of which were independently confirmed and fixed by VS Code's own developers after the authors filed issue reports, a rare case of a CV-based SE tool generating real, externally validated bug fixes in a widely used open-source project.
