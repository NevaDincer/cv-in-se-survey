# Deep GUI: Black-box GUI Input Generation with Deep Learning

- **Year:** 2021
- **Venue/Source:** ASE 2021 (36th IEEE/ACM International Conference on Automated Software Engineering)
- **DOI:** 10.1109/ASE51524.2021.9678778

## Metadata

- **se_area:** Testing (automated Android/mobile GUI test input generation)
- **se_task:** Black-box, platform-independent GUI test input generation, producing an app-crawling tool (Monkey++, extending Google Monkey) that generates more effective touch/scroll/swipe actions than pure random testing, using only screenshots (no access to app implementation, XML layout, or source code)
- **cv_technique:** UNet-based deep convolutional neural network (image-segmentation-style architecture) with a MobileNetV2 encoder (pretrained on ImageNet, used via transfer learning) that takes a raw screenshot as input and outputs multi-channel "heatmaps" (one per action type: touch, scroll, swipe) predicting the probability that each pixel is a valid location for that action; framed by the authors as a single-step deep Q-Learning formulation; agglomerative clustering (scikit-learn) is used at inference time to group heatmap pixels into "widget" clusters for a cluster-based action-sampling readout
- **platform:** Mobile (Android; also evaluated cross-platform on Web, via Selenium/Firefox, without retraining)
- **rationale:** Robustness / generalizability (a completely black-box, platform-independent approach that works regardless of an app's underlying implementation, non-native/web-wrapped apps, obfuscated or unusual code, where white-box/XML-tree-based tools fail or perform poorly); ease of use (no need to probe implementation details; the trained model transfers to a new platform, web, with zero retraining); efficiency (transfer learning from MobileNetV2/ImageNet weights makes the data-hungry training process more data- and time-efficient, important given the deliberately slow, animation-filtering data-collection process)
- **artifact_type:** Full-interface (whole-screen screenshot processed as input) producing localized (per-pixel/per-widget heatmap output identifying specific touch/scroll/swipe target locations)
- **eval_method:** Empirical evaluation using the Androtest benchmark (31 real-world Android apps for testing, plus training/validation splits) measured via Emma line coverage over one-hour crawling runs (9 parallel runs per app, statistical significance via one-tail Kolmogorov-Smirnov tests); introduces a "Crawling Complexity" (CC) metric based on Shannon entropy of coverage distributions to identify apps where intelligent input generation should matter most; separate cross-platform evaluation on the top 15 US websites (20 runs each, 600 steps) counting distinct URLs visited, comparing Deep GUI (Android-trained, unmodified) against a random agent; ablation comparing transfer-learning-initialized vs. randomly-initialized model weights
- **challenges:** Data collection is very time-consuming (requires monitoring the screen for ~5 seconds per action to filter out animated/illegitimate changes), limiting dataset size/expressiveness even with transfer learning mitigating this; the complex hybrid-readout hyperparameters (e.g., weighted vs. cluster sampling mixture ratios, per-action-type biases) are difficult to tune systematically due to the expense of validating on real apps; the approach is explicitly "context-blind," it does not consider prior interactions/history when choosing the next action, unlike context-aware tools, though the authors argue this could be extended via multi-step Q-Learning in future work; improvement over Google Monkey is most pronounced only for apps with high "Crawling Complexity" (complex GUIs), with negligible or occasionally negative differences on simple apps

## Summary

Deep GUI is a black-box, platform-independent technique for generating GUI test inputs that improves on Google Monkey's purely random Android testing by using deep learning to predict, from a screenshot alone, which screen regions and action types (touch, scroll, swipe) are likely to produce a meaningful change in the app's UI state. The core model is a UNet architecture with a MobileNetV2 contracting path, initialized through transfer learning from ImageNet, that outputs a multi-channel heatmap over the screenshot: each channel's pixel values represent the predicted probability that a given action at that location is valid, meaning it produces a legitimate, non-animation UI change. Training data is collected automatically and entirely black-box, with apps crawled through random actions while screenshots, actions, and resulting UI-change labels get recorded, using a 5-second pre-action monitoring window to filter out animated changes that aren't caused by the interaction itself. At inference time, two readout mechanisms, weighted pixel sampling and agglomerative-clustering-based widget sampling, combine to choose actions from the heatmaps. Implemented as Monkey++, an extension of Google Monkey, and evaluated on the Androtest benchmark (31 apps), Deep GUI significantly beats vanilla Google Monkey's line coverage specifically on apps with high "Crawling Complexity," a novel entropy-based metric the authors introduce to capture how much a random crawler's coverage varies run to run. A particularly notable result is cross-platform generalization: without any retraining, the Android-trained model drives a Firefox browser through the top 15 US websites via Selenium and clearly beats a random baseline on distinct URLs visited, supporting the authors' claim that GUI conventions look similar enough across platforms for a purely visual model to transfer on its own.
