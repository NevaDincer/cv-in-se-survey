# Vision-based Widget Mapping for Test Migration across Mobile Platforms: Are We There Yet?

- **Year:** 2023
- **Venue/Source:** 2023 38th IEEE/ACM International Conference on Automated Software Engineering (ASE)
- **DOI:** 10.1109/ASE56229.2023.00068

## Metadata

- **se_area:** Testing
- **se_task:** Cross-platform GUI test migration (specifically: widget mapping, identifying the semantically equivalent target-platform widget for a given source-platform widget, as the core enabling step for translating GUI test events from iOS to Android and vice versa)
- **cv_technique:** Multiple vision-based widget descriptor/comparison algorithms evaluated and recombined into 89 configurations: SIFT (three variants, SIFT-M/METER, SIFT-L/LIRAT, SIFT-F/FMA, differing in supporting matching algorithms such as RANSAC), ORB, Image Hashing (IH) for the graphic visual feature; OCR-extracted text compared via Word2Vec+tf-idf, Levenshtein Edit Distance, and a custom similarity formula; plus non-CV positional features location (Euclidean distance) and size, and LIRAT's grid-based relative location. Five prior vision-based approaches (MAPIT, METER, LIRAT, WebEvo, FMA) are re-implemented as baselines/sources of these components.
- **platform:** Mobile (cross-platform: iOS and Android)
- **rationale:** Robustness/platform-agnosticism: vision-based (screenshot-derived) matching avoids reliance on platform-dependent textual sources (Android content-descriptor vs. iOS accessibility label, or app source code), which the paper argues is brittle and hard to generalize to less-well-known platforms; context-driven matching (visual/textual consistency of semantically equivalent widgets across platform versions)
- **artifact_type:** Localized (per-widget descriptors extracted from screenshots, graphic appearance, OCR text, on-screen location/size of individual widgets, not whole-screen or temporal/video artifacts)
- **eval_method:** Construction and release of a real-world dataset of 6,730 bi-directionally mapped widget pairs from 1,197 screen pairs across 50 popular cross-platform (iOS/Android) apps spanning 10 app categories; 89 configurations evaluated twice per configuration (iOS-to-Android and Android-to-iOS) for a total of 13,460 widget-mapping requests per configuration; metrics: precision, recall, F1; manual classification of widgets into 8 inconsistency subcategories (T0-T2 textual, G0-G3 graphical, Mix) to analyze where vision-based matching succeeds/fails; internal comparison isolating the effect of feature-comparison algorithm and matching method choices
- **challenges:** (1) ~28.1% of semantically-equivalent mapped widgets display inconsistent appearance (different text, or different shape/color of graphics) across the iOS/Android versions of the same app, directly undermining vision-based matching; (2) current graphic-comparison algorithms (SIFT/ORB/IH) can detect consistency but struggle to produce meaningful graded similarity values when graphics are inconsistent; (3) more visual features do not always help, adding size alone can hurt performance, and combining too many features without a well-designed matching/aggregation method can dilute reliability (e.g., using text on purely graphical widgets adds noise); (4) OCR can miss characters, undermining text-based consistency checks; (5) the study is limited to one-to-one widget mappings, excluding one-to-many/many-to-one cases that occur in practice.

## Summary

This paper runs the first systematic empirical study of vision-based widget mapping for cross-platform (iOS to Android) GUI test migration. Vision-based matching gets promoted as platform-agnostic, but how well it actually works, and why it fails when it does, had not been closely studied before this; only one prior technique, MAPIT, had used visual features for this purpose. The authors build the first public real-world dataset of 6,730 verified widget-mapping relations from 50 popular cross-platform apps, then extract and re-implement five existing vision-based approaches (MAPIT, METER, LIRAT, WebEvo, FMA) as sources of widget descriptor features, text, graphic appearance, location, size, relative location, feature-comparison algorithms (SIFT variants, ORB, image hashing, Word2Vec, edit distance), and matching methods, and systematically recombine all of it into 89 configurations. About 28% of ground-truth mapped widgets turn out to have inconsistent appearance across platforms, and a number of the derived configurations, particularly MAPIT variants, outperform the five original techniques, showing real headroom for improvement. Feature selection turns out to be non-trivial: more features don't automatically help, text only helps for textual widgets and needs to be applied carefully, location is surprisingly one of the most important features alongside text, and the commonly emphasized graphic feature matters comparatively less. Current graphic-comparison algorithms still need work to handle appearance inconsistency well. The best configuration found, image hashing for graphics plus edit distance for text plus location and size, using MAPIT-style weighted-average matching, improved F1 by 5.78 to 56.92% over the five original approaches.
