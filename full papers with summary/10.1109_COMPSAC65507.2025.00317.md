# Exploring the Black-Box: Testing Image Synthesis Systems through Metamorphic Exploration

- **Year:** 2025
- **Venue/Source:** COMPSAC 2025 (49th IEEE Annual Computers, Software, and Applications Conference)
- **DOI:** 10.1109/COMPSAC65507.2025.00317

## Metadata

- **se_area:** Testing (software quality assurance / test-oracle design for AI-driven, deep-learning-based systems)
- **se_task:** Metamorphic testing of a deep-learning image synthesis (visible-infrared image fusion) network to detect implementation defects (specifically, an incorrect FFTShift tensor-dimension operation) that traditional testing cannot catch due to the neural-network "oracle problem" (no ground truth for correct output given non-deterministic, black-box model behavior)
- **cv_technique:** AutoEncoder-based visible-infrared image fusion network (encoder with 2D FFT-based frequency-domain feature-enhancement modules) as the system under test; classical image-quality metrics used as evaluation/comparison signals, Structural Similarity Index Measure (SSIM) / Structural Dissimilarity (DSSIM), and a custom Frobenius-norm-based tensor-variance metric, used to quantify and detect the defect's visual/numerical impact
- **platform:** General (deep learning image-processing/computer-vision system; visible-infrared image fusion research software, not a GUI, mobile, web, or desktop application in the traditional SE artifact sense)
- **rationale:** Robustness (Metamorphic Exploration is explicitly proposed as a way to reveal hidden implementation-vs-theory mismatches even when the tester lacks full knowledge of a complex system's internals, i.e., context-driven understanding-building); necessity/oracle-problem-driven (traditional test oracles cannot specify precise expected outputs for non-deterministic black-box neural networks, so a relational/metamorphic approach is required instead)
- **artifact_type:** Full-interface (whole synthesized/fused image outputs compared across metamorphic test variants) and temporal in a loose sense (batch-size variation across a fixed input, not a video/sequence, but multiple related output instances derived from the same source)
- **eval_method:** Custom Hypothesized Metamorphic Relation (HMR), "batch-size invariance": reconstruction results for the same fixed source input should be identical regardless of batch size / zero-padding configuration, tested via a Frobenius-norm-based variance metric (sigma-squared, threshold epsilon=0.01, calibrated via grid search over 10,000 samples for 100% sensitivity) on 50 randomly selected KAIST dataset visible-channel images; comparative sensitivity analysis against SSIM/DSSIM (found the proposed Frobenius-norm metric more sensitive to low-level computational/numerical errors, while SSIM/DSSIM better captures perceptual/semantic similarity); root-cause code review confirming the defect (FFTShift incorrectly applied across the batch dimension instead of only spatial H,W dimensions)
- **challenges:** Threat of misclassifying benign floating-point/GPU-parallelism numerical variance as an actual "bug" (a main threat-to-validity the authors explicitly discuss); setting an appropriate variance threshold epsilon is difficult, too low causes false positives from floating-point noise, too high risks missing subtle real bugs; the proposed ME/HMR design is demonstrated on only a single case study (one visible-infrared fusion AutoEncoder network) and is not yet automated or integrated into CI/CD, which the authors identify as future work; generalizability to other deep learning architectures (GANs, diffusion models, NLP models) is untested and left for future work

## Summary

This paper takes on the software-testing oracle problem for deep-learning image synthesis systems: because neural network outputs are non-deterministic, from random initialization, dropout, and floating-point or GPU-parallelism effects, and their internals stay largely opaque even to their own developers, traditional testing can't specify one correct expected output to check against. The authors apply Metamorphic Testing and its extension, Metamorphic Exploration, which validate a deep learning system by checking whether a Hypothesized Metamorphic Relation, an expected invariance between related inputs and outputs, actually holds. Their case study is a visible-infrared image fusion AutoEncoder network they were developing themselves, where they define and test the relation that a fixed source image's fused reconstruction should stay identical whether that image sits inside an artificially expanded batch (via zero-padding) or gets processed alone at batch size 1. Applying this with a custom Frobenius-norm-based variance metric across 50 test images from the KAIST visible-light dataset turned up a real, previously undetected bug: an FFTShift operation meant only for the spatial height and width dimensions was mistakenly being applied across all four tensor dimensions, including the batch dimension, causing cross-sample feature pollution and visible quality loss whenever batch size exceeded one, a bug invisible under the framework's default single-sample inference setting. The most notable technical contribution is a comparative sensitivity analysis showing the proposed Frobenius-norm variance metric catches this kind of low-level numerical defect far more reliably than the more common SSIM/DSSIM perceptual-similarity metrics. The authors are also candid about the risk that this approach could misclassify benign floating-point non-associativity as a false bug, and recommend combining numerical and semantic-level checks with thresholds tuned to inference precision.
