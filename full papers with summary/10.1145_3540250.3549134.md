# Avgust: Automating Usage-Based Test Generation from Videos of App Executions

- **Year:** 2022
- **Venue/Source:** ESEC/FSE 2022
- **DOI:** 10.1145/3540250.3549134

## Metadata

- **se_area:** Testing (test generation)
- **se_task:** Usage-based/functional GUI test generation for mobile apps, learned from videos of app usages performed on other (source) apps and transferred to a new target app
- **cv_technique:** Autoencoder (AE) for vision-only screen embedding/classification of app screenshots; screen classifier and widget classifier combining visual (autoencoder-derived) and textual (OCR-derived) features; OCR for extracting on-screen text; k-NN and MLP classifiers applied on top of visual embeddings for screen/widget classification
- **platform:** Mobile (Android)
- **rationale:** Context-driven (learns semantic "usage" patterns like Sign In, Search, Add to Cart from real usage videos across many apps and transfers this understanding to an unseen target app); robustness (vision-only classification avoids reliance on brittle app-specific runtime/accessibility metadata; works even when such metadata is unavailable or inconsistent)
- **artifact_type:** Full-interface (whole-screen classification) and localized (widget-level classification/cropping)
- **eval_method:** Empirical evaluation on 374 videos of 18 common usages across 18 popular apps; test generation evaluated on 3 target apps per usage (51 tests total): manual judgment of whether generated tests accomplish the intended usage (68.6% success), plus precision/recall comparison against closest human-written test for the remainder; classification accuracy evaluated via leave-one-out cross-validation (Top-1/Top-5 accuracy) compared against the prior state-of-the-art Screen2Vec (S2V); widget classification manually verified by 3 annotators (77.4% correct recommendation rate)
- **challenges:** Test generation is a developer-in-the-loop process (not fully automatic), limiting scalability; 31% of generated tests do not fully accomplish the intended usage; dynamically-obtained runtime UI layout information paradoxically decreases classification accuracy compared to vision-only input, likely due to text-only noise (e.g., app-specific content descriptions) not generalizing across apps; approach depends on having a diverse enough set of source-app videos covering the target usage; evaluated only on Android and a curated set of 18 apps, limiting generalizability claims

## Summary

Avgust generates usage-based GUI tests for a target mobile app (e.g., "Sign In", "Add to Cart") by learning a general model of that usage from videos of other apps performing the same usage, then guiding a developer-in-the-loop test generation process on the new app. Its core technical contribution is a vision-only screen and widget classification pipeline: an autoencoder learns visual embeddings of app screens/widgets from raw screenshots, which are combined with OCR-extracted textual features to classify screens into semantic categories and recommend widgets to interact with at each step, guided by an Information Retrieval (IR) model built over the usage videos from multiple source apps. The system is evaluated on 374 videos spanning 18 common app usages across 18 popular Android apps: for 68.6% of generated tests, Avgust fully and correctly reproduces the intended usage on an unseen target app, and for most of the rest, the generated test still captures a majority of states/transitions found in the closest human-written test, suggesting practical time-saving value even when not fully correct. A notable finding is that Avgust's vision-only classifiers consistently outperform the prior state-of-the-art Screen2Vec (S2V) in both screen and widget classification accuracy, and that adding dynamically-crawled runtime layout information (rather than relying purely on visual/OCR features) actually decreases accuracy, an unusual result attributed to a mismatch between the noisy runtime text and the vision-centric training distribution. The paper's contribution is notable for being one of the few works targeting usage-specific (rather than coverage-maximizing) automated test generation, using computer vision as the primary channel for cross-app usage transfer.
