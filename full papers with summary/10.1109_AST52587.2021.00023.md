# A framework for the automation of testing computer vision systems

- **Year:** 2021
- **Venue/Source:** 2021 IEEE/ACM International Conference on Automation of Software Test (AST)
- **DOI:** 10.1109/AST52587.2021.00023

## Metadata

- **se_area:** testing
- **se_task:** automated test-case generation and robustness testing for vision/image-recognition systems (the vision system is the software-under-test, not a tool used to test other software)
- **cv_technique:** Mask R-CNN (pretrained on MS COCO) used as the example object-detection/classification system-under-test; Structural Similarity Index Measure (SSIM) used as an image-difference metric to quantify how much a generated test image deviates from its original; a suite of image-modification operators (color inversion, single/random pixel changes, affine transformation, blur, darken/brighten, and weather effects, fog, rain, snow, sun/shadow) used to generate test inputs
- **platform:** general (an industrial surface-quality-inspection vision system; illustrative experiments run on generic photographic images, not mobile/web/desktop software UIs)
- **rationale:** robustness (the explicit goal is testing whether a vision system's output stays stable under small input perturbations and correctly signals failure under severe ones) and ease of use / extensibility (the framework is designed with a uniform Python interface so new modifiers, detectors, or similarity metrics can be plugged in easily)
- **artifact_type:** full-interface in the loose sense that whole images (not localized GUI widgets) are the test artifacts, but this does not map well onto the survey's usual GUI-artifact taxonomy since the system under test is an image classifier/object detector, not a software UI.
- **eval_method:** a small preliminary experimental study (not the target riblet-inspection system, which was not yet ready for testing, but a stand-in Mask R-CNN/COCO object detector) applied to 5 original images, each modified with 2-3 of the implemented operators (10 modified images total); for each, the paper reports the SSIM score alongside a qualitative description of the resulting object-detection/classification errors (e.g., cars misclassified as boats after color inversion). No accuracy/precision/recall numbers, ground-truth labels, or statistical analysis; the explicit finding is that SSIM score and detection-quality degradation do not correlate well (e.g., a 0.00 SSIM affine transform caused only one misclassification, while other lower-magnitude changes caused more).
- **challenges:** the paper's own preliminary results show weak/no correlation between the SSIM similarity metric and actual object-recognition degradation, meaning SSIM alone is an unreliable proxy for "how much the modification should be allowed to change the output," which the authors flag as needing further investigation; the study is explicitly described as a first proof-of-concept using only a subset of possible modification/image combinations (not a full factorial evaluation); the real target application (riblet surface quality inspection) was still under development and could not yet be tested with the framework at the time of writing; and the framework does not model or test any of the physical/hardware failure modes it discusses conceptually (broken sensors, distorted lenses) beyond synthetic image degradation.

## Scope note

this paper is the inverse of the survey's usual direction. It doesn't use computer vision to support a software-engineering task; instead it applies software-engineering testing techniques (automated test-case generation, metamorphic-style image modification, SSIM-based output comparison) to test a computer-vision system as the system under test, an industrial riblet-surface quality-inspection classifier, evaluated here via a Mask R-CNN/COCO stand-in. If the survey, following Bajammal et al. 2022, specifically scopes CV techniques applied to SE tasks, this paper likely falls outside that scope and belongs to the adjacent testing-of-ML/CV-systems literature instead. The extraction below was completed only because it was one of the target DOIs provided; inclusion needs confirming.

## Summary

This paper proposes a Python-based testing framework for a problem the authors say is under-studied: systematically and automatically testing vision and image-recognition systems, rather than only manually evaluating them on a static labeled test set. The framework has three modular parts: a pluggable classifier or object-recognition component, demonstrated with a pretrained Mask R-CNN on MS COCO; a modifier component implementing a library of image-perturbation operators (inversion, pixel changes, affine transforms, blur, brightness and darkness changes, and weather-like effects such as fog, rain, snow, and sun or shadow); and an image-diff component that computes the Structural Similarity Index Measure (SSIM) between an original and a modified image to quantify how similar the perturbation should be considered. Test suites get generated by applying modification operators to an initial seed suite, producing either a "should behave similarly" suite for small perturbations, or a "should raise an error" suite for severe ones, like an all-black image simulating a broken light source. The motivating application is riblet-surface quality inspection for aerodynamic drag reduction in aviation, though that target system wasn't ready for testing yet, so the preliminary study instead applies the framework to a stand-in Mask R-CNN detector across 5 sample images. A notable, somewhat counterintuitive finding is that SSIM score poorly predicts actual detection degradation: some near-zero-SSIM transformations barely affected recognition while some higher-SSIM ones caused more misclassifications, which the authors flag as an open problem needing further study.
