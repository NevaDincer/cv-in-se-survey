# MAPIT: UI Test Migration Across Mobile Platforms

- **Year:** 2021
- **Venue/Source:** 2021 36th IEEE/ACM International Conference on Automated Software Engineering (ASE)
- **DOI:** 10.1109/ASE51524.2021.9678643

## Metadata

- **se_area:** testing
- **se_task:** Bi-directional migration/transfer of usage-based GUI (UI) test cases, including UI events, test oracles, and system events, between "sibling" closed-source mobile apps implemented on different platforms (Android and iOS), without access to source code.
- **cv_technique:** ORB (Oriented FAST and Rotated BRIEF) keypoint/feature-descriptor extraction for widget screenshot images; Hamming distance for descriptor matching; Lowe's ratio test for filtering good keypoint matches; a normalized image similarity score (ratio of matched descriptors to max descriptor count) combined with geometric similarity (Euclidean distance between widget screen positions) and size similarity (normalized widget-size difference) into a weighted "visual similarity score." (Also combined with non-CV NLP techniques: Word2Vec embeddings + tf-idf and cosine similarity for textual widget-attribute matching, and Tesseract OCR to extract on-screen widget text as additional textual data.)
- **platform:** mobile
- **rationale:** robustness: CV-based visual widget matching is used because closed-source apps provide limited/unreliable textual metadata (resource ids, accessibility labels, etc. differ or are missing across Android/iOS), so relying on text alone is fragile. Visual (image) similarity of UI widgets, which "tend to have very similar looks by design" across sibling apps, provides a more robust complementary signal. The paper's own evaluation shows the composite visual+textual mapper outperforms either single modality in nearly all cases, justifying CV as an accuracy/robustness enhancement over text-only prior work (e.g., TestMig).
- **artifact_type:** localized (widget-level: cropped screenshot images of individual UI elements compared for image, position, and size similarity, not whole-screen/full-interface matching, and not temporal/video or natural-language input)
- **eval_method:** Empirical evaluation on 25 pairs of real-world, widely used, closed-source sibling Android/iOS apps across 5 categories (News, Shopping, ToDo List, Web Browser, Mail Client; 5 apps each, listed in Table II). For each app pair, 4 representative usage-scenario test cases (Table III) were manually recorded via Appium/Robot framework and used as both source and ground-truth tests, transferred bi-directionally, yielding 200 test-transfer cases containing 828 UI events, 176 oracle events, and 50 system events. Metrics: (1) event-mapping accuracy, measured by manually comparing each mapped event to ground-truth equivalent states/events, compared across three mapping strategies, vision-only, text-only, and MAPIT's composite (vision+text), broken down by app category and transfer direction (Fig. 8); (2) usefulness, measured via a manual-effort-reduction metric from prior work (Zhao et al. 2020) counting event insertions/deletions/substitutions needed to fix a transferred test vs. writing it from scratch (Fig. 9); (3) performance/runtime (average ~101s for Source Data Extraction, ~217s for Test Migration, ~5 min/test). No baseline tool comparison was possible against the closest prior work, TestMig, because TestMig requires source code (unavailable for the closed-source subjects) and only supports one-way iOS-to-Android transfer; instead, an internal ablation (vision-only vs. text-only vs. composite) served as the comparison. Results: >75% overall event-mapping accuracy; >55% average manual-effort reduction; 58/200 (29%) test cases transferred with 100% correctness (eliminating manual effort). No formal human/user study beyond the authors' manual verification of correctness.
- **challenges:** Authors explicitly report: (1) sibling apps whose events/states are not related 1-to-1 (1-to-N mappings) are especially hard to support, particularly for bi-directional transfer, and occurred in ~8% of the 100 test scenarios; (2) MAPIT cannot extract UI models from certain commercial apps due to (a) obfuscation hiding UI elements, (b) hybrid web+native apps not analyzable by Appium, (c) UI states blocking data extraction/screenshots for security reasons (e.g., login screens), and (d) unsupported action types (e.g., scrolling); (3) currently supports only click and keyboard-input UI events (no swipe/scroll), though the architecture is designed to be extensible; (4) transferring test oracles across platforms is inherently harder than transferring UI events because supported oracle/attribute types differ between Android and iOS, requiring heuristic (not always possible) mappings, and some oracle attributes (e.g., Android's "clickable") have no iOS equivalent and become "not mappable"; (5) reliance on regular-expression matching to parse source tests into MAPIT's internal representation constrains the input test formats/frameworks it can handle; (6) fixed similarity thresholds tuned globally across all apps were found to be suboptimal for some categories (e.g., iOS-to-Android mapping of Web Browser apps performed worse), suggesting thresholds may need per-category tuning; (7) early incorrect event mappings can cascade, causing the target app to "get lost" and making all subsequent events map incorrectly, which explains cases of high accuracy but low usefulness/effort-reduction.

## Summary

MAPIT migrates usage-based UI test cases bi-directionally between sibling mobile apps built on different platforms, Android and iOS, fixing three limitations the authors identify in the only prior cross-platform approach, TestMig: it needs no app source code, supports both transfer directions, and can migrate test oracles and system events on top of UI click and input events. The tool works in two phases. First, it dynamically runs an existing source test to build a UI Transition Model that captures screenshots, widget properties (including OCR-extracted text via Tesseract), and event transitions. Then it migrates the test to the target platform by mapping each source widget to its closest target widget through a composite comparison: a Visual Comparator using ORB keypoint and descriptor matching (Hamming distance, Lowe's ratio test) combined with position and size similarity, and a Textual Comparator using Word2Vec and tf-idf embeddings with cosine similarity, with a Widget Selector reconciling the two outputs. Evaluated on 25 real-world closed-source app pairs across 5 categories, 200 bidirectional test transfers covering 828 UI events, MAPIT reached over 75% event-mapping accuracy and more than 55% reduction in manual test-writing effort, with 29% of tests transferring with zero remaining manual effort. The composite visual-plus-textual mapper beat vision-only or text-only strategies in nearly every category, a notable result given that closed-source apps often lack rich textual metadata, which makes the added visual signal genuinely valuable rather than redundant.
