# Guided Bug Crush: Assist Manual GUI Testing of Android Apps via Hint Moves

- **Year:** 2022
- **Venue/Source:** CHI '22, ACM CHI Conference on Human Factors in Computing Systems, April 29–May 5, 2022, New Orleans, LA, USA
- **DOI:** 10.1145/3491102.3501903

## Metadata

- **se_area:** testing
- **se_task:** Guiding/assisting manual (exploratory) GUI testing of Android apps: helping human testers avoid missing functionalities/activities, avoid repeated exploration steps, and detect more UI bugs during manual test sessions.
- **cv_technique:** None (image-based). The tool ("NaviDroid") is built on static program analysis (AST traversal of intent()/ICC calls to build an activity/state transition graph), dynamic GUI exploration (random-action app crawling to capture states/actions from Android view-hierarchy XML dumps via `uiautomator dump`), a context-aware state-merging heuristic comparing hierarchy structure/adjacent states, and a dynamic-programming (Floyd–Warshall-based) shortest-path/path-planning algorithm. The run-time "visual hint" is a floating window/bounding box drawn at the coordinates of the target UI component (from the view-hierarchy file), a UI overlay technique, not a learned or classical CV model.
- **platform:** mobile
- **rationale:** ease of use; robustness
- **artifact_type:** localized (a highlighted bounding box / floating window drawn over a single next-action UI element to guide the tester)
- **eval_method:** Two-part evaluation. (1) Automated effectiveness evaluation on 85 open-source F-Droid apps comparing NaviDroid's extracted state-transition graph and DP-based path planning against 5 baselines (IC3, Monkey, Droidbot, DroidMate, Humanoid) for activity/state coverage, and against DFS/BFS/random exploration for path-planning efficiency (number of exploration steps). (2) A controlled user study with 32 recruited crowdtesting-platform testers (16 experimental using NaviDroid vs. 16 control without) manually testing 20 apps seeded with 30 real UI display bugs, measuring state/activity coverage, testing time, and bugs found, analyzed with Mann-Whitney U tests, plus qualitative participant feedback via post-study survey/interview.
- **challenges:** Incomplete state-transition graph extraction (misses states from unconventional/poorly structured code, AppWidget activities requiring complex trigger sequences, and dynamically rendered components with non-descriptive numeric IDs); limited to click-triggered transitions only (cannot handle scrolling, text-filling, or complex multi-action combinations); cannot properly visualize/handle highly animated or dynamic UI transitions (animation components are skipped); generalization to other platforms (iOS, web, desktop) is untested and would require platform-specific empirical study and a new state-extraction/exploration tool.

## Scope note

The paper's "visual hint" guidance is a floating-window bounding-box overlay computed directly from Android view-hierarchy (accessibility/XML) coordinates obtained via `uiautomator dump`, not from image-based computer vision. State identification, state merging, and near-duplicate detection are also done via GUI hierarchy/DOM-like structure comparison and static/dynamic program analysis (AST traversal, intent-call analysis, dynamic programming path planning), not via any image classification, object detection, OCR, or visual-similarity model. The only mention of "visual features" for state deduplication refers to a cited prior work the authors explicitly avoid using in favor of hierarchy-based merging. As such, the paper's connection to computer vision techniques is weak to nonexistent, despite the "visual"/"visualized" terminology used to describe the UI overlay.

## Summary

This paper presents NaviDroid, a tool that assists manual (exploratory) GUI testing of Android apps by highlighting recommended next actions directly on the running app's screen, inspired by "hint moves" in the game Candy Crush. Motivated by a formative study showing manual testers achieve only 57% activity coverage while remaining overconfident and frequently revisiting the same screens, NaviDroid combines static program analysis (parsing intent-triggering code) and dynamic random exploration to build an enriched state-transition graph (STG) annotated with the trigger action for each edge, using a context-aware method to merge near-duplicate states. A dynamic-programming (Floyd–Warshall-based) algorithm then plans an exploration path minimizing repeated steps, and a floating-window overlay highlights the corresponding UI component (button, back action, or long-press widget) at run time using coordinates read from the Android view hierarchy. Automated evaluation on 85 F-Droid apps showed NaviDroid achieving 74% median activity coverage and 81% median state coverage, outperforming five baselines, and saving 20–42% of exploration steps versus DFS/BFS/random search. A user study with 32 testers across 20 apps found the NaviDroid-assisted group covered 62% more states, 79% more activities, found 146% more bugs, and finished 25% faster than the unassisted control group, with participants praising the interaction design. Although framed around "visual" guidance, the underlying techniques are hierarchy- and coordinate-based rather than image/vision-based, and the paper acknowledges limitations around incomplete graphs, click-only interactions, and animated UIs.
