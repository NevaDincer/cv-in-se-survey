# Semantic Matching of GUI Events for Test Reuse: Are We There Yet?

- **Year:** 2021
- **Venue/Source:** ISSTA '21 (30th ACM SIGSOFT International Symposium on Software Testing and Analysis)
- **DOI:** 10.1145/3460319.3464827

## Metadata

- **se_area:** Testing
- **se_task:** GUI test reuse / test migration across mobile apps (semantic matching of GUI events as the core sub-problem that drives test-case migration between a source and target Android app)
- **cv_technique:** Not computer-vision-based in the image sense. The "matching" technique is NLP/word-embedding based: Word2vec; GloVe; Word Mover's Distance (WMD); FastText; BERT; NNLM; Universal Sentence Encoder (USE). Note: this paper operates purely on textual/GUI-attribute descriptors (text, resource-id, content-desc, hint, neighbor-text, etc.), not on pixel/visual data.
- **platform:** Mobile (Android)
- **rationale:** Context-driven (captures semantic equivalence of GUI widgets across differently-implemented apps to enable robust test transfer); robustness (aims to outperform brittle syntactic/ID-based matching approaches used by prior test-reuse tools)
- **artifact_type:** Localized (per-widget/per-event textual descriptors extracted from GUI states/layout files; not full-interface image analysis)
- **eval_method:** Empirical study with 253 configurations of the matching pipeline (corpus × embedding × descriptor set × matching algorithm), evaluated on 337 unique queries / 8,099 GUI events from 30 Android apps using Mean Reciprocal Rank (MRR) and TOP1 accuracy; statistical significance via two-sided t-tests
- **challenges:** Out-of-vocabulary (OOV) issues depending on training corpus; some widget attributes (e.g., activity-name) can hurt matching accuracy rather than help; word-level embeddings underperform sentence-level ones because widget text often spans multiple words; no evaluation of the downstream impact on full test-reuse effectiveness (only semantic matching in isolation, not paired with test generation)

## Summary

This paper presents the first systematic empirical study isolating the "semantic matching" component that underlies GUI test-reuse tools such as ATM and CraftDroid, decomposing it into four components: corpus of documents, word-embedding technique, event-descriptor extractor, and matching algorithm. The authors build an evaluation framework and run 253 configurations across these components on 337 real semantic-matching queries drawn from 30 Android apps (8,099 GUI events), comparing against syntactic baselines (edit distance, Jaccard) and a random baseline. Their main findings are that (1) the matching algorithm has the largest impact on the effectiveness of semantic matching, (2) sentence-level embeddings (Word Mover's Distance, Universal Sentence Encoder) substantially outperform word-level embeddings (Word2vec, used by both ATM and CraftDroid), (3) including certain widget attributes (e.g., activity-name) can hurt accuracy, and (4) training embeddings on app-domain corpora (a newly built 900K-app Google Play description corpus) outperforms generic corpora like blog text. Building on these insights, they propose SemFinder, a new matching algorithm that concatenates all attribute values into single sentences and uses sentence-level embeddings, which statistically significantly outperforms both ATM's and CraftDroid's original algorithms on MRR and TOP1 while also being computationally faster. Although central to GUI test reuse, the technique itself is textual/NLP-based rather than pixel-based computer vision, which is a scope consideration for a CV-in-SE survey. It is included here as it manipulates and reasons over GUI screen/widget representations analogous to visual GUI testing work, but readers should note the "matching" is over text descriptors, not images.
