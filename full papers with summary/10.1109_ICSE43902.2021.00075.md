# Don't Do That! Hunting Down Visual Design Smells in Complex UIs against Design Guidelines

- **Year:** 2021
- **Venue/Source:** 2021 IEEE/ACM 43rd International Conference on Software Engineering (ICSE 2021)
- **DOI:** 10.1109/ICSE43902.2021.00075

## Metadata

- **se_area:** design
- **se_task:** Visual design smell / design-guideline violation detection in UIs (automatically checking Android app UI screenshots and UI mockups against Google Material Design "don't"-guidelines, and reporting/visualizing the violations for developers)
- **cv_technique:** EAST (deep-learning-based scene text/region detector) for text region detection; Tesseract OCR for converting detected text regions into text strings; a UI widget detection tool (cited prior work, computer-vision based) for detecting non-text UI widget regions such as icons/buttons; HSV color-space based primary color extraction; Canny edge detection for detecting component/divider edges
- **platform:** mobile (Android apps built with Google's Material Design system; input is UI mockups or app UI screenshots, no source code needed)
- **rationale:** Context-driven. Visual guideline violations (design smells) can only be identified by examining the actual rendered appearance of UI components (text truncation/wrapping, icon presence/count, primary color, edges) in relation to their surrounding layout context and component metadata, since design guidelines are defined over multi-modal, in-context visual information (typography, iconography, color, edge) rather than raw pixels or source code alone.
- **artifact_type:** full-interface (analyzes entire UI screenshots/mockups, extracting and validating multiple components and their spatial/visual relationships across the whole screen) with localized detection output (violations are localized to specific highlighted component regions in the report)
- **eval_method:** Two accuracy experiments: (1) 60,756 unique real-app UI screenshots from 9,286 Android apps (derived from the Rico dataset), covering 118,999 component instances across 11 UI component types and 71 don't-guidelines; ground truth established via manual verification of all reported violations plus statistical sampling (error margin 0.05, 95% confidence) of UIs with no reported violations to estimate false negatives; metrics: precision=0.81, recall=0.90, F1=0.87 overall (per-component breakdown in Table I). (2) 493 UI mockups (413 original + 80 manually edited/injected-smell mockups) from the Material Design Kit in Figma, covering 26 guidelines for 9 component types not exercised by real-app data; UIS-Hunter achieves precision=94%, recall=95%, F1=0.95, detecting 77/80 injected violations with 5 false positives. Two user studies: (a) 5 professional front-end developers manually detected violations of 18 guidelines across 40 selected app UIs (30 known violation instances); manual detection precision=75.5%, recall=71.9%, both worse than UIS-Hunter, compared via a bag-based precision/recall formulation over 5 developers' reports. (b) 5 ordinary Android users (age 21-30) rated the severity of the 27 violation UIs from study (a) on a 5-point Likert scale; most reported violations were rated severe (4-5) by the majority, though ratings were shown to be context- and app-sensitive.
- **challenges:** Authors report: (1) accuracy depends heavily on correct CV extraction (e.g., button-type misclassification (4 variants) causes wrong guideline applicability judgments); failure of the iconography extractor to detect icons in complex/crowded components (e.g., navigation drawer) causes misjudged violations (lowest precision guideline, 0.63); inaccurate detection of thin divider edges leads to wrong judgments for divider-related guidelines. (2) Six low-frequency component types (divider, chip, date picker, tooltip, snackbar, bottom sheet) were excluded from accuracy evaluation due to data scarcity/insufficient triggering instances in the automated exploration dataset, and are left as future work. (3) The approach only covers explicit "don't"/"caution" guidelines with an illustrative example (93 of many more guidelines; animation-related guidelines explicitly excluded as requiring "sophisticated video embedding techniques...beyond the scope of this work"); implicit guidelines without illustrative examples are not covered. (4) The list component type produced zero detected violations, raising open questions about detector coverage for that component. (5) Severity/utility findings show some guideline violations are subjectively "controversial" (mixed severity opinions among users and lower detection motivation among developers), suggesting not all guideline violations are equally actionable in practice.

## Summary

This paper presents UIS-Hunter, a tool for automatically detecting "visual design smells," violations of explicit don't-guidelines in Google's Material Design system, in Android app UIs. The authors first conduct a demographic study of 93 don't-guidelines spanning 17 UI components, seven general design dimensions (layout, typography, iconography, navigation, communication, color, shape), and four component aspects (anatomy, placement, behavior, usage), identifying five types of atomic UI information needed to check guideline violations: component metadata, typography, iconography, color, and edge information. UIS-Hunter takes a UI mockup or screenshot (no source code required) as input, uses computer-vision techniques (EAST for scene-text detection, Tesseract OCR for text recognition, a widget detector for icons/buttons, HSV-based primary color extraction, and Canny edge detection) to extract these atomic information types, then validates each detected component against a knowledge base of guideline "violation conditions" expressed as first-order logic formulas, producing a report that highlights violating regions with side-by-side conformance/violation examples. Evaluated on 60,756 real-app UIs (9,286 apps) it achieves precision=0.81, recall=0.90, F1=0.87, and on 493 Figma design-kit mockups (with injected violations) F1=0.95. Two user studies show UIS-Hunter outperforms manual detection by five professional developers (75.5%/71.9% precision/recall) and that most flagged smells are rated severe by app users, though severity perception is notably context- and app-sensitive. A notable detail: the tool combines deep-learning CV extractors only for low-level perceptual primitives, then applies explicit symbolic logic for guideline aggregation, avoiding the need for large labeled datasets per guideline.
