# Automated game testing using computer vision methods

- **Year:** 2021
- **Venue/Source:** 2021 36th IEEE/ACM International Conference on Automated Software Engineering Workshops (ASEW)
- **DOI:** 10.1109/ASEW52652.2021.00024

## Metadata

- **se_area:** testing
- **se_task:** automated functional/regression testing of video games, verifying that a game's visual output (UI elements like HUD text/icons, character animation, rendering effects, object motion/physics, gameplay state changes) matches the expected behavior after a game-testing agent (scripted, RL-based, or otherwise) performs an in-game action, replacing manual human QA testers for these visual-verification tasks
- **cv_technique:** Tesseract OCR (via OpenCV) for UI text recognition; classical OpenCV template matching and simple visual feature matching for detecting fixed visual elements (e.g., weapon-cross icon); a re-trained YOLO object detector for detecting environment-specific visual features (e.g., car interior elements: mirrors, steering wheel, navigation) and for locating objects of interest to track motion; OpenPose for real-time multi-person 2D skeleton/pose estimation used in animation testing; scene segmentation methods (cited, e.g. "seamless scene segmentation") mentioned as an alternative/available option; classical image pre-processing (RGB-to-HSV conversion, edge detection, smoothing) applied to improve recognition accuracy; a custom homography-matrix-based projection technique to map 2D bounding-box detections back into 3D game-world coordinates for motion/physics verification
- **platform:** game
- **rationale:** robustness (aims to reduce costly, error-prone, and non-scalable manual human QA testing, which is described as expensive and increasingly insufficient given release deadlines and industry scale) and ease of use / engine-independence (the framework is explicitly designed as a plugin-based, engine-and-platform-agnostic architecture, usable across PCs, consoles, or different OSes and independent of Unity/Unreal/other engines, and built to reuse existing open-source CV libraries rather than requiring proprietary per-engine testing tools)
- **artifact_type:** full-interface (whole-screen HUD/UI text and icon recognition) combined with localized/temporal detection (object bounding boxes for specific in-scene features; skeleton tracking and object-trajectory tracking across a sequence of N frames for animation and motion/physics testing). The paper spans multiple artifact granularities depending on the specific test type (UI, animation, rendering, physics, gameplay).
- **eval_method:** a series of targeted accuracy/precision experiments on official Unreal Engine 4 demos (ShooterGame, CarConfigurator) and a Unity-based tank game. (1) UI text recognition tested over 1,000 synthetic weapon-change/ammo-count tests with intentionally-injected errors 50% of the time, achieving 95.6% accuracy; weapon-cross icon detection under the same protocol achieving 88.9% accuracy. (2) Environment-change detection (YOLO-based, e.g. detecting "inside car" state) tested over 1,000 trials with 50% intentional failures, achieving 100% accuracy across varied camera angles/lighting to check for overfitting. (3) Object-motion/physics verification (homography-based 2D-to-3D projection of projectile trajectories) tested over 1,000 trials across N=180-frame sequences, achieving 89.7% precision at a 10-degree angle-error threshold. Additionally a performance-overhead evaluation measuring per-frame inference latency for each CV method (OCR ~7.42ms, OpenCV feature matching ~12.1ms, YOLO ~19.37ms on an 8-core AMD Ryzen 5800x) and testing robustness to reduced image resolution (1920x1080 to 640x480 caused only a 1.2% accuracy drop while relieving a data-transfer bottleneck).
- **challenges:** accuracy for motion/physics testing was mainly degraded by occluding objects and visual artifacts (e.g., dust particles, weapon effects) obscuring the tracked object in some frames, an issue the authors explicitly flag as needing further work; UI/icon recognition errors were concentrated in frames containing heavy simultaneous visual effects (e.g., a player character being hit, triggering high-intensity screen effects); sending high-resolution frame sequences from the game process to the external CV testing service was identified as a performance bottleneck, requiring a resolution trade-off; per-frame CV inference latency (especially the ~19ms YOLO detection) could become a bottleneck if many frames need to be analyzed in sequence, for which the authors recommend a pipelined analysis approach; the GameStateChecker component requires custom, per-game-tailored foundation models for detecting game-specific effects (e.g., near-death visual states), since generic detection would fail, meaning the approach is not fully out-of-the-box transferable across games without re-training/re-customization; the evaluation is limited to internally-controlled demo scenes with synthetically injected pass/fail labels rather than real bugs found in shipped commercial games, which the authors list as future work (applying the tool to real industry games and building a shared benchmark dataset).

## Summary

This paper builds a computer-vision framework for automating video game QA, motivated by interviews with a major game studio's QA managers that surfaced test categories still stuck with costly manual testers: UI correctness (does the HUD ammo count match internal state?), animation correctness, rendering effects, physics, and gameplay logic. Rather than building new AI game-playing agents, the usual focus of prior work, the contribution here is a framework that pairs any existing game-testing agent with a decoupled, engine-independent "GameStateChecker" service, using Tesseract OCR for on-screen text, OpenCV template matching for fixed icons, a re-trained YOLO detector for environment- and object-specific features, and OpenPose for character skeleton tracking, to verify that a game's rendered output matches the expected behavior for a given state-action pair. A particularly interesting detail is the motion and physics testing method. Since human testers judge object motion from the 2D rendered image rather than the game's internal 3D representation, the authors build a homography matrix mapping known 3D reference points to their 2D screen positions, then use its inverse to project YOLO-detected bounding boxes of moving objects, like a fired projectile, back into 3D space for trajectory verification. Implemented with a plugin architecture and demonstrated on official Unreal Engine 4 demos and an open-source Unity tank game, the system reaches accuracies from 88.9% (icon recognition) to 100% (environment-change detection) across 1,000-trial synthetic test batches, and tolerates a 4x resolution reduction with only a 1.2% accuracy cost.
