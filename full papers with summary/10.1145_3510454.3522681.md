# Woodpecker: Identifying and Fixing Android UI Display Issues

- **Year:** 2022
- **Venue/Source:** 44th International Conference on Software Engineering Companion (ICSE '22 Companion)
- **DOI:** 10.1145/3510454.3522681

## Metadata

- **se_area:** testing and maintenance (UI display bug detection, localization, and automated program repair)
- **se_task:** detecting Android UI display issues (occlusion/overlap, missing/incorrect information, blurred screens) from screenshots; localizing the corresponding buggy source code; automatically repairing the issue with template-based patches
- **cv_technique:** object detection model composed of a feature-extraction network (50 convolutional layers), a Region Proposal Network (RPN) module, and an ROI pooling module, trained on data from the authors' own empirical study of 4,230 bug reports; supplemented by a GAN-based data augmentation approach to improve detection performance
- **platform:** mobile (Android)
- **rationale:** context-driven (built directly on an empirical study of real-world root causes and repair strategies for UI display issues); robustness (Android's complex rendering pipeline, with no live CSS-style correctness checking as in Web UI, motivates using CV for more accurate, image-based issue localization); automation/reduced developer burden (aims to remove manual issue replay, root-cause diagnosis, and patch authoring from the developer workflow)
- **artifact_type:** localized (bounding boxes around the specific buggy screen region), subsequently mapped through the view-hierarchy file to a bounded region of source code for patching
- **eval_method:** empirical evaluation on 30 real-world UI display issues from 30 different open-source Android apps on GitHub, measuring accuracy of detection, localization, and repair separately (87% / 85% / 77% respectively); a further real-world deployment study applying Woodpecker to 256 additional popular open-source Android apps (sampled from F-Droid), reporting number of previously undetected issues found (112, across 99 apps), automatic repair rate (106/112, 94%), and developer acceptance of submitted GitHub pull requests (76 merged, remainder pending, none rejected)
- **challenges:** bridging the gap between screenshot-level (pixel) issue detection and source-code-level localization, addressed via a two-phase mapping through the app's view hierarchy file; repair template coverage is inherently bounded (9 pre-defined templates were derived to cover 86% of issues per the empirical study, so issues outside these patterns cannot be repaired); some issues fail to repair specifically due to buggy-code localization failures; 8 of the 112 newly found issues in the large-scale study could not be repaired due to underlying logic errors or external resource problems outside the tool's scope; Android's compile-and-render repair/verification loop is inherently slower and less flexible than Web UI's live CSS-based correctness checking.

## Summary

Woodpecker is an end-to-end pipeline for automatically detecting, localizing, and repairing Android UI display issues, specifically occlusion/overlap, missing or incorrect information, and blurred screens, grounded in what the authors describe as the first empirical study of root causes and repair strategies for such issues, mined from 4,230 real bug reports. The pipeline takes an app's source code and APK as input, automatically runs the app to collect screenshots and their corresponding view-hierarchy files, and applies a Faster-R-CNN-style object detection model (50-layer feature extractor plus RPN and ROI pooling), trained on the empirical-study data and augmented with GAN-generated training images, to output a bounding box around the buggy screen area. A two-phase localization process then maps that pixel-level bounding box first to the corresponding component in the view-hierarchy file, and then to the buggy region of source code, using detailed component metadata to bridge the visual and code domains, a step the authors highlight as necessary because Android's rendering pipeline (unlike Web UI's live-editable CSS) requires a full compile-and-render cycle to verify fixes. Finally, Woodpecker matches the localized buggy code against nine pre-defined repair templates (derived to cover 86% of observed repair patterns) and automatically generates and packages a patch. In evaluation, the tool achieved 87% detection accuracy, 85% localization accuracy, and 77% repair accuracy on 30 real-world issues, and in a larger deployment against 256 additional open-source apps it surfaced 112 previously unknown issues, automatically repaired 94% of them, and had 76 of its submitted GitHub pull requests merged by developers with none rejected, a notable real-world adoption signal for an automated, template-based visual bug-repair tool.
