# GIFdroid: Automated Replay of Visual Bug Reports for Android Apps

- **Year:** 2022
- **Venue/Source:** ICSE 2022 (44th International Conference on Software Engineering)
- **DOI:** 10.1145/3510003.3510048

## Metadata

- **se_area:** Testing / Maintenance (bug reproduction and debugging support)
- **se_task:** Automated replay/reproduction of visual bug reports (GIFs/screen recordings) for Android apps
- **cv_technique:** Structural Similarity Index (SSIM) for keyframe/duplicate frame detection; image-processing-based keyframe location; GUI screenshot matching for mapping video frames to app states (uses techniques akin to those in prior visual GUI matching work, e.g., feature/structural comparison); no deep learning is used; the approach is classical image processing
- **platform:** Mobile (Android)
- **rationale:** Ease of use / accessibility (visual bug recordings, e.g. GIFs, are easier for non-technical/end users to create than textual bug reports or instrumented recordings); robustness (works without requiring touch-indicator overlays or full recordings from app launch, unlike prior video-to-scenario tools)
- **artifact_type:** Temporal (video/GIF frame sequence analysis) combined with full-interface (whole-screen GUI state matching)
- **eval_method:** Automated evaluation on 61 real-world visual bug recordings from 31 open-source Android apps (comparing generated execution trace against ground truth, reporting 82% successful reproduction, 50/61); controlled user study with 8 participants (4 experimental w/ tool, 4 control without) reproducing 10 real-world bug recordings, measuring success rate and time (statistically significant speedup, p<0.01); execution time/performance measurements (keyframe location, GUI mapping, trace generation time)
- **challenges:** Traditional image-processing methods (SSIM-based) are not robust to minor GUI changes such as configuration/parameter changes; slow rendering can cause errors in keyframe location; dynamic loading content interferes with GUI mapping; performance/overhead of the pipeline is not ideal for real-time or background use; generalizability across different device screens/resolutions is a threat mitigated only partially by diverse recording conditions in the dataset

## Summary

GIFdroid addresses the problem that visual bug reports (screen recordings/GIFs) are increasingly common because they are easy for end users to create and contain rich information, but they are hard for developers to use directly to reproduce bugs. The tool takes a visual bug recording and, using an image-processing pipeline, (1) locates "keyframes" in the video via structural similarity (SSIM)-based duplicate/near-duplicate frame filtering, (2) maps each keyframe to states in the app's UI Transition Graph (UTG, generated by existing GUI-exploration tools) via screenshot matching, and (3) generates an executable, replayable trace of GUI actions that reproduces the bug. A main contribution is that GIFdroid does not require high-resolution recordings with touch indicators or complete recordings from app launch, both common requirements of prior video-to-test tools (e.g., V2S) that are often unmet in real-world bug reports (the paper's own analysis found only ~25.8% of real recordings include touch indicators and only ~6.8% start from app launch). The automated evaluation on 61 recordings from 31 apps shows GIFdroid successfully reproduces 82% of bugs, and a user study with 8 developers confirms it significantly reduces the time needed to manually reproduce bugs compared to working from the raw recording alone (average 65.0s vs 171.4s, p<0.01). The paper is notable for grounding its design in an empirical analysis of real-world bug report characteristics before building the tool, and for using purely classical computer vision (SSIM, frame-diffing) rather than deep learning, prioritizing lightweight, dependency-free operation over recognition sophistication.
