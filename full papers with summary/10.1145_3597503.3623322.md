# 10.1145/3597503.3623322

> **SCOPE WARNING**: This paper's use of computer vision is superficial and its fit with the CV-in-SE survey is questionable. The core matching technique (TEMdroid) is a BERT-based NLP sentence-embedding model over widget text, not a computer-vision model. The only genuinely visual element is a single use of Tesseract OCR to extract text from image widgets when GUI layout files lack textual attributes (Section 3.2.1); OCR output is then treated as ordinary text and fed into the same BERT pipeline. The paper also borrows the "hard-negative mining" idea from computer vision (object detection literature) as a training-strategy analogy, but does not itself perform any visual/image-based inference. Recommend a careful decision on inclusion; likely excludable or classifiable only as a peripheral/OCR-adjacent case.

## Metadata

- **se_area:** Testing (maintenance-adjacent: test case migration/reuse across apps)
- **se_task:** GUI test case migration; widget matching / event matching for test reuse across mobile apps
- **cv_technique:** Tesseract OCR (used only to extract text from image-only widgets when layout metadata is empty); note that the primary matching model is BERT (NLP), not a CV model; the paper also draws a training-strategy analogy to hard-negative mining from computer vision/object detection
- **platform:** Mobile (Android)
- **rationale:** Robustness (handling widgets whose textual attributes are missing from the GUI layout file); ease of use (avoids requiring source-code access to the target app, unlike prior static-analysis-based approaches)
- **artifact_type:** Localized (OCR is applied to extract text from individual image widgets, not full-screen visual analysis)
- **eval_method:** Empirical evaluation on 34 real-world Android apps (SemFinder and Craftdroid datasets) using Top1 accuracy and MRR for event matching, and Precision/Recall/F1 for test case migration; ablation study; additional usefulness study on 5 industrial apps measuring precision/recall/F1/reduction (manual-effort savings)
- **challenges:** Authors report that TEMdroid still misunderstands semantically related but functionally distinct widgets (e.g., "confirm email" vs. "email"); some widgets' extracted textual information fails to represent true semantics, causing missed matches; the candidate-widget-selection component has fewer exploration rules than baselines, occasionally preventing TEMdroid from reaching the correct GUI screen. OCR reliance itself is a minor component and not deeply analyzed as a source of error (only two widgets in the SemFinder dataset relied on neighbor-text/OCR fallback).

## Summary

TEMdroid is a learning-based approach for GUI test case migration, addressing the task of matching widgets between a source app and a functionally similar target app so that test events and assertions can be automatically transferred. Unlike prior matching approaches that rely on static word embeddings (e.g., word2vec) and manually defined similarity functions, TEMdroid fine-tunes BERT to produce contextual sentence embeddings for widget text (drawn from widget text, content-description, and resource-id attributes), aligns source and target widget representations via a Siamese network, and computes similarity via cosine distance in a widget-assessment module. To address the severe class imbalance between positive (should-match) and negative (should-not-match) widget pairs, the authors introduce a two-stage training strategy: first training a hard-negative-sample miner, then training the final matching model on all positive samples plus the mined hard negatives. When a widget's own textual attributes are entirely empty (common for pure icon/image widgets), the paper extracts text via Tesseract OCR from the widget's screenshot, or falls back to neighboring-widget text. Evaluated on 34 apps across eight categories, TEMdroid achieves 76% Top1 accuracy and 85% MRR for event matching (improving on the SemFinder, ATM, and Craftdroid baselines by 17%+ and 8%+ respectively), and 89% F1 for full test case migration, with attention-weight visualizations offered as qualitative evidence that the model captures contextual widget semantics rather than relying on superficial keyword overlap.
