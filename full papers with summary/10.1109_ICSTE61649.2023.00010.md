# A State Graph-Based Improved Framework for Monkey GUI Testing for EDA Desktop Applications

- **Year:** 2023
- **Venue/Source:** 2023 13th International Conference on Software Technology and Engineering (ICSTE)
- **DOI:** 10.1109/ICSTE61649.2023.00010

## Metadata

- **se_area:** Testing
- **se_task:** Automated GUI (Monkey) testing / exploratory test generation and state-space exploration for complex desktop applications
- **cv_technique:** Screenshot-based state representation and image matching using the Wand (ImageMagick binding for Python) library; weighted random action/object-type selection guided by a dynamically built state graph
- **platform:** Desktop (Electronic Design Automation, EDA, applications built on Qt; case study uses Siemens Questa Formal Propcheck)
- **rationale:** Robustness (avoiding tarpits, loops, and stuck states); ease of use (no need to retrieve all GUI objects per state, which is prohibitively expensive for complex EDA GUIs); context-driven (guiding exploration using accumulated knowledge of previously visited states/actions)
- **artifact_type:** Full-interface (each GUI state is represented as a whole-window/whole-layout screenshot used for state identity and matching)
- **eval_method:** Controlled empirical comparison between the prior "Improved Monkey GUI Testing" baseline and the proposed "State Graph-Based Improved Monkey" on the same industrial EDA tool (Questa Formal Propcheck), same design, same running environment, and matched iteration budgets (20–300 iterations, each value averaged over 10 runs due to randomness). Metrics: wall-clock time, number of uniquely covered object types, GUI elements, action statements, views, and unique GUI states.
- **challenges:** State identification without exhaustive object retrieval (screenshot-based matching only works reliably within a single session at fixed resolution); image-comparison overhead added to the flow's runtime, mitigated by reverse-order (most-recent-first) graph search; handling complex Qt widgets (e.g., QWidget text-entry with frames) and detecting modal views to avoid wasted iterations; balancing exploration of new windows against returning to the original window layout after layout-changing actions.

## Summary

This paper extends the authors' prior "Improved Monkey GUI Testing" framework for EDA desktop applications (which pre-learns objects/actions from GUI regressions to avoid expensive per-iteration object retrieval) by adding a state graph that is built incrementally while the Monkey testing session runs. Each GUI state is represented purely as a screenshot, since retrieving the full set of visible/enabled widgets at every step is computationally infeasible for EDA tools with highly complex, data-dense interfaces (tables, trees, schematics, waveforms, popups). The Wand image-processing library is used to match new screenshots against previously visited states; when a state is recognized as already visited, the weights of its associated actions are decreased, steering the weighted-random action/object-type selection toward unexplored parts of the interface. This mechanism specifically resolves problems left open by the earlier framework, including getting stuck in fixed window layouts, failing to detect and exit modal dialogs, and safely typing into bordered text-entry widgets. Experiments on Siemens' Questa Formal Propcheck show that the state-graph-based approach achieves substantially higher coverage (unique object types, GUI elements, action statements, and views) than the non-graph-based Improved Monkey at equivalent iteration counts, and reaches equivalent coverage in far fewer iterations and less wall-clock time, at the cost of a moderate (up to ~30 minutes at 300 iterations) time overhead from the state-matching step, which is mitigated by searching the graph in reverse (most-recent-state-first) order.
