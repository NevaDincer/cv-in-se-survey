# If a Human Can See It, So Should Your System: Reliability Requirements for Machine Vision Components

> **SCOPE WARNING**: Review before including in the synthesis matrix.** > This paper runs in the *opposite direction* from the survey's apparent core focus. Rather than using computer vision as a technique to accomplish a software engineering task (e.g., GUI testing, code generation, test repair), it applies software engineering methodology (requirements engineering, machine-verifiable specification, black-box testing/verification) *to* computer vision components (image classifiers) as the system under study. The "computer vision" here is the subject being engineered/assured, not the tool being used to engineer something else. If the survey's inclusion criterion is "CV techniques applied to accomplish SE tasks," this paper is likely out of scope; if the criterion is broader, e.g. "the intersection of CV and SE" or specifically including "SE4AI/requirements-for-ML" as a sub-area, it would fit well and is a strong, highly-cited ICSE paper for that adjacent category. ## Metadata

- **se_area:** Requirements Engineering (specifically, requirements engineering for AI/ML components, "SE4AI"), with a secondary connection to verification/testing (the paper also proposes an automated requirement-checking/testing method).
- **se_task:** Defining and automatically checking machine-verifiable *reliability requirements* for Machine Vision Components (MVCs, i.e., image classifiers): specifying how much an MVC's correctness or predictions are allowed to change under realistic, safety-related image transformations, calibrated against human visual performance, and then automatically testing whether a given pre-trained model satisfies these requirements.
- **cv_technique:** Not a technique used to accomplish an SE task. Rather, the *subjects under study* are computer vision image-classification models themselves (13 state-of-the-art pre-trained CNNs, e.g., ResNet50, AugMix variants, RLAT variants). The paper's own "engineering" methodology draws on: Image Quality Assessment (IQA) metrics (VSNR, Visual Signal-to-Noise Ratio; VIF, Visual Information Fidelity) used to define a human-perceptual "visual change" metric Δv; a curated set of safety-related image transformations (RGB shift, contrast, defocus blur, brightness, frost, color jitter, JPEG compression, Gaussian noise) drawn from the CV-HAZOP hazard-analysis checklist and implemented via the Albumentations and Imagenet-C libraries; and a bootstrap-based statistical sampling procedure (not itself a CV technique) for requirement checking.
- **platform:** General / not platform-specific. Demonstrated on standard image-classification benchmarks (ImageNet/ILSVRC'12, CIFAR-10), with the stated intent that the requirements framework generalizes to any computer-vision task (object detection, semantic segmentation), though only image classification is empirically evaluated.
- **rationale:** Not applicable in the usual CV-for-SE sense (context-driven / robustness / ease-of-use). The paper's own motivating rationale is safety assurance: establishing human perceptual performance as a principled, empirically-grounded reference point for MVC reliability requirements, since purely small/imperceptible-perturbation robustness testing (common in prior ML-robustness literature) does not reflect the broader realistic range of changes MVCs must tolerate in safety-critical deployments (e.g., self-driving cars).
- **artifact_type:** Not applicable. No GUI or software artifact is identified, matched, or generated; the "artifact" is a formal requirement specification (two classes: correctness-preservation and prediction-preservation) instantiated with human-performance-derived numeric thresholds, plus a corresponding automated black-box model-checking procedure.
- **eval_method:** Human-subject experiments (~2,000 participants via Amazon Mechanical Turk, forced-choice 200ms image categorization, following Geirhos et al.'s human-vs-model experimental design) across 8 safety-related transformations on ImageNet car-recognition and 4 transformations on CIFAR-10, used to instantiate requirement thresholds; automated black-box evaluation of 13 state-of-the-art pre-trained image classifiers against the instantiated requirements using bootstrap sampling and statistical (binomial / normal-approximation, 95% confidence) testing; three research questions assessing threshold reusability across image subsets (RQ1), coverage comparison against existing robustness benchmarks Imagenet-C/CIFAR-10-C (RQ2), and the approach's ability to reveal reliability gaps missed by existing benchmarks (RQ3).
- **challenges:** Authors self-report as threats to validity: [Construct] matching MVC performance to human performance may be an inherently high bar, and the paper does not empirically test whether targeted data augmentation could help models meet the requirements (left as future work); [Internal] the assumption that transformation parameter values are uniformly distributed may not hold for specific deployment contexts (e.g., heavy snow is more relevant for some geographic regions than others); [External] budget constraints limited the set of transformations and image classes (a single binary car/not-car classification task) used in the human experiments, and extending the approach to other vision tasks (e.g., object detection, segmentation) is left as future work. Additionally, the evaluation found that none of the 13 evaluated models satisfied the instantiated requirements with 95% confidence, which the authors attribute to none of the models having been trained with data augmentation covering the human-tolerated range.

## Summary

This ICSE paper addresses a foundational software-engineering problem, the near-total absence of precise, machine-verifiable *requirements* for machine-learned vision components, by proposing that "if a change in an image does not affect a human's decision, neither should it affect the MVC's." The authors formally define two classes of reliability requirement: *correctness-preservation* (an MVC's task performance, e.g., classification accuracy, should not degrade on transformed images within a human-tolerated range of visual change) and *prediction-preservation* (an MVC's predictions on transformed images should match its predictions on the originals within that same range, which notably does not require ground-truth labels and is therefore usable even where labeled data is unavailable). The main methodological innovation is grounding the "tolerated range" of each transformation not in an arbitrary or imperceptibly small parameter range (as in most prior adversarial-robustness work) but in a human-perceptual visual-change metric Δv, derived from established Image Quality Assessment metrics (VSNR, VIF), whose thresholds are estimated empirically from large-scale human psychophysics experiments (~2,000 MTurk participants performing a 200ms forced-choice car/not-car categorization task under 8 safety-related transformations selected via the CV-HAZOP hazard checklist, such as frost, defocus blur, and brightness). Given these human-calibrated thresholds, the paper provides a fully automated, black-box requirement-checking procedure based on bootstrap sampling and statistical confidence testing, applicable to any MVC without needing access to its internals. Evaluating 13 state-of-the-art pre-trained image classifiers (including ResNet50 and several robustness-augmented variants) against these requirements revealed that none satisfied them with 95% confidence, largely because none were trained with augmentation covering the human-tolerated range. Notably, the method surfaced reliability gaps invisible to existing robustness benchmarks like Imagenet-C/CIFAR-10-C, whose pre-selected transformation-parameter grids were shown to be biased and to not adequately cover the empirically-derived human-tolerated range. While the paper's contribution is centrally a requirements-engineering and verification framework, squarely software engineering research, its "system under test" is itself a computer vision component, making it best understood as an SE4AI/requirements-for-ML contribution rather than an instance of CV techniques being applied to solve a conventional SE task.
