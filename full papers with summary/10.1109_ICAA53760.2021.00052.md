# Mobile Application GUI Similarity Comparison Based on Perceptual Hash for Automated Robot Testing

- **Year:** 2021
- **Venue/Source:** ICAA 2021 (International Conference on Intelligent Computing, Automation and Applications)
- **DOI:** 10.1109/ICAA53760.2021.00052

## Metadata

- **se_area:** Testing (automated black-box GUI/robot testing of mobile applications)
- **se_task:** Isomorphic/duplicate GUI-state identification and interface-model simplification for closed-source ("truly black-box") mobile app robot testing, to reduce interface-model state-space explosion and improve test efficiency
- **cv_technique:** YOLOv3 (one-stage CNN-based object detection) for GUI component detection (bounding-box coordinates and component type, ignoring textual/color content); perceptual hashing (pHash) via Discrete Cosine Transform (DCT) for generating compact image fingerprints of a synthesized "GUI structure image"; Hamming distance for comparing perceptual hash fingerprints to judge screen-level similarity.
- **platform:** Mobile
- **rationale:** Ease of use / practicability (enables black-box robot testing without requiring the app's source code, addressing the difficulty of testing closed-source mobile apps); robustness and efficiency (perceptual hashing is described as fast and insensitive to image size/scaling differences, letting the approach reliably detect near-duplicate ("isomorphic") screens despite variable dynamic content such as different article thumbnails).
- **artifact_type:** Full-interface (the entire screen is converted into a synthesized, color-coded "GUI structure image" based on detected component types/positions, then hashed and compared as a whole image) with a Localized detection sub-step (YOLOv3 identifies individual component bounding boxes/types before the structure image is constructed).
- **eval_method:** Controlled similarity-detection experiment on 76 screenshots collected from 10+ mobile apps (38 image pairs designed to be similar, i.e., 77 total similar pairs among 1,444 pairwise comparisons, 38x38). Evaluated using accuracy, precision, and recall (confusion-matrix-based: TP=62, TN=1357, FP=10, FN=15), yielding reported Accuracy=0.98, Precision=0.86, Recall=0.81. A qualitative example (TED Talks app) demonstrates how three visually/structurally similar "speech directory" screens are merged into a single node in a finite-state-machine (FSM) interface model, simplifying the model from 6 edges/3 destination nodes down to 2 edges/1 destination node.
- **challenges:** The paper does not explicitly enumerate limitations/threats to validity, but several can be inferred from the design: (1) recall (0.81) is notably lower than precision (0.86) and accuracy (0.98), implying the method misses a meaningful fraction of true near-duplicate screens (15 false negatives), which could leave the simplified interface model with residual redundant states; (2) the approach assumes visual/structural similarity between two screens reached via different UI paths implies functional equivalence, which may not always hold (a stated design assumption rather than a verified property); (3) constructing the "GUI structure image" discards color and textual content by design to boost robustness to dynamic content, which is a stated trade-off but could also cause under-merging or over-merging when structurally similar screens have meaningfully different functionality; (4) the evaluation dataset (76 screenshots, 10+ apps) is relatively small, raising generalizability questions typical of this kind of workshop/conference-length empirical validation.

## Summary

This short paper addresses the truly black-box testing problem for mobile applications whose source code is unavailable, where robot or UI-driven testing tools have to build and traverse an interface model with no static instrumentation. A known issue here is interface-model state-space explosion, since GUI screens reached through different paths can look like many superficially distinct states even when they represent the same underlying functionality, for example three separate "speech directory" links in a TED Talks app screen that each lead to visually and structurally similar detail pages. The authors propose a three-step pipeline to detect these isomorphic screens and merge them, simplifying the resulting finite-state-machine interface model. First, YOLOv3, chosen mainly for its speed, localizes GUI components on each screenshot and classifies their type while deliberately ignoring textual and color content, producing bounding-box coordinates and component-type labels. Second, that structural information gets synthesized into a "GUI structure image," a type-based color-coded rendering that strips away the original text and image content but keeps layout and component-type information, meant to make genuinely similar screens compare as similar images despite differing dynamic content like different article thumbnails. Third, this structure image is downscaled to 32x32, converted to grayscale, and hashed through perceptual hashing (via DCT), and Hamming distance between two fingerprints yields a similarity score, with sufficiently similar destination screens merged into a single FSM node. On an evaluation set of 76 screenshots (38 similar pairs) from 10+ real mobile apps, yielding 1,444 pairwise comparisons, the method reached 98% accuracy, 86% precision, and 81% recall distinguishing similar from dissimilar screens, evidence the authors present that the approach can simplify interface models and improve black-box robot-testing efficiency.
