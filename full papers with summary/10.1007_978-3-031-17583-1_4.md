# SpiderTailed: A Tool for Detecting Presentation Failures Using Screenshots and DOM Extraction

- **Year:** 2023 (JCKBSE 2022 conference, published in book form 2023)
- **Venue/Source:** Knowledge-Based Software Engineering: 2022, Proceedings of the 14th International Joint Conference on Knowledge-Based Software Engineering (JCKBSE 2022), Larnaca, Cyprus; Learning and Analytics in Intelligent Systems, Vol. 30, Springer (Chapter 4)
- **DOI:** 10.1007/978-3-031-17583-1_4

## Metadata

- **se_area:** Testing / Maintenance (regression testing of web applications during iterative/agile development)
- **se_task:** Presentation Failure detection: identifying when a GUI component's rendered output does not meet its intended specification, specifically by comparing "before" and "after" versions of a web page
- **cv_technique:** Template matching and feature matching using SIFT keypoints (for absolute/relative element coordinates); color histogram analysis over RGB channels (for background-color extraction); EAST scene-text detector combined with histogram analysis (for font-color extraction, after cropping to the detected text's bounding rectangle); implemented via OpenCV
- **platform:** Web
- **rationale:** Robustness (extracts abstracted, per-property visual features instead of directly diffing whole images, to reduce misdetections caused by large but semantically irrelevant pixel differences); Context-driven (pairs DOM parsing/selectors with per-element screenshots so each GUI element is analyzed in its own structural context rather than as a flat image); Ease of use (requires only the two web page versions as input, with no proprietary specification/constraint language to author, unlike some prior comparator tools)
- **artifact_type:** Localized (per-element partial screenshots derived from DOM selectors, not full-page screenshots; each of 127 tested elements is captured and analyzed individually)
- **eval_method:** Controlled human-subject experiment: a test web page with 47 of 127 elements seeded with artificial Presentation Failures was evaluated both by the tool and by 12 undergraduate/graduate subjects doing manual visual inspection (8-minute time limit). Results were cast into a TP/FP/TN/FN confusion matrix and compared via Accuracy, Precision, Recall, Specificity, and F-measure; a chi-square test compared detection vs. misdetection rates between tool and humans; wall-clock time consumption was compared and broken down by pipeline stage; false positives were further root-caused by which visual property (width, height, relative-x/y, background-color, font-color) triggered them.
- **challenges:** The chi-square test found the detection/misdetection difference between SpiderTailed and manual observation not statistically significant (p = 0.76). SpiderTailed showed a precision/specificity weakness (many false positives) versus humans' recall weakness (many false negatives). Authors identify a concrete limitation: false positives arise when a property change in a *parent* element (e.g., background color) propagates visually to a child element the method doesn't model as inherited, causing the child to be wrongly flagged; they propose ratio-based rather than absolute comparison for size/position properties as a fix. Font-color misdetections stem from the algorithm's deterministic property-selection logic and are described as hard to fix without redesigning that stage. The text-detection (EAST) stage is also flagged as the slowest step because it runs without GPU acceleration.

## Summary

SpiderTailed targets what the authors call a Presentation Failure: a case where a GUI component's rendered output no longer matches its intended specification. The idea is to catch these by comparing "before" and "after" versions of a web page during regression testing. Prior tools that diff whole images tend to misfire when two versions differ by a large but harmless visual change, so SpiderTailed extracts eight abstracted visual properties per DOM element instead: width, height, absolute and relative position, background color, and font color. SIFT-based template and feature matching locates each element's coordinates within its parent screenshot, RGB histograms pull out background color, and the EAST text detector isolates text regions so font color can be sampled after the background is excluded. These per-element property vectors, not raw pixels, get diffed to flag failures and explain what triggered each one. Built in Python and OpenCV, with BeautifulSoup for DOM parsing and Selenium for screenshots, the tool was tested against 12 human testers on a page seeded with artificial failures. It matched or beat manual testing on accuracy, recall, and F-measure, and finished in about half the time humans took, though it produced more false positives, most of them traceable to style properties inherited from a parent element that the method doesn't model as inherited.
