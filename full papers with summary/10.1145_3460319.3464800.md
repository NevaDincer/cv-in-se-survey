# WebEvo: Taming Web Application Evolution via Detecting Semantic Structure Changes

- **Year:** 2021
- **Venue/Source:** Proceedings of the 30th ACM SIGSOFT International Symposium on Software Testing and Analysis (ISSTA '21)
- **DOI:** 10.1145/3460319.3464800

## Metadata

- **se_area:** maintenance; testing
- **se_task:** Detecting web application evolution / semantic structure changes in web pages, and repairing broken element locators used by web test scripts, robotic process automation (RPA) tools, and information retrieval (IR) tools
- **cv_technique:** Element-level (not whole-page) screenshot comparison via perceptual image hashing / fingerprint-based similarity (bit-sequence comparison of hashed pixel values, using OpenCV); image mutation preprocessing techniques, greyscale conversion and color inversion, applied when direct hash similarity is below threshold, to mitigate color-scheme changes between page versions
- **platform:** web
- **rationale:** robustness; context-driven. CV is used because DOM-tree-based comparison alone cannot recognize elements that change tag/attributes/location while visually preserving their semantics and appearance (e.g., a `<p>` retagged to `<div>`), producing false positives/negatives; comparing only element-level screenshots (rather than whole-page template matching, as in the baseline Vista) makes the visual matching robust to background colors and nearby unrelated elements, and combining it with text similarity (as a pre-filter/prioritizer before image comparison) improves matching accuracy when many candidate elements look visually similar
- **artifact_type:** localized (element-level GUI widget screenshots, i.e., cropped screenshots of individual DOM/GUI elements, not the full page)
- **eval_method:** Empirical evaluation on a curated dataset of 13 real-world websites spanning 9 popular categories (e.g., education, e-commerce, entertainment, travel), each with a target page, an evolved page (collected roughly 2+ years later via the Wayback Machine), and three historic pages; ground truth of changed elements obtained via a two-step manual inspection process (DOM-based detection plus manual verification by at least two authors using browser inspector tools) totaling 16,741 elements / 25,329 LOC across sites. Compared WebEvo against (1) a DOM-tree-based change detection baseline (re-implemented from prior work) and (2) Vista, the state-of-the-art CV-based visual web test repair tool, using precision/recall/F1 for detected changed elements (added/deleted/updated). WebEvo achieved average precision 0.91, recall 0.79, F1 0.84, versus F1 0.50 for DOM-based detection and F1 0.39 for Vista (on deleted/updated elements only, since Vista cannot detect additions). An ablation (RQ2) removed the semantics-based visual search and the history-based content-change filtering to show each module's individual contribution (F1 drops to 0.64 without visual search, precision drops further to 0.40 without content-based change filtering). Runtime was also measured, showing WebEvo is 42.01% faster than Vista on average (37.04s vs 63.92s per element). An additional evaluation (RQ4) measured the percentage of real RPA/IR breakages detected: 65% of RPA breakages and 100% of IR breakages across 11 websites with known breakages.
- **challenges:** Explicitly reported: (1) False positives occur when multiple visually and textually similar elements exist in the evolved page, causing incorrect element mapping (e.g., duplicate "Web Certificate" elements). (2) False negatives occur for elements with no text content whose appearance changes substantially (e.g., an image logo replaced by a styled text logo), since the algorithm falls back to image-only comparison in such cases and both WebEvo and the baseline Vista fail here. (3) The history-based content-change detection can be fooled when websites reuse identical filenames for different images or reuse the same text for multiple days, causing false positives/negatives; authors note this could be mitigated with more CV-based image comparison or server-side static analysis (unavailable/out of scope here). (4) Text similarity relies on Levenshtein edit distance, which misses synonyms/semantically-similar-but-lexically-different text; authors suggest sentence-similarity or semantic-pattern methods as future improvement. (5) Image similarity via hashing has inherent limitations and could be improved with object-recognition techniques like SIFT/FAST. (6) Change detection granularity: WebEvo sometimes reports a coarser containing element (e.g., a `<div>`) as changed instead of the finer child elements that actually changed, reducing detection precision at the RPA/IR-breakage level. (7) External threats to validity: the approach was tuned/evaluated on manually selected popular websites with non-trivial numbers of changed elements, and detection relies on pre-defined HTML tag/attribute lists (though noted as easily extensible).

## Summary

WebEvo is a web-monitoring tool designed to detect "semantic structure changes" in evolving web pages, changes that break element locators used by information-retrieval (IR) tools, robotic-process-automation (RPA) bots, and web test scripts, while filtering out harmless, constantly-recurring "content-based changes" such as stock tickers or ad refreshes. Its pipeline has two stages. First, a DOM-tree comparison (based on Levenshtein edit distance over child-node sequences) identifies candidate added/deleted/updated elements between an old and new page, and a novel history-based technique compares the page against several historic snapshots to distinguish content-based churn from genuine structural change. Second, a semantics-based visual search maps changed elements in the old page to their counterparts in the new page using a combination of text similarity (prioritizing candidates) and element-level (not whole-page) screenshot comparison via image hashing, with greyscale and color-inversion fallbacks to handle color-scheme changes. The main novel/interesting design choice is comparing cropped element screenshots rather than whole-page template matching (as done by the prior state-of-the-art tool Vista), which sidesteps noise from backgrounds and neighboring elements. Evaluated on 13 real-world websites drawn from the Wayback Machine, WebEvo achieved F1 = 0.84 versus 0.50 (DOM-only) and 0.39 (Vista), while being 42% faster than Vista and detecting the majority of real RPA/IR-breaking changes.
