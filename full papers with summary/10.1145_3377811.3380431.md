# RoScript: A Visual Script Driven Truly Non-Intrusive Robotic Testing System for Touch Screen Applications

- **Year:** 2020
- **Venue/Source:** ICSE '20 (42nd IEEE/ACM International Conference on Software Engineering)
- **DOI:** 10.1145/3377811.3380431

## Metadata

- **se_area:** testing
- **se_task:** Non-intrusive robotic GUI test execution and non-intrusive test-script recording for touch-screen applications (test automation for platforms with no accessible OS/GUI-framework instrumentation)
- **cv_technique:** Screenshot/screen-area cropping via Canny edge detection, morphological closing, and contour detection on raw camera photos of the device under test; widget localization via template matching (OpenCV's normalized correlation-coefficient matcher, empirically chosen over the BBS algorithm) with scale normalization to correct for camera-vs-script image size differences; color-range-based skin detection plus contour analysis to track a human fingertip across video frames for automatic click-action segmentation and click-position estimation; the same contour-detection pipeline (with median blur pre-processing and a contour-size heuristic) is reused to automatically crop a representative widget image around each detected click for script generation
- **platform:** general (touch-screen devices spanning Android and iOS smartphones, a Windows tablet, a Raspberry Pi/Linux embedded device, and a closed embedded system (a GoPro camera), explicitly platform/OS-agnostic by design)
- **rationale:** robustness (fully non-intrusive operation is required to test closed or uncommon platforms (e.g., GoPro, custom embedded OSes) where no OS/GUI-framework hooks are accessible or where hooking in would itself alter device behavior/performance); ease of use / practicality (uses a cheap, commodity XY-plotter robot (~$200 hardware) rather than specialized/industrial robots, and requires no software installation on the device under test); context-driven (screenshot cropping algorithm explicitly filters out camera-photo context such as robot arms, cables, and background clutter to isolate the actual screen region before widget matching)
- **artifact_type:** localized (individual widget images, either manually captured or automatically cropped via contour detection around a clicked position, are matched via per-widget template matching against a cropped full-screen camera photo; both a full-interface screenshot-cropping step and a localized widget-matching step are used, but the load-bearing CV operation for test-action targeting is at the widget/local level)
- **eval_method:** Empirical evaluation on 21 touch-screen applications across 6 physical devices (Android/iOS phones, Windows tablet, Raspberry Pi, GoPro), covering 105 test scripts / 672 GUI action instructions. Five RQs assessed: (RQ1) flexibility, via successful automation counts and a GUI widget-action testability matrix (Table 4); (RQ2) accuracy of physically executing test scripts/actions (each script run 3x); (RQ3) efficiency, decomposing execution time into computer-vision processing time vs. robot-motion time; (RQ4) accuracy of the video-based automatic script-recording pipeline (pre-action-frame extraction, click-position identification, and widget-image-cropping accuracy, each independently validated) on 491 recorded click instructions; (RQ5) head-to-head comparison against Sikuli, a state-of-the-art intrusive visual GUI testing tool, on the same scenarios for flexibility, accuracy, efficiency, and script-recording accuracy.
- **challenges:** Camera-based (rather than OS-level) screenshots are inherently lower quality than accurately captured screenshots, causing template-matching failures on small/unclear widget images, widgets with light-colored text, and screens affected by Moiré pattern noise from camera-display interaction; low-sensitivity touch screens (e.g., the Raspberry Pi) cause unstable/inaccurate physical touches independent of the CV pipeline; the physical robot approach is markedly slower than intrusive testing (~6.5s per GUI action vs. ~0.5s for Sikuli, though whole-script timing is closer between the two once wait states are included); the video-based script-recording technique only supports automatic recording of click actions; drag and swipe actions are not reliably distinguishable via the fingertip-tracking heuristic and require semi-automatic (human-assisted) recording; skin-color-based hand detection can fail when on-screen content is itself skin-colored, and perspective/camera-angle effects distort estimated click positions; the XY-plotter's physical working area limits RoScript to devices no larger than roughly A4 paper size; several semantic GUI actions (e.g., multi-finger gestures, hardware-button- or sensor-triggered actions, keyboard-focus-only interactions) are acknowledged as entirely out of scope for the current instruction set.

## Scope note

None. Strong fit for the CV x SE survey. RoScript's entire test-execution and test-recording pipeline is built on computer vision (edge/contour detection for screen localization, template matching for widget localization, skin/contour-based hand tracking for action recording) applied to a canonical SE testing task (GUI test automation), with the CV component doing genuinely load-bearing work: it is the *only* mechanism available for interacting with and verifying state on the closed/non-instrumentable platforms (e.g., GoPro) that motivate the paper.

## Summary

RoScript is a robotic GUI test automation system designed to address a gap in existing tools: intrusive frameworks like Appium, UIAutomator, and Sikuli require OS- or GUI-framework-level access to the application under test, which is unavailable on closed or uncommon platforms (e.g., a GoPro camera, custom embedded systems). RoScript instead drives a cheap, commodity XY-plotter robot fitted with a stylus pen to physically touch a device's screen, using an overhead camera and computer vision, rather than any device-side instrumentation, to localize GUI widgets and verify test outcomes, making it applicable to essentially any touch-screen device regardless of underlying OS or GUI framework. Its visual test-script language (extending prior tools like Sikuli) expresses GUI actions (click, drag, swipe) and robot-control instructions (e.g., take_screen_photo, move_outside_of_screen) using widget images cropped from camera photos rather than exact coordinates or accessibility-tree identifiers. The core CV pipeline performs screen-area cropping from noisy camera photos via Canny edge detection, morphological closing, and contour analysis, then locates individual widgets via scale-normalized template matching, and translates matched screen-space coordinates into real-world robot-arm coordinates for physical execution. To reduce script-authoring cost, RoScript also introduces a non-intrusive, video-based script-recording technique: it tracks a human tester's fingertip across a camera-recorded demonstration video using skin-color detection and contour analysis, segments the video into individual click actions based on the fingertip's vertical trajectory, and automatically crops a representative widget image for each detected click to generate executable test code. Evaluated across 21 applications on 6 diverse devices (including a GoPro, for which no existing intrusive tool works at all), RoScript achieved 91.4%/94.6% script/action-level execution accuracy and 84.5% click-recording accuracy. While it is slower and slightly less accurate than the intrusive baseline Sikuli on platforms where Sikuli is applicable, it uniquely supports platforms Sikuli cannot reach at all.
