# Design-Implementation Discrepancy Analysis for Mobile Application Interfaces Using Object Detection Methods

- **Year:** 2024
- **Venue/Source:** IEEE ICIET 2024 (12th International Conference on Information and Education Technology)
- **DOI:** 10.1109/ICIET60671.2024.10542829

## Metadata

- **se_area:** Design / Development (design-to-implementation GUI fidelity verification)
- **se_task:** Automated comparison of a GUI design mockup image against the corresponding implemented interface screenshot to detect layout/component discrepancies
- **cv_technique:** Image preprocessing (scaling, grayscale conversion, gradient computation, binarization) + flood-fill algorithm for non-text component segmentation; EfficientNet classification model (8 component categories) for component typing; CRAFT model for text-component detection/OCR; Hungarian algorithm for optimal bipartite component matching using Intersection-over-Union (IoU) as the weight function; compared against a YOLOv3 baseline
- **platform:** Mobile
- **rationale:** Ease of use / reduced manual effort (replaces time-consuming, labor-intensive manual visual inspection, especially valuable under manpower shortages); robustness (component detection shown to be more stable and accurately localized than a YOLOv3 baseline, which produced overlapping or spurious frames); context-driven (also framed as a pedagogical tool to help students see design-implementation alignment)
- **artifact_type:** Full-interface (whole-screen component detection, quantity/type comparison, and spatial matching between two full GUI images)
- **eval_method:** Qualitative/visual comparison of detection stability against YOLOv3 on sample design/implementation image pairs; a custom similarity score (per-category min/max component-count ratio); a case study applying the pipeline to real student App Development course projects, comparing Figma design mockups against their Android Studio implementations, with results visualized via matched/unmatched colored bounding boxes
- **challenges:** No existing public GUI dataset matched the study's design-vs-implementation pairing requirement, forcing the authors to collect data from a student course rather than production apps; YOLOv3 baseline is prone to overlapping or empty-region false detections that would corrupt downstream matching; merging overlapping text and non-text component detections (to avoid double-counting text-labeled buttons) required an additional heuristic merging step; evaluation is largely qualitative/illustrative rather than a large-scale quantitative benchmark.

## Summary

This paper automates a task traditionally done by hand: checking whether an implemented mobile app interface faithfully matches its original GUI design mockup. The pipeline first detects GUI components in both the design image and the implementation screenshot, using classical image processing (grayscale conversion, gradient and binarization, flood-fill segmentation) for non-text elements, an EfficientNet-based classifier for categorizing components into 8 types, and the CRAFT text-detection model as OCR for text elements, with a merging step to avoid double-counting text embedded in buttons. A quantity and type-based similarity score comes from the detected component counts, then a finer spatial comparison follows: components across the two images get matched through the Hungarian algorithm solving a bipartite maximum-weight matching problem, where match weights are IoU values between component bounding boxes. Results get visualized with colored bounding boxes, paired versus unpaired components, so differences are easy to spot at a glance. The authors show their detection pipeline is more stable than a YOLOv3 baseline, which tends to mislocate or duplicate component frames, and demonstrate the tool on real student projects, Figma designs against Android Studio implementations, from an App Development course, framing the system as both a practical QA aid and a pedagogical tool that helps students internalize the importance of faithfully translating design specs into working interfaces. The evaluation stays mostly illustrative and qualitative rather than a large quantitative benchmark against ground-truth discrepancy labels.
