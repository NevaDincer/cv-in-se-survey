# Robust UI Automation Using Deep Learning and Optical Character Recognition (OCR)

- **Year:** 2021
- **Venue/Source:** Proceedings of International Conference on Recent Trends in Machine Learning, IoT, Smart Cities and Applications, Advances in Intelligent Systems and Computing, vol. 1245 (Springer)
- **DOI:** 10.1007/978-981-15-7234-0_4

## Metadata

- **se_area:** testing, with an explicit maintenance angle: the paper's central pitch is eliminating manual test-automation maintenance
- **se_task:** UI test automation for enterprise cloud applications (SAP S/4HANA), visual and DOM-independent generation and execution of GUI test scripts, explicitly framed as also enabling UI test-driven development (TDD)
- **cv_technique:** deep-learning object detection (YOLO) for locating/classifying UI elements and icons directly from screenshots; a custom-trained OCR convolutional neural network (trained on ~20k synthetically generated text-on-background images) for reading text labels inside detected UI element regions
- **platform:** general (cloud/enterprise web application, demonstrated on SAP S/4HANA HANA cloud UI, screenshot-driven so technology-agnostic by design)
- **rationale:** robustness (explicitly framed as solving the fragility of DOM/xpath/ID-based automation that breaks on every UI property change, since it instead mimics how a human visually parses a screen) and ease of use (a minimal-effort "triplet" instruction syntax, <action> <label> <value>, lets testers write test cases just by looking at the UI, without locating technical selectors)
- **artifact_type:** localized (individual UI elements/icons and their text labels are detected and cropped for OCR, rather than whole-screen parsing) though driven from full-interface screenshots
- **eval_method:** purely quantitative internal validation, no comparison against a labeled benchmark or prior tool. Object-detection accuracy first on 7 UI element classes (~250 images/class, ~96% accuracy after ~36h training), then scaled to 20 classes relevant to SAP S/4HANA workflows (~95% accuracy after ~80h training). OCR text-recognition accuracy of 99.9% overall, broken down by text/background color combination (Table 1: 100% for high-contrast combinations, dropping to ~0.1% for same-color text-on-background, which the authors treat as a desirable failure mode since a human tester could not read such text either).
- **challenges:** authors note manual annotation of training images is itself a bottleneck to scaling (explicitly named as their next roadmap item); training was resource-constrained (2 vCPU / 16GB RAM, no GPU, leading to 36-80 hour training times, which they note "could have been expedited greatly by the usage of GPUs"); UI elements without any visible text label can only be disambiguated by icon appearance, requiring a separately trained closed-set icon classifier rather than the general label-matching approach; and the whole approach still depends on functional (not just cosmetic) UI stability, since a genuine functional change to the application will still break the automation, which the authors treat as an "ideal fail" rather than eliminate.

## Summary

This paper proposes a DOM-independent, technology-agnostic approach to GUI test automation for enterprise cloud software, demonstrated on SAP S/4HANA. The pitch responds to a familiar pain point: DOM- or xpath-based automated tests break constantly under frequent cloud releases, and fixing them eats up more SDLC time than almost anything else in testing. The system works in two phases. Testers first write a short, human-readable instruction set using a triplet syntax, action, label, value (for example "fill username testuser" or "click log on"), just by looking at the screen, without touching source code or browser dev tools. An execution engine then replays these instructions by taking a live screenshot, running it through a YOLO-based detector to locate and classify UI elements, cropping the predicted regions, and passing those crops to a custom-trained OCR CNN to read their labels. Icons without visible text fall back to the detector's own class prediction. The evaluation is an internal accuracy check rather than a benchmark comparison: object detection reached about 95 to 96% accuracy across 20 SAP-relevant element classes, and the OCR component hit 99.9% text-recognition accuracy overall, with one telling exception. Text rendered in the same color as its background is unreadable to the OCR, exactly as it would be to a human tester, which the authors treat as a feature rather than a bug. Because the system never reads the DOM, the central claim is that it only needs re-authoring when the application's actual functionality changes, not its markup.
