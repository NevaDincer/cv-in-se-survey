# Psychologically-Inspired, Unsupervised Inference of Perceptual Groups of GUI Widgets from GUI Images

- **Year:** 2022
- **Venue/Source:** ESEC/FSE '22 (30th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering)
- **DOI:** 10.1145/3540250.3549138

## Metadata

- **se_area:** Design (GUI design understanding); also relevant to Development (GUI-to-code generation) and Testing (GUI automation)
- **se_task:** Automatic segmentation/grouping of GUI widgets into perceptual groups (e.g., cards, lists, tabs, menus) from GUI screenshots/images, to support downstream UI-related SE tasks
- **cv_technique:** Enhanced UIED pipeline combining Google OCR (text detection) with traditional unsupervised image processing (contour/connected-component analysis for non-text widget detection); rectangle/wireframe boundary geometry analysis for container recognition; DBSCAN (density-based spatial clustering) for widget clustering by center point/top-left coordinates and area; rule-based cluster-conflict resolution, iterative proximity-based group pairing, and continuity-based detection-error correction (missed/misclassified widget recovery via cropped-region re-detection and majority-vote re-classification)
- **platform:** Mobile (Android app GUIs) and general UI design (Figma UI design prototypes)
- **rationale:** Context-driven (grouping decisions explicitly grounded in Gestalt psychology principles - connectedness, similarity, proximity, continuity - that describe how humans interpret GUI layout context); Robustness (pixel-only, implementation-independent method that avoids the metadata/runtime misalignment problems of prior supervised approaches, and includes explicit error-correction steps for missed/misclassified widgets); Ease of use (fully unsupervised, requires no training data or GUI metadata, works directly on screenshots or design images)
- **artifact_type:** Full-interface (whole GUI screenshot/image is segmented into hierarchical perceptual groups spanning the entire screen, not a single widget or localized patch)
- **eval_method:** Two custom-built datasets: 1,091 GUI screenshots from 772 Android apps (ground truth derived from Rico dataset view hierarchies, manually filtered for perception-implementation misalignment) and 20 UI design prototypes from Figma (ground truth from designers' group hierarchies). Ground-truth and predicted groups represented as bracket-annotated widget-type strings compared via Levenshtein edit distance (thresholds 0-4) to determine true/false positives; metrics are precision, recall, and F1. Widget detection separately evaluated on Rico using IoU>0.9 against runtime ground truth (precision/recall/F1). Baseline comparison against the heuristic-based state-of-the-art Screen Recognition (Zhang et al., CHI 2021) and against original UIED. Both detection-based (using own detector output) and metadata-based (using ground-truth widgets) grouping evaluated to isolate detection-error impact. Processing time measured (1.7s/GUI average on commodity hardware, no GPU needed). Results: enhanced UIED reaches 0.626 F1 (vs 0.524 original); perceptual grouping reaches 0.593 F1 (detection-based) / 0.672 F1 (metadata-based) on app GUIs and 0.783 F1 on design prototypes, versus 0.092/0.123/0.232 F1 for Screen Recognition respectively. Qualitative/manual error analysis of typical failure cases also reported.
- **challenges:** Authors explicitly report: (1) widget occlusion or modal windows cause incorrect grouping because occluded widgets present in runtime metadata are not visually available, degrading metadata-based grouping (proposed future fix: an occlusion/modal classifier plus figure-ground separation); (2) ambiguity in "correct" grouping - some valid alternative groupings differ from the single ground-truth annotation, causing correct results to be scored as errors; (3) GUI widget over-/under-segmentation by the underlying detector propagates into grouping mistakes even when the overall group structure is otherwise correctly recognized; (4) the method currently addresses only structural/visual grouping, not semantic grouping of interaction/content meaning, which the authors list as future work.

## Summary

This paper proposes an unsupervised, pixel-only method for partitioning a GUI screenshot into perceptual groups of widgets (e.g., cards, lists, tabs, menus), motivated by the observation that humans perceive GUIs as structured wholes rather than collections of isolated elements, and that runtime view hierarchies often do not correspond to these intuitive perceptual groups. The main contribution is the first systematic, theoretically-grounded (rather than ad-hoc heuristic) approach to this problem, built on the four core Gestalt psychology principles of grouping. The pipeline first detects text and non-text widgets using an enhanced version of UIED (replacing its OCR component with Google's Vision API and adding container-aware merging), then applies four sequential grouping stages mirroring the Gestalt laws: connectedness (rectangular container/wireframe recognition via boundary geometry), similarity (DBSCAN clustering of widgets by position/size, with conflict resolution), proximity (iterative pairing of adjacent, structurally similar clusters into larger blocks), and continuity (correcting missed or misclassified widgets by contrasting sibling subgroups within a perceptual group). A distinctive detail is the continuity-based error-correction stage, which exploits the internal consistency of a just-formed perceptual group (e.g., repeated cards) to detect and fix upstream widget-detection errors, effectively using group-level structure as a self-correcting signal for widget-level output - a feedback loop largely absent from prior detection-only or heuristic grouping methods.
