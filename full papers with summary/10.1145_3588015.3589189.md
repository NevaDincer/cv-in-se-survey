# Visual Expertise in Code Reviews: Using Holistic Models of Image Perception to Analyze and Interpret Eye Movements

> **SCOPE WARNING**: questionable fit.** This paper does not apply a computational computer-vision technique to a software-engineering artifact. It is a human-subjects eye-tracking study of developers reviewing code, interpreted through *theoretical* holistic models of image perception borrowed from psychology/radiology (Nodine & Kundel's global-focal model, Swensson's two-stage model, Kundel et al.'s holistic-vs-search-to-find model). No image, screenshot, GUI, or diagram is processed by any CV algorithm. The "image perception" in the title refers to how human experts visually process a stimulus (code-as-image), not to machine vision. Recommend excluding or reclassifying unless the survey's definition of "CV in SE" is meant to include eye-tracking/HCI studies that merely borrow perception-science theory.

## Metadata

- **se_area:** Development / Maintenance (code review, program comprehension)
- **se_task:** Code review / defect (logical error) detection during manual code reading
- **cv_technique:** None (no computational CV algorithm is used or proposed). The paper applies theoretical, non-computational models of human image perception from radiology/psychology as an interpretive framework for eye-tracking metrics.
- **platform:** General (desktop monitor, 24", displaying short C code snippets)
- **rationale:** Not applicable. No CV technique is deployed, so no CV-adoption rationale applies. The methodological rationale is instead to borrow well-established perception-science theory to fill a gap in SE eye-tracking interpretation standards.
- **artifact_type:** Not applicable. No CV-generated artifact; output is eye-tracking metrics (fixations, saccades, dwell time, etc.) and statistical test results.
- **eval_method:** Controlled eye-tracking experiment with 23 participants (8 experts, 15 novices) reviewing 6 replicated C code examples (each with one seeded logical error) using an SMI 250 REDmobile eye tracker (250 Hz); non-parametric Friedman rank-sum tests across three review phases; retrospective think-aloud interviews.
- **challenges:** Small (n=23) and unbalanced (8 vs. 15) sample limits generalizability; code examples are short (15–60 lines) and artificial compared to real-world code of thousands of lines; three-way equal-thirds phase division may smooth over meaningful strategy switches; expert phase-based behavior less pronounced than theory predicted, possibly because the examples were too simple.

## Summary

The study investigates whether "holistic models of image perception," originally developed in radiology and psychology to explain how experts scan medical images (e.g., mammograms) for anomalies, can also explain how expert programmers visually process source code during a code review. Twenty-three participants (8 experienced, 15 novice programmers) reviewed six short, seeded-error C code snippets while an SMI 250 REDmobile eye tracker recorded fixations and saccades; a standard battery of eye-tracking metrics (fixation count/duration, saccade length, dwell time, time-to-first-fixation on the error, etc.) was computed and analyzed across three temporal review phases using non-parametric statistics. The main finding is that experts detect errors faster and with less visual effort (shorter, fewer fixations; longer saccades) than novices, and that experts' scanning behavior shows some, though not fully pronounced, evidence of the theorized alternation between a broad "global" scan and a focused "focal" examination of anomalies, aligning partially with the global-focal, two-stage, and holistic/search-to-find models from radiology. The paper's contribution is conceptual/theoretical: it argues these psychology-derived frameworks are a promising, under-used lens for interpreting SE eye-tracking data, rather than proposing any new computer-vision or machine-learning technique.
