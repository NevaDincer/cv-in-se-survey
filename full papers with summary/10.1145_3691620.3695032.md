# Beyond Manual Modeling: Automating GUI Model Generation Using Design Documents

- **Year:** 2024
- **Venue/Source:** ASE 2024 (39th IEEE/ACM International Conference on Automated Software Engineering)
- **DOI:** 10.1145/3691620.3695032

## Metadata

- **se_area:** design (spans early-stage UI/UX design artifacts) feeding into testing (model-based testing / MBT)
- **se_task:** automatic generation of formal GUI models (IFML) from UI/UX design documents, to serve as oracles/inputs for model-based testing rather than reverse-engineering models from code or runtime exploration
- **cv_technique:** Segment Anything Model (SAM) for zero-shot GUI element/candidate segmentation; rule-based correction mechanism (3 rules) to refine SAM output; template matching (OpenCV) for transition-arrow detection; OCR (EasyOCR) for transition-condition text; VGG for image-embedding-based cosine-similarity screen matching (state combination/deduplication)
- **platform:** general / smart-TV applications (industrial, controller-based interaction), authors note flexibility to other design-tool outputs (Figma, Sketch)
- **rationale:** context-driven (design documents reflect design intent, distinct from code-consistent reverse-engineered models, enabling functional-issue detection); robustness (SAM's pre-trained zero-shot segmentation generalizes across varied design-document visual styles without requiring large labeled training sets, which are scarce for this domain); ease of use / efficiency (drastically cuts manual modeling time)
- **artifact_type:** full-interface (screen-level element and layout recognition) combined with temporal/structural (transition-graph / state-machine construction across screens)
- **eval_method:** precision/recall/F1 on GUI element recognition benchmarked against the UIED baseline, using 840 manually-annotated ground-truth elements across 4 real commercial smart-TV apps (IoU ≥ 0.9 for TP); GUI-screen-level full-correctness comparison; modeling time and downstream MBT statement-coverage comparison across manual, fully-automated (DemGen), and hybrid (auto + manual refinement) workflows; ablation studies on the rule-based correction mechanism and the state-combination similarity threshold θ; post-experiment semi-structured interviews with 6 industry stakeholders
- **challenges:** tight spacing between adjacent GUI elements causes SAM to merge them into single (mis-)perceived units; elements with low-contrast boundaries are hard for SAM to segment; design documents are inherently scarce in number, ruling out training/fine-tuning-based deep learning approaches; the state-combination similarity threshold θ trades off redundant vs. missing GUI states, requiring careful tuning (0.8 default); despite improved automated accuracy over UIED, practitioner interviews revealed persistent trust concerns about fully automated models for downstream tasks, motivating a hybrid human-in-the-loop workflow as the practically preferred approach.

## Summary

This ASE 2024 industry-collaboration paper (Nanjing University with Samsung Electronics China) tackles GUI model generation for model-based testing (MBT) from a novel source: UI/UX design documents, rather than the conventional reverse-engineering of models from source code or dynamic app exploration. The authors argue that reverse-engineered models are, by construction, consistent with the code and thus cannot serve as independent oracles for functional bugs, whereas design documents encode the intended behavior. Their tool, DemGen, has three components: (1) GUI Element Recognition, which uses the Segment Anything Model (SAM) to segment candidate bounding boxes from design-document screens, refined by three hand-designed correction rules addressing SAM's characteristic over-segmentation errors (duplicated texture detections, overlapping element fragments, non-interactive background-layout elements); (2) Transition Recognition, using template matching for arrows and OCR for transition-condition text; and (3) Model Construction, which deduplicates near-identical screens via VGG-embedding cosine similarity and assembles everything into a formal IFML model usable for downstream test-path generation. Evaluated on four real commercial smart-TV applications with design documents from Corporation S, DemGen outperforms the state-of-the-art UIED baseline by 0.15/0.09/0.12 points in precision/recall/F1 and produces models yielding higher MBT statement coverage at a fraction of manual modeling time (e.g., 33 seconds vs. 90 minutes for one app). A main finding, notable for its practical honesty, is that despite DemGen's quantitative superiority, practitioner interviews revealed a preference for a hybrid workflow (auto-generation + manual refinement) over full automation, due to reliability concerns, directly informing the paper's recommended real-world deployment pattern.
