# Improving Code Extraction from Coding Screencasts Using a Code-Aware Encoder-Decoder Model

- **Year:** 2023
- **Venue/Source:** 38th IEEE/ACM International Conference on Automated Software Engineering (ASE 2023)
- **DOI:** 10.1109/ASE56229.2023.00184

## Metadata

- **se_area:** Maintenance / program comprehension (knowledge extraction and reuse from video tutorials)
- **se_task:** Code extraction from programming screencasts and screenshots; OCR post-processing / error correction
- **cv_technique:** Optical Character Recognition (Tesseract OCR) combined with a fine-tuned code-aware encoder-decoder transformer (CodeT5) used as a text-correction model over OCR output; not a classical image-feature CV technique but text recognition from images/video frames
- **platform:** General / desktop (IDE screenshots and screen-recorded video tutorials, tested with Visual Studio Code)
- **rationale:** Robustness (correcting inaccurate OCR output caused by code complexity and font/format variation) and context-driven (recovering source code that is not distributed alongside tutorial videos, enabling reuse)
- **artifact_type:** Full-interface (cropped code-editor area screenshots) and temporal (video frames sampled from YouTube tutorials)
- **eval_method:** Character-based and token-based Normalized Levenshtein Distance (NLD) against ground-truth code, compared with Tesseract-only and the ACE statistical-language-model baseline; also average processing time per snippet
- **challenges:** Training data restricted to Java only (limiting generalizability to CodeT5's other pretrained languages); simulated IDE screenshots used as a proxy for real screencasts, which may not fully represent real-world video conditions; Tesseract performs poorly on frames with dark IDE backgrounds; automation pipeline can introduce positional/timing errors when capturing screenshots; hardware constraints prevented fine-tuning the larger CodeT5-large variant

## Summary

This paper introduces CodeT5-OCRfix, a post-processing approach that fine-tunes the pretrained code-aware encoder-decoder model CodeT5 to correct errors Tesseract OCR makes when extracting source code from programming screencasts and screenshots. The authors build a large training corpus by scraping over 10,000 Java GitHub projects, splitting files into snippets, rendering them across 18 font and size combinations representative of popular IDEs, screenshotting them in parallel across 18 virtual monitors via xrdp, and running Tesseract to get noisy OCR output paired with ground truth. After quality filtering (a 60% similarity threshold and a z-score digit-ratio outlier filter), that yields 585,583 training pairs. CodeT5-small and CodeT5-base get fine-tuned via HappyTransformer on this dataset. Evaluated on both a screenshot test set and a manually curated set of 100 YouTube Java tutorial videos, CodeT5-OCRfix clearly outperforms raw Tesseract, un-fine-tuned CodeT5, and the prior statistical-language-model baseline ACE, reaching near-perfect accuracy on screenshots (token/char-NLD around 0.98 to 0.99) and clear gains on videos (token-NLD 0.81 versus 0.73 for Tesseract and 0.69 for ACE), while running roughly 400 times faster than ACE per snippet. One notable finding is that dark IDE backgrounds substantially hurt OCR quality across all methods, and that ACE sometimes corrupts already-correct tokens, which drags its accuracy below raw OCR's.
