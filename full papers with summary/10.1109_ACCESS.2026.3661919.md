# BinSight: Enhancing Executable Binary Classification Accuracy Through Kernel Density Estimation-Based Visualization

- **Year:** 2026 (received Nov 2025, published Feb 2026)
- **Venue/Source:** IEEE Access
- **DOI:** 10.1109/ACCESS.2026.3661919

## Metadata

- **se_area:** Not a standard SE lifecycle phase, closest mapping is maintenance/security analysis (static binary analysis, reverse engineering support for malware triage and unpacking-tool identification).
- **se_task:** Executable binary classification; malware family classification; packer/packaging-tool identification (e.g., distinguishing AutoIt, Inno Setup, NSIS, Themida, UPX variants and their versions); implicitly supports code-similarity/code-reuse analysis as future work.
- **cv_technique:** Kernel Density Estimation (KDE)-based 2D density image generation (via Seaborn kdeplot, Gaussian kernel, with tuned bandwidth/threshold/grid parameters) applied to structural feature sequences; run-length weighted compression prior to KDE; two-stage robust-percentile outlier removal (median/MAD-based) as image preprocessing; CNN classification via fine-tuned ResNet-50 (pretrained on ImageNet); perceptual hashing (pHash, 256-bit, 16x16) for image-similarity-based de-duplication/clustering used in dataset construction and leakage control; baseline comparison against conventional grayscale byte-to-image visualization (Nataraj et al.-style).
- **platform:** General/not applicable in the usual mobile-web-desktop-game sense, the artifacts are Windows PE (Portable Executable) binary files, not UI screens. Method is stated to be theoretically extensible to ELF and Mach-O.
- **rationale:** Robustness (primary motivation: conventional grayscale byte-to-pixel visualization is shown to overfit to layout-dependent, non-structural artifacts such as headers, causing inflated/leaked performance; KDE-based density representation is argued to be more robust to such superficial edits and to generalize to structurally distinct unseen samples); also context-driven in the sense that different structural feature types (raw bytes, block averages, block histograms, basic-block instruction counts, basic-block sizes) are chosen to expose different levels of structural context (byte density vs. control-flow structure) that plain byte visualization cannot capture.
- **artifact_type:** Not applicable in the GUI-artifact taxonomy sense (full-interface / localized / temporal / natural input); the visual artifact produced is a synthetic 256x256 statistical density image derived from a 1D structural feature sequence (byte array, histogram, or basic-block metric sequence), not a rendering of a UI or natural photo. If forced into the taxonomy, it is closest to a "localized/derived" representation of the whole-binary structure rather than any UI region.
- **eval_method:** Two custom datasets built from 30,612 collected Windows PE executables (malware + benign), de-duplicated and clustered via pHash Hamming-distance thresholds into "families" (family_name) and near-duplicate "groups" (group_id) to control visual/label leakage; byte-based dataset (8,493 executables, 46 families) evaluated with 5-fold StratifiedGroupKFold (SGKF); code-structure/packer dataset (5,081 executables, 14 packer/packaging-tool families) evaluated with 3-fold SGKF; group_id used exclusively as the CV grouping key so near-duplicate samples never span train/test; nested SGKF for validation/early stopping; metrics reported as 5-fold or 3-fold mean +/- std of accuracy, macro-averaged Precision/Recall/F1, and macro ROC-AUC; class-weighted cross-entropy plus per-group upsampling/downsampling to handle two levels of imbalance; ablation-style comparisons across visualization types (grayscale baseline vs. raw-byte/average/histogram KDE) and across sequence-expansion methods (RAW/BASE/EXTEND/SQUARE_EXTEND); additional controlled comparison isolating the effect of the outlier-removal step; also a supplementary experiment stripping grayscale images to code-section-only bytes to diagnose header-driven data leakage.
- **challenges:** (1) Building the multi-stage extraction/visualization pipeline (Ghidra-based basic-block CFG extraction, outlier removal, sequence expansion, KDE rendering) increases end-to-end analysis/preprocessing time for very large datasets, even though KDE rendering itself is a single-shot offline step; (2) fundamentally block-based static analysis (disassembly, basic-block extraction) degrades under code obfuscation or multilayer packing, since the disassembler can fail to separate basic blocks correctly; (3) being a density-based visualization, KDEBinViz cannot directly reconstruct or interpret actual execution flow or program control intent; (4) visualization quality and downstream classification performance are sensitive to KDE hyperparameters (bandwidth adjustment factor, grid size, density threshold), and a full sensitivity analysis of these was left to future work; (5) the packer/packaging-tool dataset is heavily class-imbalanced (dominated by Themida), requiring relaxed per-class minimum-group constraints that the authors note should be kept in mind when interpreting results.

## Scope note

, review before including:** this paper is about malware/executable-binary classification and packer/packaging-tool identification, a cybersecurity/static malware analysis task, not one that maps cleanly onto the standard SE lifecycle (requirements, design, development, testing, maintenance). The CV usage itself is central and non-trivial (a novel KDE-based 2D visualization method feeding a CNN classifier), so it's a strong CV paper, but its SE relevance is borderline, closer to security analysis than software engineering. Some prior CV4SE surveys (e.g., Bajammal et al.) do include malware-visualization work under "code/binary analysis," so this may still be in scope depending on how the survey draws its boundary. ## Summary

BinSight proposes KDEBinViz, a visualization method that converts static structural features of Windows PE executables, raw byte arrays, block-averaged byte values, block byte-histograms, and basic-block instruction-count and size sequences extracted via a Ghidra-built control-flow graph, into 2D kernel-density-estimation images for CNN (ResNet-50) classification, instead of the conventional approach of mapping raw bytes directly to grayscale pixels. The central argument is that grayscale byte-to-image visualization is highly susceptible to visual data leakage: CNNs learn superficial, layout-dependent artifacts, like consistent packer or header stubs, rather than true structural logic, inflating benchmark performance when data splits aren't leakage-controlled. To test this rigorously, the authors build a strict, group-aware evaluation protocol (pHash-based near-duplicate clustering plus StratifiedGroupKFold) and two datasets: a general byte-based malware/benign set and a harder code-structure-based packer/packaging-tool set. Under this protocol, the grayscale baseline collapses to 24.90% macro F1 on the packer dataset, dropping further to 32.37% accuracy when headers are stripped away, which exposes the leakage, while KDEBinViz's basic-block-size representation reaches 97.59% macro F1, a 72.69-point gap, and also gives a smaller but consistent 2.57-point improvement (91.91% vs. 89.34%) on the more heterogeneous general dataset. The paper also contributes a two-stage adaptive outlier-removal algorithm (median/MAD plus percentile) and a run-length weighted compression scheme tailored to KDE's outlier sensitivity, and shows through t-SNE and confusion-matrix analysis that KDEBinViz features form well-separated per-family clusters where grayscale features collapse into one chaotic cluster.
