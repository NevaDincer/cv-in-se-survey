# Automated Mobile Apps Testing from Visual Perspective

- **Year:** 2020
- **Venue/Source:** ISSTA 2020 (Doctoral Symposium)
- **DOI:** 10.1145/3395363.3402644

## Metadata

- **se_area:** Testing
- **se_task:** Fully visual (no internal program/accessibility access) automated mobile app testing: GUI abstraction of screenshots into structured element representations, then learning app-function-based test models via a double-RNN architecture to generalize test actions across multiple apps sharing a function (e.g., 'login', 'search')
- **cv_technique:** YOLOv3 object detection (customized loss for accurate bounding boxes; 12 GUI element types; trained on the RICO mobile-UI dataset) for GUI element/structure extraction; unsupervised autoencoder neural network for compressing GUI structure into feature vectors; relative entropy over feature vectors for GUI similarity comparison; double RNN (RNN-A for action sequences, RNN-I for GUI/interface sequences) for dynamic behavior/test-model learning
- **platform:** Mobile
- **rationale:** Context-driven (mimics how a human tester visually cognizes an app, independent of platform-specific code); Robustness (aims at a generalized, platform- and version-independent test model rather than one tied to a specific AUT)
- **artifact_type:** Full-interface (mobile app screenshots captured via camera/screen projection, acted on via a physical robotic arm)
- **eval_method:** None reported yet. This is an ISSTA Doctoral Symposium proposal paper. An evaluation PLAN is described (accuracy/precision/recall/F1/mAP for the object-detection and RNN components; planned real-app comparison against related work on platform dependency, permission requirements, efficiency, supported test types, and bug-detection quality) but no results are presented; the paper states that only the GUI Abstraction module (3.1) has been preliminarily implemented, while GUI Cognition and Action Association (3.2, the core RNN-based learning contribution) is future work
- **challenges:** Framework not yet fully implemented at time of writing; only the perception/abstraction stage exists; hardware-in-the-loop robotic-arm test execution adds physical/engineering complexity beyond the CV pipeline itself; whether function-based generalization (e.g., a learned 'login' or 'search' model) actually transfers across visually dissimilar apps is asserted but unproven; no baseline comparison data available yet

## Summary

Proposes a fully vision-based, platform-independent framework for automated mobile app testing that deliberately avoids reading any internal program information (source code, layout files, accessibility trees). Test execution is physically decoupled from the software under test via a robotic arm that mimics human touch, with visual information captured by camera or screen projection. This design choice is explicitly aimed at cross-platform/cross-version generality, since the same visual-cognition pipeline can, in principle, drive testing regardless of the underlying app implementation.

The technical approach has two stages. **GUI Abstraction (3.1)**: a customized YOLOv3 (loss function modified to prioritize accurate bounding-box output over classification accuracy, since missed elements are judged more harmful to testing than misclassified ones) detects 12 common GUI element types from a RICO-trained model, and an unsupervised autoencoder further compresses the resulting GUI structure into a feature vector, deliberately using GUI *structure* (colored by element type) rather than the raw interface image, so the system reasons about UI meaning rather than pixel appearance. **GUI Cognition and Action Association (3.2)**: a joint double-RNN architecture (RNN-A for the action/element sequence, RNN-I for the interface/GUI sequence) is trained not per individual app but per *app function* across a group of same-type apps (e.g., learning what "search" looks like across several book-reader apps), with the explicit goal of generalizing test-action intent rather than memorizing one app's specific interface-jump graph. Relative entropy between GUI feature vectors is used to judge GUI similarity at three granularities (near-identical / partially similar e.g. login screens / substantially different), which both suppresses combinatorial state-space explosion and helps recognize same-type GUIs across apps. The paper's contribution is explicitly framed as a research *direction*: recognizing apps purely visually, building a generalized cross-app test model, and achieving flexible rather than rigid automated execution, rather than a validated system.
