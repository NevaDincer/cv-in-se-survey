# Prioritize Crowdsourced Test Reports via Deep Screenshot Understanding

- **Year:** 2021
- **Venue/Source:** ICSE 2021 (43rd IEEE/ACM International Conference on Software Engineering)
- **DOI:** 10.1109/ICSE43902.2021.00090

## Metadata

- **se_area:** Testing (crowdsourced test report management / triage)
- **se_task:** Crowdsourced test report prioritization
- **cv_technique:** SIFT (feature-point matching for problem-widget image similarity, via FLANN); pretrained CNN widget-type classifier (14 widget types); CNN+RNN encoder-decoder (adapted from Xiao et al.) for widget intent captioning when no matching text is available
- **platform:** Mobile
- **rationale:** Context-driven (screenshots are treated as structured collections of meaningful widgets instead of raw width×height×RGB pixel matrices, so visually different-but-same-bug or visually similar-but-different-bug reports are disambiguated correctly); Robustness (explicitly designed to handle theme/dark-mode color variation, identical-screenshot-different-bug cases, and same-bug-different-screenshot cases that break prior pixel-matrix approaches)
- **artifact_type:** Localized (Problem Widget extracted via text-matching or CNN+RNN intent classification) combined with full-interface context (Context Widget = all remaining widgets on screen, classified by a 14-type CNN into a distribution vector)
- **eval_method:** Empirical study on 536 real crowdsourced test reports from 10 mobile apps (manually bug-categorized by testing experts); APFD (Average Percentage of Faults Detected) metric; compared against IDEAL, IMAGE-only, BDDIV (prior state of the art), and RANDOM baselines; also RQ1/RQ2 evaluate the widget-classification CNN (89.98% accuracy) and TextCNN bug/reproduction-step classifier (96.65% accuracy) in isolation
- **challenges:** Widget-type classifier limited to 14 predefined categories and depends on quality of a self-built 36,573-image training set; approach explicitly restricted to apps with grid or list layouts; dataset and NLP vocabulary are Chinese-language, raising cross-language generalizability questions (authors argue OCR/NLP/MT maturity mitigates this); crowdworker report quality is uncontrolled; addresses prioritization only, not deduplication

## Summary

DeepPrior tackles the problem that crowdsourced mobile app testing generates huge volumes of test reports (often >80% duplicates), making manual review costly. Instead of treating screenshots as generic image feature vectors, the prior state of the art, DeepPrior performs "deep screenshot understanding": it extracts all UI widgets from a screenshot via CV/DL, locates the specific "Problem Widget" responsible for the bug (matched via widget-screenshot-to-text alignment, or a CNN+RNN model when no text is available), and treats all remaining widgets as "Context Widgets" classified into a 14-type distribution vector. In parallel, NLP (TextCNN) splits crowdworker text into Bug Description and Reproduction Step segments, converting the latter into an "action-object" sequence. These four features are aggregated into Bug Feature (Problem Widget + Bug Description) and Context Feature (Context Widget + Reproduction Step), and a weighted DEEPSIMILARITY metric (SIFT/FLANN for images, Word2Vec/Euclidean for text, DTW for action sequences) drives a greedy set-cover-style prioritization algorithm seeded by a synthetic NULL Report. On a 536-report/10-app dataset, DeepPrior beats the prior state-of-the-art BDDiv approach by 3.81% average APFD while using less than half the computational overhead, and it is notably more stable across runs than BDDiv. The paper's three worked motivating examples (different app themes, different bugs on identical screenshots, same bug on different screenshots) are a clear, concrete illustration of why naive pixel-matrix screenshot similarity fails and widget-level understanding is needed.
