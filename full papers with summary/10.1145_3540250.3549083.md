# Cross-Device Record and Replay for Android Apps

- **Year:** 2022
- **Venue/Source:** ESEC/FSE '22 (30th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering)
- **DOI:** 10.1145/3540250.3549083

## Metadata

- **se_area:** testing (also touches maintenance/debugging, since record-and-replay underlies failure reproduction, regression testing, and test-case migration)
- **se_task:** Cross-device record and replay for Android apps: capturing a GUI event trace on one device and faithfully replaying it on a device with a different screen size/orientation/density, particularly for apps with responsive GUI restructuring
- **cv_technique:** None (see scope concern above). The closest analog is a heuristic "UI segmentation" algorithm named after and loosely inspired by VIPS (Vision-based Page Segmentation), but it operates on the Android accessibility-tree view hierarchy (bounding-box geometry, background-color heuristic, textual attributes) rather than image pixels; widget similarity is computed via TF-IDF/cosine similarity over view text, not any visual/embedding-based matching
- **platform:** mobile (Android)
- **rationale:** Not CV-driven. The approach is motivated by robustness (tolerating GUI restructuring/non-determinism across devices without brittle pixel-coordinate assumptions) and context-driven adaptation (responsive-pattern-aware replay tailored to each device's layout), achieved through accessibility-tree heuristics rather than visual perception
- **artifact_type:** Not applicable in the CV-artifact sense; if forced into the taxonomy, it is closest to "full-interface" (whole-GUI-state segmentation/matching at replay time) but implemented via accessibility data, not imagery
- **eval_method:** Case study on 30 usage scenarios across 7 top commercial apps (Calculator, YouTube, MS To Do, MS Outlook, MS Word, Adobe Reader, Firefox) with non-trivial responsive patterns, replayed across 3 emulated Android devices (Pixel XL phone, Pixel 3 XL phone, Pixel C tablet) in both directions (180 replay runs); comparison against state-of-the-art baselines RERAN (same-device, pixel-precise) and SARA (self-replay augmented, cross-device within limited scope) on 47 additional usage scenarios across 14 more apps (603 further replay runs, 1,167 total replay settings); metrics: replay success rate (event-in-order + subjective goal achievement, with an "in-order main-event replay" oracle), time/space overhead (ms per event, KiB per log), and per-scenario stability across devices; manual root-cause analysis of 105 failure cases; no user study; replay-success judged by the authors following prior work's protocol
- **challenges:** Authors report: (1) framework assumes deterministic record/replay environments, which never fully holds, and apps with dynamic content (e.g., live feeds) break replay (1.9% of failures); (2) implementation limitations in the extensible SegmentUI/Similarity/RespPatterns modules, especially overlapping views defeating the horizontal/vertical-cut segmentation heuristic (57.1% of failures, dominated by 30 overlapping-view cases), plus missed/unmodeled responsive patterns, and no support for self-rendered UIs (WebView, game engines) since UI Automator cannot dump them; (3) reliance on accessibility metadata quality: incomplete or incorrect accessibility text (labels/descriptions) causes the largest share of real failures (41.0%, "app bugs" including 39 accessibility-info bugs); (4) evaluation limited to popular, professionally-developed apps, so results may not generalize to less well-maintained/open-source apps; (5) usage scenarios were author-created, a possible bias source; (6) replay-success determination still requires a human in the loop. The authors explicitly suggest future data-driven/learned approaches (e.g., learned view representations) could address the segmentation/similarity limitations. This is an implicit acknowledgment that heuristic, non-visual matching is a ceiling on current performance.

## Scope note

The paper's UI segmentation is only nominally "vision-based." It borrows the name and inspiration of the VIPS (Vision-based Page Segmentation) algorithm for its spatial-locality logic, but the actual implementation operates entirely on the Android accessibility tree (view bounding boxes, text/id/desc/hint strings, TF-IDF/cosine similarity) via UI Automator, not on pixels, screenshots, or any learned CV model. No image processing, object detection, OCR, or vision model is used anywhere in the approach. The paper explicitly cites other works (UIS-Hunter, Seenomaly) as the ones that "exploit computer-vision techniques," positioning itself as different. This paper is fundamentally a GUI-testing / record-and-replay systems paper with heuristic, accessibility-tree-based GUI understanding, not a CV-in-SE paper.

## Summary

This paper introduces Rx, a framework for cross-device record and replay (R&Rc) of Android apps: capturing a GUI interaction trace on one device and replaying it correctly on another device with a different screen size or orientation, even when the app's responsive UI design causes the layout (and therefore the exact sequence of needed events) to differ substantially between devices. The core contribution is a one-pass, greedy, non-backtracking replay algorithm built on two design principles: view segments (spatially and functionally related groups of widgets) should have a bipartite-matched correspondence across devices, and cross-device layout changes follow a small, enumerable set of "responsive patterns" recommended by Android/Material Design (Expand, Scroll, Options, Divide, Navigate, etc.). When a logged event's receiver widget is absent from the replay-time GUI, Rx tentatively applies responsive actions to reveal it, reverting them if unsuccessful, and otherwise drops the event as a discardable triggering action, avoiding the costly exhaustive search and app restarts used by prior test-migration approaches. Evaluated on over 1,000 replay settings spanning 24 commercial apps, Rx achieved an 86.7% success rate on cross-device scenarios beyond any prior non-search-based technique's scope, while remaining competitive with the same-device, pixel-precise RERAN tool. A distinctive detail is that despite naming its segmentation routine after VIPS (a "vision-based" web-page segmentation algorithm), Rx's matching is entirely accessibility-tree- and text-based (TF-IDF/cosine similarity, view bounding boxes, background-color heuristics) rather than pixel- or image-based, making its actual reliance on computer vision minimal to none.
