# cvrip: A Visual GUI Ripping Framework

- **Year:** 2025
- **Venue/Source:** Journal of Software: Evolution and Process
- **DOI:** 10.1002/smr.70009

## Metadata

- **se_area:** testing (GUI/model-based testing), with elements of maintenance (the ripped GUI transition model supports downstream tasks like test repair, fault diagnosis, and test migration)
- **se_task:** GUI ripping: automatically exploring an application's screens to build a UI transition graph (UTG) of GUI states and state transitions, without relying on internal GUI framework structure (activities, widget hierarchies, resource IDs) that traditional ripping tools require
- **cv_technique:** a custom-trained YOLO v5 object detector (binary executable vs. nonexecutable widget classification, trained on a filtered/cleaned subset of the RICO dataset) for widget detection, compared against edge-and-contour analysis (Canny edge detection plus Gaussian filtering, dilation, and contour extraction), YOLO v3, and UIED; PaddleOCR for text widget detection, merged with detected widget boxes; SSIM and SSIM+ORB (Oriented FAST and Rotated BRIEF) for full-screenshot image comparison to recognize GUI states; a state-recognition acceleration layer using perceptual image hashing (phash, dhash, ahash) or a ResNet-50 (ImageNet-pretrained) feature embedding compared by Hamming or cosine distance to prune candidate states before running the more expensive SSIM comparison
- **platform:** mobile (Android applications, actions triggered via adb), though the approach is explicitly framed as platform-agnostic since it depends only on screenshots and does not use platform-specific GUI structure APIs
- **rationale:** context-driven (traditional GUI ripping depends on the underlying GUI framework exposing structure information, which is unavailable or inconsistent across platforms, in nonnative components such as Android WebViews, and in commercial apps with code protection; a vision-based approach removes this dependency and only needs the operating system to provide screenshots and input injection); ease of use (the same technique can in principle be reused across different GUI frameworks and platforms without reimplementation, since it never touches internal widget hierarchies)
- **artifact_type:** full-interface (whole application screenshots, both single-frame widget detection on one screen and pairwise screenshot comparison across consecutive states to build the transition graph)
- **eval_method:** 20 Android apps spanning multiple categories (Airbnb, Wikipedia, Pinterest, Yelp, AntennaPod, Markor, etc.), evaluated with the multilevel GUI comparison criteria (GUICC: activity, layout, executable, content coverage) rather than code coverage. RQ1 compared four widget detectors (canny+ocr, yolov3+ocr, yolov5+ocr, uied+ocr) over 1000-action ripping runs, with yolov5+ocr scoring best on a held-out 1k-screenshot/44-app test set (precision 0.57, recall 0.65, F1 0.61) and winning on GUICC coverage with statistical significance (Wilcoxon signed-rank tests). RQ2 compared SSIM vs. SSIM+ORB and different resize rates/thresholds, settling on SSIM at 0.5 resize and a 0.9 similarity threshold, validated separately against 5000 same-app screenshot pairs for state-classification accuracy. RQ3 measured acceleration methods (phash, dhash, ahash, ResNet-50), finding roughly 19-31% reduction in ripping time with negligible coverage loss and recommending phash. RQ4 compared widget-selection heuristics (random, spatial diversity/ART, equivalence grouping, non-large-text-block-first, combined), with the combined strategy winning on activity and content coverage. RQ5 showed model-based exploration beats model-less random CV-based exploration (reimplementation of White et al.) on coverage and even runs faster. RQ6 compared cvrip's best configuration against non-CV baselines Fastbot, Ape, and Monkey over 2000 actions, finding cvrip matches Ape and beats Fastbot/Monkey on activity coverage, though it ran roughly 2-3x slower in wall-clock time (about 4.5 s/action vs. Fastbot/Ape's faster agent-resident approach) and found fewer unique crashes (8 vs. 10 and 11).
- **challenges:** the paper reports several author-acknowledged limitations: visual widget detection still misses or falsely reports widgets, requiring compensating heuristics (result degradation for low-confidence/small/oddly-shaped widgets, random-coordinate clicking, cross-app screen matching); cross-app exploration can only be curbed reactively (an excluded full-screen image triggers a restart) rather than prevented before the jump, and this fails on apps like AntennaPod with many cross-app-triggering widgets (34.5% of content-level coverage was outside the app); OCR-based large-text-block detection is unreliable because OCR fragments long paragraphs into broken pieces; state recognition granularity is sensitive to resize rate and similarity threshold with no universally correct setting; the abstract-feature acceleration step can itself introduce redundant states when a screenshot pair has high SSIM similarity but low abstract-feature similarity; absolute ripping speed lags non-CV tools substantially (about 120-150 minutes for 2000 actions versus roughly 50 minutes for Fastbot/Ape) due to adb round-trip overhead; and the experiment covers only 20 apps under a fixed-default-strategy methodology, so the authors describe the results as preliminary and not proof of superiority over more sophisticated non-CV strategies.

## Summary

cvrip is a GUI ripping framework that builds a GUI transition graph purely from screenshots, without relying on any underlying GUI framework's structural information (activities, view hierarchies, resource IDs). This makes it portable across platforms and applicable to nonnative components such as Android WebViews, where traditional structure-dependent rippers struggle. The system detects widgets on each screen using a custom YOLO v5 model trained to distinguish executable from nonexecutable widgets on a cleaned subset of the RICO dataset, merged with PaddleOCR text detection, and outperforms edge-and-contour analysis, YOLO v3, and UIED in this executable-widget-focused setting. To recognize whether a new screenshot represents a previously visited state, it uses SSIM image comparison (with a lighter perceptual-hash or ResNet-50 feature prefilter to cut comparison cost as the state space grows). Exploration follows a click-first strategy with fallback actions (swipe, long press, drag, restart) governed by probability weights, plus techniques for handling false/missing widget detections and preventing cross-app exploration via predefined excluded screens. On 20 Android apps, evaluated using multilevel GUI comparison coverage criteria, the authors find their YOLO v5 detector, an SSIM-based recognizer with 0.5 resize and 0.9 threshold, phash-based acceleration, and a combined widget-selection heuristic each outperform their alternatives, and that the assembled system achieves coverage competitive with the non-CV tools Ape and Fastbot, though considerably slower in wall-clock terms and with fewer detected crashes. The paper positions itself as an experimental study establishing that visual GUI ripping is a viable direction rather than a finished replacement for structure-dependent tools.
