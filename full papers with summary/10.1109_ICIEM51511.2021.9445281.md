# A Novel approach of GUI Mapping with image based widget detection and classification

- **Year:** 2021
- **Venue/Source:** ICIEM 2021
- **DOI:** 10.1109/ICIEM51511.2021.9445281

## Metadata

- **se_area:** Testing
- **se_task:** Automated web GUI widget detection and classification (labels, buttons, input boxes, checkboxes, links, etc.) directly from a target URL, to support automated regression-resistant test-case generation for rapidly-updated web applications
- **cv_technique:** OpenCV-based object detection using bounding boxes and color variation (unsupervised, no trained image repository); k-Nearest Neighbor (kNN) classifier for widget-type classification
- **platform:** Web
- **rationale:** Ease of use (avoids building/maintaining huge labeled GUI-widget training image repositories by taking a live URL as input instead); Robustness (aimed at coping with continuously/rapidly-updated GUI components, e.g. e-commerce sites)
- **artifact_type:** Full-interface (web page screenshots with widgets highlighted via rectangular bounding boxes)
- **eval_method:** Demonstrated on ~10 real-time websites (Gmail, Google, a government services portal, Instagram, LinkedIn, Twitter, Skype, Snapdeal, a generic login/website sign-in page, Yahoo, Amazon) using Selenium (via PyAutoGUI) to click through and capture post-interaction screenshots after fixed wait intervals (2s/5s/10s); reports object-detection TIME per site (Table III, ~9.6-10.3s per page) and a sample 32-screenshot detection report for Google.com with widget x,y coordinates, matched trained-sample type, URL link, and screen-link filename; no accuracy/precision/recall figures are actually computed or reported despite the abstract and conclusion claiming the method 'yields accuracy'
- **challenges:** Authors themselves state in Conclusions & Future Work that detection accuracy, classification accuracy, and testing-coverage probability with proper analysis 'will be calculated ... and presented' in future work, i.e., no quantitative accuracy evaluation exists in this paper itself, only detection-time measurements; the technical description of the object-detection and kNN-classification steps is very shallow (no architecture, training data, or parameter details given); writing/technical exposition throughout is notably thin and imprecise

## Scope note

Despite the abstract's claim of "better accuracy," the paper never reports an actual accuracy, precision, or recall figure for either widget detection or classification. The only quantitative results shown are per-website object detection time (Table III) and a raw coordinate/type/link report for Google.com screenshots. The stated future work is explicitly to compute and present the accuracy metrics the abstract already claims. This is worth careful scrutiny on evaluation quality: it arguably has a use-case illustration (the Google.com report) but not a real evaluation.

## Summary

This paper proposes a lightweight, training-repository-free approach to automated web GUI testing. Rather than pre-training a widget classifier on a large labeled image dataset, which the authors argue fails to generalize since real-world GUI components are custom-designed per site, the method takes a live URL as input, uses Selenium to drive a browser and trigger interactions, and applies OpenCV to detect widget bounding boxes and color variation directly on the resulting screenshots, described as an "unsupervised dataset" approach. Detected widgets then get classified into domain-specific types (text field, button, combo box, list, tree, scroll bar, menu, menu item, toggle button, tabs, slider) via a kNN classifier. The GUI object classification logic uses simple visual heuristics: a screenshot that changes entirely relative to the original gets inferred as a hyperlink or button trigger, a cursor-icon appearance gets inferred as an input box, and an in-page list appearing gets inferred as a combo box. The pipeline is demonstrated qualitatively across roughly ten real, well-known websites (Google, Twitter, W3Schools, Amazon, Gmail, Instagram, LinkedIn, Skype, Snapdeal, Yahoo), showing bounding-box-annotated screenshots and per-site object-detection timing, consistently around 9.6 to 10.3 seconds per page. A sample structured report covers 32 screenshots captured while crawling Google.com, listing widget coordinates, inferred type, matched training sample, URL, and screen-link filename, intended as the artifact that would drive downstream automated test-case generation. The motivation throughout is cutting the cost of manually re-authoring test cases every time a fast-iterating web application updates its GUI. The paper is explicit that this is exploratory work, closing with a promise to compute detection accuracy, classification accuracy, and testing-coverage probability in future work.
