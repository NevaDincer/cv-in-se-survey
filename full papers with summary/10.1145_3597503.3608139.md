# On Using GUI Interaction Data to Improve Text Retrieval-based Bug Localization

- **Year:** 2024
- **Venue/Source:** ICSE 2024 (46th International Conference on Software Engineering)
- **DOI:** 10.1145/3597503.3608139

## Metadata

- **se_area:** Maintenance (bug localization)
- **se_task:** Text-retrieval-based (TR-based) bug localization for Android apps, augmented using GUI interaction data collected while reproducing bugs
- **cv_technique:** None applied algorithmically to images; screenshots are used only as a reference for human annotators manually mapping GUI screens/widgets to source code files during dataset construction. The retrieval techniques themselves are IR/NLP-based: BugLocator, Lucene (classical IR), SentenceBERT and UniXCoder (DL-based text embedding models); none are CV models
- **platform:** Mobile (Android)
- **rationale:** Context-driven (aims to bridge the lexical gap between bug reports and source code by using additional contextual signal, GUI screen/widget metadata, collected during bug reproduction)
- **artifact_type:** Full-interface (screen-level GUI metadata), but based on structured metadata (screen class, widget IDs/content descriptions), not pixel-level visual features
- **eval_method:** Empirical study on a manually-constructed dataset of 80 bug reports (with GUI interaction/metadata) across 39 Android apps; augmentation techniques (filtering, boosting, query expansion/replacement) evaluated against four TR-based bug localization baselines (BugLocator, Lucene, SentenceBERT, UniXCoder) using Hits@1/5/10 metrics; statistical significance testing (Wilcoxon signed-rank test)
- **challenges:** Manual construction of the GUI interaction dataset required significant effort (rigorous, two-coder manual labeling with 88.33% inter-coder agreement) and is not automatically scalable; effectiveness varies significantly by baseline technique and augmentation configuration (only some configurations improve results); the study only evaluated 80 bug reports and 4 TR baselines, so generalizability is limited; SentenceBERT/UniXCoder were used zero-shot (not fine-tuned) which may understate DL baseline performance

## Summary

This paper studies whether GUI interaction data collected while reproducing a bug (e.g., which screens and widgets were touched) can improve text-retrieval-based (TR) bug localization for Android apps, i.e., ranking source files by likelihood of containing the bug given a bug report. The authors manually build a dataset of 80 bug reports, each annotated with the GUI screens and widgets involved during bug reproduction and mapped to the corresponding buggy source files (screenshots were used by human annotators as a reference during this manual mapping process, but are not themselves processed by any CV algorithm). They then propose several ways to use this GUI metadata to augment four existing TR-based bug localization techniques (BugLocator, Lucene, SentenceBERT, UniXCoder): filtering out files unrelated to the involved GUI screens, boosting the relevance score of files related to the involved screens, and query expansion/replacement using GUI-derived terms. The best-performing configurations (combining filtering with SC (screen class) information, and boosting with GS (GUI structure) information) improve Hits@10 by 12.5-18% and Hits@5 by 6-29% over the unaugmented baselines, and the improvements are shown to be largely complementary/orthogonal across different baseline techniques (i.e., not redundant with existing textual signal). The paper is included in the corpus because it superficially involves "screenshots" and "GUI" data in a software maintenance task, but its methodological core is information retrieval over structured metadata rather than any pixel-level computer vision technique. Screenshots function only as a human-in-the-loop annotation aid rather than an algorithmic input, which is why this paper is flagged above for possible scope exclusion from a CV-in-SE survey.
