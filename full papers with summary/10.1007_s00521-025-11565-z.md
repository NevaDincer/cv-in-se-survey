# ViT-DtC: vision transformer-based design-to-code framework for code generation from generated UI designs and hand-drawn sketches

- **Year:** 2025
- **Venue/Source:** Neural Computing and Applications
- **DOI:** 10.1007/s00521-025-11565-z

## Metadata

- **se_area:** Development
- **se_task:** Unified two-layer design-to-code pipeline that (1) automatically classifies an input UI design image into one of four categories (web, Android, iOS, or hand-drawn sketch) and (2) generates domain-specific-language (DSL) tokens describing the UI layout via the category-appropriate encoder-decoder, compiled into platform-specific executable code (HTML/XML/Storyboard) using the pix2code compiler
- **cv_technique:** Vision Transformer (ViT, google/vit-base-patch16-224, pretrained on ImageNet-21k) fine-tuned as a 4-way image classifier; the same pretrained ViT re-purposed (classification head removed, raw patch-embedding hidden states extracted) as the visual encoder in an all-transformer encoder-decoder architecture with GPT-2 as the autoregressive decoder; a custom 'unifying annotator' converts heterogeneous hand-drawn-sketch bounding-box annotations (JSON and XML formats, from 3 different source datasets) into unified row-based DSL tokens compatible with the pix2code dataset structure
- **platform:** General (web, Android, iOS, and hand-drawn sketches unified within a single framework)
- **rationale:** Ease of use (a single framework automatically detects design type, eliminating the manual step of routing an input to a platform-specific compiler that all prior work required); Context-driven (ViT's global self-attention across image patches is explicitly argued to better capture UI layout/spatial composition than a CNN's local receptive field, which is particularly relevant for design-to-code)
- **artifact_type:** UI design mockup / hand-drawn sketch, four types: pix2code-style web/Android/iOS synthetic screenshots and a newly unified hand-drawn-sketch dataset assembled from four public sources (sketch2aia, Microsoft Sketch2Code, Kaggle Sketch2Code, and a hand-drawn-styled version of the pix2code web dataset)
- **eval_method:** Classification layer: accuracy on a combined 4-class held-out test set of 1139 images (250 each for web/Android/iOS + 389 hand-drawn), achieved a perfect 100%. Code-generation layer: token-level accuracy (correct/incorrect token match plus a length-mismatch penalty term, following Beltramelli's pix2code evaluation protocol) using a greedy-search decoding strategy, benchmarked head-to-head against 5 published baselines (pix2code, an attention-based hierarchical model, and HGui2Code/SGui2Code/AGui2Code) on the standard pix2code web/iOS/Android test sets, plus a standalone (non-comparable, since no prior work tested this combination) evaluation on the new hand-drawn dataset. 5 training repetitions per dataset to confirm result stability.
- **challenges:** The paper's own ablation attributes its striking web-dataset accuracy jump (97.28%, vs. 85-94% baselines) largely to simplifying the DSL token vocabulary (collapsing style/state tokens like button-active/button-red/button-green into a single 'button' token and dropping pure layout-structure tokens like single/double/quadruple), not to the ViT architecture alone, meaning results are not purely attributable to the encoder swap; assembling the unified hand-drawn dataset required reconciling three incompatible annotation formats (JSON x2, XML x1) via a custom-built annotator plus a full manual review pass to correct erroneous annotations (5 Android + 1 iOS image also found and fixed independently); token-level accuracy does not directly capture visual/layout fidelity of the final rendered page; the framework does not yet model UI element style/color/state, explicitly deferred to future work

## Summary

Most prior design-to-code work, pix2code itself and everything that followed it (attention-based hierarchical decoders, HGui2Code, SGui2Code, AGui2Code, YOLO-based sketch pipelines), handles one design modality at a time: either a generated web, iOS, or Android screenshot, or a hand-drawn sketch, and someone still has to route the input to the right platform-specific compiler by hand. ViT-DtC folds both into one pipeline. A fine-tuned Vision Transformer first classifies any incoming design image as web, Android, iOS, or hand-drawn. The same pretrained ViT, with its classification head stripped, then serves as the encoder in an all-transformer encoder-decoder, paired with a GPT-2 decoder that generates DSL tokens, compiled to HTML, XML, or Storyboard code through the original pix2code compiler. A real engineering contribution here is dataset unification. Three of the four hand-drawn-sketch sources used incompatible JSON or XML bounding-box annotations, so the authors built a custom annotator to convert them into the row-based DSL format pix2code expects, then manually reviewed the conversions. They also simplified the web dataset's token vocabulary, collapsing style-carrying button tokens into one generic "button" token and dropping pure layout tokens that don't describe real elements. The classifier hits a perfect 100% on a 1,139-image held-out set. The generator beats or ties every tested baseline: 97.28% on web (versus 94% for the best prior model), 82.47% on iOS, and 81.16% on Android, plus 84.82% on the new hand-drawn dataset with no comparable prior number. The authors are candid that the web-dataset jump owes a lot to token simplification, not the ViT swap alone, and that style, color, and state remain future work.
