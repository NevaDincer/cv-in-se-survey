# Eye of the Mind: Image Processing for Social Coding

> **SCOPE WARNING**: Exclusion assessment (IC/EC application):** This paper is primarily an empirical mining study + crowdsourced human survey about developers' *behavior* of sharing images. It does not itself apply, train, or evaluate a CV technique on a software visual artifact for an SE task (IC2/IC3 are not well satisfied). The one CV usage shown (Fig. 4, object detection on a single posted screenshot) is a hand-picked illustrative demo for the "possible future" discussion section, not a method the paper proposes, implements, or evaluates. (visual output/discussion rather than CV-as-technique) even though it is not literally software visualization.

- **Year:** 2020

## Metadata

- **se_area:** Maintenance / knowledge transfer (developer communication in social coding platforms, bug reports, Q&A)
- **se_task:** Empirical characterization of the growing trend of developers sharing images (alongside text) in social coding environments (StackOverflow, Bugzilla/Mozilla), plus a small illustrative proof-of-concept applying object detection/recognition to a posted image to show it could substitute for or augment textual bug-report content
- **cv_technique:** Object localization/recognition (used only illustratively on two example images, Fig. 4 and Fig. 5, via an unspecified off-the-shelf detector plus keyword-text matching/annotation; no CV method is trained, evaluated, or benchmarked in this paper)
- **platform:** General (web-based social coding platforms: StackOverflow, Bugzilla/Mozilla bug trackers)
- **rationale:** Context-driven only in the speculative/future sense. The paper's actual empirical contribution is a mining study + crowdsourced human survey, not a working CV technique applied to an SE artifact
- **artifact_type:** Developer-shared images in bug reports/Q&A posts (screenshots of code, runtime errors, menus, dialog boxes, program I/O, performance charts, algorithm diagrams; Figure 1 taxonomy of 10 categories)
- **eval_method:** (1) Mining study: StackOverflow (2013-2018, 1.15M threads tagged Python/Java/JavaScript, 2.93M posts) and Bugzilla/Mozilla (Core, Firefox, Firefox Android, Firefox iOS, 26,808 posts) to quantify the trend of image-attachment over time; (2) Crowdsourced survey with 168 developers (Mechanical Turk + BountySource-gated) rating 22,561 images for informativeness (Q1/Q2) and content category (Q3), plus asking why developers share images (Q4); (3) Statistical test (Mann-Whitney) comparing issue/question closure time with vs. without an attached image; (4) One illustrative CV demo (object detection on a single StackOverflow-posted screenshot, Fig. 4) and one illustrative machine-generated-annotation mockup (Fig. 5); neither is a trained/evaluated system
- **challenges:** No benchmark datasets exist for detecting objects specific to software screenshots/artifacts (the paper explicitly calls for one); current CV training data is dominated by natural-image domains (humans, streets, handwriting) rather than software UI grid-structured content; the entire 'future' vision (auto-generating/synthesizing visual artifacts) is speculative and unimplemented

## Summary

This ICSE-NIER paper argues, via two empirical studies, that developer image-sharing in social coding platforms is (a) growing steadily over time and (b) meaningfully informative rather than decorative. The trend-mining study shows StackOverflow posts-with-images rising linearly from 2013-2018 across Python/Java/JavaScript tags, and Bugzilla/Mozilla change-requests-with-images roughly doubling (200%) between years even as total change requests grew only 20%. A follow-up crowdsourced study with 168 professional developers (rating 22,561 images) found 87.8% of shared images were judged informative beyond the accompanying text, and 86.9% of associated text was judged unlikely/very unlikely to be understandable without the image; a separate open-coding pass produced a 10-category taxonomy of what images communicate (code screenshots dominate at 62.8% overall, run-time errors and dialog boxes next, with StackOverflow skewing toward code and Bugzilla skewing toward run-time-error/dialog-box screenshots). A closure-time analysis found issues/questions with images close significantly faster.

The paper's "vision" section (5-6) is where CV enters: the authors sketch a future where tools automatically retrieve/synthesize images to complement textual bug reports, illustrating the idea with one worked example: applying (unspecified) object detection to a StackOverflow-posted screenshot of a Windows profiler tool (Fig. 4) to show that keyword-matching plus object localization could annotate the relevant UI region a user was asking about, and a mocked-up "machine-generated" annotated Bugzilla screenshot (Fig. 5) contrasted with the human-made one. The authors are explicit that achieving this vision requires new benchmark datasets specific to software-artifact object classes, since existing CV training corpora are built for humans/streets/nature/handwriting rather than grid-structured software interfaces. They argue software UI recognition should be comparatively easier than open-domain CV because software's component vocabulary is finite and known. No system is built or evaluated; the paper's core contribution is the empirical characterization of developer behavior, with CV appearing only as a forward-looking illustration.
