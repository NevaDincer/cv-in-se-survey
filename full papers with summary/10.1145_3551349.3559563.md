# A model for automatic generating reusable code from multiple GUIs

- **Year:** 2022
- **Venue/Source:** 37th IEEE/ACM International Conference on Automated Software Engineering (ASE '22), Doctoral Symposium / Poster track
- **DOI:** 10.1145/3551349.3559563

## Metadata

- **se_area:** development (UI/GUI implementation and code generation), with explicit attention to design/reuse concerns (componentization) that also touch software design
- **se_task:** GUI-to-code translation ("Code Generation from Images", CGI) across multiple platforms (web, Android, iOS), specifically targeting reusable/componentized code generation and navigation between multiple generated GUIs within one application
- **cv_technique:** not a single implemented technique by the author; the paper surveys and plans to build on techniques from prior work, including direct object detection/recognition and convolutional-feature-extraction + multimodal classification for identifying visual elements, plus separate handling of hierarchical/spatial layout, textual vs. non-textual element representation, and style data representation
- **platform:** web, Android, iOS (explicitly cross-platform / multi-GUI)
- **rationale:** ease of use / productivity (reduces repetitive, tedious manual GUI-to-code translation); context-driven (aims to capture hierarchical, spatial, and navigational relationships between multiple GUIs, not just single-screen translation); reuse/componentization as a first-class design goal distinguishing this work from prior single-screenshot pix2code-style approaches
- **artifact_type:** full-interface (whole GUI screenshots/images as input), from either hand-drawn or high-fidelity mockups, aimed at generating reusable "web component"-style code artifacts and cross-GUI navigation structures
- **eval_method:** to date, only a systematic literature mapping identifying problem classes and artifacts (Table 1); planned future evaluation includes two additional systematic reviews (data representation techniques; code generation techniques), design and implementation of an architectural model, controlled experiments, benchmarking against existing SOTA models, and an action-research study conducted in an industrial software factory setting
- **challenges:** identifying individual and grouped visual elements together with their hierarchical/spatial arrangement; choosing a data representation that generalizes across text/non-text elements and style information; selecting an effective code-generation/transformation technique (template-based replacement vs. language-model-based generation); fundamental uncertainty about how much of the GUI-to-code task can be automated versus still requiring developer intervention (e.g., adapting to a framework, styling, behaviors not visible in a static image); the work itself acknowledges it is still in an early design phase with open research questions (RQ1–RQ3) rather than a validated solution.

## Summary

This ASE '22 poster/DSR paper lays out a PhD research plan for automating "Code Generation from Images" (CGI), translating GUI screenshots or mockups into reusable, componentized code across web, Android, and iOS, rather than presenting a finished tool. The author frames the CGI problem as three sub-challenges: (1) detecting and recognizing visual elements and their hierarchical/spatial arrangement within an image, (2) choosing a data representation for these elements (ranging from simple type/dimension/placement vectors to combined image+code representations), and (3) transforming that representation into code via techniques ranging from template-based replacement to language-model-driven generation. Distinct from prior single-screen tools like pix2code, the explicit differentiator here is a focus on componentization and reuse: inferring which visual elements can be treated as reusable "web components" across multiple related GUIs in the same application, and supporting navigation between those generated GUIs. Using Design Science Research methodology, the paper reports results only from an initial systematic literature mapping, summarized in a small table linking problem classes (element identification, hierarchical/spatial representation, textual/non-textual representation, style representation, code generation) to specific prior artifacts (e.g., pix2code, CNN/GAN-based detectors). The paper proposes three concrete research questions about reducing developer involvement, incorporating reuse/componentization, and choosing suitable code-generation techniques, and outlines a future evaluation plan combining further systematic reviews, an architectural model, controlled experiments against SOTA baselines, and action research in an industrial software factory. Because no artifact or empirical result belonging to the author is yet reported, this paper functions primarily as a well-organized problem framing and related-work synthesis for the CGI/UI-code-generation subarea.
