# Algorithm for Mapping Layout Grids in User Interfaces: Automating the "Squint Test

- **Year:** 2024 (TMPA 2021 workshop; published in Springer CCIS vol. 1559)
- **Venue/Source:** Tools and Methods of Program Analysis (TMPA 2021), Communications in Computer and Information Science (CCIS), vol. 1559, pp. 3-14
- **DOI:** 10.1007/978-3-031-50423-5_1

## Metadata

- **se_area:** testing (automated UI quality/usability assessment, specifically automated visual-complexity evaluation as a precursor to predictive user-behavior/interaction-quality models)
- **se_task:** reverse-engineering an implicit layout grid from a UI screenshot: automatically inferring the alignment grid (rows/columns) that UI elements are visually organized into, and coding each grid cell as filled or empty (whitespace), to support quantitative assessment of a UI's visual complexity, aesthetics, and orderliness (an automation of the informal "Squint Test" from usability engineering, where a designer half-closes their eyes to perceive coarse visual hierarchy)
- **cv_technique:** a classical (non-learned) OpenCV-based image-processing pipeline: Canny edge detection (noise removal, gradient calculation, edge thinning, edge linking), followed by image pixelization/downsampling (resize-down-then-up via bilinear interpolation) to coarsen the visual representation, followed by a custom column/row segment-scanning algorithm (parameterized by grid accuracy, allowed noise/error tolerance, and minimum grid step) to overlay grid lines, followed by threshold-based cell coding (percentage of white pixels in a cell determines a 0/1 "empty vs. filled" label)
- **platform:** general (explicitly stated to support mobile, web, and desktop UI screenshots; validated in this paper specifically on web UI screenshots)
- **rationale:** context-driven (motivated by the fact that code-based UI analysis, e.g. HTML/CSS, cannot reveal alignment grids that are only implicit in the rendered visual layout, unlike explicit grids present in design mockups, so an image-based/CV approach is required to "see" the UI the way a human user does, independent of platform or underlying code) and ease of use/scalability (the fully automated algorithm removes the need for human labelers used in the authors' own prior manual-grid-overlay study, enabling "batch" processing of large screenshot sets to build the large datasets needed for up-to-date visual-complexity/user-behavior prediction models)
- **artifact_type:** full-interface (the entire UI screenshot is processed and decomposed into a whole-page 2D grid/matrix representation, rather than analyzing or localizing individual isolated widgets)
- **eval_method:** two-part validation. (1) A parameter-sensitivity demonstration showing how tuning a single configuration parameter (Minimum border width) changes whether visually-related small elements (e.g., menu items) are correctly grouped into one grid cell versus incorrectly split into several. (2) A quantitative validation applying the algorithm to 497 website homepage screenshots (university/college sites) and comparing the algorithm's output metrics (Columns, Rows, Cells, Whitespace ratio) against subjective human ratings from a survey of 70 participants (43 female, 27 male, ages 18-29) who rated each screenshot on 7-point Likert scales for Complexity, Aesthetics, and Orderliness (4,235 total ratings, 8-10 raters per screenshot). Backward-selection linear regression models were fit for each of the three subjective scales using the four algorithm-derived metrics as predictors, all three regressions statistically significant (Whitespace significant in all three models; Columns and Cells also significant for Aesthetics and Orderliness) though with modest explanatory power, especially for Complexity (R² = 0.024, R²_adj = 0.022) versus stronger fits for Aesthetics (R²_adj = 0.242) and Orderliness (R²_adj = 0.129).
- **challenges:** the algorithm has no universal parameter settings across UIs; different platforms (e.g., desktop vs. web) and layouts require manual experimentation with grid accuracy, noise tolerance, and minimum-grid-step parameters to produce results that look "correct" to representative users, and this tuning process is not yet formalized (explicitly named by the authors as the paper's main limitation, with automated parameter auto-tuning left as ongoing/future work); the cell-coding threshold (fixed at a default of 3% white-pixel ratio) is described by the authors as an inherently "fuzzy" choice justified only by rough alignment with human perception rather than a principled derivation; the regression model explaining subjective Complexity ratings from the algorithm's grid metrics had very low explanatory power (R²_adj = 0.022), notably weaker than the authors' own prior manual (human-labeled) grid-overlay study (R²_adj = 0.263), suggesting the automated grid extraction captures Aesthetics/Orderliness perception better than Complexity specifically; the authors' own earlier manual-labeling study (cited as prior work) found substantial inter-labeler disagreement (27.8% relative standard deviation in total grid-cell counts across 8 human labelers), showing that "ground truth" for this task is inherently ambiguous even for humans, which limits how precisely any automated method can be validated against it.

## Summary

This paper automates a familiar usability heuristic, the "Squint Test," where a designer half-closes their eyes to grasp a layout's visual hierarchy at a glance. The authors build an OpenCV pipeline that reverse-engineers the alignment grid implicit in any UI screenshot (mobile, web, or desktop), since that grid shows up in design mockups but isn't recoverable from HTML or CSS. The algorithm runs in four steps. Canny edge detection finds the boundaries, the edge image gets pixelized to coarsen fine detail, a column-by-column and row-by-row scan detects and overlays grid lines using tunable accuracy and noise-tolerance parameters, and each resulting cell is coded as blank or filled based on a white-pixel-ratio threshold. The output is a compact 2D matrix of the UI's layout, meant to feed downstream visual-complexity research at a scale the authors' own earlier manual approach, where 8 people hand-labeled grids for just 19 screenshots, couldn't reach. The main empirical test applies the algorithm to 497 real website homepages and regresses its derived metrics (columns, rows, cells, whitespace ratio) against ratings of Complexity, Aesthetics, and Orderliness from 70 participants across 4,235 total ratings. Whitespace came out as a significant predictor in all three models, and Aesthetics and Orderliness fit reasonably well, but the Complexity model performed worse than the authors' earlier manual study, a result they attribute to how fuzzy "ground truth" is here, since even their own human labelers disagreed substantially with each other. The authors admit the algorithm's parameters still need manual tuning per platform, with automated tuning left as future work.
