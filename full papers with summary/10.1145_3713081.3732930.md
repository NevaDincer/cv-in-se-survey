# TestFlow: Advancing Mobile UI Testing through Multi-Step Reinforcement Learning

- **Year:** 2025
- **Venue/Source:** ISSTA Companion 2025 (34th ACM SIGSOFT International Symposium on Software Testing and Analysis, Companion)
- **DOI:** 10.1145/3713081.3732930

## Metadata

- **se_area:** Testing (mobile UI/GUI test automation)
- **se_task:** Multi-step, long-horizon mobile UI test execution/agent-based testing: a GUI agent that follows natural-language test instructions across complex, cross-page workflows (e.g., multi-step app tasks like ordering food) without the greedy step-by-step errors and long-horizon dependency neglect seen in prior agents
- **cv_technique:** Vision-Language Model (Qwen2.5-VL, a multimodal LLM) used as the GUI agent's perception+decision-making backbone, processing mobile screenshots (diverse resolutions, multilingual GUIs) to select and localize on-screen actions (coordinate outputs evaluated via bounding-box containment)
- **platform:** Mobile
- **rationale:** Context-driven (industrial dataset of 12,000 manually-labelled real human operation trajectories spanning diverse commercial scenarios (food delivery, healthcare, gaming, finance, insurance) used to ground training in realistic app usage); robustness (Task-aware Reinforcement Learning explicitly designed to counteract greedy policy convergence/parametric drift across long multi-step workflows, improving adaptability to dynamic, evolving UI environments)
- **artifact_type:** Full-interface (whole-screen GUI perception) combined with localized (specific coordinate/action outputs on individual UI elements)
- **eval_method:** Empirical evaluation on the Android Control benchmark (public UI automation benchmark) using Qwen2.5-VL-7B as base model; metrics: Step Success Rate (SSR) and Whole Task Success Rate (WTSR); compared against a base Qwen2.5-VL model and a Supervised-Fine-Tuning-only (SFT-only) ablation of TestFlow, on high-level-instruction, long-trajectory samples. TestFlow achieves 55.37% SSR / 33.69% WTSR vs. 39.88%/26.83% for base Qwen2.5-VL and 51.38%/30.73% for SFT-only
- **challenges:** Only "preliminary" results reported on one benchmark/base model size (7B), limiting generalizability claims; explicitly acknowledges that current approach lacks online/continuous adaptation to real-world dynamic conditions (UI variations, network fluctuations) without full retraining, which is left as future work; the composite reward function requires manually-tuned weighting coefficients (λ1, λ2, λ3) balancing format/accuracy/task-completion rewards, introducing a design/tuning burden; assertion-based task-completion reward depends on a separate "assertion model," an additional component whose own reliability is not deeply analyzed in this short paper

## Summary

TestFlow tackles a known weakness of LLM/VLM-based mobile GUI testing agents: they tend to act "greedily" at each step, causing error accumulation and failure to properly complete complex, long-horizon, multi-step testing tasks (e.g., a 10+-step cross-page workflow like ordering food through several app screens). The authors propose a two-stage training pipeline built on a Vision-Language Model backbone (Qwen2.5-VL): first Supervised Fine-Tuning (SFT) on short-trajectory and low-level device-operation instructions, then a "Task-aware Reinforcement Learning" phase, an enhanced variant of Group Relative Policy Optimization (GRPO), with the KL-divergence loss term removed (following the DAPO framework) to encourage exploration, and a custom composite reward function integrating format-consistency reward, action-accuracy reward (using bounding-box containment for coordinate-based click actions), and task-completion reward (via an automated assertion model, +5 for success/-2 for premature failed termination), applied to long-trajectory and high-level instructions requiring visual-linguistic reasoning. Training data is stratified into a four-tier taxonomy (short-trajectory, low-level, long-trajectory, high-level) and augmented with an in-house industrial dataset of 12,000 manually labeled human operation trajectories spanning diverse commercial app domains. On the Android Control benchmark using Qwen2.5-VL-7B as the foundation model, TestFlow achieves 55.37% Step Success Rate and 33.69% Whole Task Success Rate on high-level, long-trajectory instructions, substantially outperforming both the base VLM (39.88%/26.83%) and an SFT-only ablation (51.38%/30.73%), with the paper reporting particular strength in reducing false terminations during multi-step workflows. As an ISSTA Companion (short/tool-track-style) paper, the work is presented as preliminary/industrial experience (from Ant Group) demonstrating the value of task-aware RL atop a vision-language GUI agent for mobile test automation, with future work aimed at online RL and an autonomous multi-modal debugging assistant.
