## Summary

Judge targets a core bottleneck in automated web GUI testing (AWGT) tools like Crawljax: deciding whether two crawled pages represent the same underlying "state" or two distinct ones (page-pair classification), which existing DOM- or screenshot-similarity approaches get wrong for so-called "near-duplicate" (ND) pages, pages that are behaviorally identical but superficially different because of dynamically loaded content, framework-generated attribute IDs, asynchronous element reordering, or expandable lists/grids. The paper's technical contribution is a two-phase, purely DOM-based "merge-and-classify" pipeline (no image or screenshot input is used, notably distinguishing it from screenshot-based rivals like PDiff or the hybrid FragGen it benchmarks against). First, a novel tree-hash-based structure-merging algorithm walks the DOM bottom-up, hashing each subtree's structure and collapsing sibling subtrees with identical hashes (while protecting clickable and leaf elements from being merged away), which neutralizes the effect of variable-length lists/grids and strips out volatile text/attributes. Second, a dedicated contrastive-learning model (a Transformer encoder, BERT or Longformer, trained MoCo-style with a momentum encoder, a large negative-sample queue, and SimCSE-style dropout-based positive-pair generation) embeds the simplified DOMs into vectors that an SVM then classifies as duplicate or distinct, deliberately encoding tag identity/counts instead of tag order to further neutralize reordering effects. Evaluated against 13 baselines on ~590k labeled page pairs, Judge improves macro-F1 by 8.95–28.90% on average and by up to 99.32% on the hardest out-of-distribution test set; integrated into Crawljax on six real open-source apps, it improves JavaScript branch coverage by 2.62–14.12% over the best existing page-pair classifiers while being 94–99.5% faster than edit-distance baselines. A notable detail is the paper's explicit taxonomy of four DOM-level "near-duplicate" phenomena (dynamically loaded data, dynamically generated attributes, dynamic element reordering, extendable elements), each mapped to a specific part of the merge-and-classify pipeline designed to neutralize it.
