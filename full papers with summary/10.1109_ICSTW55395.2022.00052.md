# Cross-Device Difference Detector for Mobile Application GUI Compatibility Testing

- **Year:** 2022
- **Venue/Source:** 2022 IEEE International Conference on Software Testing, Verification and Validation Workshops (ICSTW)
- **DOI:** 10.1109/ICSTW55395.2022.00052

## Metadata

- **se_area:** testing
- **se_task:** Cross-device GUI compatibility testing for mobile applications (detecting and localizing display differences between screenshots of the same app page rendered on different devices/resolutions)
- **cv_technique:** Pixel-based element boundary/region segmentation via row/column pixel scanning; Optical Character Recognition (OCR) for text extraction; text-element aggregation via geometric heuristics (Horizontal/Vertical Gap Distance, Height Difference, Overlap Ratio); color histogram comparison for text color similarity; SSIM (Structural Similarity Index) for image-element matching; IoU-based boundary/region matching for element correspondence and evaluation
- **platform:** mobile
- **rationale:** Context-driven and robustness-oriented: the approach is designed specifically for the practical, high-volume industrial testing context at Baidu, where manual cross-device visual comparison by test engineers is slow and error-prone due to "visual fatigue" from repetitive checks across many device/resolution combinations (mobile fragmentation). It aims to be robust to differing screen resolutions/sizes across devices without needing DOM/GUI-hierarchy access, making it lightweight and easy to integrate into existing automated testing pipelines (only two screenshots as input, no auxiliary instrumentation, platform-agnostic across Android/iOS).
- **artifact_type:** full-interface (whole-screen screenshot pairs are segmented into elements; differences are detected and visualized at the element/region level within the full page)
- **eval_method:** Custom dataset (CdDiff dataset, publicly released) of 725 screenshot pairs collected from three Baidu apps (Baidu Netdisk, Baidu App, Baidu Tieba; 23/24/18 page scenarios respectively) captured on 10 different Android/Harmony smartphone models (varying OS versions, resolutions, screen sizes). Differences (Add, Delete, Shift, Alter types) were synthetically embedded based on interviews with Baidu test engineers about common compatibility errors, and annotated with LabelImg at both image level (same/different) and element/region level (665 total difference regions). No comparison against prior baseline tools was run empirically (only discussed qualitatively in related work); evaluation is against the authors' own labeled ground truth. Two evaluation dimensions: (1) Image-dimension classification, using accuracy, precision, recall, and F1-score for judging whether an image pair has any difference (overall accuracy 0.924, precision 0.925, recall 0.945, F1 0.935 on combined dataset); (2) Difference-region localization, with precision/recall/F1 computed via IoU threshold (θiou) between predicted and labeled difference rectangles at θiou = 0.1, 0.2, 0.4 (best result θiou=0.1: precision 0.771, recall 0.885, F1 0.824). Also includes qualitative visualization examples and a failure-case analysis (false negatives/positives) but no formal human user study of tester efficiency/usability.
- **challenges:** Authors explicitly report: (1) CdDiff assumes a whole detected "search box" or larger bounding region is a single element, causing it to miss internal text-content differences enclosed within a larger visually-similar element (e.g., differing text inside a search box); (2) some detected differences are flagged by the algorithm but not perceived as real faults by human testers, so predictions still require manual verification; (3) the method does not work on pages with non-solid-color backgrounds, such as full-screen video or game scenes, since element boundary detection relies on pixel-scanning against solid backgrounds; (4) several main parameters (IoU threshold for text/element matching, HGD, VGD) were tuned experimentally/manually on one sub-dataset (Dataset A) rather than set adaptively, and performance degrades on more visually complex screenshots (Dataset B) due to page-understanding (segmentation) errors; (5) manually labeled difference regions sometimes fuse multiple adjacent differences into one label, causing precision/recall to be sensitive to the IoU threshold chosen. (inferred from experimental setup: evaluation is limited to a single company's apps and Android/Harmony devices only, with no cross-platform iOS validation despite claiming platform independence, and no runtime/scalability analysis is reported.)

## Summary

This paper presents CdDiff (Cross-Device Difference Detector), a computer-vision-based method for detecting and localizing GUI display discrepancies between screenshots of the same mobile app page rendered on different devices, addressing the "mobile fragmentation" problem in compatibility testing. CdDiff takes only a pair of screenshots (a "base image" from a known-correct device and a "test image" from another device) as input, without requiring DOM/GUI-hierarchy access, making it lightweight and platform-agnostic. It works in two stages: a "page understanding" module that segments each screenshot into fine-grained elements (text or image type) via pixel-scanning boundary detection, OCR-based text recognition, and geometric text-aggregation rules; and a "discrepancy positioning" module that pairwise-matches base and test elements (using text-content/color-histogram similarity for text, SSIM for images, and location-difference metrics to resolve ambiguous matches), flags unmatched elements as differences, and visualizes them with bounding boxes on a stitched side-by-side image for manual tester review. The main contribution is both the CdDiff algorithm and a newly built, publicly released dataset of 725 labeled screenshot pairs across 3 Baidu apps and 10 devices, with synthetically embedded Add/Delete/Shift/Alter-type differences informed by interviews with real test engineers. Experiments report 0.924 overall accuracy for difference classification and up to 0.824 F1 for difference-region localization, with explicit limitations around single-element assumptions, non-solid backgrounds, and manual parameter tuning.
