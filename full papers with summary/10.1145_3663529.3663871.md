# RFNIT: Robotic Framework for Non-invasive Testing

- **Year:** 2024
- **Venue/Source:** Companion Proceedings of the 32nd ACM International Conference on the Foundations of Software Engineering (FSE Companion '24)
- **DOI:** 10.1145/3663529.3663871

## Metadata

- **se_area:** Testing (mobile application testing)
- **se_task:** Non-invasive, hardware-realistic automated GUI/functional testing of Android apps via a physical robot that performs touches, scrolls, typing, and device rotation on a real smartphone
- **cv_technique:** Image processing / edge detection to identify screen boundaries and dimensions when initializing the robot ("Image Processor" module: camera + edge-detection utilities); computer-vision-based on-screen element/text recognition used both to locate UI elements for interaction (e.g., locating and clicking the "Calc" app icon) and as the test oracle (`get_element_text`) to read result fields directly from the captured screen image
- **platform:** Mobile (Android smartphones, tested on real physical hardware rather than emulators/AVDs)
- **rationale:** Robustness (physical robot + camera enables testing of real sensors like gyroscope/accelerometer and true hardware behavior that emulators cannot faithfully reproduce) and context-driven (vision is used to locate specific GUI elements and read result text rather than relying on instrumentation/accessibility APIs)
- **artifact_type:** Full-interface (camera-captured images of the whole device screen) combined with natural input (physical robotic manipulation: touch pen, device rotation, mimicking real human gestures)
- **eval_method:** Architecture/case-study description rather than a large-scale quantitative evaluation; illustrated via a worked pytest-integrated example (a calculator app test) and mention of a prior feasibility experiment (automatic detection of data loss on Android devices) using a preliminary version of the framework
- **challenges:** No quantitative accuracy/robustness figures are reported for the vision-based element recognition or oracle in this short paper; the framework is still an early/preliminary infrastructure with limited public validation; camera positioning, lighting, and calibration for a physical test bench are plausible practical challenges given the setup described but are not explicitly discussed (inferred from the physical robotic setup)

## Summary

RFNIT (Robotic Framework for Non-Invasive Testing) is a tool-paper proposing a physically robotic approach to mobile application testing that avoids the fidelity gaps of Android Virtual Devices (AVDs) and of prior "stationary smartphone" robotic testers. Unlike earlier robotic frameworks that hold the phone still and move a stylus, RFNIT mounts the smartphone itself on a moving robotic arm while keeping a touch pen and camera fixed on a test bench, which allows the device to be physically rotated (enabling orientation-change testing, NFC-card proximity gestures, and compound gestures like "chop twice for flashlight" or "twist for camera") while a real accelerometer/gyroscope responds naturally. The architecture has four modules: Robotic Test (exposes a PyTest-like API), Image Processor (camera capture + edge detection for screen recognition and element localization), Gestures (touch, scroll, rotation, NFC, zoom abstractions), and Robotic Manipulator (translates gesture commands into physical robot motion). A worked example shows a six-step test: screen identification, returning home, opening the app drawer, launching a calculator app by visually searching for its icon, performing button-tap interactions, and asserting on a result read directly from the screen image via `get_element_text`. The paper is explicitly a short vision/tool paper: it describes the architecture and a single illustrative case study (an app for detecting Android data loss) rather than presenting a rigorous quantitative evaluation of the vision components' accuracy.
