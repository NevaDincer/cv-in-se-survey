# Chouette: An Automated Cross-Platform UI Crawler for Improving App Quality

- **Year:** 2023
- **Venue/Source:** 2023 38th IEEE/ACM International Conference on Automated Software Engineering Workshops (ASEW)
- **DOI:** 10.1109/ASEW60602.2023.00029

## Metadata

- **se_area:** testing (maintenance-adjacent; end-to-end/regression test augmentation and screenshot-based QA support)
- **se_task:** automated GUI crawling for screenshot collection, cross-platform regression/exploration testing, bug/ticket discovery
- **cv_technique:** Canny edge detection; morphological closing (dilation + erosion) for region merging; edge deduplication (containment/size-based filtering) to derive tappable regions
- **platform:** mobile (Android, iOS) and web (mobile web, desktop web), explicitly cross-platform
- **rationale:** context-driven (exploits Duolingo's minimal, plain-background UI design to keep CV simple); robustness (reduces test breakage from frequent app changes since crawling doesn't hardcode navigation paths); ease of use / low maintenance (shared CV module reused across three platforms, reducing per-platform code and maintenance cost)
- **artifact_type:** full-interface (screenshots of entire app screens); the underlying CV operates on localized regions (tap-point rectangles) to decide interactions, but the produced artifact is full-screen screenshots
- **eval_method:** production deployment case study over ~6 months (2023) at Duolingo; effectiveness measured via (1) number of screenshot views per month compared to traditional end-to-end test screenshots, (2) lines-of-code reuse analysis via `cloc` across shared vs. platform-specific code, (3) number of bug tickets filed from Chouette screenshots vs. end-to-end test screenshots across Android/iOS/Web
- **challenges:** long runtimes (10-20 hours per platform across 26 UI languages at peak 80 concurrent sessions); no native "back" navigation on iOS, requiring app restarts to reset state; need to wait several seconds after each tap to detect screen changes, multiplied over dozens of taps per screen; search space explosion if crawl depth is not bounded (main crawl capped at 3 taps from home, though a linear purchase-flow variant is allowed to go to depth 10); difficult to benchmark against existing tools since the tool was purpose-built for Duolingo's needs; no ground-truth data from prior years to explain a drop in Chouette-sourced tickets after the first three months of the study period.

## Summary

Chouette is a computer-vision-based GUI crawler built at Duolingo as a lightweight complement to traditional end-to-end tests. Its main goal isn't finding bugs directly but collecting screenshots that localization, design, and marketing teams already depend on, while cutting the human maintenance cost that plagues brittle, hand-scripted E2E tests. Rather than using accessibility trees or view hierarchies, Chouette treats each screen purely as an image: it runs Canny edge detection, a dilate-then-erode closing operation to merge nearby edges into coherent regions, a second edge pass, and a deduplication step that removes near-duplicate or contained regions, producing a set of tap points that correspond to interactable UI elements. The tool then explores breadth-first up to three taps from the home screen, with a separate deeper crawl, up to 10 taps, dedicated to the purchase and payment flow, since that sequence is linear and commercially important. Built in Python with Appium for mobile and Selenium for web, and run through Jenkins across 26 UI languages and multiple emulated device configurations, Chouette shares 53.7% of its code as a single cross-platform CV module, cutting the maintenance burden relative to platform-specific tests. Over six months of production use it generated roughly 200 bug tickets and accounted for 32.8% of all screenshot views, despite fairly high runtimes (10 to 20 hours per platform per run), a tradeoff the authors consider acceptable since screenshot consumers don't need real-time results. What stands out is that the paper treats screenshot usefulness and ticket-filing rate, not crash-finding, as its main success metrics.
