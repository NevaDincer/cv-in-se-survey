# GLIB: Towards Automated Test Oracle for Graphically-Rich Applications

- **Year:** 2021
- **Venue/Source:** ESEC/FSE 2021 (29th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering), Athens, Greece
- **DOI:** 10.1145/3468264.3468586

## Metadata

- **se_area:** Testing
- **se_task:** Automated test oracle for detecting non-crashing GUI/graphical glitches (visual display bugs) in graphically-rich applications, specifically mobile/PC/console video games, addressing the gap left by existing GUI testing techniques that only detect crash-inducing bugs
- **cv_technique:** CNN-based binary image classifier (10 convolutional layers with batch normalization, max-pooling, 4 fully-connected layers, softmax output) for detecting abnormal (glitched) UI screenshots; combined with a saliency-map technique (gradient of output label with respect to input pixels, à la Simonyan et al.) for post-hoc localization of the glitch region within a flagged screenshot
- **platform:** Game (mobile, PC, and iOS games; primarily built/evaluated on the Unity engine but also tested on Unreal Engine and self-defined engines)
- **rationale:** Robustness (a novel code-based data augmentation approach injects real bug code via hotfix patching to generate training screenshots with authentic UI glitches, rather than heuristically approximating glitch appearance as prior work does, yielding more precise/generalizable training data) and context-driven (grounded in an empirical characteristic study of 466 real bug reports and code commit diffs from NetEase game teams to identify actual glitch manifestations and root causes)
- **artifact_type:** Full-interface (classifies entire game UI screenshots as normal/glitched, with subsequent pixel-level saliency localization)
- **eval_method:** Empirical characteristic study (RQ1/RQ2) categorizing 201 filtered real glitch screenshots into 8 manifestation types and 4 code-level root causes; quantitative detection evaluation (RQ3) comparing GLIB's code-based augmentation against a no-augmentation baseline and against a rule/heuristic-based augmentation baseline adapted from prior work (Owl Eyes), using accuracy/precision/recall/F1 on a held-out test set of 192 real glitch and 365 normal screenshots, achieving 100% precision, 99.5% recall, 99.8% F1 (a 76.7% recall improvement over the non-augmented baseline); practical field evaluation (RQ4) applying GLIB to 14 real-world games unseen during training (PC, iOS, Android; multiple engines), reporting 53 detected glitches with 48 confirmed and fixed by developers, versus fewer confirmed bugs from the rule-based baselines; qualitative case study visualizing saliency-map heatmaps to confirm accurate glitch localization; explicit generality analysis across games, languages, platforms, and engines
- **challenges:** Author-reported/discussed limitations: the approach currently targets only three specific code-level root-cause categories (camera-disable errors, camera clearflag errors, incorrect post-processing effects) and explicitly defers harder-to-generalize GPU-driver/hardware-level rendering bugs to future work; rule-based baselines using fixed, limited color palettes or heuristics fail on out-of-distribution glitch appearances (e.g., unseen color-block RGB values, transparent color blocks resembling dialog boxes); text-related glitches are hard to localize/generate since game engines rarely expose text-position JSON and text may appear as rendered Word-Art rather than OCR-able characters; the training data augmentation still requires white-box source-code access to the games used for training (though the trained model can then be applied black-box to unseen games); manual scene traversal for collecting bug-free screenshots is the one remaining manual step, posing a threat to external validity if scene selection is not sufficiently diverse.

## Summary

This paper targets a testing gap in graphically-rich applications (games): existing automated GUI testing detects crash-inducing bugs but misses non-crashing visual glitches (abnormal color blocks, random noise, partial repetition, frame overlay, object missing, abnormal text, overexposure, black borders) that nonetheless degrade user experience. Motivated by an empirical characteristic study of 466 real bug reports and code-commit diffs from NetEase game studios, the authors identify eight glitch manifestation categories and trace them to concrete source-code root causes (e.g., incorrectly disabled rendering cameras, wrong camera clearflag settings, missing post-processing effect clearance). Building on these findings, they propose GLIB, which uses a novel code-based data augmentation strategy, injecting the identified buggy code patterns into real game apps via hotfix patching to generate screenshots containing authentic (not merely heuristically mimicked) UI glitches, to train a CNN binary classifier, paired with a saliency-map technique for localizing the glitch region within flagged screenshots. Evaluated against Owl Eyes' heuristic rule-based augmentation and a no-augmentation baseline, GLIB achieves near-perfect detection (100% precision, 99.5% recall, 99.8% F1) on a held-out set of real-world glitch screenshots, substantially outperforming both baselines, particularly in recall. A notable detail is the practical field deployment: applying GLIB to 14 previously unseen commercial games spanning PC, iOS, and Android platforms and multiple engines (Unity, Unreal, custom), it surfaced 53 previously undetected glitches, 48 of which were subsequently confirmed and fixed by the respective development teams, demonstrating real-world utility beyond benchmark evaluation, alongside explicit ablations confirming generality across games, languages, platforms, and engines.
