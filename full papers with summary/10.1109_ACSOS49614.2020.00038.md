# Automating GUI Testing with Image-Based Deep Reinforcement Learning

- **Year:** 2020
- **Venue/Source:** ACSOS 2020
- **DOI:** 10.1109/ACSOS49614.2020.00038

## Metadata

- **se_area:** Testing
- **se_task:** Image-based deep reinforcement learning (A3C) for exploratory GUI testing of web applications; agent receives a screenshot as state and outputs a per-pixel click probability map
- **cv_technique:** CNN (5-layer conv+maxpool feature extractor over 128x128 RGB screenshots); LSTM cell (state memorization across the episode); combined with A3C (asynchronous advantage actor-critic) reinforcement learning
- **platform:** Web
- **rationale:** Context-driven (screenshot mirrors what a human tester perceives); Robustness (resilient to fields being emptied by a human mid-run, generalizes across pages without needing revisit metadata)
- **artifact_type:** Full-interface (downscaled 128x128 RGB screenshot)
- **eval_method:** Simulation study on a commercial web app; compared against random testing and a Q-learning baseline (Bauersfeld et al.) on number of unique states discovered over 10,000 actions, averaged over 10 runs; separate 100-click benchmark comparing unique URLs found against 2 inexperienced and 1 experienced human tester
- **challenges:** Requires training until convergence per application (not zero-shot across apps); action space reduction still depends on HTML/DOM element boundary information rather than pure pixels, so it is not purely vision-only; can only detect crash/exception-type errors, not logical/functional bugs; evaluated on a single application domain

## Summary

This paper treats GUI exploration testing as a reinforcement learning problem: the state is a screenshot of the current view, the action is an interaction with a GUI element, and the reward is +1 for discovering a new application state and 0 otherwise. The pipeline runs a CNN, then flattens into an LSTM, then splits into separate actor and critic dense heads. The actor outputs a per-pixel probability heatmap over the screenshot, which then gets combined with HTML element bounding boxes to compute a per-element, rather than per-pixel, action distribution. This element-based reduction turned out to train much faster than raw per-pixel clicking or a pixel-click-plus-simulated-click variant. The core result is that a purely visual, screenshot-based DRL agent, built to mimic how a human perceives and clicks through an interface, outperforms random and Q-learning baselines by up to 6x in unique states discovered over 10,000 actions, and finds more unique URLs in a 100-click challenge than inexperienced human testers (52 versus 37 or 38), coming within 2 URLs of an experienced tester, while running the whole 100-click experiment in under 10 seconds against roughly 5 minutes for humans. The LSTM's memory of previously visited states lets the agent traverse a fixed set of navigation pages exactly once each, with no redundant revisits, purely from visual history. The paper also reports novel bugs the agent found that conventional automated tests missed. This is a Master's-thesis-derived industry paper from Ericsson, evaluated on one real commercial web application rather than a benchmark suite, with future work aimed at richer RL algorithms and actions like typing and drag-and-drop.
