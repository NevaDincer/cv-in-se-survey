# Semantic Test Repair for Web Applications

- **Year:** 2023
- **Venue/Source:** ESEC/FSE '23 (31st ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering), San Francisco, CA, USA
- **DOI:** 10.1145/3611643.3616324

## Metadata

- **se_area:** Testing (maintenance of automated GUI/regression test scripts)
- **se_task:** Automated repair of broken web UI test scripts (record/replay Selenium tests) after the application under test evolves, relocating target UI elements and repairing broken test workflows
- **cv_technique:** ResNet-50 (image encoder, fine-tuned/adapted to output 384-dim embeddings aligned with the text encoder); combined with Sentence-BERT (NLP model) in a hybrid, unified text+image semantic embedding space; cosine similarity for matching
- **platform:** Web (browser-based applications tested via Selenium WebDriver)
- **rationale:** Robustness (DOM attributes and pixel-level visual appearance are shown to be unstable across app versions, so the technique instead uses semantic content (text and icon meaning) that is more stable under UI redesign); context-driven (contextual semantic information of surrounding UI elements is explicitly incorporated to disambiguate elements when individual text/image similarity is insufficient)
- **artifact_type:** Localized (matches individual GUI elements, icons/images and their text labels, captured via on-page screenshots of specific elements, not full-screen classification)
- **eval_method:** Empirical study on 6 real-world open-source web apps (AddressBook, Claroline, Collabtive, PWMA, MantisBT, MRBS) across multiple releases (1540 total test breakages), comparing repair ratio against 3 baselines (Water: DOM-based; Vista: vision-based; WebEvo: string+image similarity based); breakage taxonomy (NSSP/NSNP/NSR/MSDP) analysis; manual correctness judging by 3 graduate students with Cohen's Kappa inter-rater agreement (>99%); running-time comparison (tracing + repair time); parameter sensitivity analysis on weighting factor α and similarity threshold t; standalone evaluation of the semantic model's precision/recall on SNLI (text-text) and an icon-label dataset (text-image, image-image pairs), plus precision comparison against Vista/WebEvo on 2,587 manually labeled similar-element pairs; ablation replacing Sentence-BERT with Word2Vec and ResNet with a transformer-based label model (LabelDroid-style)
- **challenges:** Authors report: (1) the icon-image training dataset may not be sufficiently large/representative, limiting precision on icon-related elements; (2) generalizability threat: evaluated only on 6 web apps, so results may not generalize to other applications; (3) empirically, Semter still fails to repair breakages where UI elements change drastically (e.g., text-to-icon conversion, multiple visually/textually similar elements on a page, or fundamental widget-type changes like dropdown→radio button), and repair effectiveness for NSNP/MSDP/NSR breakage classes remains comparatively low; (4) efficiency is lower than the simplest DOM-based baseline (Water) due to the cost of context extraction, though authors describe total time as "acceptable.

## Summary

This paper presents Semter, a semantic test repair technique for web application record/replay (Selenium) test scripts that break as the application's GUI evolves. Rather than relying on DOM attributes (which change with page structure) or raw visual appearance (which changes with restyling), Semter captures the semantic meaning of UI elements (their visible text and icon images) and matches broken elements to their counterparts in the updated application via a hybrid deep-learning semantic model combining Sentence-BERT for text and a fine-tuned ResNet-50 for images, both projected into a shared 384-dimensional embedding space compared with cosine similarity. A distinctive detail is that this individual-element similarity is augmented by contextual semantic similarity: text/image embeddings of nearby DOM-sibling elements are matched pairwise and weighted in, which the paper shows (via an α-ablation) improves repair ratio by up to 8.7% on average, since surrounding labels help disambiguate visually/textually similar elements. Semter also reuses Vista's local one-step page exploration to handle workflow breakages caused by page insertion/removal. Evaluated on six real-world open-source web apps against three state-of-the-art baselines (Water, Vista, WebEvo), Semter achieved an 84% average repair ratio versus 40–54% for baselines, with acceptable running time and 0.92 precision for its semantic-similarity component, establishing that semantics-driven, human-like element matching outperforms DOM- or vision-only repair strategies for web test maintenance.
