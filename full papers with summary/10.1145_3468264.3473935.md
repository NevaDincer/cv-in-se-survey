# An Empirical Study of GUI Widget Detection for Industrial Mobile Games

- **Year:** 2021
- **Venue/Source:** ESEC/FSE 2021 (29th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering), Athens, Greece
- **DOI:** 10.1145/3468264.3473935

## Metadata

- **se_area:** Testing
- **se_task:** Empirically evaluating whether existing GUI widget/object-detection techniques (developed for general-purpose mobile apps) can be effectively applied to detect clickable widgets in industrial mobile games, to support automated game testing (usability and compatibility testing) in place of costly manual/semi-automated methods
- **cv_technique:** Object detection benchmarking of two established deep-learning detectors, Faster R-CNN (two-stage, anchor-box-based, VGG16 backbone, region proposal network) and YOLOv2 (single-stage, anchor-box-based via k-means clustering, Darknet19 backbone), pretrained on COCO and evaluated/retrained on both the general-purpose Rico UI dataset and a newly constructed mobile-game GUI dataset; also employs classical image processing (Suzuki's Contour Tracing algorithm) as part of a heuristic data-cleaning pipeline to filter mislabeled/empty bounding boxes
- **platform:** Game (mobile; specifically Android games from NetEase, Tencent, and Cygames, evaluated against contrast with general-purpose mobile apps)
- **rationale:** Context-driven (grounded in a two-phase industrial survey, scrum interviews with 2 senior QA experts plus a 53-respondent questionnaire at NetEase Games, establishing that accurate GUI widget detection is the main bottleneck for automating mobile game testing) and robustness (systematically investigates why general-purpose detectors fail to transfer to the game domain, characterizing root causes such as widget density and stylistic diversity)
- **artifact_type:** Full-interface (whole-screenshot object detection identifying multiple widget bounding boxes per game screen)
- **eval_method:** Two-phase qualitative industrial survey (structured interviews plus questionnaire) to establish testing pain points (RQ1); construction of the first mobile-game GUI widget detection benchmark (2,993 GUIs, 38,776 widgets across 9 games from 3 companies, via a semi-automated POCO-based collection pipeline plus a novel two-stage heuristic data-cleaning method, coarse filtering for invalid coordinates, fine-grained filtering via size thresholds and Suzuki contour tracing for irregularly large/empty boxes); quantitative cross-dataset evaluation of Faster R-CNN and YOLOv2 (with multiple hyperparameter settings) trained/tested across combinations of the Rico dataset and the new game dataset, using precision/recall/F1 at a strict IoU threshold of 0.8 (RQ2); in-depth qualitative root-cause analysis comparing GUI element density and visual/art-style diversity between game and non-game GUIs (RQ3), including a case study on "return" button icon diversity across nine games
- **challenges:** Central empirical finding: general-purpose object detectors trained on Rico suffer catastrophic performance collapse when applied to games (e.g., Faster R-CNN F1 drops from 55.9% on Rico to 7.7% on games), and the reverse transfer (game-trained models tested on Rico) is similarly poor, indicating a fundamental domain gap rather than a data-quantity issue; root causes identified are (1) far higher GUI widget density in games (55% of game screens have >9 elements vs. only 8% for regular apps, with widgets packed closely together, causing missed detections), and (2) extreme heterogeneity/diversity of widget visual styles across games (irregular shapes like ancient buildings or cat claws, widgets overlaid on background art, and near-total dissimilarity of even semantically identical widgets like "return" buttons across different games/art styles), which existing anchor-box detectors and their fixed hyperparameters are not designed to handle; additional data-quality challenges from automatic labeling (invalid/out-of-screen coordinates, irregularly large boxes, and "empty" boxes from occluded/overlapping widgets) required a custom cleaning pipeline; authors note potential dataset-scale and model-selection (only 2 detector families tested) threats to validity.

## Summary

Motivated by the practical bottleneck of manual and semi-automated mobile game testing at NetEase Games, this paper presents the first empirical study of whether existing deep-learning-based GUI widget detection techniques, originally developed and validated for general-purpose mobile apps, transfer effectively to industrial mobile games. The authors first conduct a two-phase industrial survey (scrum interviews with senior QA leads plus a 53-respondent questionnaire) confirming that precise, automated detection of clickable GUI widgets is viewed by practitioners as the critical enabler for scaling up game testing automation, since current tools like POCO are engine-limited and error-prone around overlapping visual effects. To enable systematic study, they build the first mobile-game GUI widget detection benchmark: 2,993 screenshots with 38,776 widgets collected from 9 commercial games across three publishers, using a semi-automated POCO-instrumentation pipeline supplemented by a novel heuristic data-cleaning algorithm (coarse filtering for invalid coordinates plus fine-grained filtering using size thresholds and Suzuki contour tracing to remove irregularly large or visually "empty" mislabeled boxes). Benchmarking Faster R-CNN and YOLOv2 (with multiple hyperparameter configurations) across Rico and the new game dataset reveals a stark and consistent finding: detectors that perform reasonably on Rico (up to ~56% F1) collapse to single-digit F1 scores on games, and the reverse transfer direction fails just as badly, indicating games are not merely "harder" but genuinely out-of-distribution for these models. A detailed root-cause analysis, a notable contribution beyond the benchmark itself, traces this gap to two concrete, quantified factors: game GUIs pack roughly 7x more interactive elements per screen on average than regular apps, and game widgets exhibit dramatically higher visual/stylistic heterogeneity (illustrated starkly by nine visually unrelated "return" button designs across nine games), both of which existing anchor-box-based detectors are not designed to accommodate, motivating calls for new, game-specific detection architectures and larger, more diverse benchmarks.
