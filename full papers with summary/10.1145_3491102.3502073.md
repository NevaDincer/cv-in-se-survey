# Towards Complete Icon Labeling in Mobile Applications

- **Year:** 2022
- **Venue/Source:** CHI Conference on Human Factors in Computing Systems (CHI '22)
- **DOI:** 10.1145/3491102.3502073

## Metadata

- **se_area:** development (accessibility/UI-metadata infrastructure that supports downstream accessibility repair, UI design search, and conversational agents)
- **se_task:** complete-coverage icon labeling in mobile app screenshots: recognizing the semantic type of every icon on a screen (both frequent "common" icon types and rare "long-tail" types), plus extracting supporting contextual semantics (nearby text association and secondary "modifier" symbols within an icon, e.g., a Disabled slash or Notification Dot), operating purely on screenshot pixels without relying on the accessibility view hierarchy or app source code
- **cv_technique:** an object detection model (based on prior work, Zhang et al.) for UI element/icon localization; ResNet-50 (ImageNet-pretrained, fine-tuned) image classification for the 98 "common" icon types; a prototypical-network few-shot learning model (episode-based k-way m-shot training) for the 331 "long-tail" icon types, benchmarked against kNN and Relation Network baselines; heuristic pixel/layout-based nearby-text grouping using detected text/icon/container element types and spatial relationships; OCR for text-modifier recognition; an SSD (Single Shot MultiBox Detector, MobileNetV1 backbone + Feature Pyramid Network) object-detection model and a MobileNetV1 image-classification model (compared head-to-head) for recognizing the remaining six non-text modifier symbol types; crowdsourcing used only as a final fallback when all automated steps fail
- **platform:** mobile (iOS)
- **rationale:** robustness (motivated explicitly by the unreliability of the accessibility view hierarchy as an icon-recognition context source. Cited findings show hierarchies mismatch screenshots in over half of screens and that 59% of screens contain UI elements missing from the accessibility hierarchy, so the system is designed to work from pixels alone, generalizing across apps and even to scenarios like shared UI design images that never had a hierarchy at all) and context-driven (nearby text and modifier symbols are explicitly incorporated because pixel-only icon classification alone is often ambiguous or even reverses an icon's meaning, e.g., a Disabled modifier on a Camera icon)
- **artifact_type:** localized (individual icon-level detection, classification, and semantic augmentation within a full screenshot, rather than whole-screen or purely full-interface analysis)
- **eval_method:** constructs and analyzes a new large-scale annotated dataset (327,879 icons from 66,138 screens across 3,904 iPhone apps, derived from the AMP dataset, annotated via crowdsourcing plus automated pixel+label-based clustering to discover 331 long-tail types beyond 90 pre-defined types, verified by a QA team); evaluates each pipeline module individually: common icon classification (96.3% test accuracy, 92.4% macro precision, 89.5% macro recall), long-tail few-shot classification (78.6% accuracy, beating kNN [68.5%] and Relation Network [74.6%] baselines), nearby-text grouping heuristics (92.8% precision, 98.7% recall, 95.3% accuracy against 2,535 manually-labeled icon-text groupings from 500 screens), and modifier identification (comparing an image-classification model [84.4% accuracy] against an object-detection model [87.4% accuracy] on 463 manually-verified real icons), then evaluates the complete end-to-end pipeline on "imperfect" object-detection output (93.8% of icons successfully detected; 90.7% overall classification accuracy on matched detections) rather than only on ground-truth-cropped icons; finally conducts a human validation study with 23 recruited workers (uninvolved in prior annotation) rating the usefulness/relevance of annotation labels, predicted labels, nearby text, and modifiers for 2,064 icon examples on Likert-type usefulness scales, reporting Cohen's kappa inter-rater agreement for each label type.
- **challenges:** the long-tail few-shot classifier struggles specifically when the training and testing distributions differ for the same icon type (e.g., the same real-world object, a battery or a ruler, photographed or drawn from a different angle or abstraction level), which the authors explicitly identify via failure-case analysis; larger, more colorful icons are frequently misdetected by the upstream object-detection model as "Picture" rather than "Icon," an acknowledged detection-stage bottleneck the authors suggest could be mitigated with heuristic post-processing; end-to-end pipeline accuracy (90.7%) is measurably lower than each isolated module's accuracy because of error propagation from imperfect object-detection bounding boxes, and long-tail icon precision specifically drops to 60% in the end-to-end setting due to confidence-threshold routing sending low-confidence common icons into the long-tail path; the object-detection-based modifier model performs worst specifically on the Disabled modifier (which, unlike other modifiers, covers nearly the entire icon, a shape object detectors handle poorly) while the classification-based modifier model performs worst on the small, weak-signal Notification Dot; the human validation study found only fair inter-rater agreement (Cohen's κ = 0.28) for the underlying ground-truth annotation labels themselves, underscoring that even human-assigned icon labels carry real subjectivity, and modifier-symbol usefulness ratings were notably low (only 38% considered relevant), with the authors tracing many "not useful" ratings specifically to systematic Disabled-modifier misdetections; the validation study deliberately excluded people with disabilities (studying only non-disabled raters), leaving actual screen-reader-user validation as explicit future work despite accessibility being a primary motivating use case.

## Summary

This paper tackles a specific, well-documented accessibility gap in mobile apps: icons are the second most common UI element type after text, yet are frequently left unlabeled or mislabeled, and more than half of standalone icons have no accompanying text to compensate. Prior icon-recognition systems classified only a limited, fixed set of the most frequent ("common") icon types and failed outright on anything outside that set, while approaches that lean on contextual metadata (the Android/iOS accessibility view hierarchy, source code) are undermined by the fact that this hierarchy frequently doesn't match what's actually rendered on screen. The authors first construct and deeply analyze a new dataset of 327,879 annotated icons from 66,138 iPhone app screens, using crowdsourced annotation for a curated set of 90 predefined icon types plus a novel pixel-and-label-based iterative clustering procedure (crowd workers describe unrecognized icons in free text, then icon-pixel k-means clustering and label-keyword merging jointly discover new categories) to surface 331 additional "long-tail" icon types. This reveals that while 98 common types (after merging in a few especially frequent long-tail clusters) cover 92.8% of all icons, the remaining long-tail icons, despite their individual rarity, often expose core app functionality specific to a given app category (e.g., delivery-truck icons in shipping apps, transit icons in navigation apps) and thus cannot simply be ignored. Building on this analysis, the paper's core system contribution is a fully pixel-based, hierarchy-independent pipeline: an object detector locates and crops icons from a screenshot; a fine-tuned ResNet-50 classifier assigns common icon types (96.3% accuracy); icons it flags as unrecognized are routed to a prototypical-network few-shot classifier trained specifically to generalize from as few as tens of examples per long-tail class (78.6% accuracy, clearly outperforming kNN and Relation Network baselines); layout heuristics associate each icon with any semantically relevant nearby text; and a dedicated object-detection model identifies secondary "modifier" symbols (like a Disabled slash or Notification Dot) that can materially change or refine an icon's meaning, trained on a carefully constructed synthetic dataset since real modifier examples are extremely rare. A particularly notable design and evaluation choice is that the paper doesn't stop at per-module accuracy numbers: it explicitly re-evaluates the entire pipeline end-to-end on realistic, imperfect upstream object-detection output (rather than only on cleanly cropped ground-truth icons) to honestly quantify error propagation, and it closes with a 23-participant human validation study directly measuring whether generated labels, nearby text, and modifier annotations are actually perceived as useful, finding annotation and predicted labels rated useful over 80% of the time, but flagging modifier-symbol usefulness as a clear weak point (38%) traceable to specific, diagnosed model failure modes.
