# Object Detection for Graphical User Interface: Old Fashioned or Deep Learning or a Combination?

- **Year:** 2020
- **Venue/Source:** ESEC/FSE '20 (28th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering)
- **DOI:** 10.1145/3368089.3409691

## Metadata

- **se_area:** development; testing; maintenance
- **se_task:** GUI element (widget and text) detection from GUI screenshots, supporting downstream SE tasks such as GUI code generation, GUI automation/testing, and GUI search
- **cv_technique:** Canny edge detection; contour tracing (Suzuki's algorithm); template matching; flood-fill algorithm; connected-component labeling; gradient-map-based binarization; Faster R-CNN (two-stage, anchor-box); YOLOv3 (one-stage, anchor-box); CenterNet (one-stage, anchor-free); ResNet50 image classifier; Tesseract OCR; EAST scene text detector
- **platform:** mobile
- **rationale:** context-driven (GUI elements have unique visual characteristics (large in-class variance, high cross-class similarity, packed/close-by layouts, mix of heterogeneous widgets/images/text) that generic CV object-detection methods designed for physical-world objects and document OCR are not tuned for, motivating a GUI-specific top-down coarse-to-fine detection design); robustness (the proposed old-fashioned pipeline is explicitly designed to be robust to noisy backgrounds and close-by/packed elements where existing bottom-up edge/contour methods and generic deep models fail)
- **artifact_type:** full-interface (CV techniques operate over entire GUI screenshots to localize and classify all constituent elements/regions within them)
- **eval_method:** Large-scale empirical study on 50,524 GUI screenshots (923,404 GUI elements) from 8,018 Android apps drawn from the Rico dataset, split 40K/5K/5K train/validation/test with 5-fold cross-validation; compares 2 old-fashioned baselines (REMAUI, Xianyu) and 3 deep learning object detectors (Faster R-CNN, YOLOv3, CenterNet) plus 2 text-detection baselines (Tesseract OCR, EAST scene text detector); metrics are precision, recall and F1 based on Intersection-over-Union (IoU) matching of predicted vs. ground-truth bounding boxes, evaluated primarily at a strict IoU>0.9 threshold (also across a range of IoU thresholds); additional experiments test sensitivity to anchor-box settings and training-data size (2K/10K/40K); the authors' own new method is evaluated on a 25,000-image subset and reported for non-text, text, and combined element detection, plus downstream region-classification accuracy and end-to-end object detection (localization + classification) performance, all benchmarked against the same baselines.
- **challenges:** The authors explicitly report that (1) generic deep learning detectors (Faster R-CNN, YOLOv3, CenterNet) cannot achieve a good balance between GUI-element coverage (recall) and bounding-box accuracy at high IoU thresholds, since statistical regression on high-layer CNN feature maps is imprecise for the fine-grained accuracy GUI detection demands; (2) old-fashioned bottom-up edge/contour methods (REMAUI, Xianyu) perform poorly on packed, close-by, or complex-background GUIs, causing over-/under-segmentation; (3) neither OCR (Tesseract) nor generic object detectors reliably detect GUI text, since GUI text behaves like scene text rather than document text; (4) deep learning models require substantial training data and their performance is sensitive to model architecture; (5) even their own proposed method fails in specific cases (visually identical regions that map to different widget types, e.g., text label vs. borderless text button; inconsistent detection in repetitive/dense UI regions; and ambiguity between a standalone text label and text embedded in a widget), which the authors leave as future work.

## Summary

This paper presents the first large-scale empirical study of GUI element detection, framing it as a domain-specific computer-vision object-detection problem central to many software engineering tasks (GUI code generation, GUI testing, GUI search). The authors identify four characteristics that distinguish GUIs from natural images (large in-class visual variance, high cross-class similarity, densely packed/close-by elements, and a mix of heterogeneous widgets, images, and text) and show empirically, across 50,524 Android GUI screenshots from the Rico dataset, that neither classic old-fashioned CV pipelines (REMAUI, Xianyu, relying on Canny edge/contour aggregation) nor generic deep object detectors (Faster R-CNN, YOLOv3, CenterNet) satisfy the strict bounding-box accuracy GUI detection demands, and that OCR tools (Tesseract) are a poor fit for GUI text compared to a scene-text detector (EAST). Building on these findings, the authors design a novel hybrid method: a GUI-specific "top-down coarse-to-fine" old-fashioned pipeline (flood-fill block detection, gradient-map binarization, connected-component labeling) for non-text region proposal, combined with a fine-tuned ResNet50 classifier for region classification and the pretrained EAST model for text detection. The most distinctive detail is this deliberate departure from the field's default assumption that "more deep learning is better." Instead of a purely learned pipeline, the authors show that a carefully engineered non-learned detector, informed by GUI-specific structural regularities, can outperform state-of-the-art deep detectors by up to 47.7% in F1 on a 25,000-image evaluation.
