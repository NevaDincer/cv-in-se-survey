# Practical Non-Intrusive GUI Exploration Testing with Visual-based Robotic Arms

- **Year:** 2024
- **Venue/Source:** ICSE 2024 (46th IEEE/ACM International Conference on Software Engineering), Lisbon, Portugal
- **DOI:** 10.1145/3597503.3639161

## Metadata

- **se_area:** Testing
- **se_task:** Non-intrusive automated GUI exploration testing of mobile apps and embedded/ubiquitous operating systems using a physical robotic arm, for code-coverage-driven exploration, crash-bug detection, and, as a novel capability, detection of hardware/software compatibility bugs (e.g., widgets occluded by irregular screen cutouts) that intrusive frameworks cannot perceive from a real end-user perspective
- **cv_technique:** Classical computer vision pipeline for GUI screen and widget recognition from physically-taken robotic-arm camera photos: edge detection plus flood-fill for approximate screen localization, camera calibration (chessboard-based) and geometric correction for image distortion/deflection, Canny edge detection plus morphological closing plus contour extraction with nested/oversized-candidate filtering for non-text widget detection, a two-granularity OCR pipeline (rough extraction plus confidence-thresholded refined extraction) for text widgets, and SIFT-based image similarity comparison between two devices' GUI responses to automatically detect compatibility bugs
- **platform:** Mobile (Android apps) and embedded/industrial ubiquitous operating systems (demonstrated on XiUOS, an IoT-oriented embedded OS using the LVGL graphics library)
- **rationale:** Robustness (a purely non-intrusive, vision-based approach is required to test devices/platforms, embedded systems, customized OSes, that do not expose intrusive testing interfaces like Appium, and to detect real-world compatibility bugs, such as buttons overlapped by camera/sensor cutouts, that are invisible to code-level/interface-invoking intrusive frameworks) and ease of use (a general, platform-agnostic testing approach usable across heterogeneous hardware without per-device instrumentation)
- **artifact_type:** Full-interface (recognizes the entire device GUI screen from a physical photo) combined with localized widget-level detection for individual GUI elements, driving embodied natural-input interaction (a physical 4-DOF robotic arm performing real touch/slide/click operations, i.e., natural input rather than software-simulated events)
- **eval_method:** Empirical evaluation on 20 real-world mobile apps comparing RoboTest (and ablation variants RoboTest-Random and RoboTest-Edge, differing only in exploration strategy) against Monkey (intrusive) and VTest (state-of-the-art non-intrusive robotic-arm baseline) across three RQs: code coverage (line/branch coverage over 3600-second and 200-step runs, each repeated 10 times), bug detection capability (crash bugs plus a novel compatibility-bug count, with all detected bugs manually re-confirmed by testing experts), and time overhead (robotic-arm movement distance as a proxy for wall-clock overhead); plus a qualitative case study on the XiUOS embedded OS (2 LVGL apps, 50-100 manually-counted test steps, since XiUOS lacks code-coverage instrumentation) measuring GUI widget recognition success rate (98% and 96%), operation generation success rate, and per-step timing breakdown
- **challenges:** Author-identified/discussed limitations: robotic-arm-based non-intrusive testing inherently carries movement-time overhead compared to intrusive approaches (addressed via the proposed PoP-guided exploration strategy, though RoboTest is still slower per-operation than software-only tools like Monkey); computer-vision GUI widget/screen recognition on low-resolution, lighting-affected physical camera photos is fundamentally harder than on high-resolution app screenshots used by prior visual GUI-understanding work, requiring custom distortion/deflection correction and a specialized two-stage OCR pipeline; a small fraction of widgets are still misrecognized (e.g., ~2-4% miss rate in the XiUOS case study) or generate non-effective operations (e.g., due to non-interactive images/text or domain-specific unclickable industrial data displays); compatibility-bug detection requires a reference device with matching screen size for valid GUI comparison, and threshold/hyperparameter choices (e.g., SIFT similarity threshold) were tuned via small-scale pilot studies rather than exhaustive search, posing a threat to generalizability.

## Summary

This paper addresses two persistent limitations of automated GUI testing: intrusive frameworks (e.g., Appium-based tools) cannot run on embedded or customized operating systems that lack the required OS-level interfaces, and even when they can run, they cannot detect compatibility bugs that only manifest from a genuine end-user perspective, such as a button rendered underneath a phone's camera cutout, which is perfectly clickable via its XML identifier but physically inaccessible to a real user. The authors propose RoboTest, a non-intrusive GUI exploration testing framework that pairs computer-vision-based GUI understanding with a physical 4-degree-of-freedom robotic arm. Its CV pipeline first recognizes the device's GUI screen within a camera photo (correcting for lens distortion and device-placement deflection via chessboard camera calibration), then extracts widgets using a combination of Canny edge detection, morphological closing, contour-based candidate filtering, and a two-pass OCR strategy tuned for the lower resolution and lighting variability of physically-captured images (as opposed to prior work that assumes clean, high-resolution app screenshots). A novel "Principle of Proximity"-guided exploration strategy reduces costly robotic-arm travel distance by preferentially targeting widgets spatially near the previous interaction, and a SIFT-based GUI-comparison mechanism between a device with an irregular screen and a same-size reference device automatically flags compatibility bugs from differing responses to duplicated operations. Evaluated on 20 real-world apps, RoboTest-Center outperforms the prior state-of-the-art non-intrusive baseline VTest by 13.9-33.0% in code coverage and 21-28.5% in movement-distance overhead, while uniquely detecting 12-13 real compatibility bugs (manually confirmed) that neither Monkey nor VTest could find at all. A notable detail is the case study applying RoboTest, unmodified in approach, to XiUOS, a real industrial embedded IoT operating system with no code-instrumentation support, achieving 96-98% widget recognition accuracy and uncovering both a memory-leak crash bug and a genuine hardware-software compatibility bug, demonstrating the approach's generalizability well beyond conventional mobile app testing.
