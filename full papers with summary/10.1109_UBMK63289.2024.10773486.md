# Image Processing-Enabled Validation for Robotic Test Automation: A Case Study on POS Devices

- **Year:** 2024
- **Venue/Source:** IEEE UBMK 2024, 9th International Conference on Computer Science and Engineering
- **DOI:** 10.1109/UBMK63289.2024.10773486

## Metadata

- **se_task:** Robotic test automation and screen-output validation for POS (Point of Sale) devices
- **cv_technique:** Grayscale preprocessing; Optical Character Recognition via EasyOCR for reading on-screen text; threshold-based fuzzy string matching between OCR output and expected result

## Summary

This paper presents Roboclick, a robotic arm-based test automation system developed by Virgosol (under a Turkish KOSGEB R&D grant) for physically testing POS payment terminals. The system combines a RAMPS 1.6/Arduino Mega 2560-controlled robot, with X/Y stepper motors for a pressing head, a Z-axis motor for key presses, and a fourth motor for card insertion/removal, with a camera pointed at the device screen. The camera feed is processed with a Python computer-vision pipeline: frames are converted to grayscale and passed to the EasyOCR engine to extract on-screen text, which is then compared against an expected result string using a configurable similarity threshold to decide pass/fail. Test scenarios are authored in the open-source, BDD-based Gauge framework, allowing natural-language scenario definitions. The authors report an empirical study across 100 POS devices, finding Roboclick cuts average per-scenario test time from 35s to 18s (48.6% reduction) and cuts the human-tester error rate from 5% to 1% (80% reduction), while also covering complex end-to-end multi-platform scenarios that traditional software-only automation tools cannot reach. The paper frames this as enabling full DevOps-style continuous testing/integration/deployment for physical payment hardware, a domain where prior automation was largely manual.
