## Summary

CSEFuzz combines symbolic execution and fuzz testing to address a well-known problem: fuzz testing's effectiveness depends heavily on the quality of its initial seed corpus. The approach first runs symbolic execution through Symbolic PathFinder to generate a large set of candidate test cases with high code coverage, then instruments and dynamically executes the program under test to record each candidate's coverage profile. From these profiles it derives "test-case templates," sets of covered program elements, and applies a greedy set-cover-style algorithm to select a minimal subset of templates that jointly cover as many program elements as possible, under one of three white-box coverage criteria: decision, condition, or path coverage. One representative test case per selected template becomes an initial seed for the Kelinci/AFL-based fuzzing engine, which mutates seeds and watches for new paths and crashes. Evaluated on 11 open-source Java programs against Kelinci's own afl-cmin seed-selection command, CSEFuzz cuts seed-selection and validation time by 94 to 99.5%, while covering 5 to 32 more paths and catching 12 to 16 more defects than afl-cmin, because it retains and validates crash-triggering candidates that afl-cmin's own validation stage would discard as invalid. A worked example shows a defect reachable only via the exact input x==100276, essentially undiscoverable by random mutation but captured directly by symbolic execution and preserved through CSEFuzz's selection pipeline. The paper has no visual or computer-vision component; it is a pure program-analysis and fuzz-testing contribution.
