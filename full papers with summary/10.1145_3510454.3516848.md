# NaviDroid: A Tool for Guiding Manual Android Testing via Hint Moves

> **SCOPE WARNING**: This paper likely does **not** belong in the CV-in-SE survey. NaviDroid's pipeline is built entirely on static analysis (ICC/intent matching against AndroidManifest.xml) and dynamic GUI exploration (UI hierarchy trees, random-action app explorers), combined with a Floyd-Warshall/DP-based shortest-path planner. Guidance is rendered via an Android floating window that highlights a UI element's on-screen coordinates. This is a UI-hierarchy/coordinate-based overlay, not image-based recognition. No CV technique (OCR, image matching, object detection, embeddings, VLM, etc.) appears anywhere in the pipeline. Recommend excluding unless the survey's CV definition is broadened to cover UI-hierarchy-based visual augmentation.

## Summary

NaviDroid is a companion tool paper that supports manual/human Android GUI testing by proactively suggesting the next best UI action, styled after "hint moves" in Candy Crush. It first builds an enriched state transition graph (STG_action) by combining static analysis (matching Intent parameters against AndroidManifest.xml to detect inter-component communication transitions) with dynamic exploration (an app-explorer performing random clicks/scrolls/text-input to capture states and trigger actions not visible statically, e.g., dynamically rendered menus). A context-aware state-merging step collapses near-duplicate states first by identical UI hierarchy, then by checking whether neighboring (n-1, n+1) states are also similar. Given this STG, NaviDroid formulates path planning as a dynamic-programming problem (four-tuple ⟨G, d, V, DP⟩) using a Floyd-Warshall-derived shortest-distance matrix and a visited-state bitmask to compute a low-repetition path covering all states, effectively a TSP-style formulation. During live testing, the tool runs an ADB-based backend service that tracks the tester's current state, looks up the next unexplored state on the planned path, and overlays a floating window (WindowManager/AddView) highlighting the triggering component (click, "back", or "long-press test widget" actions). If the tester deviates from the plan, the path is dynamically re-planned from the new current state after 5 seconds of inactivity. Automated evaluation on 85 F-Droid apps showed 81% median state coverage, beating five baselines, with 20–42% fewer exploration steps than DFS/BFS/Random planners. A user study with 32 crowdtesting participants found the NaviDroid-assisted group covered 62% more states, 61% more activities, found 146% more bugs, and took 33% less time than an unassisted control group; a follow-up SUS survey of 30 professionals rated average task helpfulness at 4.51/5. Despite the polished evaluation, the technique itself is UI-hierarchy- and coordinate-driven rather than vision-based.
