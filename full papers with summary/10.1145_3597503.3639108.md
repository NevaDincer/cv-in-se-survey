# Comprehensive Semantic Repair of Obsolete GUI Test Scripts for Mobile Applications

- **Year:** 2024
- **Venue/Source:** ICSE '24 (46th International Conference on Software Engineering)
- **DOI:** 10.1145/3597503.3639108

## Metadata

- **se_area:** Maintenance (regression testing script maintenance following GUI evolution)
- **se_task:** Automated repair of obsolete/broken GUI test scripts for Android apps
- **cv_technique:** None directly used by COSER's core algorithm. Uses Sentence-BERT (NLP sentence embedding model) for external semantic (text) similarity; UniXcoder (pretrained code model, fine-tuned on BigCloneBench) for internal semantic (code snippet) similarity via clone detection. Perceptual grouping of GUI elements borrows a container-recognition heuristic inspired by prior CV-based UI grouping work, but this is not itself a vision model applied in COSER.
- **platform:** Mobile (Android)
- **rationale:** Robustness (handling major/substantial GUI changes that defeat prior visual-similarity approaches); context-driven (leveraging source code as ground truth for element intent, going beyond surface appearance)
- **artifact_type:** Localized (individual GUI elements and their matches) combined with temporal/structural (transition graph capturing navigation paths between screens)
- **eval_method:** Empirical evaluation on 20 open-source Android apps (262 test scripts, 3485 test actions); comparison against METER, GUIDER, AppTestMigrator, and a NULL baseline using #K_c (correctly repaired scripts) and #A_c (correctly repaired actions) metrics, confirmed by 5 postgraduate reviewers reaching consensus; ablation study isolating external vs. internal semantics; sensitivity analysis on similarity threshold θ; wall-clock efficiency comparison.
- **challenges:** Requires access to app source code (assumes vendor-side testing); static analysis cannot capture GUI elements created dynamically at runtime; fails when elements have empty external properties and no internal semantic code path (auto-generated elements); imprecision inherited from underlying models (Sentence-BERT/UniXcoder mismatches); cannot repair actions where functionality was genuinely added/removed with no analog in either version; per-action repair cost dominated by deep-learning-based matching (mitigated with caching).

## Scope note

This paper's relationship to CV may be weak/indirect. COSER's own matching mechanism is essentially NLP-based (text similarity via Sentence-BERT) and uses code-clone detection (UniXcoder); it does not use an image/CV model in the classical sense. It only mentions a visual heuristic borrowed from a prior CV-based work ([35] Xie et al., ESEC/FSE'22, container recognition) when grouping GUI elements into "perceptual groups"; this heuristic isn't actually implemented in COSER, it's only referenced. The compared tools METER and GUIDER do use visual similarity, but they aren't the subject of this paper. Whether it should be included in the survey's scope needs to be reviewed.

## Summary

COSER (COmprehensive SEmantic Repair) is a technique for automatically repairing GUI test scripts that break when Android apps evolve between versions. Unlike prior approaches (METER, GUIDER) that rely solely on "external semantics": visual/structural properties of GUI widgets obtainable at runtime. COSER additionally extracts "internal semantics": code snippets from the app's source that define a widget's actual behavior, based on three common developer binding patterns (direct XML binding, callback binding, and context-sensitive binding such as switch-case handlers). A Transition Analyzer statically builds a graph of inter- and intra-activity navigation (e.g., via Intents, menus, navigation drawers) which is refined dynamically during repair. The Script Repairer matches old GUI elements to new ones first via external semantics (Sentence-BERT cosine similarity against a 0.7 threshold) and falls back to internal semantics (UniXcoder-based code clone similarity) when the match is unconvincing, additionally supporting "Action Adaptation": reducing test actions when functionality is removed and amplifying them via graph-based pathfinding when interaction sequences become more complex. Evaluated on 20 open-source Android apps, COSER correctly repaired 90% of test actions versus 46–67% for prior tools (METER, AppTestMigrator, GUIDER), while also being the most efficient (555.5 minutes total vs. 560–680 for competitors). A notable detail: an ablation study shows external-only and internal-only semantics each independently repair different, largely non-overlapping subsets of actions, with their combination yielding a substantial synergistic gain of 405 additional test actions repaired beyond what either alone could achieve.
