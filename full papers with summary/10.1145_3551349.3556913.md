# Automatically Detecting Visual Bugs in HTML5 Canvas Games

- **Year:** 2022
- **Venue/Source:** 37th IEEE/ACM International Conference on Automated Software Engineering (ASE '22), October 10–14, 2022, Rochester, MI, USA
- **DOI:** 10.1145/3551349.3556913

## Metadata

- **se_area:** testing
- **se_task:** visual bug detection (automated visual/GUI regression testing) in HTML5 <canvas> games
- **cv_technique:** Image similarity metrics for automated visual comparison: percentage overlap (pixel-exact match), mean squared error (MSE), structural similarity index (SSIM); embedding similarity (ESIM) using a pre-trained ResNet-50 (ImageNet, torchvision/PyTorch, inference-only, final convolutional layer embeddings compared via cosine similarity); plus an image preprocessing/masking pipeline (asset transformation: crop/scale/tile/rotate, pasting, mask generation and application, cropping) used to decompose full-canvas screenshots into per-object images for comparison against auto-generated oracle assets. No new model is trained.
- **platform:** web (specifically HTML5 <canvas>-based web games)
- **rationale:** Context-driven and ease-of-use: standard DOM-based web test automation cannot see <canvas> content because canvas graphics are rendered as a bitmap and not represented in the DOM, and the industry-standard alternative (whole-screenshot snapshot testing) is defeated by the canvas's dynamic/randomized rendering, producing many false positives and requiring laborious manual curation/verification of oracle screenshots. The authors' CV-based approach removes the need for manually curated oracle images by automatically generating oracle assets from the game's internal object representation (COR) and comparing individual decomposed object images, and it reuses an off-the-shelf pre-trained vision model (ResNet-50) in inference mode only, requiring "only very basic applied machine learning knowledge" and no data labeling/training/fine-tuning, prioritizing robustness to in-game randomness/dynamism and ease of adoption over building a custom model.
- **artifact_type:** localized (per-object/region visual comparison rather than whole-screen); decomposes full-canvas screenshots into individual object images (using the canvas objects representation, COR) and compares each against its corresponding auto-generated oracle asset image; not temporal (single-frame snapshots per test, not video) and not natural-language input.
- **eval_method:** A custom test <canvas> game ("catching game") was built with the PixiJS framework and a free asset pack, run at 720p/60fps with random projectile-catching gameplay and various animation types (sprite, rotation, background tiling). An automated test case (scripted browser session with automated clicks/mouse movement) took 10 snapshots per run. 24 synthetic visual bugs (6 each across 4 taxonomy-defined types: state, appearance, layout, rendering, from Macklon et al.'s canvas bug taxonomy) were injected, and confirmed as representative of real industrial canvas bugs by an industrial partner (Prodigy Education). Baseline: traditional/industry-standard snapshot testing (whole-screenshot comparison, as used by tools like Percy) using PCT/MSE/SSIM. Thresholds for pass/fail were empirically selected per metric from 10 non-buggy repetitions (to yield zero false positives). Metrics: accuracy (TP/(TP+FN)) per bug and overall, plus Mann-Whitney U test and Cliff's delta for statistical significance/effect size of similarity-score distributions between buggy/non-buggy cases, and wall-clock execution duration comparison. Results: the proposed approach achieved 100% accuracy on all 24 injected bugs with MSE, SSIM, or ESIM (75% with PCT), versus 44.6% (PCT), 33.3% (MSE), 44.6% (SSIM) for the snapshot-testing baseline; the proposed approach took ~3 additional seconds per snapshot due to preprocessing overhead.
- **challenges:** Authors explicitly report: (1) evaluated on only a single, custom-built canvas game (external validity); thresholds and performance may not generalize to other canvas games, especially those with less clear similarity thresholds, requiring per-game manual threshold tuning; (2) only tested on a 2D game built with PixiJS; unclear how the approach performs on other 2D frameworks, 3D canvas games, or non-canvas games; (3) the approach depends on the availability of a canvas objects representation (COR) and on the game using discrete assets for rendering; it would not work for games lacking a COR or not using assets; (4) certain graphics types (e.g., skeletal animations, particle effects) were not present in the test game and are not accounted for by the current implementation; (5) handling of partial transparency in masks required an empirical workaround (making it fully transparent), which may miss bugs affecting partially transparent regions; (6) embedding similarity (ESIM) results were sensitive to the chosen background fill color used in masking, suggesting ESIM may be less appropriate given the extensive preprocessing; (7) injected bugs, while validated with an industrial partner as visually representative, have different root causes than naturally occurring real-world bugs (construct validity); (8) the approach assumes no bugs originate in the COR or assets themselves (internal validity, unverified assumption).

## Summary

This paper proposes an automated, computer-vision-based approach for detecting visual bugs in HTML5 <canvas> games, addressing the gap that DOM-based web test automation cannot inspect canvas content (which is rendered purely as a bitmap) and that traditional whole-screenshot snapshot testing is undermined by the dynamic, randomized nature of game rendering. The core idea is to leverage a canvas objects representation (COR), an internal per-object model that canvas frameworks like PixiJS maintain (positions, sizes, rotations, assets), to automatically decompose a screenshot into individual object images and simultaneously auto-generate a corresponding "oracle" image for each object directly from its source asset and transformation parameters, eliminating the need to manually curate and maintain oracle screenshots. Each object/oracle pair is then compared using one of four similarity metrics (percentage overlap, MSE, SSIM, and an embedding similarity based on a pre-trained, non-fine-tuned ResNet-50) with an empirically chosen threshold. Evaluated on a custom PixiJS test game against 24 synthetic bugs spanning four taxonomy-defined bug types, the approach reached 100% detection accuracy with MSE, SSIM, or ESIM, versus only 44.6% for standard snapshot testing, at a modest extra runtime cost (~3s per snapshot). A notable detail is that the injected bugs were validated for realism with an industrial partner (Prodigy Education), and the full testbed and dataset were open-sourced for reproducibility.
