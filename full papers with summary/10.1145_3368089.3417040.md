# Towards Learning Visual Semantics

- **Year:** 2020
- **Venue/Source:** ESEC/FSE '20 (28th ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering)
- **DOI:** 10.1145/3368089.3417040

## Metadata

- **se_area:** Maintenance / program comprehension (automated software understanding to support downstream maintenance and search tasks; closest mapping among {requirements, design, development, testing, maintenance})
- **se_task:** Automatically deriving high-level functional/semantic descriptions of software from its visual (graphical) outputs, to support tasks such as automated code reuse, fault diagnosis, and software search
- **cv_technique:** Convolutional Neural Networks (CNNs) for image understanding, recognizing visual objects, their attributes (e.g., color), and spatial relationships within a single visual output; dedicated text-block detectors for on-screen text; visual relation extraction techniques (visual dependency representations) to infer relationships between visual elements; video understanding (differencing/temporal analysis across sequential visual outputs) when multiple timestamped outputs are available
- **platform:** General (visual outputs from Java, Python, PHP, and C++ programs; covers both GUI elements and non-GUI visual outputs like charts/geometric shapes)
- **rationale:** Context-driven (visual outputs are treated as evidence of actual runtime behavior/functional semantics, not just static appearance); ease of use / automation (aims to replace costly, error-prone manual code reading and coarse specification-mining techniques)
- **artifact_type:** Full-interface (whole visual output as an image) plus temporal (sequences of visual outputs treated as video when available)
- **eval_method:** Preliminary prototype evaluation on 16 real-world subject programs (from GitHub, VTK, F-Droid, Matplotlib) spanning multiple languages/domains; precision and recall of generated semantics descriptions computed against manually-derived ground-truth functionality descriptions (true positive if description captures demonstrated functionality); efficiency measured via model training/loading time
- **challenges:** Fundamentally limited to "visual software" whose visual outputs meaningfully demonstrate behavior. Not all software behavior is visually manifested; lack of existing labeled datasets of software-produced visual outputs required a manual snowballing dataset-construction process; imprecision stems from underlying IVU (image/video understanding) and NLG (natural language generation) accuracy; the prototype only recognizes object labels from individual images (video/temporal component not fully realized in the early prototype); two of 16 subjects failed due to insufficient CNN training data for their specific visual object types.

## Summary

This paper introduces Visual Semantics Learning (VSL), a novel vision for automatically understanding software's high-level functional behavior by analyzing its graphical outputs rather than its source code. The authors define "visual software" as programs that produce visual (not necessarily GUI-only) outputs meaningfully demonstrating behavior, and propose a three-stage pipeline: (1) Visual Output Generation (VOG), which automatically exercises visual-output-triggering APIs using control-flow analysis and constraint solving when existing test inputs are insufficient; (2) Image/Video Understanding (IVU), which applies CNN-based object/attribute/relationship recognition to each visual output as an image, and additionally treats sequences of outputs as video to capture temporal changes and interactions; and (3) Natural Language Generation (NLG), which composes short natural-language "semantics descriptions" from the recognized visual element labels using a hybrid template-based and statistically-learned sentence generation approach. A main practical contribution is a snowballing strategy to bootstrap training data for non-GUI visual objects (e.g., geometric shapes, charts) where no existing datasets exist, by iteratively training detectors, applying them to new samples, and manually calibrating results. The authors implemented a simplified open-source prototype and evaluated it on 16 diverse real-world applications (chart generators, QR code generators, dialers, geometric-shape drawers), achieving 96% precision and perfect recall, with failures attributed specifically to insufficient CNN training for two subjects. The paper positions VSL as complementary to, and broader in scope than, prior GUI-focused work like ReDraw, since it targets automated machine understanding (not code generation) and is not limited to GUI-only visual elements.
