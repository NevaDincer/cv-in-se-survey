# VINS: Visual Search for Mobile User Interface Design

- **Year:** 2021
- **Venue/Source:** CHI 2021 (ACM CHI Conference on Human Factors in Computing Systems), Yokohama, Japan
- **DOI:** 10.1145/3411764.3445762

## Metadata

- **se_area:** Design (UI/UX design support and inspiration-seeking during interface design)
- **se_task:** Visual (image-based) search/retrieval of similar mobile UI design examples, given a query UI screen (wireframe or high-fidelity), to support designer inspiration, comparison of alternatives, and UI layout auto-completion, replacing purely text/keyword-based design search
- **cv_technique:** Object detection (Single Shot MultiBox Detector, SSD, with MobileNets backbone) to localize/classify 11-12 UI component classes and produce a segmented layout; a custom attention-aware convolutional autoencoder (with a novel "Box Attention" spatial map conditioning mechanism adapted from box-attention object-relationship literature) for structural image embedding, combined with a separate label encoder-decoder capturing the multi-hot class-label content vector; final joint embedding via concatenation, similarity computed via Euclidean distance for ranked retrieval
- **platform:** Mobile (Android and iOS UI designs); also includes abstract wireframes as an input modality
- **rationale:** Context-driven (formative interviews with 24 UI designers empirically establishing that keyword-only search fails to capture structural/functional design similarity) and ease of use (supports designers across different design stages, from rough wireframes to high-fidelity mockups, and enables auto-completion of partial layouts)
- **artifact_type:** Full-interface (analyzes and retrieves whole UI screen layouts as segmented structural representations, rather than isolated components)
- **eval_method:** Formative semi-structured interviews with 24 professional UI/UX designers (thematic coding) to motivate design requirements; construction and crowdsourced annotation (via RectLabel, with IoU-based quality control) of a new large-scale VINS dataset (4,800 images: 257 wireframes + 4,543 high-fidelity screens across Android/iOS) with Pascal-VOC-format bounding boxes; quantitative detection evaluation (mean Average Precision, AUC) benchmarked against Rico's existing view hierarchies, showing large accuracy gains; quantitative retrieval evaluation via precision@K (K=1 to 10) against a baseline autoencoder, ablating the number of attention maps; qualitative retrieval evaluation via visualized query examples; expert evaluation study with 5 additional professional designers rating Top-5 retrieved results for relevance, layout/functionality fit, and design-variation usefulness via free-form survey questions; a demonstrated end-to-end auto-completion use case for partial layouts
- **challenges:** Author-acknowledged limitations: detection performance is notably weaker for certain classes (checked view, icon) due to high cross-class visual similarity, small object size, and class imbalance/limited training instances; the dataset covers only 11 predefined UI component classes, limiting generalizability to UIs with different or finer-grained component types (e.g., specific icon/button semantics); the retrieval model currently ignores visual styling features (color, font, imagery) and uses only a flat (non-hierarchical/tree-structured) representation of UI structure; evaluation studies used relatively small test/expert-panel sizes; the system has not yet been validated through longitudinal integration into designers' actual daily workflows (left as future human-AI interaction work).

## Summary

This paper presents VINS, a visual (image-based) search framework designed to help mobile UI designers find structurally and functionally similar design examples, addressing the well-documented limitation that keyword-based search fails to capture layout structure and content. The authors first conduct formative interviews with 24 professional designers confirming that keyword search is slow, imprecise, and insufficient for expressing layout intent, and that similarity should account for structure, functionality, and visual elements together. To support the approach, they construct and publicly release the VINS dataset, 4,800 crowdsourced, quality-controlled bounding-box-annotated UI images spanning abstract wireframes and high-fidelity Android/iOS screens across 11 component classes, filling a gap left by noisy/broken view-hierarchy annotations in the existing Rico dataset. VINS itself has two stages: an SSD/MobileNets object detector localizes and classifies UI components to produce a segmented layout, and a novel attention-aware autoencoder (augmented with a "Box Attention" spatial conditioning mechanism) combined with a label encoder-decoder learns a joint structure-and-content embedding used for Euclidean-distance-based ranked retrieval. The detector achieves 76.39% mAP on the full VINS dataset (a 26+ point improvement over Rico-based training), and the retrieval model achieves 80-92% precision@K, outperforming a prior autoencoder baseline by 4-6 points. A notable detail is the expert evaluation study, where professional designers rated retrieved results as highly relevant and useful for both close-layout-matching and inspirational design-variation purposes, and the system also demonstrated an emergent capability for auto-completing partial UI layouts from as few as 2-3 detected components, a use case the authors compare favorably against the more computationally expensive sketch-based Swire baseline.
