# GIFdroid: An Automated Light-weight Tool for Replaying Visual Bug Reports

- **Year:** 2022
- **Venue/Source:** 44th International Conference on Software Engineering Companion (ICSE '22 Companion)
- **DOI:** 10.1109/ICSE-Companion55297.2022.9793742

## Metadata

- **se_area:** Maintenance (bug reporting / debugging support)
- **se_task:** Automated replay/reproduction of Android bugs from screen-recorded (GIF/video) visual bug reports
- **cv_technique:** Frame-similarity-based keyframe extraction using Y-Diff (luminance difference in YUV space) combined with SSIM (Structural Similarity Index); GUI-to-state mapping via a weighted combination of SSIM (pixel/structural similarity) and ORB (Oriented FAST and Rotated BRIEF, a local invariant feature descriptor) similarity scores; graph search (DFS over a UI Transition Graph) plus Longest Common Subsequence matching for execution-trace reconstruction
- **platform:** Mobile (Android)
- **rationale:** Robustness (combines SSIM and ORB because each has complementary failure modes: SSIM is sensitive to image distortion, ORB is scale/rotation invariant, and the combination measurably improves matching precision); ease of use (fully automated, image-processing-only approach avoids heavyweight instrumentation or high-resolution/touch-indicator requirements needed by prior tools like V2S); efficiency (light-weight, can run offline, reduces developer manual replay effort)
- **artifact_type:** Temporal (a sequence of video/GIF frames is processed to extract keyframes and reconstruct an ordered action trace); localized in the sense that individual keyframes are matched to discrete GUI states in a transition graph
- **eval_method:** Automated evaluation against a manually-labeled ground-truth dataset (61 recordings from 31 open-source apps, 539 reproduction steps), using precision/recall/F1 for keyframe location (vs. 4 baselines: ILS-SUMM, Hecate, PySceneDetect, Comixify), Precision@k for GUI mapping (vs. 10 baselines incl. SIFT/SURF/ORB/SSIM/color histogram), and sequence similarity for execution-trace generation (vs. V2S and an ablation without LCS); plus a controlled user study (8 participants, 4 experimental vs. 4 control) measuring bug-reproduction time on 10 real-world GitHub bug recordings
- **challenges:** Real-world bug reports are often low-resolution, lack touch indicators (74.2% of recordings in the authors' prior empirical study), and rarely start from app launch (only 6.8% begin at launch), forcing the tool to both tolerate imperfect keyframe/state matching and auto-complete the missing launch-to-entry-point trace; extracted keyframes/GUI mappings are not 100% accurate, propagating errors into trace generation; approach fully reproduced only 82% (50/61) of recordings, with failures concentrated in inaccurate last-index detection

## Summary

GIFdroid tackles the practical problem that video- or GIF-based Android bug reports, while easy for end users to create, are tedious for developers to manually replay because recordings are long, often lack touch indicators, and rarely start from app launch. The tool proposes a fully automated, purely image-processing-based pipeline (no app instrumentation required) with three stages. First, Keyframe Location detects "steady state" frames, sequences of visually similar consecutive frames, using a luminance-based (Y-Diff/YUV) SSIM similarity score, filtering out partial-rendering transition frames. Second, GUI Mapping aligns each keyframe to a node (GUI state) in a pre-existing UI Transition Graph (UTG, collected via Google's Firebase automated exploration tool) by combining SSIM and ORB similarity scores (empirically weighted 50/50), since SSIM alone is fragile to visual distortion while ORB contributes robust local-feature matching. Third, Execution Trace Generation uses depth-first search over the UTG to enumerate candidate paths from app launch to the final keyframe, then selects the candidate whose Longest Common Subsequence with the mapped keyframe sequence is greatest (breaking ties toward the shortest path), which both corrects for mapping errors and reconstructs the missing pre-recording trace. Implemented in Python using OpenCV (ORB) and Scikit-Image (SSIM), GIFdroid runs offline in O(n³) time via dynamic programming. Automated evaluation on 61 recordings from 31 apps shows GIFdroid outperforming keyframe-extraction and GUI-matching baselines by large margins and fully reproducing 82% of bugs; a small user study found participants using GIFdroid's generated trace reproduced bugs roughly 2.6x faster on average than a from-scratch control group.
