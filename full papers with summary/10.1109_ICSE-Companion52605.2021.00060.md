# WEBEVO: Taming Web Application Evolution via Semantic Structure Change Detection

- **Year:** 2021
- **Venue/Source:** IEEE/ACM 43rd International Conference on Software Engineering: Companion Proceedings (ICSE-Companion)
- **DOI:** 10.1109/ICSE-Companion52605.2021.00060

## Metadata

- **se_area:** Maintenance (web monitoring to support downstream IR/RPA tool robustness; also touches testing, since broken test scripts are a stated motivation)
- **se_task:** Detecting semantically significant structural changes between two versions of a web page (change detection for web monitoring), distinguishing them from content-only refreshes and cosmetic/refactoring changes
- **cv_technique:** Pixel-level image similarity comparison between element screenshots (`getPicSim`), applied iteratively on the original image, a greyscale-converted version, and a color-inverted version to increase match tolerance; paired with text similarity (Levenshtein edit distance) as a pre-filter/ranking step (max-heap of candidates) before the visual comparison
- **platform:** Web
- **rationale:** Robustness (explicitly designed to reduce false positives that plague pure DOM-tree diffing); context-driven (uses historic page versions to distinguish "content-based" churn from real structural changes, and matches elements based on surrounding structure/text context)
- **artifact_type:** Localized (comparison is done element-by-element via cropped screenshots of individual DOM elements, not whole-page screenshots)
- **eval_method:** Empirical evaluation on 10 real-world websites (8 categories: e.g., w3schools, amazon, apple, linkedin, usps); precision/recall/F1 per site computed against a manually established ground truth of changed elements; direct comparison against a DOM-tree-only baseline and against the prior tool VISTA
- **challenges:** DOM-tree-only methods conflate content refresh with real structural change, producing many false positives (~0.54 F1); relies on availability of multiple historic snapshots of the target page to learn what "normally" changes; visual matching is a simple heuristic pipeline (greyscale/inversion fallback) rather than a learned model, so it may not generalize to more diverse visual perturbations than tested; evaluation set is small (10 sites) and average gap between versions (~2 years) may not reflect more frequent, incremental UI changes.

## Summary

WEBEVO targets a practical pain point for information-retrieval (IR) and robotic-process-automation (RPA) tools that scrape or interact with websites: naive DOM-diffing between two versions of a page is noisy, since it cannot tell apart trivial content refreshes (e.g., rotating ads, updated prices) from genuine structural/layout changes that actually break scripts. The paper's core contribution is a three-stage pipeline: (1) a DOM-tree analysis module proposes candidate changed elements by comparing attributes/structure of old vs. new DOM subtrees; (2) a "History-Based Semantic Structure Detection" module consults several historic snapshots of the *old* page to learn which elements churn naturally, filtering these out as content-based noise; (3) a "Semantics-based Visual Search" module then uses computer vision to re-establish element-to-element correspondence between the old and new page for the remaining, non-content changes, using text similarity to rank candidates and pixel-based image similarity (with greyscale and color-inversion fallbacks) to confirm visual matches. On 10 popular real-world sites, WEBEVO reports an average F1 of 0.86, versus ~0.54 for DOM-only detection and 0.33 for the prior visual tool VISTA. The authors attribute this gap to WEBEVO's use of finer-grained, per-element rather than whole-page, screenshots combined with text semantics. The paper is a short companion/ICSE workshop paper (author's MS/early-stage work), so the CV methodology itself is comparatively simple (classical pixel similarity, not learned features) and the evaluation, while comparative, is modest in scale.
