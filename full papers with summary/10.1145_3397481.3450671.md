# Auto-Icon: An Automated Code Generation Tool for Icon Designs Assisting in UI Development

- **Year:** 2021
- **Venue/Source:** IUI '21 (26th International Conference on Intelligent User Interfaces)
- **DOI:** 10.1145/3397481.3450671

## Metadata

- **se_area:** development
- **se_task:** automated code generation / UI implementation support (icon-to-code conversion, code accessibility/readability improvement)
- **cv_technique:** image tracing (Potrace-based edge detection, polygon approximation, Bezier curve smoothing) to convert raster icon images to vector icon fonts; CNN-based image classification (MobileNetV2, compared against ResNet-50, VGG-16, and traditional CV baselines using color histogram/SIFT with SVM/decision tree) for icon label prediction; HSV color-space based primary color detection
- **platform:** web (front-end UI development, front-end code/CSS/HTML output; integrated into Alibaba's Imgcook code-generation platform)
- **rationale:** ease of use, robustness
- **artifact_type:** localized (icon images within UI screens converted to icon fonts with descriptive labels/color)
- **eval_method:** quantitative model evaluation (accuracy/latency benchmarking of classification models on a self-collected 100k-icon dataset from Alibaba Iconfont, 100 categories, 41k images used for train/val/test 8:1:1 split); controlled user study with 10 developers producing icon code with vs. without the tool, rated for time and 5-point Likert readability/acceptability by 10 independent judges, with Mann-Whitney U significance testing; large-scale industrial deployment evaluation on Imgcook (6,844 icons across 2,031 UIs) using BLEU score to measure code modification after human review; preceding qualitative preliminary study (interviews with 10-12 front-end developers) motivating the tool design
- **challenges:** high cross-class visual similarity among icons (subtle distinguishing features), icons being small/transparent/low-contrast, inconsistent/informal crowd-sourced labeling terminology requiring association-rule mining to build a controlled vocabulary, context-dependent icon meaning causing wrong predictions for polysemous icons (e.g., "information" vs. "glossary"), icon font's imperfect cross-browser/cross-device compatibility, model currently limited to 100 pre-defined categories with sufficient training data, and single-icon-only prediction (no whole-UI context) limiting generalization to other UI elements like buttons

## Summary

This paper presents Auto-Icon, a tool combining computer vision and deep learning to automate the conversion of UI icon images into accessible, efficient icon-font code during front-end development. Motivated by interviews with front-end developers revealing that manual icon-to-font conversion and writing descriptive code comments are laborious and rarely done in practice, the authors built a three-part pipeline: (1) an image-tracing algorithm (based on Potrace, using edge detection, polygon optimization, and Bezier curve smoothing) that converts raster icon images into scalable vector icon fonts for faster rendering; (2) a MobileNetV2-based CNN classifier, trained on a self-collected and manually-coded 100k-icon dataset from Alibaba Iconfont (refined via association-rule mining into 100 semantic categories), that predicts a descriptive label for each icon, achieving 87.7% accuracy while running fast enough (17.5ms) to meet UI rendering constraints; and (3) an HSV-color-space method for detecting each icon's primary color. The tool was evaluated through a controlled user study with developers (65.2% development-time reduction and 48.5% readability improvement over manual coding) and large-scale deployment within Alibaba's Imgcook platform, where 84% of generated icon code required no further modification (BLEU score). Limitations include context-independent predictions, restricted category coverage, and imperfect icon-font browser compatibility, with future work suggested toward whole-UI context and extension to other UI elements like buttons.
