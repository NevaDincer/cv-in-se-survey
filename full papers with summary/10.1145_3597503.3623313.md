# EGFE: End-to-end Grouping of Fragmented Elements in UI Designs with Multimodal Learning

- **Year:** 2024
- **Venue/Source:** 2024 IEEE/ACM 46th International Conference on Software Engineering (ICSE '24)
- **DOI:** 10.1145/3597503.3623313

## Metadata

- **se_area:** development (UI-design-to-code generation tooling)
- **se_task:** automatically grouping "fragmented elements" (small basic shape/vector/icon primitives in a UI design prototype's view hierarchy that have no independent visual semantics on their own, e.g., the 7 basic shapes composing a single calendar-decoration icon) into the semantically meaningful UI components a developer would actually treat as one unit, as a pre-processing step to reduce redundancy and improve readability/maintainability of automatically generated GUI front-end code
- **cv_technique:** a multimodal Transformer encoder (following a DETR-style encoder architecture) that fuses ResNet-50 (ImageNet-pretrained) visual embeddings of each UI element's rendered image with non-visual attribute embeddings (a pre-trained BERT text encoder for element text descriptions, plus learned embeddings for element class/type, bounding-box frame coordinates, and RGBA background color) extracted from the design file's view hierarchy metadata; the fused per-element sequence (ordered via depth-first traversal of the view hierarchy) is classified per-element into start-merge/merge/non-merge labels via a feed-forward + softmax head, turning the grouping problem into an end-to-end sequence-labeling task rather than a two-stage detect-then-rule-based-group pipeline; compared head-to-head against pure-image-classification baselines (EfficientNet, Vision Transformer, Swin Transformer) and against prior two-stage fragmented-element-grouping baselines (UILM: object-detection + hand-crafted rules; ULDGNN: graph neural network; UIED: hybrid CV+CNN GUI element detector)
- **platform:** mobile (the evaluation dataset consists of mobile-app UI design prototypes; the authors explicitly flag lack of validation on desktop/web layouts as a threat to validity)
- **rationale:** robustness (motivated by two established failure modes of prior two-stage detect-then-group approaches: cumulative/compounding errors from separating detection and grouping into distinct stages, and poor robustness to visually overlapping and very small ["tiny"] UI elements, both of which the paper directly measures and improves on) and context-driven (explicitly designed as a multimodal approach because relying on pixel information alone, as pure image-classification baselines do, is shown to be insufficient to fully understand a UI design prototype. Element text description, type/class, spatial frame, and color from the view hierarchy are incorporated precisely because they supply UI-understanding context the rendered pixels alone do not)
- **artifact_type:** localized (per-element image patches and their view-hierarchy attributes are the atomic unit of classification, with grouped output being sub-sequences of adjacent elements), notably a hybrid pixel-plus-structured-metadata approach rather than a purely pixel-based one, since it depends on the design tool's view hierarchy (a JSON element tree with bounding boxes, class, color, text) being available, unlike CV pipelines that work from screenshots alone
- **eval_method:** constructs and publicly releases a new dataset of 4,606 professionally-designed Sketch UI prototypes (353,932 total elements: 19,059 start-merge, 29,814 merge, remainder non-merge; 178,361 "tiny" elements and 2,235 overlapping elements specifically isolated for targeted evaluation), manually annotated by 18 professional front-end developers with quality review by two paper authors, split 8:1:1 (train/val/test) at the file level to avoid leakage; RQ1 element-classification comparison against EfficientNet/ViT/Swin Transformer baselines using precision/recall/F1 (EGFE: 0.847/0.837/0.842 vs. best baseline Swin Transformer: 0.675/0.682/0.679); RQ2 grouping-performance comparison against UILM/ULDGNN/UIED using Levenshtein-edit-distance-based matching to compute precision/recall/F1 across edit-distance thresholds 0–4 (EGFE beats the best baseline by 29.75%/31.07%/30.39% at threshold 4), plus separate breakdown for tiny elements (19.9%/16.0%/18.0% F1 improvement) and overlapping elements (41.7%/30.6%/36.2% F1 improvement) specifically; RQ3 ablation study removing each attribute feature (text, color, class, frame, image) one at a time, showing image removal causes the single largest performance drop (18.93% macro F1); and a separate downstream empirical human-evaluation study applying EGFE-grouped output as input to an industrial GUI-to-code tool (Imgcook), where 10 experienced front-end developers rated code snippets (blind to method) on readability, maintainability, code availability, and modification time for 60 generated React code snippets across three UI categories (travel, communication, shopping), finding statistically significant improvements (Mann-Whitney U test, p<0.05) on all four metrics with EGFE.
- **challenges:** the method has only been validated on mobile-app UI design prototypes and not on desktop or web layouts, an explicitly acknowledged external-validity limitation left to future work; dataset annotation quality is a threat to validity despite strict quality control, and the datasets used by prior competing methods (UILM, ULDGNN) were unavailable due to industrial confidentiality, preventing direct cross-dataset comparison; failure-case analysis identifies two recurring error patterns: nearby widgets being incorrectly merged into one group due to element misclassification (suggested fix: address class imbalance / weighted training), and artistic-font components being incorrectly split into multiple groups because they are composed of many generic "shape" primitives that the model cannot distinguish from unrelated shapes (suggested fix: incorporate an OCR tool to recognize artistic-font text, still within an end-to-end formulation); performance depends on the design file's view hierarchy metadata being present and reasonably well-formed, which is a narrower precondition than pipelines that work from rendered screenshots alone; grouping precision/recall/F1 are still well below 1.0 even at the most permissive edit-distance threshold (0.772/0.831/0.80), indicating meaningful residual error even in the best configuration.

## Summary

This paper targets a specific pain point in industrial UI-design-to-code pipelines: professional designers frequently build visually cohesive UI components (icons, decorations, backgrounds) out of many small, individually meaningless "fragmented" shape/vector primitives, and automated code generators that don't recognize this produce needlessly redundant, hard-to-maintain code (e.g., eight separate image views for what should be one icon). Prior approaches to this "fragmented elements grouping" problem used a two-stage pipeline, detecting candidate regions with computer vision or hand-crafted heuristics, then applying rule-based post-processing to merge them, which the authors show suffers from compounding errors and struggles badly with small ("tiny") and visually overlapping elements. The paper's contribution, EGFE, reframes grouping as a single end-to-end sequence-classification task: every element in a UI design prototype's view hierarchy is embedded by fusing a ResNet-50 visual encoding of its rendered image with BERT-encoded text descriptions and learned embeddings of its class, bounding box, and color, and this fused multimodal sequence is fed through a DETR-style Transformer encoder that jointly classifies each element as the start of a merge group, a continuation of one, or standalone, eliminating hand-crafted post-processing entirely. On a newly constructed and released dataset of 4,606 professionally designed UI prototypes, EGFE substantially outperforms both pure-image-classification baselines and prior two-stage grouping methods, with the largest relative gains specifically on the hardest cases (tiny and overlapping elements) that motivated the work, and an ablation confirms that visual (image) features contribute the single largest share of performance among the fused modalities, validating the core premise that combining pixel information with structured design metadata beats either alone. The paper's most notable applied contribution is that it doesn't stop at intrinsic grouping metrics: it plugs EGFE's output into a real industrial GUI-to-code tool (Imgcook) and runs a blind human evaluation with ten professional front-end developers, who rate EGFE-grouped code as significantly more readable, maintainable, quicker to adjust, and more directly usable than code generated without grouping, a rare instance in this literature of measuring a CV-adjacent SE technique's benefit at the level of an actual downstream deliverable (shippable code quality) rather than only an intermediate detection/classification metric.
