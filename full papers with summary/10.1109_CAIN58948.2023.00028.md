# Towards Understanding Machine Learning Testing in Practise

- **Year:** 2023
- **Venue/Source:** 2023 IEEE/ACM 2nd International Conference on AI Engineering - Software Engineering for AI (CAIN)
- **DOI:** 10.1109/CAIN58948.2023.00028

## Metadata

- **se_area:** Testing (specifically, testing of ML systems/pipelines, arguably adjacent to, rather than within, conventional software testing)
- **se_task:** Understanding ML testing practices via mining visualizations generated during ML development (data exploration, model evaluation, fairness/explainability checks, production monitoring)
- **cv_technique:** None implemented. The paper only proposes to leverage "existing work in image analysis" (unspecified algorithms) on visualizations extracted from Jupyter notebooks, as future work.
- **platform:** General (data science / Jupyter notebook ecosystem; not tied to mobile, web, or desktop GUI)
- **rationale:** Context-driven (visualizations are described as central to interpreting and evaluating ML pipelines, requiring domain-expert interpretation); no robustness or ease-of-use rationale is given, since no technique is implemented.
- **artifact_type:** Not applicable / not determinable, the paper does not target GUI artifacts but rather static visualizations (plots/charts) embedded in notebooks, which does not map cleanly onto full-interface, localized, temporal, or natural-input categories.
- **eval_method:** None. The paper is a research proposal; it describes an intended two-phase methodology (small-scale qualitative study followed by a larger empirical study) but reports no results.
- **challenges:** Authors self-report: (1) data collection at scale via the Kaggle API and reproducing notebooks in Docker is resource- and time-intensive; (2) notebooks do not follow software engineering best practices, complicating analysis; (3) isolating code cells that specifically generate visualizations is technically difficult; (4) obtaining associated datasets needed to reproduce notebooks is often infeasible; (5) prior work on mining Jupyter notebooks is limited, so methodological precedents are scarce.

## Summary

This short position paper sets out a research agenda for understanding how machine learning practitioners test ML systems in practice, by mining visualizations embedded in publicly available Jupyter notebooks, mostly sourced from Kaggle. The authors argue that ML testing is a highly interactive, cognitive process leaning heavily on visual inspection, for data exploration, model comparison, fairness and explainability auditing, and production monitoring, yet this visual side of ML testing has been largely ignored by a research community focused on written test code. The proposed methodology has two phases: a qualitative study of a small, curated sample of top-voted notebooks from a handful of Kaggle competitions to surface general trends, followed by a larger empirical study informed by those findings. Since notebooks interleave text, code, and images in a machine-parsable JSON format, the authors plan to mine and analyze each modality separately, applying NLP to text and code, and image analysis, not yet specified, to the visualizations, aiming for insight into program comprehension and debugging during ML testing. The paper stays explicitly exploratory: no implementation, dataset, or results, just a discussion of anticipated engineering challenges and potential secondary contributions, such as an open dataset or tool for future notebook-mining research.
