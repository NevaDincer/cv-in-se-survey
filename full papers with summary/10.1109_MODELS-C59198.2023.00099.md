# NEURAL-UML: Intelligent Recognition System of Structural Elements in UML Class Diagram

- **Year:** 2023
- **Venue/Source:** 2023 ACM/IEEE International Conference on Model Driven Engineering Languages and Systems Companion (MODELS-C)
- **DOI:** 10.1109/MODELS-C59198.2023.00099

## Metadata

- **se_area:** design
- **se_task:** Semantic recognition (classification and localization) of structural elements, classes and six relationship types (Association, Inheritance, Aggregation, Composition, Dependency, Realization), in UML class diagrams stored as raster images, so that non-standardized/image-based diagrams can be interpreted and reused for downstream tasks such as consistency checking, code generation, and design-to-code tracing.
- **cv_technique:** YOLOv8 (anchor-free, multi-scale object detection with CNN backbone pre-trained on COCO); patch-based image preprocessing to isolate annotated elements; stratified k-fold cross-validation for training/evaluation; IoU-based bounding-box matching and centroid-distance localization analysis.
- **platform:** general (offline/desktop research framework; input is diagram images collected from Git repositories, not tied to a specific mobile/web/game runtime)
- **rationale:** Context-driven: the technique is chosen to handle the specific structural/visual properties of UML class diagrams, highly variable diagram dimensions across modeling tools, severe class imbalance among element types, and non-essential textual content, rather than for general robustness or ease-of-use per se. YOLOv8 is explicitly selected for its ability to adapt to varying image sizes via multi-scale detection layers (avoiding a lossy manual resizing/normalization step) and for its accuracy/speed trade-off suited to detecting classes and relationships of greatly varying scale within a diagram.
- **artifact_type:** localized (bounding-box detection and classification of discrete structural elements, classes and relationship symbols, within a full diagram image; output is per-element category + location, not a full-diagram/global label, a temporal signal, or a natural free-form input)
- **eval_method:** Two custom-built, annotated datasets derived from the Lindholmen/Hebig et al. open-source UML dataset: Set A (13,800 filtered class-diagram images, 1,318 manually annotated, 10,625 total annotations across 7 categories) used for training/testing via stratified 5-fold cross-validation, and Set B (700 class diagrams from Ho-Quang et al., fully hand-annotated by 3 annotators with cross-checking, 11,997 annotations) used solely to test generalization/inference of the model trained on Set A (no training on Set B). Metrics: classification accuracy (per-fold average and standard deviation, via confusion matrices), Intersection over Union (IoU) for localization accuracy, F1 score (precision/recall based on centroid-distance tolerance in pixels), and k-fold cross-validation accuracy (MSE-based). No comparison against other published systems' quantitative results (no direct baseline reproduction); evaluation is against the authors' own two dataset splits. No human user study of the tool was conducted (only human annotators for dataset creation). Results: Set A, accuracy 92.59% and IoU 85%; Set B, accuracy 94.11% and IoU 87.95%; Navigable-Dependency and Inheritance-Realization relationship pairs were the most confused/least accurately localized (up to ~8 pixel deviation) due to close visual/graphical similarity.
- **challenges:** Authors explicitly report: (1) class imbalance in the source dataset required annotating only a subset and using patch-based cropping, since sending partially-annotated full diagrams to YOLO would prevent convergence; (2) YOLO/CNN architecture is not suited to interpreting textual content within diagrams and tends to ignore it during learning, so class names/attributes/operations are not extracted; (3) confusion between visually similar relationship types (Inheritance vs. Realization, Navigable vs. Dependency) due to close graphical resemblance and annotation proximity/overlap; (4) the Navigable relationship is the hardest to localize precisely because of its highly variable graphical style across diagrams/tools; (5) the model currently handles diagrams from modeling tools but not freehand/sketched diagrams, authors state this as future work; (6) dataset collection depends on scraping public Git repositories, many of whose links/repos are no longer accessible or maintained, reducing usable data over time; (7) annotations exclude notes, interfaces, and finer structural/textual relationships, limiting current semantic scope (acknowledged as future enrichment).

## Summary

This paper presents NEURAL-UML, a framework for training a deep-learning-based system to recognize and localize the structural elements of UML class diagrams, classes and six relationship types (Association, Inheritance, Aggregation, Composition, Dependency, Realization), directly from raster images. The authors address the scarcity of annotated data for semantic (as opposed to mere diagram-type) analysis by building a large-scale dataset pipeline: web-scraping UML diagrams from ~93,607 Git repositories (Hebig et al.'s Lindholmen dataset), filtering to class diagrams with a pre-trained classifier from Ho-Quang et al., and manually annotating subsets with a custom-built cross-platform annotation tool, yielding two datasets (Set A: 13,800 filtered/1,318 annotated diagrams; Set B: 700 fully annotated diagrams). The detection/classification backbone is YOLOv8, chosen for its multi-scale, anchor-free architecture that natively handles the highly variable dimensions of class diagrams without lossy resizing, and diagrams are split into patches to avoid imbalance-induced convergence problems. Evaluated via stratified 5-fold cross-validation on Set A and held-out generalization testing on Set B, the model achieves 92.59% accuracy/85% IoU (Set A) and 94.11% accuracy/87.95% IoU (Set B), with most confusion occurring between visually similar relationship pairs (Inheritance/Realization, Navigable/Dependency). A notable detail is the explicit design decision to treat text and unannotated elements (notes, interfaces) as a "background" reject class, since the YOLO architecture is deliberately not used for textual/OCR-based content extraction. Both the annotated datasets and code are released publicly to support further research.
