# Computer Vision Intelligence Test Modeling and Generation: A Case Study on Smart OCR

- **Year:** 2024
- **Venue/Source:** 2024 IEEE International Conference on Artificial Intelligence Testing (AITest 2024)
- **DOI:** 10.1109/AITest62860.2024.00011

## Metadata

- **se_area:** testing
- **se_task:** AI/software functional test modeling, test case generation, and evaluation-metric design for validating a computer-vision (OCR) function; specifically, systematic test-case selection and accuracy assessment for image-based receipt text extraction ("test case generation and evaluation for computer-vision/OCR systems")
- **cv_technique:** Optical Character Recognition (OCR), the system under test; underlying OCR pipelines typically use Convolutional Neural Networks (CNN) for text detection/classification (mentioned as background, not implemented by the authors); the two OCR systems tested are commercial mobile "text scanner" apps, CamScanner and Scanner Pro
- **platform:** mobile
- **rationale:** Context-driven and robustness-focused: the paper systematically varies environmental/context conditions (lighting, shot angle/distance, image quality) and input content complexity (store logos, item lists, transaction details, language) to determine which factors most affect OCR robustness and accuracy; it is not about ease-of-use testing but about identifying failure-inducing conditions for a deployed CV function
- **artifact_type:** full-interface (the test target is the OCR app's end-to-end text-extraction output on captured receipt images) with natural input (real/simulated photographs of receipts captured under varying real-world conditions such as lighting, angle, and distance, rather than synthetic/adversarial perturbations)
- **eval_method:** Case study on two commercial mobile OCR ("text scanner") apps, CamScanner and Scanner Pro. A custom 3D classification test model (context classification tree, input classification tree, output classification tree) is used to derive a 3D decision table; total theoretical test complexity CC*IC*OC = 14*25*10 = 3500, reduced via test coverage criteria to 24 concrete test cases (one base case plus single-parameter variations) built from photographed shopping receipts. No public benchmark dataset (e.g., IMPACT, COCO-Text) is used directly, the authors build their own receipt image set and Ground Truth transcriptions. Four custom accuracy metrics are proposed and reported: Flex Character Accuracy (FCA), String Segment Accuracy (SSA), Ordered String Segment Accuracy (OSSA), and Text-Line Accuracy (TLA), plus overall/sectional character accuracy (store info, item list, transaction, misc.) and a pass/fail threshold of >=95% character accuracy. Results: pass rates of 83% (CamScanner) and 75% (Scanner Pro) across the 24 test cases; overall FCA 92% (CamScanner) vs 88% (Scanner Pro); FCA up to 96.7% under normal context for both apps, dropping to 88.5% (CamScanner) and 82.5% (Scanner Pro) under complex context (poor lighting/long distance); TLA is markedly lower than FCA/SSA/OSSA for both apps (e.g., aggregate metrics in Table II: FCA 97.9%, SSA 90.9%, OSSA 60.6%, TLA 25.0%). No human user study is conducted; evaluation is entirely automated accuracy-metric comparison against manually prepared ground truth.
- **challenges:** Authors explicitly note: (1) the framework/test-case selection process is manual and not yet automated (stated as future work); (2) the case study covers only receipt images/one input domain, generalization to other image-based text extraction types is untested; (3) automated metrics (SSA, OSSA, TLA) can be distorted by benign OCR behaviors that don't matter to human readers (e.g., CamScanner dropping spaces, or line-feed/segmentation errors from irregular spacing), showing the proposed metrics may not perfectly reflect real usability; (4) text positional/geometric information is deliberately excluded from accuracy calculation because scanner apps output unformatted text, limiting evaluation fidelity for layout-sensitive use cases; (5) combinatorial explosion of context x input x output parameters (3500 theoretical combinations) required ad hoc reduction to 24 test cases rather than systematic combinatorial (T-way) testing, which the authors defer to future work. (Inferred from experimental setup: small sample size of only 24 test cases and 2 apps limits statistical generalizability, and reliance on manually captured receipt photos may introduce uncontrolled confounds.)

## Summary

This paper is about testing a computer-vision system, not using CV to solve a software-engineering task, so it sits closer to SE testing methodology applied to a CV system than to the usual CV-for-SE approach. The authors propose a 3D classification test model, context, input, and output classification trees, to systematically derive test cases for an image-based receipt text-extraction function, cutting a theoretical 3,500-combination decision table down to 24 practical test cases through coverage criteria and single-factor variation. They introduce four accuracy metrics: Flex Character Accuracy (FCA), String Segment Accuracy (SSA), Ordered String Segment Accuracy (OSSA), and Text-Line Accuracy (TLA), which evaluate OCR output at character, string-segment, and text-line granularity, building on prior character and word-accuracy measures like Levenshtein distance. The framework gets validated in a case study comparing two commercial apps, CamScanner and Scanner Pro, on photographed shopping receipts under varying lighting, distance, and content-complexity conditions. Both apps perform well under normal conditions, FCA up to 96.7%, but degrade under harder contexts, and one notable finding is that TLA comes out far weaker than the other three metrics for both apps, as low as 25%, traced to specific bugs like space-dropping and line-feed misalignment. That gap shows different metrics catch different failure modes that character accuracy alone would miss. The main contribution is a systematic, coverage-driven test design method and a multi-granularity metric suite for CV functional testing, demonstrated here but not yet automated.
