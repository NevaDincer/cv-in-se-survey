# Learning to Denoise Raw Mobile UI Layouts for Improving Datasets at Scale

- **Year:** 2022
- **Venue/Source:** CHI '22 (ACM Conference on Human Factors in Computing Systems), New Orleans, LA, USA
- **DOI:** 10.1145/3491102.3502042

## Metadata

- **se_area:** development (data/tooling infrastructure supporting downstream mobile UI design and modeling tasks)
- **se_task:** Automated cleaning/annotation of mobile UI layout datasets (view hierarchies): detecting invalid/mismatched UI elements and assigning semantically meaningful object types, to produce higher-quality training/evaluation data for UI-related ML models (e.g., widget captioning, screen summarization, UI component detection)
- **cv_technique:** ResNet-50-based binary classifier with an extra bounding-box mask channel for invalid object detection; two multimodal object-type recognition architectures: a Graph Neural Network (message-passing neural network) combining ResNet-50 pixel encodings with node text/positional embeddings over the view-hierarchy tree, and a DeTR-inspired Transformer model (ResNet-50 backbone + Transformer encoder over the screenshot + parallel decoder over view-hierarchy nodes)
- **platform:** mobile (Android; built on the Rico dataset)
- **rationale:** robustness (correcting noisy/misaligned/invisible UI elements captured at runtime), ease of use (reducing costly manual labeling by automating dataset cleaning at scale)
- **artifact_type:** full-interface (whole-screen view hierarchies annotated element-by-element against the full screenshot)
- **eval_method:** Quantitative evaluation on a held-out test split of the newly created CLAY dataset (59,555 human-annotated screens from 8,508 apps): precision/recall/F1 for invalid-object detection (82.7% F1) and weighted/macro precision-recall-F1 for 24-way object-type classification (85.9%/84.7% F1 for GNN/Transformer), compared against a heuristic Android-class-mapping baseline; supplemented by manual error analysis (100 sampled false positives/negatives per phase) and confusion-matrix inspection of type-recognition errors
- **challenges:** severe class imbalance between valid and invalid objects (~8:1), ambiguous human-labeling boundaries for "misaligned" objects, confusions among visually similar types (e.g., BUTTON/TEXT, IMAGE/PICTOGRAM, CARD_VIEW/CONTAINER), sparse data for rare object types (e.g., ADVERTISEMENT, MAP), limited generalization since models are trained only on Android screenshots/layouts, and residual need for more substantial structural repair (e.g., adding missing objects) beyond node-level relabeling

## Scope note

The paper is fundamentally a dataset-curation/HCI contribution (cleaning mobile UI view-hierarchy datasets for future ML research) rather than a study addressing a defined software engineering activity such as requirements, testing, or maintenance. CV is used substantively (ResNet/GNN/Transformer models), but the SE link is indirect: the output is a benchmark dataset and denoising pipeline intended to support later UI-modeling work, not an SE task itself.

## Summary

This CHI 2022 paper addresses the poor quality of UI layout data (view hierarchies) commonly used in mobile UI research, where captured layouts often contain invalid objects with no valid on-screen visual correspondence and object types that are either too generic (e.g., "View") or too app-specific to be useful. The authors introduce the CLAY pipeline, a two-phase deep-learning approach that first detects invalid objects using a ResNet-based binary classifier operating on screenshot pixels with a bounding-box mask channel, then assigns each remaining object a semantically meaningful type from a 24-class taxonomy using either a Graph Neural Network or a DeTR-inspired Transformer model, both fusing pixel crops, text attributes, and positional encodings. To train and evaluate the pipeline, they construct the CLAY dataset of 59,555 human-annotated screens derived from the public Rico corpus, collected via 1,577 hours of crowd labeling with quality auditing. Experiments show the invalid-object detector reaches 82.7% F1 and the type-recognition models reach 84.7–85.9% F1, substantially outperforming a heuristic Android-class-mapping baseline, with GNN performing better on common types and Transformer more balanced across rare types. Detailed error analysis reveals persistent confusions between visually similar categories and difficulty with rare classes and boundary-ambiguous invalid objects. The work's primary contribution is the released CLAY dataset and denoising models as reusable infrastructure for future data-driven mobile UI research, rather than an evaluation of a specific software engineering task.
