# An Empirical Investigation into the Use of Image Captioning for Automated Software Documentation

- **Year:** 2022
- **Venue/Source:** 2022 IEEE International Conference on Software Analysis, Evolution and Reengineering (SANER)
- **DOI:** 10.1109/SANER53432.2022.00069

## Metadata

- **se_area:** maintenance
- **se_task:** automated software documentation generation, specifically predicting natural-language functional descriptions (both high-level, screen-purpose descriptions, and low-level, component-purpose descriptions) directly from mobile app GUI screenshots and/or GUI metadata, to bridge the "lexical gap" between abstract natural language and structured code/GUI representations
- **cv_technique:** neural image captioning models applying CNN-encoder + RNN-decoder architectures: im2txt (Inception v3 CNN encoder + LSTM decoder, evaluated with weights pretrained on ImageNet vs. fine-tuned on domain-specific GUI datasets), NeuralTalk2 (VGGNet CNN encoder + Bidirectional RNN decoder, with and without CNN fine-tuning), and Show-Attend-and-Tell/SAT (VGG16 CNN encoder + LSTM decoder with a visual attention mechanism); a fourth, non-CV comparison model (Seq2Seq, BRNN-GRU encoder + LSTM decoder) is trained purely on textual GUI metadata (not images) as a contrast condition
- **platform:** mobile (Android)
- **rationale:** context-driven (the central hypothesis is that GUIs, being rich pixel-based encodings of underlying program functionality, can supply an information source largely unexploited by prior code+NL-only documentation techniques, providing latent semantic signal to help infer undocumented program properties and abstractions per Robillard et al.'s identified documentation research challenges) and ease of use (envisions downstream applications such as automated technical documentation, end-user tutorials, and accessibility "screen-to-functionality" tools that would reduce manual documentation burden on developers)
- **artifact_type:** full-interface (high-level captioning of entire screenshots) and localized (low-level captioning of individual, spatially-referenced GUI components within a screen); the paper explicitly studies both granularities in parallel
- **eval_method:** constructs and releases a new dataset (CLARITY: 45,998 human-authored functional captions across 10,204 Android screenshots sourced from the REDRAW dataset, collected via a two-phase MTurk crowdsourcing study with quality vetting, 2,419 HITs rejected for quality); empirical dataset analysis via LDA topic modeling (RQ1) and n-gram-based "naturalness"/cross-entropy analysis benchmarked against Gutenberg, Java code, and Stack Overflow corpora (RQ2); trains and evaluates 15+ model configurations (im2txt, NeuralTalk2, SAT, Seq2Seq) across high/low/combined caption granularities, evaluated quantitatively via BLEU-1 through BLEU-4 scores on a held-out CLARITY test set (RQ3), benchmarked against the same models trained on general-purpose datasets (Flickr8K, MSCOCO); and a large-scale qualitative human evaluation (RQ4) with 220 additional MTurk participants rating model-generated captions for accuracy, unnecessary information, and understandability via Likert-style questions, compared against reference (human) captions.
- **challenges:** image-captioning models struggled to predict diverse, screen-specific functionality, tending to default to the most frequently-seen functionality types (e.g., back/menu buttons) seen during training, an explicitly acknowledged open problem requiring larger/more diverse datasets or domain-specific model ensembles; predicted captions often contained "<UNK>" (unknown) tokens for unrecognized/rare app-specific concepts (e.g., "album cover," "store location") due to limited vocabulary, motivating future work combining image-based captions with GUI-metadata vocabulary; a notable mismatch was found between automated BLEU-score rankings and human-perceived caption quality (participants consistently rated im2txt captions best despite NeuralTalk2 scoring higher BLEU in some configurations), calling into question reliance on reference-based automated metrics alone for this task; models trained on the domain-specific but comparatively small CLARITY dataset underperformed the same architectures trained on the much larger general-purpose MSCOCO dataset by ~10–27 BLEU points, though performance was comparable to models trained on the similarly-sized Flickr8K dataset; the Seq2Seq metadata-only model did not consistently converge on high-level captions and performed poorly overall, and was excluded from certain analyses; low-level captions were capped at 4 per screen for MTurk task feasibility, meaning some GUI components on information-dense screens may lack natural-language descriptions in the dataset, an acknowledged external-validity limitation.

## Summary

This paper investigates whether the visual, pixel-based information encoded in mobile app GUI screenshots can be automatically translated into natural-language functional descriptions, as a new information source to help close the well-known "lexical gap" between source code and natural-language documentation. The authors first construct and open-source the CLARITY dataset: 45,998 human-authored functional captions (at both high-level, whole-screen granularity and low-level, per-component granularity with explicit spatial references) for 10,204 Android screenshots drawn from the REDRAW dataset, collected via a carefully quality-controlled two-stage Mechanical Turk crowdsourcing study. An empirical analysis of this dataset (topic modeling via LDA, and "naturalness"/predictability analysis via n-gram cross-entropy compared against Gutenberg, Java-code, and Stack Overflow corpora) finds that CLARITY captions exhibit strong, learnable semantic patterns, second only to raw Java code in predictability. This motivates the paper's central experiment: training and rigorously evaluating three neural image-captioning architectures (im2txt, NeuralTalk2, and Show-Attend-and-Tell) that each pair a CNN image encoder with an RNN language decoder, comparing multiple CNN pretraining/fine-tuning regimes (ImageNet vs. domain-specific GUI datasets) against a text-only Seq2Seq baseline trained purely on GUI metadata rather than pixels. Across more than 15 trained model configurations evaluated with BLEU scores and a large 220-participant human study, SAT (which uses visual attention to focus on salient image regions) achieved the best automated BLEU scores overall, while im2txt was rated most accurate, readable, and relevant by human evaluators, a genuinely interesting and explicitly flagged discrepancy between automated machine-translation metrics and human judgment that the authors argue future GUI-documentation research should not ignore. The paper's five "lessons learned" distill practical guidance for the field: GUI screenshots do carry learnable functional semantics comparable to general image-captioning benchmarks of similar dataset size; models benefit substantially from domain-specific (GUI) pretraining rather than generic ImageNet/MSCOCO features; screenshots and textual GUI metadata appear to encode complementary (orthogonal) information suggesting future multimodal fusion; caption diversity/specificity remains an open, largely unsolved problem, since models default to whatever functionality types were most common in training; and human evaluation is essential alongside automated metrics given their observed disagreement. As one of the first empirical investigations to treat entire GUI screens (not just individual components or accessibility labels, as in prior narrower work) as a documentation-relevant visual data source, the paper positions image captioning as a promising but still nascent complement to traditional code-and-text-based automated documentation techniques.
