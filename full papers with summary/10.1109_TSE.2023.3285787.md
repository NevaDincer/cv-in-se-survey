# Mobile App Crowdsourced Test Report Consistency Detection via Deep Image-and-Text Fusion Understanding

- **Year:** 2023
- **Venue/Source:** IEEE Transactions on Software Engineering (TSE), Vol. 49, No. 8, August 2023, pp. 4115–4134
- **DOI:** 10.1109/TSE.2023.3285787

## Metadata

- **se_area:** Testing (crowdsourced testing quality control / bug-report triage, maintenance-adjacent)
- **se_task:** Automatically detect whether a crowdsourced test report's attached app screenshot is *consistent* with its textual bug description (i.e., whether the bug described in the text can actually be matched to a bug visible in the screenshot), in order to automatically filter out low-quality/inconsistent reports before developers spend time reviewing them. This is explicitly framed as a triage/quality-control task, not a bug-detection task.
- **cv_technique:** Two-stage pipeline (RECODE). **Stage 1 (CLASSIFIER)**: a fine-tuned BERT model ("RECODE-BERT") classifies each report's textual description into 1 of 10 empirically-derived bug-type categories (Functional Defect, Crash, Layout Problem, Display Problem, Network Error, Null Screen, Performance Problem, Error Prompt, Garbled Error, Transition Problem), keeping the top-3 predictions to handle multi-bug ambiguity; trained on a class-balanced dataset built by an AUGMENTOR that performs keyword-replacement text augmentation sourced from GitHub issues/commits, app-store reviews, industry test reports, and Stack Overflow. **Stage 2 (DECOMPOSER + DETECTOR)**: DECOMPOSER extracts widgets from screenshots by combining traditional CV contour/edge-based segmentation with a modified VGG-16 deep-learning classifier (14 Android widget types, 89.98% test accuracy) and OCR for text-widget extraction and layout characterization; it also parses textual descriptions via dependency parsing (Baidu's DDParser) to extract "locating features" (color words C, position words P, text words X, type words Y) plus negative-word/double-negative-word and prompt-word cues from curated keyword datasets. DETECTOR then applies a **General Strategy** (weighted locating-feature matching between extracted widgets and text) for 4 visually non-distinctive bug types, and a **Specific Strategy** per bug type for the other 6, each exploiting a distinct visual signature. For example, Null Screen → binarize the screenshot and detect large continuous borderless regions (threshold θ=0.75); Network Error / Crash / Performance Problem / Error Prompt → OCR pop-up/prompt text and keyword-match; Garbled Error → detect non-UTF-8 characters in OCR output.
- **platform:** Mobile (Android; 22,720 real-world crowdsourced test reports collected from the MoocTest platform, covering 50+ apps and 1,100+ crowdworkers)
- **rationale:** Context-driven (the paper's central empirical justification is that different bug types have systematically different visual signatures on screenshots (a Null Screen is nearly all-black/white, a Network Error shows HTTP codes, and so on), so a single generic strategy cannot serve all bug types well, motivating the two-stage classify-then-strategy design); explicit rejection of one-stage/generic multimodal approaches as impractical. The authors show and argue that (a) even their large 22.7k-report dataset is insufficient to train a generic image-text fusion model like ViLBERT/VL-BERT/Unicoder-VL from scratch, and (b) buggy widgets are typically *non-salient* (a single button or text view) within the full screenshot, so generic salient-object-oriented multimodal encoders fail to extract useful features for them. This is the rationale for combining classical CV decomposition with per-bug-type heuristic strategies rather than an end-to-end vision-language model.
- **artifact_type:** Localized (individual widget crops obtained via contour/CNN-based decomposition, used for fine-grained text-widget matching) operating over Full-interface screenshots (the whole-activity image is the raw CV input before decomposition)
- **eval_method:** Large-scale empirical dataset (22,720 reports; only 18.07%, i.e. 4,105, judged consistent by 5 expert human labelers with Fleiss' κ ≈ 0.88-0.95 across labeling sub-tasks; this rate itself is the paper's core motivating empirical finding). **RQ1 (CLASSIFIER)**: accuracy/precision/recall/F1 (top-1/2/3) on a held-out test set and on an extended "All Report Set," benchmarked against SETU (a prior crowdsourced-report feature-extraction baseline) and 3 ablation configurations of BERT (pretrained-only, non-augmented, mixed-with-inconsistent-reports), plus a per-category breakdown across all 10 bug types. **RQ2 (DETECTOR/whole pipeline)**: binary consistency classification (accuracy/precision/recall/F1) against ViLBERT (a representative one-stage multimodal baseline, retrained on the report dataset), a RECODE-one-stage ablation (General Strategy applied uniformly, no per-type Specific Strategies), and SETU+DETECTOR (SETU's classifier swapped in for RECODE-BERT); includes a preliminary hyperparameter sweep for the top-i confidence weighting (δ₁,δ₂,δ₃). **RQ3 (user study)**: 10 senior-SE-experienced participants split into with/without-RECODE groups reviewing 20 crowdsourced reports (8 consistent, 5 distinct bugs) for a real GitHub app, measuring bug-inspection time and bugs-found (Friedman test confirms no significant capability difference between groups, p=0.031), plus a 6-question Likert (System Usability Scale-style) questionnaire covering usability, efficiency, usefulness, correctness, helpfulness, accessibility.
- **challenges:** Quantitative highlights: RECODE-BERT (top-3) reaches 96.91% accuracy / 97.10% precision / 97.23% recall / 97.17% F1 on the test set, outperforming SETU by 49.8–116.2% across the four metrics, and generalizes even better on the full unfiltered report set (98.76% accuracy). Full RECODE (top-3) reaches 91.35% accuracy / 70.39% precision / 89.94% recall / 78.97% F1 for the binary consistency task, outperforming ViLBERT by 116.98% in accuracy. The authors note ViLBERT degenerates to predicting "consistent" for nearly all reports (spuriously perfect recall, useless precision), which they attribute to insufficient training data scale and the non-salient-widget problem described above. The user study shows RECODE improves bug-review efficiency by **1.4×** (1073.53s → 444.65s average per participant) while *preserving* bug-finding effectiveness (4.2→4.4 of 5 bugs found on average, i.e., discarding inconsistent reports did not cause missed bugs in this trial). Authors are explicit that report *consistency* is only the "lowest line" of report quality. A consistent report can still be low-quality (e.g., missing reproduction steps), so RECODE deliberately does not claim to solve the broader low-quality-report problem, only the objectively-definable consistency subset. Threats to validity acknowledged: internal (implementation/model-adaptation correctness, mitigated via third-party code review), external (representativeness of the single MoocTest platform and its app mix, though authors argue crowdsourced-testing mechanisms are broadly similar across platforms like TestIO/Baidu Crowdtesting/Testin), and construct (manually-labeled ground truth, mitigated via double-labeling/discussion and use of experienced labelers per Salman et al.'s student-as-developer-proxy justification).

## Summary

RECODE tackles a concrete and severe quality-control problem in crowdsourced mobile app testing: across a 22,720-report real-world dataset, the authors find that only 18.07% of reports have textual descriptions that actually match the bug visible in their attached screenshot. The rest are "inconsistent": meaningless spam, GUI-design complaints mistaken for bugs, or genuine mismatches from unskilled crowdworkers, forcing app developers to waste substantial review time distinguishing signal from noise. Rather than a monolithic vision-language model, RECODE is architected as an explicitly two-stage pipeline motivated by a stated failure of one-stage approaches: the authors argue (and empirically show via a ViLBERT baseline that degenerates to always-predicting-consistent) that existing multimodal fusion models both need more training data than is realistically obtainable and structurally miss the non-salient, small buggy widgets that dominate real screenshots. Stage 1 classifies each report's text into one of 10 empirically-derived bug categories using a BERT model fine-tuned on a keyword-augmentation-balanced dataset built from external resources (GitHub issues, app-store reviews, Stack Overflow). Stage 2 then applies bug-type-specific detection strategies: some rely on generic locating-feature (color/position/text/type word) matching between screenshot widgets and text, while others exploit highly distinctive visual signatures unique to a bug type (e.g., an almost entirely black/white screen for Null Screen, HTTP status codes for Network Error, malformed character encodings for Garbled Error). The CV components combine classical contour/edge-based widget segmentation, a VGG-16-derived widget-type classifier, and OCR. Evaluated against SETU and ViLBERT baselines, RECODE substantially outperforms both on classification and consistency-detection metrics, and a controlled 10-participant user study demonstrates a 1.4× real-world review-time improvement without loss of bug-finding recall. The paper is notable within the CV-in-SE space for combining CV (screenshot decomposition), NLP (dependency parsing, BERT), and an explicit taxonomy-driven, per-bug-type heuristic detection layer, and for candidly scoping its contribution to the "consistency" subset of the broader low-quality-report problem rather than overclaiming general report-quality assessment.
