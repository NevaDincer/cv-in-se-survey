# Test Script Intention Generation for Mobile Application via GUI Image and Code Understanding

- **Year:** 2025
- **Venue/Source:** ACM Transactions on Software Engineering and Methodology (TOSEM), Vol. 35, No. 1, Article 18
- **DOI:** 10.1145/3722105

## Metadata

- **se_area:** Testing (maintenance aspects of testing artifacts: test script comprehension/documentation)
- **se_task:** Automatic generation of natural-language "test intentions" (comments/descriptions) for GUI-based mobile app test scripts, to support test script understanding, maintenance, and modification
- **cv_technique:** CNN-based image feature extraction (VGG-16, fine-tuned) combined with an LSTM sequence decoder in an Encoder-Decoder image-captioning architecture for widget image understanding; Optical Character Recognition (OCR) for text extraction from GUI screenshots; (code side, non-CV) code2seq/AST-based encoder-decoder with bi-directional LSTM and attention for code intention generation
- **platform:** Mobile (Android)
- **rationale:** Context-driven (widget images and screenshots are analyzed in the context of the GUI layout hierarchy and XPath structure to disambiguate widgets lacking explicit textual labels, such as icons); Robustness (OCR and image captioning are used as a fallback pipeline when textual attributes such as content-desc are unavailable directly from GUI layout files, e.g., for widgets rendered on Canvas or in HTML, or dynamically generated at runtime)
- **artifact_type:** Localized (CV is applied to individual widget-level screenshots/crops within the app GUI, not the whole interface at once, to caption single icons/buttons lacking text)
- **eval_method:** Widget image captioning model evaluated on a self-built dataset of 2,000 widget images (for fine-tuning, 7:2:1 train/val/test split) plus a separate held-out evaluation set of 5,000 Rico-dataset widget images labeled by 3 graduate students (Fleiss' kappa ≥0.9 agreement threshold, third-party experts adjudicate disagreements); exact-match accuracy metric reaching 97.46% vs. 78.34% for the unfine-tuned base model. End-to-end TestIntention evaluated on 500 test scripts (2,323 operations) across 50 real open-source Android apps (AndroZooOpen dataset) using BLEU@1-4, CIDEr, METEOR, and ROUGE-L against baselines code2seq, DOME, an LLM-based (in-context learning) approach, and ablations (GUIIntention-only, CodeIntention-only); also an RQ2 operation-mapping success-rate analysis (71.6% of steps successfully mapped) and an RQ3 user study with 15 participants comparing task completion time on test scripts with vs. without generated intentions (85.13s vs. 17.13s, ~79.88% time savings)
- **challenges:** Authors report that (1) operation mapping fails for ~28% of steps, largely "transition operations" (e.g., scroll()) that carry no concrete intention even for human experts; (2) the approach depends on availability of app source code (Java only, no Kotlin support) for CodeIntention, limiting applicability to closed-source or Kotlin-based apps; (3) the approach does not formally incorporate test oracles/expected results, left as future work; (4) evaluation apps/scenarios are limited in number (50 apps, student-authored scripts) which the authors acknowledge as a validity threat, mitigated by diversity of app categories and functional coverage requirements.

## Summary

TestIntention addresses the problem that mobile GUI test scripts (e.g., Appium-based) are rarely commented and are difficult to understand because, unlike application source code, they do not contain business logic directly, only widget selectors (ID or XPath) and operations. The approach formalizes a test script as an operation-sequence model and splits intention inference into two complementary pipelines: GUIIntention, which handles XPath-located widgets by extracting textual information from GUI layout files, applying OCR to screenshots when text is absent, and using a CNN(VGG-16)+LSTM encoder-decoder image-captioning model to caption widgets with no textual cues at all (e.g., icons); and CodeIntention, which handles ID-located widgets by statically mapping selectors to response methods via five templates and generating descriptions with an AST-based code2seq-style model. The results are merged and deduplicated via Word2Vec similarity into a final natural-language report. The distinctive contribution is the systematic template-based response-method mapping algorithm bridging test scripts to business logic, combined with the CV-based widget captioning fallback for icons lacking any textual metadata. Evaluated on 500 scripts across 50 real apps, TestIntention substantially outperformed code2seq, DOME, and an LLM-based baseline on BLEU/CIDEr/METEOR/ROUGE, and a 15-participant user study showed about 80% reduction in the time needed to understand unfamiliar test scripts.
