# Deep learning-based prototyping of android GUI from hand-drawn mockups

- **Year:** 2020 (e-first online 17 Feb 2021)
- **Venue/Source:** IET Software, Vol. 14, Iss. 7, pp. 816-824
- **DOI:** 10.1049/iet-sen.2019.0378

## Metadata

- **se_area:** Design / Development (bridges GUI mockup design and front-end implementation; positioned as automated GUI prototyping and code generation)
- **se_task:** Automatic generation of a working Android GUI prototype from a hand-drawn (paper-and-pen) mockup image
- **cv_technique:** YOLOv5 (YOLOv5x pretrained on COCO, fine-tuned on a custom dataset); CNN-based backbone/neck/head architecture with Cross-Stage-Partial (CSP) modules and Spatial Pyramid Pooling (SPP); object detection + classification of GUI component bounding boxes; custom heuristic algorithms for bounding-box overlap resolution and component alignment (non-CV post-processing)
- **platform:** Mobile (Android)
- **rationale:** Ease of use / developer burden reduction (automates the time-consuming manual translation of hand-drawn mockups into code); context-driven (recognizes spatial layout/positions of components to reconstruct hierarchy); robustness (explicitly evaluates performance vs. drawing distortions, varying pen colours, lighting, and five different developers' drawing styles)
- **artifact_type:** Full-interface (entire hand-drawn screen mockup is detected, classified, aligned, and converted into a complete Android GUI prototype)
- **eval_method:** Precision, Recall, and F-score per component class computed on a 100-image held-out test set; confusion matrix across the 13 GUI component classes; overall recognition accuracy (98.54%); qualitative comparison table against four prior systems (Pix2Code, two Sketch2Code variants, Doodle2App) on architecture, input type, dataset size, text handling, distortion sensitivity, and accuracy
- **challenges:** No public/standard dataset existed for hand-drawn mobile mockups, so authors had to manually collect and label a small custom dataset (390 training images, 100 test images, only 13 predefined component shapes, 5 developers); model confuses check boxes with radio buttons when corners are drawn rounded; on/off state misclassified when the inner circle isn't shaded distinctly; hand-written text is not yet handled (left as future work); output styling is limited to a single colourless "plain" style; approach assumes a flat single-frame layout rather than complex nested hierarchies

## Summary

This paper presents a three-phase pipeline for converting hand-drawn Android GUI mockups into working GUI prototypes. The first phase uses YOLOv5 (initialized from the YOLOv5x checkpoint pretrained on COCO and fine-tuned on a custom hand-drawn mockup dataset) to detect and classify 13 predefined GUI component shapes, such as buttons, list views, switches, sliders, checkboxes, and radio buttons, each assigned a distinct hand-drawable shape convention. The second phase applies two deterministic heuristic algorithms to resolve bounding-box overlaps and to snap misaligned adjacent components into proper alignment, compensating for the inherent imprecision of freehand sketching. The third phase constructs a flat single-frame GUI hierarchy from the aligned, classified components and emits a JSON description that is translated into Android XML layout code. The dataset itself is a notable contribution: since no public hand-drawn mockup dataset existed, the authors built one from five developers using varied pens, lighting, and paper backgrounds, and leveraged YOLOv5's built-in mosaic/colour/scale augmentation to compensate for its modest size. The system achieves 98.54% average recognition accuracy on a 100-image test set, outperforming four prior systems (Pix2Code, two Sketch2Code variants, Doodle2App) in the paper's comparison table, though it does not yet support hand-written text or styled (non-plain) output, both flagged as future work. The full implementation is released on GitHub.
