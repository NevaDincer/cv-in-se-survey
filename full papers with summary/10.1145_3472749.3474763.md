# Screen Parsing: Towards Reverse Engineering of UI Models from Screenshots

- **Year:** 2021
- **Venue/Source:** UIST '21, The 34th Annual ACM Symposium on User Interface Software and Technology
- **DOI:** 10.1145/3472749.3474763

## Metadata

- **se_area:** development (with a strong reverse-engineering/maintenance flavor, since the extracted UI hierarchy is explicitly used to drive GUI code generation)
- **se_task:** reverse engineering of UI structure from screenshots (screen parsing), applied downstream to UI-to-code generation, accessibility-metadata generation, and UI similarity search
- **cv_technique:** Faster R-CNN with a ResNet-50 backbone (UI element/object detection); LSTM-based encoder–decoder transition parser with attention (stack-based graph/hierarchy prediction); Deep Averaging Network (DAN) classifier (element-group labeling)
- **platform:** mobile (iOS and Android apps)
- **rationale:** context-driven (infers structure purely from pixels when accessibility/view-hierarchy metadata is missing or incomplete); robustness (global, learned inference vs. brittle hand-written heuristics)
- **artifact_type:** full-interface (the model parses the entire screen into one complete, grounded hierarchy tree, not an isolated widget or single frame)
- **eval_method:** quantitative comparison against baselines (a heuristic system called "Screen Recognition" and a statically-trained parser) using four metrics: edge F1, F1 restricted to leaf-node edges, Graph Edit Distance, and container-match (IoU-based) score, on two large mobile UI datasets (AMP: 130k iOS screens, internal; RICO: 80k Android screens, public); additional breakdown of performance by screen complexity (number of elements) and qualitative failure-case analysis
- **challenges:** end-to-end accuracy is bottlenecked by the upstream object detector (errors/missing detections propagate into hierarchy prediction, as shown by the "RCNN Oracle" upper bound not reaching 1.0); training data required heavy filtering because many screens had incomplete/missing ground-truth view hierarchies (e.g., only ~40k of the AMP screens were usable); the group-labeling classifier does not model joint probabilities across multiple groups; performance degrades noticeably past ~32 elements per screen; generated SwiftUI code omits style/appearance information (colors, font sizes); the model is constrained to output single connected directed trees, which is a simplifying assumption about UI structure.

## Summary

This paper introduces "screen parsing": the task of predicting a structured, hierarchical UI model (analogous to a view/presentation hierarchy) directly from a screenshot, borrowing techniques from NLP dependency parsing. The pipeline has three learned stages: a Faster R-CNN detector locates and classifies UI elements on the screen; a stack-based, LSTM encoder–decoder transition parser (with attention over detected elements) incrementally builds a directed tree connecting all elements via Arc/Emit/Pop actions; and a Deep-Averaging-Network classifier labels the resulting intermediate group nodes (e.g., Tab Bar, List Item, Toolbar) from a fixed per-dataset label set. A main methodological contribution is training the parser with a "dynamic oracle," which admits multiple equally-optimal action sequences per tree rather than one canonical sequence, yielding up to 23% better performance than a standard static-oracle training procedure, since UI hierarchies (unlike short NL sentences) can be very deep with exponentially many optimal derivations. The system is trained and evaluated on two large mobile datasets (AMP/iOS and RICO/Android) and consistently beats a heuristic accessibility-metadata baseline ("Screen Recognition") across F1, graph-edit-distance and container-match metrics, notably because it is "abstractive" (can build deep, multi-level groupings) where heuristic approaches largely cannot. A striking design choice is defining three formal desiderata for valid screen-parse output (complete, grounded, abstractive) and using them to systematically compare screen parsing against related tasks (UI element detection, GUI Skeleton generation, scene graph generation). The paper closes with three demonstrator applications built directly on the predicted hierarchy: UI-embedding-based similarity search, improved accessibility/navigation-order metadata generation for screen readers, and a SwiftUI code generator that walks the predicted tree with a compiler-style visitor pattern.
