# GUI-Guided Test Script Repair for Mobile Apps

- **Year:** 2022 (journal publication; earlier preliminary results reported in a 2019 ICSE companion paper)
- **Venue/Source:** IEEE Transactions on Software Engineering (TSE), Vol. 48, No. 3, March 2022
- **DOI:** 10.1109/TSE.2020.3007664

## Metadata

- **se_area:** Maintenance (test script repair/regression testing)
- **se_task:** Automated repair of broken GUI test scripts for mobile apps (Android and iOS) after app updates, treating the app as a black box (no source code, DOM, or accessibility-tree access required)
- **cv_technique:** Canny edge detection + contour detection (to identify GUI element boundaries from screenshots, with edge dilation to merge character-level contours into word-level ones); Optical Character Recognition via the Microsoft Azure Cognitive/Cloud-based Computer Vision API (MSCVA) to extract and classify textual vs. graphical elements, including a dark-mode heuristic that inverts pixel colors before OCR when average screen brightness is low; SIFT (Scale-Invariant Feature Transform) feature-descriptor matching to compare graphical (icon/image) elements for similarity.
- **platform:** Mobile (Android and iOS)
- **rationale:** Robustness/ease of use (fully automatic, requires no manual model construction, and is applicable to closed-source or obfuscated apps where static analysis and reverse engineering are infeasible, a main motivation given industry outsourcing of mobile testing); context-driven (region-based screen matching distinguishes blocking, background, and content regions to reflect how differently these regions affect user-perceived screen equivalence).
- **artifact_type:** Full-interface matching at the screen level (via region decomposition into blocking/background/content regions) combined with localized matching at the individual GUI-element level (textual and graphical element matching) to support step-by-step test action repair.
- **eval_method:** Empirical evaluation on 22 real-world open-source Android apps and 6 corresponding iOS apps; effectiveness measured via five custom metrics (NAE, actions executable; NAT, actions retained; NAP, actions with preserved semantics; NAR, actions repaired; SC, statement coverage); efficiency measured via wall-clock time breakdowns (recording, checking, local/global repair construction); robustness analysis via sensitivity testing of four matching thresholds; comparative evaluation against the model-based CHATEM baseline (with and without manually completed models) on 9 apps; manual verification of repair correctness by two postgraduate students acting as independent judges; separate applicability study on the iOS subset (RQ5).
- **challenges:** Authors self-report: (1) major/drastic GUI redesigns make it difficult to find a matching destination screen or construct a repair sequence, since METER's search over candidate elements and replacement action forms is intentionally limited for performance; (2) functionality deletion can make repair impossible; (3) the screenshot-based matching is a "weak oracle": when multiple test actions produce visually similar destination screens, METER can select an incorrect repair (6 such cases found via manual review); (4) technical limitations of the underlying CV/OCR libraries (e.g., MSCVA failing to recognize very small text) block some repairs; (5) backtracking after a failed repair attempt (by restarting and replaying the partial script) may not fully restore app state if the attempted action had a persistent side effect (e.g., deleting a file); (6) GUI-matching thresholds were tuned empirically based on the authors' experience with common mobile screen sizes/fonts, raising generalizability concerns across devices; (7) the pool of subject apps skews toward open-source apps, and only 6 iOS apps were available as counterparts, limiting external validity.

## Summary

This paper presents METER, a black-box approach to repairing broken GUI test scripts for mobile apps that relies entirely on computer vision techniques applied to app screenshots, rather than on source code, DOM structure, or platform-specific accessibility metadata. The main motivating observation is that human testers, when fixing a broken script, typically look at the app's GUI rather than its code to identify what changed and infer a plausible fix. METER automates this visual-comprehension process. Given a base-version app, an updated version, and existing test scripts (with intentions recorded by first executing them on the base version), METER determines whether each test action still achieves its original screen transition on the updated app via a region-based screen-matching algorithm: screens are decomposed into blocking (e.g., dialogs, slide-over menus), background (e.g., nav/tab bars), and content regions, each represented by its extracted textual and graphical GUI elements. Textual elements are matched by word-set similarity; graphical elements by SIFT feature-descriptor overlap; element boundaries are found via Canny-based contour detection with rules to filter noise (too small/large/slim/fat contours) and merge adjacent word fragments recovered via Azure's OCR service. When a test action's original transition is not preserved, METER searches locally (within the current screen) and then globally (across the whole app) for a counterpart of the original target element, and constructs a bridging sequence of navigation actions using a graph of previously observed app behaviors (intentions), validating candidate sequences dynamically. Evaluated on 22 Android and 6 iOS real-world apps, METER preserved 63.7% and 38.8% of test actions broken by GUI changes on the two platforms, respectively, and produced repairs judged correct in essentially all manually reviewed cases. A notable comparison against the model-based CHATEM baseline showed METER achieves comparable effectiveness fully automatically, whereas CHATEM required tens of hours of manual model construction to reach similar quality, highlighting the practical advantage of METER's black-box, CV-driven design for closed-source or difficult-to-instrument mobile platforms.
