# Context-aware Bug Reproduction for Mobile Apps

- **Year:** 2023
- **Venue/Source:** 2023 IEEE/ACM 45th International Conference on Software Engineering (ICSE)
- **DOI:** 10.1109/ICSE48619.2023.00196

## Metadata

- **se_area:** Maintenance / Testing (bug reproduction as a precursor step to debugging)
- **se_task:** Automated crash/bug reproduction from natural-language bug reports for mobile (Android) apps
- **cv_technique:** ResNet-based image encoder (icon classification model from prior work, Mehralian et al.) used as one modality within a multi-modal Cross-Encoder neural matching network; icon/image features are fused with a DistilBERT text encoder's hidden state via a fully-connected layer to produce a step-to-GUI-event similarity score
- **platform:** Mobile (Android)
- **rationale:** Context-driven (the core motivating rationale: it uses local context, i.e., nearby/sibling/parent/child component text and icon image, and global context, i.e., nearby state-transition information in a State Transition Graph, to compensate for missing/misleading GUI component names); robustness (multi-modal fuzzy matching plus global path planning is designed to be robust to missing reproducing steps, ambiguous/duplicate components across pages, and noisy natural-language descriptions, and is explicitly evaluated for robustness under text mutations)
- **artifact_type:** Localized (individual GUI component icon images/textual attributes matched against reproducing steps) combined with temporal (sequence of GUI events / State Transition Graph traversal over time to reproduce a crash path)
- **eval_method:** Empirical comparison against two state-of-the-art baselines (ReCDroid, ReCDroid+MaCa) on 102 crash bug reports from 69 Android apps across three datasets (ReCDroid's dataset, AndroR2, and a newly collected GitHub-derived dataset); metrics include reproduction success rate and reproduction time (RQ1); step-matching accuracy via Hit@k (k=1,3,5,10) and Mean Reciprocal Rank against ReCDroid and MaCa matching modules (RQ2); a user study with 21 graduate students/practitioners comparing automated vs. manual reproduction and collecting 5-point Likert usefulness ratings (RQ3); a robustness study using EDA (Easy Data Augmentation) text mutations at 10%/20% mutation rates on 30 reports (RQ4)
- **challenges:** Assumes each reproducing step corresponds to a single GUI interaction, which does not hold for abbreviated multi-step actions (e.g., "create a contact") or steps requiring common-sense inference (e.g., "click the big button"); cannot reproduce bugs requiring specific prior knowledge/credentials (e.g., valid username/password); does not cover all runtime actions (e.g., hardware-dependent operations like Bluetooth/NFC, fast continuous clicking) due to emulator/engineering limitations; relies on platform-specific tools (Droidbot for exploration, Appium for execution) that would need replacement for other platforms (iOS/web); pre-exploration (STG construction) is time-consuming, though amortizable across multiple bug reports for the same app; large mutations (20%) in reproducing-step wording can change semantic meaning even for humans, reducing reproduction success

## Summary

ScopeDroid is a context-aware approach for automatically reproducing crashes in mobile apps from natural-language bug reports. It addresses four practical challenges: missing or misleading component names, incomplete/missing reproducing steps, ambiguous components repeated across pages, and the tendency of prior greedy-matching approaches to lose global context. The pipeline has three stages. First, it builds an initial State Transition Graph (STG) via automated exploration (Droidbot) and extracts ten types of textual attributes per GUI component (type, displayed text, content description, hint, resource id, absolute location, and four contextual attributes drawn from sibling/parent/child/neighbor components), plus the component's cropped icon image. Second, a multi-modal neural matching network, combining a DistilBERT-based Cross-Encoder over concatenated reproducing-step and component text with a ResNet-based icon-image encoder, fused via a fully connected layer, computes a fuzzy similarity matrix between every reproducing step and every candidate GUI event, trained using a novel heuristic-based synthetic data-generation method (leveraging linguistic patterns and the Rico dataset) rather than costly manual labeling. Third, a path-planning algorithm scores candidate GUI-event sequences using a weighted combination of matching accumulation, a length penalty (to avoid meaningless loops), and goals-scored (steps completed), while iteratively enriching the STG as new states/components are discovered during guided exploration, until a crash is triggered. Evaluated on 102 real crash reports from 69 Android apps, ScopeDroid reproduces 63.7% of crashes, outperforming ReCDroid and ReCDroid+MaCa baselines by 32.6%–38.3%, with substantially higher step-matching accuracy (Hit@1 of 53–61% vs. 17–38% for baselines) and favorable developer usefulness ratings (mean 4.14/5) despite occasionally being outperformed by expert manual reproduction on complex reports; a data-augmentation-based robustness study shows graceful degradation under moderate wording perturbations.
