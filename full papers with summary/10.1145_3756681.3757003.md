# LLM Code Customization with Visual Results: A Benchmark on TikZ (vTikZ)

- **Year:** 2025
- **Venue/Source:** EASE 2025 (28th International Conference on Evaluation and Assessment in Software Engineering)
- **DOI:** 10.1145/3756681.3757003

## Metadata

- **se_area:** Development (AI-assisted code generation/editing, feature location within source code)
- **se_task:** LLM-based code customization/editing of TikZ (LaTeX graphics) code to achieve a specified visual change described in natural language, requiring feature location (finding the code responsible for a visual element) and correct code patch generation
- **cv_technique:** None used as a core algorithmic component of the proposed benchmark's evaluation pipeline (which instead uses rendered-image exact/parameterized matching and code-similarity metrics). CV/VLM techniques are explored only as a discussed, empirically-tested-but-rejected alternative: Vision-Language Models (Llama-3.2-Vision, GPT-4o-mini) used as automated "oracles" to judge whether an image reflects an applied instruction (found unreliable, misclassified 20-51% of test cases); object detection (zero-shot and fixed-vocabulary) and tools like OmniParser/Gemini Spatial are discussed as potential but limited approaches for localizing image regions to edit
- **platform:** General (TikZ/LaTeX vector graphics code; explicitly framed as relevant to broader visual-output-generating domains: SVG, web/HTML-CSS, 3D modeling/Blender, p5.js)
- **rationale:** Ease of use (aims to enable non-experts to customize visual code via natural language instructions without deep TikZ/programming expertise); robustness (parameterized ground-truth framework designed to avoid unfairly penalizing valid alternative code solutions)
- **artifact_type:** Full-interface (whole rendered image of the TikZ diagram, compared image-to-image and used as multimodal input for LMM evaluation)
- **eval_method:** Benchmark of 100 manually curated TikZ code-customization tasks (50 "scientific diagrams," 50 "animal drawings"), each with parameterized ground-truth solutions; five evaluation metrics: CompileMetric, LocationMetric, SuccessCustomizationMetric (primary, binary), SimilarityMetric (CrystalBLEU), LineMetric (complementary); Best-of-N sampling (N=1 and N=5) across 6 LLM/LMM configurations (Llama-3.1-8B, Mixtral-8x7B, Llama-3-70B, Llama-3.3-70B, DeepSeek-R1-Distill-Llama-70B, GPT-4o with and without image input); human-in-the-loop annotation of 300 generated variants (human_score, human_comment) via a custom reviewing tool; separate preliminary experiment testing VLMs (Llama3.2-Vision, GPT-4o-mini) as automated visual-correctness oracles
- **challenges:** Best-performing model (GPT-4o) succeeds on only ~28% of the 100 tasks even with 5 attempts (Best-of-N=5), and only 13% in one-shot, indicating current LLMs are far from reliable at this cross-modal code-editing task; feature location (identifying which code corresponds to a visual element to edit) is a major failure mode (LLM "does not find the feature" in 67 of 225 analyzed failures); adding image input to GPT-4o gave only marginal/inconsistent improvement, suggesting a lack of multimodal consistency; VLM-based automated visual oracles were shown to be unreliable (20-51% misclassification rates), so a fully vision-based automatic evaluation pipeline is not yet feasible; the vTikZ dataset is small (100 examples) and TikZ itself is argued not to require "full" SE expertise, limiting generalizability to broader SE contexts

## Summary

vTikZ is a benchmark for evaluating whether Large Language Models can correctly customize existing TikZ (LaTeX vector graphics) code to satisfy a natural-language visual editing instruction (e.g., "add a third pair of wings to the bee"), a task requiring feature location within the code, generation of a syntactically valid patch, and alignment between the resulting rendered image and user intent. The authors construct a dataset of 100 manually curated TikZ editing scenarios (drawn from LaTeX StackExchange and the nllg/datikz dataset) with a novel "parameterized ground truth" framework, using placeholder directives like §range() and §choice(), that allows multiple valid code solutions to be recognized rather than penalizing correct-but-different edits, plus a custom human-in-the-loop reviewing tool used to annotate 300 generated variants. They evaluate six open- and closed-source LLMs/LMMs (Llama-3.1/3/3.3, Mixtral, DeepSeek-R1-Distill, and GPT-4o with/without image input) using five metrics including a primary binary SuccessCustomizationMetric, finding that even the best model (GPT-4o) succeeds on only 13% of tasks in a single attempt and 28% with five attempts (Best-of-N), with the dominant failure modes being failure to locate the correct code region to edit (67/225 analyzed failures) and correct-location-but-wrong-edit (65/225). Critically for this survey's CV-in-SE scope, the paper explicitly investigates using computer vision as an automated oracle for grading generated images (via Vision-Language Models like Llama-3.2-Vision and GPT-4o-mini, and discusses object-detection-based region localization) but finds these approaches unreliable (VLM oracles misclassified 20-51% of samples), and therefore this benchmark's actual reported results use code/image exact- and parameterized-matching rather than a learned visual judge, meaning the CV/VLM component functions as a discussed limitation and future-work direction rather than a validated method used to produce the paper's core empirical findings, as flagged above.
