# DeepLSH: Deep Locality-Sensitive Hash Learning for Fast and Efficient Near-Duplicate Crash Report Detection

> **SCOPE WARNING**: This is a software maintenance and data-mining paper on crash-report (stack trace) deduplication using locality-sensitive hashing and a Siamese neural network. It contains no computer vision task or visual input of any kind: stack traces are one-hot encoded text sequences processed with CNN filters. The only CV connection is that the compared baseline (CNNH+LSH) was originally designed for image retrieval and is repurposed here for text; the authors explicitly state their objective is not image-related. This paper likely does not belong in a CV-in-SE survey.

- **Year:** 2024
- **Venue/Source:** ICSE '24 (46th International Conference on Software Engineering), Lisbon, Portugal, ACM
- **DOI:** 10.1145/3597503.3639146

## Metadata

- **se_area:** Maintenance (automatic crash bucketing / bug triage)
- **se_task:** Near-duplicate crash report (stack trace) detection and retrieval for triage automation
- **cv_technique:** Siamese deep neural network with 1D convolutional filters over one-hot encoded stack-trace sequences (CNN/CNN-LSTM/Autoencoder-style feature extractors are mentioned as interchangeable options); custom locality-sensitive-hashing-preserving loss function with binarization regularization; compared against MinHash, SimHash, and CNNH+LSH (a deep hashing method originally proposed for image retrieval)
- **platform:** General (backend/server-side software maintenance tooling; no GUI, mobile, web, or game context)
- **rationale:** Not CV-driven; the technique is applied to text (Java stack traces), not images or visual data. Rationale for the underlying approach itself is efficiency/scalability (sublinear approximate nearest-neighbor search for large volumes of textual crash reports) and robustness (preserving locality-sensitive guarantees/accuracy across many similarity metrics), not any CV-specific rationale (context-driven, robustness to visual variation, ease of use of images).
- **artifact_type:** Not applicable; no visual/image artifact is processed; input artifacts are textual Java stack traces and metadata (timestamps, versions, exception messages).
- **eval_method:** Original proprietary dataset from an ERP software vendor (Infologic) made available by the authors, consisting of real-world Java stack traces with ~499,500 training pairs plus validation/test splits; evaluated against ~12 stack-trace similarity metrics (Jaccard, Cosine/TF-IDF, Edit distance, Brodie et al., PDM/Rebucket, TraceSim, Moroo, DURFEX, etc.); metrics include Recall Rate (RR@k), Mean Reciprocal Rank (MRR), Precision/Recall/F-score for LSH-guarantee preservation, and wall-clock runtime analysis (24–27s average for 100 million queries vs. hours for exact k-NN linear scan); baselines: exact k-NN linear scan, standard LSH (MinHash, SimHash), and CNNH+LSH (deep hashing baseline adapted from image retrieval literature). No user study.
- **challenges:** Authors report that MinHash/SimHash are each tailored to a single similarity measure (Jaccard/Cosine only) and cannot generalize to the specialized stack-trace similarity metrics used in practice; the CNNH+LSH baseline, when adapted from its original image-retrieval design, shows considerable degradation in search performance and low precision (false positives) on stack-trace metrics based on Levenshtein/edit distance. As future work, the authors note the method has only been evaluated on proprietary Java stack traces and intend to test on other public/non-Java datasets and other text-similarity tasks (e.g., Word Mover's Distance with NLP techniques). (These are the authors' own stated limitations/future-work items rather than an explicit "Limitations" section.)

## Summary

DeepLSH addresses automatic crash bucketing (grouping near-duplicate software crash reports, i.e. Java stack traces, to speed up bug triage) by learning locality-sensitive hash functions that approximate arbitrary, non-standard stack-trace similarity measures (e.g., PDM/Rebucket, TraceSim, Brodie et al.) for which no exact LSH family exists. The core contribution is a Siamese deep neural network trained end-to-end with an original loss function that directly optimizes the locality-sensitive property (collision probability monotonically increasing with similarity), combined with regularization terms that handle the non-smooth binarization step required to produce discrete hash codes. Given a query stack trace, the learned hash function allows constant-time approximate nearest-neighbor retrieval via standard (L,K)-parameterized LSH hash-table lookup, instead of an expensive pairwise similarity computation across the entire historical crash database. The method is evaluated on a large real-world industrial dataset of over 100,000 stack traces against roughly a dozen similarity metrics, showing it nearly matches MinHash (Jaccard) and outperforms SimHash (Cosine) while generalizing to metrics neither technique supports, and reduces query time from hours (exact linear scan) to about 24–27 seconds for 100 million queries. A distinctive detail is that DeepLSH repurposes a CNN-based deep-hashing architecture (CNNH+LSH) originally built for image near-duplicate retrieval, applying its convolutional filters to one-hot encoded stack-trace tokens instead of pixels, and shows this image-oriented baseline underperforms substantially on text-based, edit-distance-style similarity metrics.
