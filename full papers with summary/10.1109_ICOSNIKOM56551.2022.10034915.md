# Making DelProctor Proctoring Applications Using OpenCV

- **Year:** 2022
- **Venue/Source:** ICOSNIKOM 2022 (IEEE International Conference of Computer Science and Information Technology)
- **DOI:** 10.1109/ICOSNIKOM56551.2022.10034915

## Metadata

- **se_area:** Development (requirements/domain analysis, design, and implementation of a web and client application). The CV component itself supports an end-user-facing proctoring function, not an SE lifecycle task in the traditional sense; the SE angle here is that the application itself was engineered using SE process stages, not that CV is applied to SE artifacts.
- **se_task:** Building an AI-based online-exam proctoring system (DelProctor): identity/face verification of examinees, and detection of exam-fraud behaviors (multiple faces, head-direction/gaze deviation, prohibited objects such as phones or books, unauthorized multi-monitor setups) during online exams administered through a Moodle LMS plugin
- **cv_technique:** OpenCV library functions for object detection (bounding-box object recognition, e.g. detecting phones or books), face recognition and face matching (identity verification against a stored face sample), and head-direction/head-movement detection, all classical, non-deep-learning-specified OpenCV computer-vision routines, applied on the client computer's webcam feed to reduce server load
- **platform:** Web/Desktop client (a client-server web application; client-side image processing runs on the examinee's own computer, distinguishing it from server-side proctoring approaches; it also integrates as a Moodle LMS plugin)
- **rationale:** Ease of use and resource efficiency. The CV processing load was deliberately shifted to the client computer specifically to reduce server-side resource requirements, a stated design/cost rationale rather than an accuracy or robustness one. The paper is also context-driven, since the features and fraud-detection targets came from a needs-analysis questionnaire distributed to actual exam supervisors at the target institution, grounding the tool's design in real observed cheating behaviors.
- **artifact_type:** Full-interface (whole webcam video frames analyzed for face verification, object presence, and head direction) combined with localized detection outputs (bounding boxes around detected objects/faces in Figures 4 and 6 of the paper)
- **eval_method:** Small-scale field exam simulation with real IT Del students, six exam sessions across a handful of locations, with cheat-detection categories CD1 through CD5 tallied (face-matching fraud, multiple-face fraud, head-direction fraud, prohibited-object fraud, hidden-app fraud) and raw detection counts reported, along with noted false negatives in head-direction and object detection. A separate System Usability Scale (SUS) questionnaire was given to six exam supervisors (lecturers and teaching assistants), yielding an average SUS score of 66.67, rated "marginal high" on standard SUS interpretation scales. There was no comparison against baseline proctoring tools and no precision/recall/accuracy metrics for the CV components themselves.
- **challenges:** Object detection was explicitly reported by exam supervisors, through the SUS feedback, as not accurate and needing further development. The exam simulation revealed false negative errors in head-direction and object detection. The evaluation is small-scale, a handful of participants and sessions, and lacks any quantitative accuracy metrics (precision/recall) for the underlying CV components, relying instead on raw counts and subjective usability feedback. The paper does not benchmark its OpenCV-based approach against alternative CV techniques or proctoring tools, which limits generalizable conclusions about CV technique effectiveness.

## Summary

This paper documents the design and development of DelProctor, an AI-based online-exam proctoring application built for Institut Teknologi Del (IT Del), an Indonesian university, motivated by increased cheating risk during pandemic-era remote exams delivered through Moodle LMS. The authors follow a fairly conventional software engineering process: domain analysis through a questionnaire distributed to identify actual cheating behaviors observed at the institution, UML-based conceptual class modeling, low-fidelity UI mockups, and a client-server architecture chosen specifically to offload computationally expensive image processing onto the examinee's own client computer rather than a central server. They integrate the open-source OpenCV library to provide the application's core anti-cheating capabilities: face recognition for identity verification against a stored face sample, face-count detection to flag multiple people in frame, head-direction and movement detection, and object detection to flag prohibited items like cell phones or books. The system is deployed as a client application, built to load the Moodle exam page through a webview and enforce that exams only run inside the DelProctor client, plus a companion web application for administrators, lecturers, and data management. A small field evaluation with actual students running simulated exams across six sessions produced fraud-detection counts across five categories, alongside a System Usability Scale survey of six exam supervisors yielding an average score of 66.67, categorized by the authors as "high marginal" acceptability. A notable and self-acknowledged limitation, drawn directly from supervisor feedback, is that the OpenCV-based object detection component was found to be inaccurate and in need of further refinement. That admission somewhat undercuts the practical readiness of the CV components as deployed, and it reinforces this paper's position as primarily an applied case study in building a proctoring system using SE process methodology, with OpenCV serving as an off-the-shelf implementation tool rather than the object of research contribution or rigorous evaluation.
