# Towards LLM-Based Automatic Playtest

- **Year:** 2025
- **Venue/Source:** FSE Companion 2025 (33rd ACM International Conference on the Foundations of Software Engineering, Companion)
- **DOI:** 10.1145/3696630.3728700

## Metadata

- **se_area:** Testing (automated game/mobile app playtesting)
- **se_task:** Automatic playtest/functional testing of match-3 mobile games (e.g., Candy Crush-style games), generating and executing valid game moves to maximize code coverage, game score, level progression, and crash/bug discovery
- **cv_technique:** OpenCV (classical computer vision) for icon/candy recognition on game-board screenshots, detecting candy icons and their board coordinates, used to convert the visual game board into a structured numeric matrix; the paper additionally investigates but rejects direct use of an LLM's own multimodal/vision capabilities (GPT-4 Vision) for this task after finding it inaccurate for precise spatial localization of candies
- **platform:** Mobile (Android; game genre: match-3 puzzle games)
- **rationale:** Robustness / necessity (LLMs' native vision capabilities were empirically found to be unreliable for precise spatial candy-icon localization, so classical CV, OpenCV template/icon recognition, is used instead as a preprocessing step to produce a clean, LLM-consumable structured representation); ease of use (converts a visually complex, real-time game board into a simple numeric matrix that an LLM can reason over via text-only prompting, avoiding the need for the LLM to directly interpret raw screenshots)
- **artifact_type:** Full-interface (whole game-board screenshot converted into a full 2D grid/matrix representation)
- **eval_method:** Empirical comparison against three baseline testing tools (Monkey, random-based; LIT, rule-based human-like playtest; RLT, reinforcement-learning-based) over 150 iterations on an open-source match-3 game (CasseBonbons); metrics: JaCoCo line code coverage, game score, game level reached, and number of crashes triggered; ablation study isolating contributions of rule-prompt vs. few-shot example prompt vs. combined prompting strategy
- **challenges:** LLM hallucinations can generate invalid moves/solutions that fail to make progress; time-sensitivity, since LLMs' response latency may make them unsuitable for games with strict real-time constraints (e.g., racing games); scalability/generalizability is unproven beyond match-3 games, and whether the same visual-to-matrix transformation approach generalizes to other mobile game genres is left as future work; explicitly demonstrated that current multimodal LLMs (GPT-4V) cannot be trusted for precise spatial/vision reasoning in this domain, motivating the fallback to classical CV

## Summary

This paper presents Lap (LLM-based Automatic Playtest), a system for automatically playtesting match-3 mobile puzzle games (in the style of Candy Crush) using an LLM (ChatGPT/GPT-o1-mini) as the decision-making engine. A central design finding, empirically justified early in the paper, is that current multimodal LLMs (tested via GPT-4's vision capabilities) are unreliable at precisely localizing game icons/candies within a screenshot. The model correctly performs coarse image understanding but fails at fine-grained spatial queries, consistent with OpenAI's own documented limitations. To work around this, Lap uses classical computer vision (OpenCV) as a preprocessing step: it captures a screenshot of the game board via Android Debug Bridge (ADB), applies OpenCV-based icon recognition to detect each candy's type and screen coordinates, and converts the board into a structured numeric matrix (one number per candy color) that the LLM can reason over purely as text, sidestepping the LLM's weak visual-spatial reasoning entirely. The LLM is then prompted (with game rules and 15 few-shot examples of valid matching moves) to suggest swap actions, which are translated back into screen coordinates and executed via ADB swipe commands. Evaluated on the open-source game CasseBonbons over 150 iterations against three baselines (random Monkey testing, rule-based LIT, and a reinforcement-learning tool RLT), Lap achieved higher code coverage (~79%), higher game scores (27,520 vs. 14,560 for the best baseline), higher levels reached, and more crash discoveries (5 vs. 1 for the next-best tool). An ablation study shows that combining explicit rule prompts with few-shot examples is more effective than either alone. The paper is a notable example of a hybrid CV+LLM pipeline where classical, deterministic computer vision (OpenCV) is deliberately chosen over an LLM's own multimodal capabilities specifically because the latter was shown empirically to be insufficiently precise for the spatial reasoning the SE task (game testing) requires.
