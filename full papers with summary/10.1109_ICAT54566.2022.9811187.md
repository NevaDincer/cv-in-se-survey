# Application of Machine Learning for GUI Test Automation

- **Year:** 2022
- **Venue/Source:** ICAT 2022 (XXVIII International Conference on Information, Communication and Automation Technologies)
- **DOI:** 10.1109/ICAT54566.2022.9811187

## Metadata

- **se_area:** testing
- **se_task:** automatic generation of automated regression-test scripts (in TCL) for an EDA (electronic design automation) tool's GUI, by converting screen-recording videos of manual/existing test executions into sequences of internal API commands
- **cv_technique:** CNN (VGG16 architecture, trained from scratch, not using ImageNet pretrained weights, with custom 1024-unit and 2-unit fully-connected output layers) for per-frame image classification
- **platform:** desktop (EDA/IC physical-design software, Siemens Calibre RealTime)
- **rationale:** ease of use / effort reduction (goal is to reallocate human tester effort away from repetitive script-writing toward review/approval tasks); context-driven (proposed as the third module of a broader 3-module framework converting requirements to test cases to video to script, and leverages video assets the organization already produces)
- **artifact_type:** temporal (frame-by-frame classification of a screen-recording video, with per-frame predicted labels aggregated into a sequential API-command script)
- **eval_method:** training/validation accuracy and loss curves only (95% max training accuracy, 94% validation accuracy, ~0.2 final loss); single case-study dataset (15 test-run recordings, 40,440 total frames, 2 classes); no comparison against non-ML baselines or other CV architectures
- **challenges:** proof-of-concept scale, only 2 GUI-interaction classes were modeled (cursor-on-DRC-button vs. elsewhere), so scalability to realistic numbers of GUI states/classes is untested; screen resolution directly affects feature-extraction quality, requiring a consistent, sufficiently high-resolution capture standard; VGG16 training is computationally expensive (significant CPU/GPU time and memory for the fully-connected layers), pushing the authors toward cloud-based training; as the number of interaction classes grows, the authors note classification-based labeling may become impractical and a clustering-based approach might be needed instead, but this is left as future work; overfitting observed after ~40 epochs required early stopping.

## Summary

This short industry paper from Siemens Digital Industries Software is a case study on bringing machine learning into GUI regression-test automation for Calibre RealTime, an EDA tool used in integrated-circuit physical design. The authors frame their contribution as the third module of a proposed three-module test-automation framework: converting natural-language requirements into structured test cases, converting test-case step sequences into video recordings (both only sketched conceptually and not implemented here), and converting an existing screen-recording video of a test execution into an automated TCL test script, which is the module the paper actually builds and evaluates. For that third module, screen recordings captured via Camtasia during automated regression runs get broken into individual frames, cleaned, class-balanced, resized to 224x224x3, and used to train a VGG16-based CNN from scratch to classify each frame, for instance "cursor resting on the DRC-run button" versus "cursor elsewhere." At inference time, a new video gets sampled frame by frame, repetitive same-state predictions are collapsed, and the resulting label sequence maps through a lookup table to internal API commands, producing an automated test script. The model reaches 95% training accuracy and 94% validation accuracy, with a final loss of 0.2. The evaluation is limited to a single two-class proof-of-concept with no comparison to baselines or ablations, and the authors are explicit that this is preliminary work, with future plans covering optimum integration timing, data augmentation, and ML architectures beyond VGG16.
