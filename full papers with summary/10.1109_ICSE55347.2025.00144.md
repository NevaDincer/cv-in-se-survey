# SeeAction: Towards Reverse Engineering How-What-Where of HCI Actions from Screencasts for UI Automation

- **Year:** 2025
- **Venue/Source:** 2025 IEEE/ACM 47th International Conference on Software Engineering (ICSE)
- **DOI:** 10.1109/ICSE55347.2025.00144

## Metadata

- **se_area:** development (UI automation infrastructure, spanning testing/bug-reproduction and robotic process automation use cases)
- **se_task:** non-intrusive reverse engineering of structured human-computer-interaction (HCI) actions, recognizing a [command][widget][location] triple (e.g., "[click][button][in popup]") for each user action performed in a desktop-application screencast, as the missing step enabling screencast-to-UI-automation-script pipelines for record-and-replay testing, bug reproduction, and robotic process automation
- **cv_technique:** a custom deep-learning video-action-recognition model using three parallel 3D Convolutional Neural Networks (one per input stream) for spatio-temporal feature extraction, trained end-to-end via joint learning (shared/concatenated feature fusion across streams) and multi-task learning (three prediction heads: two classification heads for command and widget, one LSTM-based sequence generator for free-form location phrases); Structural Similarity (SSIM) used to compute frame-to-frame similarity maps and detect/crop change regions; UIED (an existing hybrid GUI-element-detection tool) plus Google OCR used downstream in the applied tool to detect and identify the specific target widget
- **platform:** desktop (Windows, Linux, macOS; evaluated on five applications: Word, Zoom, Firefox, Photoshop, Windows 10 Settings)
- **rationale:** robustness/generality (explicitly motivated as a non-intrusive alternative to existing HCI-action-recording techniques that require OS/GUI-framework accessibility support, source-code instrumentation, or app-specific implementation assumptions, all of which fail for non-accessible-friendly custom widgets such as non-Android WebViews, and is robust to changes in screen resolution/size and widget spatial arrangement compared to raw screen-coordinate-based approaches) and ease of use (produces human-understandable structured action descriptions, similar to those found in usage tutorials and bug reports, rather than low-level system/API calls, making the output directly interpretable and reusable as automation-script boilerplate)
- **artifact_type:** temporal (the core recognition task operates over short video fragments/frame sequences representing a single user action, fusing whole-frame context, localized cropped change regions, and similarity maps across time) combined with localized (the downstream widget-identification step in the applied tool operates on individual widget bounding boxes)
- **eval_method:** constructs and labels a new dataset (7,260 video-action pairs from 288 screencasts, 12.8 hours total, across 5 desktop apps, manually labeled by two authors with 7 person-weeks of effort and inter-annotator discussion for disagreements); evaluates three research questions via 5-fold cross-validation: RQ1 overall model performance (command classification: 0.84 accuracy/0.82 F1; widget classification: 0.87 accuracy/0.85 F1; location phrase generation: 0.77 BLEU, 0.76 ROUGE, 0.51 METEOR, 2.85 CIDEr); RQ2 an ablation study across all 7 combinations of the three input streams (original frames, cropped change regions, similarity maps), showing the full three-stream joint-learning model outperforms any single- or two-stream variant; RQ3 an ablation comparing the multi-task-learning formulation against independent per-task learning and a traditional (unstructured) video-captioning baseline, showing multi-task learning most benefits the harder location-generation subtask and that unstructured captioning produces "impossible" command-widget combinations (e.g., "zoom out button in popup"); additionally a pilot user study applying an integrated screencast-to-actionscript (S2AS) tool (SeeAction + heuristic video segmentation + UIED widget detection) to 100 real Firefox bug-reproduction screencasts, comparing bug-reproduction success rates (measured via matching Externally Visible State) between six recruited participants using either the original human-written steps-to-reproduce text or the tool's generated action scripts, split by independently-annotated bug-report quality grade (Cohen's kappa 0.81 inter-rater agreement on quality grading).
- **challenges:** location-phrase generation is markedly harder than command/widget classification (e.g., confusing visually similar containers like "toolbar" vs. "address bar" or "window" vs. "popup"), since it must compose free-form phrases across many similar GUI contexts; command/widget confusions concentrate among visually or behaviorally similar classes (scroll-up vs. scroll-down, dropdown vs. button/popup, window vs. page vs. popup) and rarer classes suffer from limited training instances; the downstream UIED widget-detection component required manual tuning of two sensitive parameters (mingrade, minelearea) and still produced noisy or missed bounding boxes, propagating errors (e.g., icon misclassified as text) into incomplete or incorrect final action scripts; video segmentation, determining where one user action ends and the next begins, is identified as needing further research, since inaccurate segmentation (over-segmenting a single click into "hover"+"click", or splitting one long "select text" into many fragments) can confuse human users following the generated scripts and would similarly hurt automatic replay tools; the pilot study's overall bug-reproduction success rate using generated scripts was ~60–65%, an improvement over reproduction from original bug-report text (especially for low-quality/missing-step reports) but still well below the 100% success rate achievable with genuinely high-quality human-written reproduction steps; external validity is limited to five desktop applications, and the authors note extension to other domains (mobile, games) and alternative backbone architectures (Transformer, BERT) as future work; the pipeline compounds errors across multiple stages (segmentation → action recognition → widget detection), which the authors acknowledge is "not perfect enough to support all practical applications" yet.

## Summary

This paper addresses a specific missing link in non-intrusive UI automation: while recording HCI actions from screencasts avoids the intrusiveness of instrumentation-based recording (which requires OS/GUI-framework accessibility support or app source-code access, and thus fails on custom or non-accessible-friendly widgets), no prior technique could recognize a complete, human-understandable structured action description, "[command] [widget] [location]," such as "[click] [button] [in popup]," purely from the visual content of a screen recording. The authors propose SeeAction, a computer-vision model that processes an action screencast fragment into three complementary, spatially-aligned image-sequence streams (the raw RGB frames, SSIM-derived similarity maps highlighting where the screen changed, and cropped change regions isolating just the affected area), each encoded by its own 3D CNN for spatio-temporal feature extraction, with the three feature vectors then jointly fused and fed into three task-specific heads: two classifiers (for one of 11 command types like click/drag/scroll, and one of 11 widget types like button/checkbox/popup) and one LSTM-based sequence generator producing a free-form location phrase. To train and evaluate this model, the authors build and release the first dataset of its kind, 7,260 manually labeled video-action pairs spanning 12.8 hours of usage of five popular desktop applications (Word, Zoom, Firefox, Photoshop, Windows 10 Settings) across Windows, Linux, and macOS, achieving 0.84/0.87 classification accuracy for command/widget and reasonable BLEU/METEOR/CIDEr scores for location generation. Careful ablations show that combining all three input streams substantially outperforms any subset (confirming the value of the similarity-map and change-region channels, which suppress irrelevant visual noise present in raw frames), and that formulating the three sub-tasks as multi-task learning specifically improves the hardest sub-task (location generation) while a naive unstructured video-captioning baseline produces nonsensical command-widget pairings. Beyond the core recognition model, the paper's most practically compelling contribution is a pilot field study: the authors build a full screencast-to-actionscript (S2AS) tool by pairing SeeAction with a simple similarity-based video segmenter and an existing GUI-widget-detection tool (UIED), then apply it to 100 real Firefox bug reports with attached screencasts. In a controlled comparison, six recruited participants attempting to reproduce these bugs succeeded far more often using the tool's auto-generated action scripts (61/100) than using the bug reports' original human-written steps-to-reproduce text (38/100), with the gap being largest for bug reports independently graded as low-quality or entirely missing reproduction steps. This offers direct, if preliminary, evidence that non-intrusive screencast-based action recognition can meaningfully improve a concrete, high-value software maintenance workflow (bug triage and reproduction) beyond its use for record-and-replay test automation.
