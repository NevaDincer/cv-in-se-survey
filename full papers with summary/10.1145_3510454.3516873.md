# Gallery D.C.: Auto-created GUI Component Gallery for Design Search and Knowledge Discovery

- **Year:** 2022
- **Venue/Source:** 44th International Conference on Software Engineering Companion (ICSE '22 Companion)
- **DOI:** 10.1145/3510454.3516873

## Metadata

- **se_area:** Design
- **se_task:** GUI design search / design inspiration retrieval and knowledge discovery
- **cv_technique:** Faster R-CNN (CNN feature extraction + region proposal network) for GUI component object detection; HSV colorspace detection for primary color extraction; Optical Character Recognition (OCR) for text extraction from components; image augmentation (random resize/reposition) to bridge domain gap between runtime screenshots and app-store poster screenshots
- **platform:** Mobile (Android)
- **rationale:** Context-driven (components must be shown embedded in real, practically-composed GUIs rather than as isolated artwork); ease of use (multi-faceted search by class, size, color, text, category lowers the barrier to finding relevant design inspiration); design knowledge discovery (aggregated demographics reveal design trends/conventions)
- **artifact_type:** Localized (individual GUI components: buttons, checkboxes, switches, etc., extracted and indexed separately from their parent screens, though parent-GUI context is retained for each)
- **eval_method:** Informal qualitative evaluation via 7 professional designers (usage scenarios/think-aloud style feedback on three real design tasks); no quantitative detection accuracy reported in this companion paper (referred to prior work [5] for that)
- **challenges:** App introduction (marketing) screenshots are "poster-like" images mixed with non-GUI content (app name, promotional text) and lack any hierarchy/metadata, unlike instrumented runtime screenshots, requiring synthetic augmentation to adapt a detector trained on annotated runtime screenshots; only high-reputation companies/apps are curated for the comparison feature, limiting generality; designers reported some retrieved results are low-quality/non-professional-looking, reducing reference value; extending beyond Android (e.g., iOS, web) is left as future work

## Summary

Gallery D.C. is a web application that builds a large-scale, searchable gallery of individual GUI components (11 types: buttons, checkboxes, switches, progress bars, spinners, etc.) mined from real-world Android apps, aiming to support designers during the ideation/inspiration stage of GUI design. The system addresses three gaps in prior GUI design-search tools: lack of design practicality (existing tools show artwork rather than real, shipped designs), lack of granularity (component-level rather than whole-screen search), and lack of knowledge discovery support. Its pipeline combines two data sources: automated GUI exploration of instrumented Android APKs (yielding 68k annotated runtime screenshots) and a web-crawled corpus of 469k "app introduction" marketing screenshots, which the authors frame as an underexploited "gold mine" because they display the app's best-designed screens. Since marketing screenshots carry no hierarchy metadata, the authors train a Faster R-CNN object detector on augmented (resized/repositioned) runtime screenshots to simulate the poster-like marketing images, then use it to decompose components from both sources, yielding 32k component designs across 130k apps. The resulting web app supports multi-faceted search (component class, size, color via HSV, on-component text via OCR, app category), visual "design demographics" dashboards (piecharts, scatterplots, bar charts of component distributions), per-component detail pages with similar-component suggestions, and a head-to-head design-comparison view across companies (e.g., Google vs. Microsoft component styles). A qualitative study with 7 professional designers illustrates three usage scenarios: component-level style ideation, cross-company design-system benchmarking, and category-level design-trend discovery (e.g., social apps favoring flat, wide buttons), with generally positive feedback.
