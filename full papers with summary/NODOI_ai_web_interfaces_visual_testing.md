# Artificial Intelligence in Automated System for Web-Interfaces Visual Testing

- **Year:** 2020
- **Venue/Source:** CEUR Workshop Proceedings, Vol-2604, 4th International Conference on Computational Linguistics and Intelligent Systems (COLINS 2020), Lviv, Ukraine
- **DOI:** Not assigned (CEUR-WS conference proceedings paper, no DOI)

## Metadata

- **se_area:** testing (visual regression testing of web interfaces, integrated alongside an existing functional test suite)
- **se_task:** automated visual regression testing that detects meaningful visual changes in a web interface's GUI across versions while filtering out the pixel-level noise that strict exact-pixel snapshot comparison treats as false defects
- **cv_technique:** a comparison of two image segmentation algorithms applied to interface screenshots to isolate visual elements before cross-version comparison, the K-means clustering algorithm and the Mean Shift density-based clustering algorithm, within a system built on TensorFlow with a maintained baseline-image store that testers can review and update
- **platform:** web (case study interface is the Ukrainian International Airlines flight booking website)
- **rationale:** context-driven (a graphical interface is inherently non-static and changes frequently through upgrades and evolving requirements, so exact pixel-by-pixel snapshot comparison produces a large number of false defects from incidental rendering differences rather than genuine bugs); automation (integrating visual checks into an existing functional test suite built with Cypress, Python, and JavaScript)
- **artifact_type:** full-interface (whole-page screenshots of the tested web application, segmented and compared as complete interface states)
- **eval_method:** a qualitative case study comparing K-means and Mean Shift segmentation applied to the same screenshot of the UIA booking page's main interface, judged by visual inspection of which method preserved distinct UI elements more clearly and behaved more consistently across image resolutions; no quantitative accuracy metric, precision or recall figure, or held-out test set is reported
- **challenges:** the paper's evaluation is limited to a single qualitative case study on one interface rather than a quantitative benchmark across multiple applications; K-means required a predetermined number of clusters, was sensitive to initial center placement, and tended to over-smooth text regions; the authors state explicitly that even their improved segmentation approach does not solve all problems in tracking visual interface changes, and the system still depends on a human reviewer to accept, reject, or update flagged changes rather than fully automating the decision

## Summary

This paper proposes an AI-based visual testing system for web interfaces intended to complement traditional functional test suites built with Cypress. The authors argue that a graphical interface is inherently non-static, changing frequently through upgrades and evolving requirements, and that comparing screenshots with strict pixel-by-pixel matching produces a large number of false defects from incidental rendering differences rather than real interface bugs. To reduce this noise, the system segments each screenshot into visual elements before comparison, and the paper compares two segmentation techniques for this purpose: the K-means clustering algorithm and the Mean Shift density-based clustering algorithm. Applied to a screenshot of the Ukrainian International Airlines flight booking website's main page, Mean Shift is found to preserve distinct UI elements more clearly than K-means, avoid excessive smoothing of text regions, and produce more consistent results across different image resolutions, while K-means requires a predetermined cluster count and is sensitive to its initial center placement. The resulting system, built with Python, JavaScript, TensorFlow, and a MySQL-backed baseline image store, lets testers review detected visual changes and accept, reject, or update the stored baseline accordingly. The paper's evaluation is a single qualitative case study on one interface rather than a quantitative benchmark, and the authors acknowledge that even their improved segmentation still does not resolve all problems in reliably tracking visual interface changes.
