# DecompoVision: Reliability Analysis of Machine Vision Components through Decomposition and Reuse

- **Year:** 2023
- **Venue/Source:** ESEC/FSE '23, 31st ACM Joint European Software Engineering Conference and Symposium on the Foundations of Software Engineering
- **DOI:** 10.1145/3611643.3616333

## Metadata

- **se_area:** Requirements (machine-verifiable reliability requirements engineering) with a secondary Testing/Verification component (black-box requirement-satisfaction checking)
- **se_task:** Specifying and checking machine-verifiable reliability requirements for Machine Vision Components (MVCs) that solve *complex* vision tasks with multiple output types (e.g., object detection, instance segmentation), by decomposing the complex task into atomic subtasks and composing/reusing subtask-level requirements, experiments, and analysis artifacts
- **cv_technique:** Not a CV technique used to perform SE work; rather, the vision tasks/models under reliability analysis: object detection (Faster R-CNN, RetinaNet variants) and instance segmentation (Mask R-CNN), decomposed into localization, classification-given-localization, and segmentation-given-classification-and-localization subtasks; human-performance baselining via forced-choice image categorization tasks
- **platform:** General (safety-critical vision systems broadly, e.g., autonomous driving, medical image analysis), not tied to mobile/web/desktop/game
- **rationale:** Robustness (the central goal is quantifying/guaranteeing MVC reliability against operational scene changes such as added frost or brightness shifts, using human-tolerated perceptual thresholds as the pass/fail baseline)
- **artifact_type:** Not applicable in the GUI-artifact sense used elsewhere in this taxonomy; the "artifacts" here are full input images (transformed vs. original) fed to the MVC under test, not GUI screens, code, or natural-language artifacts
- **eval_method:** Empirical evaluation on 23 Detectron2-based MVCs (3 RetinaNet + 10 Faster R-CNN for object detection; 10 Mask R-CNN for instance segmentation) over 2 image transformations (frost, brightness) and 2 object classes (person, bus) on PASCAL VOC; ~2,900 human participants via Mechanical Turk for threshold estimation; comparison against the PASCAL-VOC-C benchmark and a "naive" non-decomposed baseline; runtime/peak-memory measurement to quantify resource savings from artifact reuse (up to 81% runtime reduction); a proved theorem (Theorem 1) that subtask requirement satisfaction implies composed requirement satisfaction
- **challenges:** (1) Internal validity inherited from the underlying ICRAF framework: test-time transformation parameters are assumed uniformly distributed, which may not match real deployment distributions; (2) external validity limited by budget: human experiments covered only two transformations (frost, brightness) and two c-tasks (object detection, instance segmentation), leaving generalization to other transformations/tasks as future work; (3) composed reliability thresholds are a conservative lower bound (minimum across subtasks), so satisfying the composed requirement does not guarantee all subtask requirements are individually tight; (4) when the composed requirement fails, the framework cannot definitively localize which subtask requirement(s) caused it without additional distance-measure development (acknowledged as future work); (5) collecting human-tolerated threshold data is inherently costly and time-consuming (tens of hours of crowdworker time per subtask), which the paper's reuse mechanism only partially mitigates.

## Summary

DecompoVision extends the prior ICRAF framework, which produces machine-verifiable reliability requirements for *single-output* vision tasks like image classification using human perceptual tolerance as the correctness baseline, to *complex* vision tasks ("c-tasks") that produce multiple output types, such as object detection (bounding boxes + labels) or instance segmentation (boxes + labels + masks). The main insight is a decomposition principle (DP): because many c-tasks can be expressed as a sequential composition of atomic subtasks (e.g., object detection = localization ⊙ classification-given-localization), both the c-task itself and its performance metrics (e.g., Average Precision as a function of a decomposable precision-recall curve) can be decomposed accordingly, without needing to decompose the MVC's internal architecture, preserving black-box analysis. This lets the framework (1) generate correctness-preservation and prediction-preservation requirements per subtask and compose them into a c-task-level requirement, (2) reuse human experiment data, requirements, and test/analysis artifacts across c-tasks that share subtasks (e.g., detection and segmentation both reuse localization and classification), and (3) localize reliability weaknesses to specific subtasks rather than reporting one opaque scalar. Evaluated on 23 real object-detection/instance-segmentation models, DecompoVision surfaces reliability gaps invisible to the PASCAL-VOC-C benchmark and a naive non-decomposed baseline, while cutting requirement-checking runtime by up to 81% through artifact reuse, notably by reusing localization/classification analysis computed for Faster R-CNN when evaluating Mask R-CNN, which is architecturally built on top of it.
